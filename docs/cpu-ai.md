# CPU の思考

コード: `rules/cpu_player.gd`（思考と調整値）、`rules/cpu_deck.gd`（CPU の編成）、
`tools/cpu_match.gd`（CPU どうしの 1 局）、`tools/cpu_matches.gd`（何局も回す集計）。
テスト: `tests/rules/test_cpu_player.gd`、`tests/rules/test_cpu_danger.gd`（危険の見積もり）、`tests/rules/test_cpu_deck.gd`、
`tests/tools/test_cpu_match.gd`。スキルごとの使い方のテストは、そのスキルのテスト（`tests/rules/skills/`）。

CPU は 1 人のプレイヤーとして、移動・攻撃・樽の攻撃・盾の攻撃・回復・スキル・必殺技・進化先の選択・ターン終了を自分で選び、対戦を最後まで進める。
中ボスを狩って聖遺物を取るかどうかも、自分で決める（`docs/relic-buff.md` の「CPU」）。

## 形

    var cpu := CpuPlayer.new()
    battle.apply(cpu.next_action(battle))

- `next_action(対戦)` は、いまのフェーズのプレイヤーの次の行動（`BattleAction`）を 1 つ返す。**対戦の状態は変えない。**
  決着のあとと中立のフェーズでは `null`。返す行動は、必ず `Battle.can_apply()` が受け付ける。
- ノードに依存しない。画面は、返ってきた行動を人の操作と同じに `Battle.apply()` へ渡して、イベントを再生する。
- 1 体の駒は「動く → 攻撃・回復・スキル・待機」の 2 回に分けて返る（動かないときは、攻撃・回復・スキル・待機の 1 回）。全部の駒が終わったら `EndPhaseAction` を返す。
- 進化先を選ぶのを待っている駒がいれば、`EvolveAction` を返す。
- 必殺技を使えて、いま使うのが得なら、駒を動かす前に `UseUltAction` を返す（下の「必殺技」）。
- 1 つのインスタンスを、どの対戦・どちらのプレイヤーにも使い回せる。覚えているのは盤面の歩数の表だけで、
  使い回しても作り直しても、同じ状態からは同じ行動を返す。

## ルールとのつなぎ方

**ルールを二重に持たない。** CPU は、ルールの計算（射程、ダメージ、移動範囲、経験値）を自分では書かない。

- 選べること（動けるマス、いまの位置から攻撃・回復できる相手）は `Battle.options()` に聞く。
- 行動の結果は、`Battle.clone()` に `apply()` して、**起きたイベント**から読む（ダメージ、撃破、回復、経験値、レベルアップ、決着）。
  「動いてから攻撃する」手は、複製の上で実際に動いてから攻撃して確かめる。ルールが変われば、CPU の読みもそのまま変わる。
- 相手が次の番に攻撃・スキルを届かせうるマスは、ルールの問い合わせの脅威範囲（`Threat.against`。`docs/threat-range.md`）に聞く。
  画面が相手の駒を選んだときに塗るマスと同じもの。
- CPU が自分で持つのは、**どの手が良いかの見積もり**（下の「調整値」）と、**候補を絞るための目安**だけ:
  - 攻撃・回復の候補は「動けるマス（ポータルの先も含む）のどれかから、射程の歩数の中にいる相手」に絞る。届くかどうかは、上のとおりルールに聞く。
    攻撃する手で立つマスは、ルールの問い合わせで、間に盾があるマスと、相手が煙幕に守られるマスを除いて選ぶ（`docs/field-effects.md`）。
  - 遠くの目標への近さは、盤面を上下左右にたどった歩数で測る（駒は無視。駒の乗っているポータルは通れない扱い。樽と盾のマスは通れない）。

## 乱数

**CPU は乱数を使わない。** 同じ状態からは、いつも同じ行動を返す。`Battle.rng` も進めない（先読みは複製の上でする）。
対戦の結果は、盤面と `Battle` のシード（中立の駒の湧きと狙い）だけで決まり、同じシードなら同じ対局になる。

## 駒を動かす順

後衛 → 前衛 → 奇襲 → 回復 → 将（`ROLE_ORDER`）。同じ役割なら、駒の番号の順。

奇襲は、前衛と後衛のあとに動く。危険の見積もりは駒を動かすたびに作り直すので、先に動いた味方が敵を倒していれば、
そのぶん危険の減った盤面で、踏み込む先を選べる。

試作の画面は、この順に返る行動を 1 つずつ再生する。駒が動き出す前にカメラを寄せ、1 体の行動が終わるたびに間を置く
（動かずに待機するだけの駒には、寄らず、間も置かない）。CPU の番の間は、下の帯に「相手（CPU）の番」と出る。
くわしくは `docs/battle-view.md` の「相手を CPU にする」（`prototype/board_prototype.gd` の `_run_cpu`）。

## 手の選び方

まだ動いていない駒は、「どこへ動くか」と「そこで何をするか」の組をすべて比べ、価値の合計がいちばん高い組を選ぶ。

    手の価値 = 行動の結果の価値（攻撃・樽・盾・回復・スキル。何もしなければ 0） + 立つマスの価値

動いたあとの駒は、いまの位置から選べる攻撃・樽・盾・回復・スキルのうち、結果の価値がいちばん高いもの。得になるものが無ければ待機。

樽を攻撃する手は、樽の周り 8 マス（爆発が届く）をなるべく避けて立つマスを選ぶ。

### 行動の結果の価値

複製の上でその行動をして、起きたイベントを足し合わせる。

| 起きたこと | 価値 |
| --- | --- |
| 勝ちが決まる（将を倒す） | ほかのどの手よりも高い |
| 負けが決まる・引き分けになる（樽で自分の将が倒れる） | ほかのどの手よりも低い（選ばない） |
| 敵にダメージ | ダメージ × 2（将は × 6、中立の駒は × 0.5。中ボスは、削ってよいと見たものだけ × 1。そうでなければ減点して、削らない。`docs/relic-buff.md` の「CPU」） |
| 敵を倒す | 60 + コスト × 10（回復役は + 10）。中立の駒は 15。中ボスは聖遺物の価値（40 + 自分の駒の数 × 12）と、残っていた HP を削るぶん |
| 倒せなかった相手 | 残った HP × 0.2 を引く（HP の少ない相手を先に狙う） |
| 自分の本陣の近く（5 マス以内）の敵 | ダメージの価値を 1.5 倍 |
| 自分の本陣に乗っている敵 | ダメージの価値を 2 倍、倒す価値に + 100 |
| 味方にダメージ（樽の爆発） | 敵への同じダメージの 1.5 倍を引く |
| 味方を回復 | 回復量 × 2 + 5。減っている割合 × 10 を足す。将なら + 10 |
| 経験値が入る | 経験値 × 0.5。レベルが上がれば + 15 |
| 相手の盾を削る | 減らした耐久力 × 0.5。壊せば + 10 |
| 敵のバリアをはがす | 2（`BARRIER_STRIP_VALUE`） + このあとに動ける味方（回復役を除く）のうち、その敵に届きそうな駒（移動力 + 射程の歩数の中）のいちばん強い攻撃（その敵の HP まで） × ダメージの価値 × 0.6（`BARRIER_STRIP_RATE`）。味方のバリアがはがれれば、2 を引く |
| スキルを使う | 起きたイベント（ダメージ、回復など）は上の行のとおり。それだけで決まらないスキルは、スキルごとの見積もり（下の「スキル」） |

中立の駒を狩る得は、ほぼ経験値で決まる（もう育たない駒は、わざわざ狩りに行かない）。
中ボスは、価値の大半を止めに置く（削っただけでは、止めを相手に取られる。`docs/relic-buff.md` の「CPU」）。

### 立つマスの価値

- **目標への近さ**: 目標まであと 1 マスにつき、役割ごとの値を引く。
- **危険**: 次の相手の番（と中立のフェーズ）に受けうるダメージ（下の「危険の見積もり」）1 につき、役割ごとの値を引く。
  受けうるダメージが HP 以上のマスは、さらに引く。この行動で倒す相手からのぶんは数えない。
- 動くだけの手（攻撃も回復もしない）は、危険を重く見る。手を出さずに敵の届くマスへ入ると、先に殴られるだけになるため。
  前衛だけは構わず前へ出て、盾になる。
- **長引いたら踏み込む**: ターン 20（`BOLD_FROM_TURN`）から 40（`BOLD_BY_TURN`）にかけて、動くだけの手の危険の重さを、攻撃する手の重さまで下げる
  （互いに届かないところで待ち合って、決着しないのを防ぐ）。
- **味方から離れすぎない（奇襲）**: 敵の駒を狙っている奇襲は、味方の前衛・後衛のいちばん近い駒から 4 マス（`SUPPORT_DISTANCE`）より
  離れた 1 マスにつき 5（`ISOLATION_WEIGHT`）を引く。目標へ 1 マス近づく価値（下の「調整値」）より大きいので、軍の先へ 1 体で走らない。
  倒せる手の価値はこれより大きいので、倒せるなら離れても踏み込む。前衛も後衛も残っていなければ、見ない。
  中ボスや敵の本陣を目標にしている間も、見ない。
- **敵の本陣のマス**: 立つ価値を足す（奇襲 150（`HQ_VALUE_RAIDER`）、それ以外 60（`HQ_VALUE_OTHER`）。回復役と、戦える駒の残っている軍の将は 0）。
  そこで占拠を続けている駒は、続けた回数 × 400（`HQ_HOLD_VALUE`）を足す（離れない）。
  目標にしていなくても、動ける範囲に空いた敵の本陣があれば、この価値で乗りに行く。奇襲は、立つ価値が倒されうるマスの減点（下の「調整値」）より大きいので、
  倒されうるマスでも、受けうるダメージがよほど大きくなければ乗る。**これは決めたこと**: 倒されうる本陣には乗らない版と対戦させると、
  乗る版のほうが強かった（乗られた側は、本陣へ駒を戻して奇襲を倒す手番を使わされる）。
  本陣を**目標にして遠くから向かう**のは、倒されないときだけ（下の「役割ごとの目標」）。
- **自分の本陣のマス**: 将が本陣におらず、敵が 10 マス（`GUARD_RADIUS`）以内にいれば、奇襲のほかの駒が立つ価値 80（`HQ_GUARD_VALUE`）を足す
  （乗っていれば、敵は占拠できない）。
- 同じ価値なら、巡航しない。

### 危険の見積もり

「その駒がそのマスに立っていたら、次の相手の番（と中立のフェーズ）に、最大でどれだけのダメージを受けうるか」。
`CpuPlayer.danger(対戦, 駒の番号, マス)` でも読める（状態は変えない）。届く敵ごとに、その敵のいちばん強い 1 回ぶんを足す。

- **届くマスと量**: 敵の脅威範囲（`Threat.against`。`docs/threat-range.md`）のまま。移動（ZOC、盾、ポータル）、射程と盾の射線、
  駒の状態（照準）、相手のスキル（ファイアボール、シャドウステップ）、相手の必殺技、アドレナリン注射でのもう一度の行動、樽の爆発、
  中立の駒の縄張りは、どれもそちらの決まり。回復役は数えない。
- **自分の煙幕の中のマス**: 煙幕に防がれないものだけを数える（隣まで寄っての攻撃、樽の爆発、スキルのダメージ。`Threat.Map.at(マス, true)`）。
- **自分のバリア**: いちばん弱い 1 回ぶんを引く（相手は、弱い攻撃で先にはがす）。
- **盾を置く価値**（`docs/skills/tactical-barricade.md`）も、置いたあとの盤面の脅威範囲で数え直す。
- 数えないもの: 森の軽減、相手どうしが道をふさぎ合うこと。

### 役割ごとの目標

| 役割 | 目標 |
| --- | --- |
| 将 | 自分の本陣。倒されうるマスからは逃げるが、そうでなければ本陣を空けず、届く敵を殴り返す（下） |
| 奇襲 | 敵の本陣（乗りに行けるとき。下）→ 中ボス（狩るとき・止めを横取りするとき）→ 敵のやわらかい駒（後衛・回復 → 奇襲 → 前衛・将の順。同じなら歩数の近いもの）を攻撃できるところまで |
| 前衛・後衛 | 中ボス（狩るとき。後衛は止めを横取りするときも）。でなければ、自分の本陣から 5 マス（`DEFENSE_RADIUS`）以内に入った敵がいれば、そのいちばん近いもの。いなければ、いちばん近い敵の駒（どちらもマンハッタン距離） |
| 回復 | 12 歩（`HEALER_SEARCH_STEPS`）以内の、減っている割合（減った HP ÷ 最大 HP）がいちばん大きい味方（将も入る）。いなければ、歩数のいちばん近い味方の戦う駒。それもいなければ将 |

- 将が逃げるかどうかは、危険の見積もり（上）で決まる。見積もりが HP 以上のマス（倒されうるマス）は大きく引く（下の「調整値」）ので、
  ほかに倒されないマスがあれば、そちらへ動く。HP より小さければ、受けうるダメージの重さは本陣から離れる重さより軽く、ふつうは本陣を空けない。
- 奇襲が敵の本陣を目標にするのは、もう乗っているとき（占拠を続ける）か、本陣が空いていて、12 歩（`RAID_STEPS`）以内で、
  いまそこに立っても倒されない（危険の見積もりが HP より小さい）とき。将が本陣にいる間は、1 体で本陣へ向かわない。
  目標にしていないときに動ける範囲に入った本陣へ乗るかどうかは、上の「敵の本陣のマス」。
- 後衛は、狙う相手から射程いっぱいに離れて立とうとする。
- 回復役は攻撃しない（ルールが攻撃を選ばせない）。
- 戦える駒（前衛・後衛・奇襲）が 1 体も残っていない軍の将は、待っていても勝てないので、前衛と同じに敵へ向かう。
- 遠くのエナジー・コアは追わない。動いた先で攻撃が届くときだけ、ついでに狩る。
- **中ボス**: 倒しきれて、横取りされないと見たときは、手の空いている前衛・後衛・奇襲が、相手の駒のかわりに中ボスを目標にする。
  相手が狩っている中ボスのそばの相手の駒は、近いものとして追い、減った中ボスへは後衛と奇襲が止めを取りに行く。
  条件と調整値は `docs/relic-buff.md` の「CPU」。

## スキル

- スキルを使う手（`UseSkillAction`）も、複製の上で使ってみて、起きたイベントから価値を読む。
- **スキルを使うために立つマスを探す。** まだ動いていない駒は、「どこに立って、どこを対象にスキルを使うか」の組を、
  動く手・攻撃する手と比べる（巡航で寄る手とも比べるので、「通常の移動で止まってバリアを張る」が選べる）。
  動いたあとの駒は、いまの位置からのスキルを、攻撃・回復・待機と比べる。
  - 対象は、スキルごとの「選ぶ価値のありそうなマス」（`SKILL_TARGETS`。スキル → マスを並べるメソッド）に絞る。
    全部のマスを複製の上で試すと、時間がかかりすぎるため。絞り方は、スキルごとの文書。
  - 対象ごとに、そこを選べるマス（通常の移動で止まれるマス）のうち、立つマスの価値がいちばん高い 1 つを選ぶ。
    いまのマスから選べる対象は `Battle.options()` の `skill_cells`、ほかのマスからは、そこへ動いた写しの駒でスキルの定義に聞く
    （`Skill.is_ready`、`Skill.target_cells`）。使えるかどうかは、複製の上で実際に動いて使って確かめる。
  - 手の価値は、ほかの手と同じ「行動の結果の価値 + 立つマスの価値」。
- 動くと外れる状態で射程が伸びている駒（照準）は、いまのマスからは伸びた射程で、ほかのマスからはもとの射程で、
  攻撃の候補と立つマスを選ぶ（`Statuses.stat_after_move`）。
- 盤に何かを置く・駒に状態を付けるスキルのように、イベントだけでは価値が決まらないものは、`SKILL_VALUES`（スキル → 見積もるメソッド）に載せる。
  見積もるメソッドは `SkillUsedEvent` と、使ったあとの複製を受け取る。見積もり方と調整値は、スキルごとの文書（`docs/skills/`）。
- 価値が 0 以下なら使わない（「明らかに得な場面」だけで使う。深くは読まない）。
- 行動を終えないスキル（シャドウステップ）は、使ったあとの複製の上で、続けてできる攻撃までを見積もりに入れる（`docs/skills/shadow-step.md`）。
  使ったあとは、動いたあとの駒と同じに、いまの位置からの攻撃か待機を選ぶ。
- 相手のスキルの危険は、脅威範囲が数えるもの（ダメージを届けるスキルと、使ったあとに移った先から攻撃できるスキル。
  アドレナリン注射でのもう一度の行動も）。上の「危険の見積もり」。

## 必殺技

- 必殺技を使えるとき（`Ults.can_use`）は、駒を動かす前に、いま使うかを決める（`ULT_USES`。必殺技 → 決めるメソッド）。
  決め方と調整値は `docs/tactical-ult.md` の「CPU」。総員突撃は、伸びた移動力で 3 体（`ASSAULT_MIN_UNITS`）以上が敵に届きそうなとき。
  魔力解放は、クールダウンの長く残った駒が、敵の近くに 1 体（`ERUPTION_MIN_UNITS`）でもいるとき（総員突撃は、数える駒がそれより少なければ、その全員）。
- 使ったあとは、いつもどおりに駒を動かす。伸びた移動力・攻撃力や、明けたクールダウンは、ルールに聞くのでそのまま読みに入る。
- 深くは読まない（「使った場合」と「使わなかった場合」のフェーズ全体を比べることはしない）。

## 進化先

駒の番号 + ターンの偶奇で、A・B を選び分ける（どちらの型も盤に出るように）。

## CPU の編成と、CPU の軍

`CpuDeck.build(軍)` が、その軍のロスターと予算（`docs/player-loadout.md`）に収まる編成を作る。乱数は使わない。

1. 4 つの役割を 1 体ずつ雇う。
2. 予算と数の上限が許すかぎり、前衛、後衛、奇襲の順にもう 1 体ずつ足す。
3. 余った予算で、前衛にアイアンシールド、奇襲にスピードブーツを 1 個ずつ順に配る。

| 軍 | 編成 | コスト |
| --- | --- | --- |
| MILITARY | シールドトルーパー（盾 2）、スナイパー、コマンドー（靴 1）、衛生兵、シールドトルーパー（盾 1）、スナイパー | 24 / 24 |
| FANTASY | パラディン（盾 1）、ソーサラー、スペルブレード、プリースト、パラディン | 18 / 18 |

**CPU の軍は、対戦を始める側が決める。** CPU は自分では軍を選ばない。
対戦の設定（`MatchSetup.set_cpu`。`docs/match-setup.md`）で軍を渡すと、この編成になる。試作では、設定画面で人が選ぶ。

## 強さの目安

次の悪手をしないことを、テストで固定している。

- 取れる将を取らない / 倒せる相手を倒さない
- 自分の将を、倒されうるマスに置いたままにする
- 自分の本陣に乗った敵を放っておく / 空いている敵の本陣に乗らない、占拠の途中で離れる
- 自分の将を巻き込む樽を爆発させる

先読みは「この 1 手の結果」と「次の相手の番に届くマス」まで。2 手先は読まない。

## 集計の道具

CPU どうしの対戦を画面なしで何局も回して、数値の見積もりを実測で確かめる。手元で回すもの（CI では回さない）。
駒・陣営の数（ダメージ、撃破、レベル、進化、必殺技、中ボス）は、決着の画面と同じ戦績の集計（`BattleStats`。`docs/battle-stats.md`）から取る。

    godot --headless --path . -s res://tools/cpu_matches.gd -- --games=120 --seed=1

| 引数 | 中身 |
| --- | --- |
| `--games=N` | 局数（既定 60）。ステージ 3 種 × 軍の組み合わせ 4 通りを順に回すので、12 の倍数にすると偏らない |
| `--seed=S` | 最初の局のシード（既定 1）。局ごとに 1 ずつ増える |
| `--max-turns=T` | このターンを超えたら打ち切る（既定 60） |
| `--decks=auto` | `auto` = CPU の編成、`even` = 両軍とも同じ役割の 6 体（前衛 2・後衛 2・奇襲 1・回復 1）で装備なし。予算は見ない（`MatchSetup.ignore_budget`） |
| `--pairings=all` | `all` = 軍の組み合わせ 4 通りを順に、`mixed` = 軍の違う 2 通り（先手を入れ替える）だけ。軍の釣り合いを見るときは、こちらのほうが同じ局数で倍の標本になる |
| `--rival=パス` | 別の版の CPU（スクリプトのパス）と対戦させる。下の「別の版と比べる」 |
| `--list=1` | 1 局ごとに 1 行（`GAME ...`。シード、ステージ、軍、勝ったプレイヤー、終わり方、ターン、必殺技の回数、倒れた中ボス）も出す。駒の種類ごとの数（`KIND ...`）、倒された駒 1 体ごとの倒され方（`FALL ...`）、倒れた中ボス 1 体ごとの倒れ方（`BOSS ...`）も付く。局を何本かに分けて並べて回し、あとで合わせるときに使う |
| `--stage=3` | このステージだけを回す（1〜3）。配置を見るときに、1 つのステージの標本を増やす |
| `--relic=wisdom` | プレイヤー1 が、対戦の始めから聖遺物を 1 つ持つ（`wisdom` = 英知、`courage` = 勇気。ゲージは足さない）。聖遺物そのものの強さを測る（`docs/relic-buff.md` の「強さ」） |
| `--hit=N`、`--level=N` | 「当たりの経験値が N だったら」「1 レベルに要る経験値が N だったら」の見積もりに使う値（既定 15、80） |

出すもの（全体、ステージごと、軍の組み合わせごと）: 局数、決着までのターン数、勝ち方の内訳（将の撃破 / 本陣の占拠 / 引き分け / 打ち切り）、
先手・後手の勝ち数、1 局あたりのレベルアップ・進化・中立の駒の撃破・駒の撃破の数、軍ごとの勝率、
雇った駒のうちレベル 2・3 に届いた割合、経験値の出どころの内訳、スキルを使った回数（スキルごと。持つ駒 1 体あたり）、
必殺技（軍ごとに、使った回数、最初に使ったターン、使った側と使わなかった側の勝率）、
中ボス（全体とステージごとに、倒れた局の割合、1 局あたりの数、倒れたターン、倒した側の勝ち負け）、
中ボスの取り合い（同じく全体とステージごとに、互角のうちに倒れた数 = 倒れた時点の戦える駒の数の差が 1 以内、相手の戦える駒が 6 マス以内にいた数、
両方のプレイヤーが削った数、相手のほうが多く削っていた止めの横取りの数と、それぞれの倒した側の勝ち負け。中ボスの番号ごと・倒したプレイヤーごとの数）、
聖遺物（軍ごとに、取った局の数、英知・勇気の数、取った局と、相手だけが取った局の勝率）、1 手を考える時間。
ステージごとの行には、軍の違う対戦での軍ごとの勝ち数も付く。最初の進化のターンは、平均と中央値。
駒の種類ごと（1 体あたり）に、倒された割合、敵のプレイヤーの駒に与えたダメージ、倒した数（樽の爆発は樽を攻撃した駒のもの。味方の巻き込みは数えない）、進化した割合も出す
（どの駒が効いているか、どの駒が働けていないかを見る）。
倒された駒の**倒され方**も、駒の種類ごとに出す（攻撃する駒だけ）: 倒された数と平均のターン、与えたダメージが 0 のまま・1 発ぶん（基本の攻撃力）以下のまま倒された割合
（「何もできずに落ちた」の目安）、ダメージを受けたのが止めの 1 回だけだった割合（一撃で落ちた。うち、レベル 1 の奇襲の一撃）、
止めを刺した駒の役割（奇襲は、同じフェーズにシャドウステップで跳んでいた割合も）。

- 同じ引数なら、いつも同じ結果になる（考える時間の欄を除く）。
- 「だったら」の欄は、同じ手順の対局で経験値だけを数え直した見積もり。数値を変えれば CPU の手も変わるので、目安として読む。

### 別の版と比べる

CPU を直したときは、直す前の版と対戦させて、強くなったかを見る。直す前の `rules/cpu_player.gd` を、
`class_name` の行を除いてリポジトリの外に書き出し、`--rival` に渡す。

    git show main:rules/cpu_player.gd | sed '/^class_name/d' > /tmp/old_cpu.gd
    godot --headless --path . -s res://tools/cpu_matches.gd -- --games=96 --pairings=mixed --rival=/tmp/old_cpu.gd

- 同じ編成・同じ盤面で、いまの CPU と別の版が 1 局ずつ先手・後手を持つ（ステージと軍の組み合わせを一巡するごとに入れ替わる。
  `--pairings=mixed` なら 12 局、`all` なら 24 局で一巡）。
- 出すもの: いまの CPU の勝ち数、別の版の勝ち数、決着しなかった局（全体と、ステージごと）。
  駒の種類ごとの表は、全体のあとに「いまの CPU の駒」「別の版の駒」に分けても出す（どの駒の使い方が変わったかを見る）。
  ほかの欄は、両方の CPU の駒を合わせた数。
- 別の版は `next_action(対戦)` を持つスクリプトなら何でもよい。ルールが変わっていて古い版が動かないときは、比べられない。
- 人の手での悪用を測るための版（ある手を狙って使う CPU）は `tools/rivals/` に置く。いまあるのは、シャドウステップで将を引きずり出す版
  （`shadow_step_pull.gd`。`docs/skills/shadow-step.md`）。

PR ごとの検査（`tools/check.sh`）に入っているのは、小さな盤面の短い 1 局が最後まで終わることだけ（`tests/tools/test_cpu_match.gd`）。
同じ 1 局を回し直して同じ結果になること、別の版の CPU を渡す入口は、長い検査（`tools/check.sh --full`）で確かめる。
