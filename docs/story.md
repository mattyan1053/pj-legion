# ストーリー

コード: `game/story.gd`（物語と話の並び、進み具合、話の流れ）、`game/story_battle.gd`（話の対戦。`docs/battle-source.md`）、
`game/story/`（物語ごとのフォルダに、物語と話のファイル。下の「物語を 1 つ足す」「物語のファイル」「話のファイル」）、`game/campaign.gd`・`game/episode.gd`・`game/story_file.gd`（ファイルを読む）、`game/campaign_list_screen.gd`（物語を選ぶ）、`game/episode_list_screen.gd`（話の一覧）、`game/card_picker.gd`（一覧の画面のキーとマウスの受け方。`docs/ui-theme.md` の「一覧の画面」）、`game/sortie_screen.gd` と `game/sortie_screen/`（出撃準備。役割ごとのファイル）、`game/talk_screen.gd`・`game/talk_figure.gd`（会話の場面と、話し手の姿）、`game/talk_log.gd`（会話のログ）、`game/deploy_map.gd`・`game/deploy_note.gd`（出撃準備の初期位置と駒の欄）、`game/open_all_key.gd`（確かめ用の解放）、`game/card_keys.gd`（物語・話のカードをキーボードで選ぶ決まり）。
テスト: `tests/game/test_story.gd`、`tests/game/test_episode_data.gd`（物語と話のファイルの書き間違い）、`tests/game/test_battle_cues.gd`（対戦の途中の会話）、`tests/game/test_placement_choice.gd`（出撃準備で決めた初期位置）、`tests/game/test_card_keys.gd`、`tests/tools/test_story_script.gd`（目次）、自動の対戦の `story`（下の「検査」）。

タイトルの「ストーリー」から物語を選び、その物語の話の一覧へ進み、選んだ話を「出撃準備 → 会話 → 対戦 → 会話」と通す。
世界は `docs/world.md`、登場人物は下の「世界と登場人物」。
会話を話の順に読むための目次は `game/story/README.md`（下の「台本」）。

## 物語

物語（Issue #49 の「ストーリーは軍の種類ごとにあっていい」）は、**軍 1 つと話の列**。`game/story/` に 1 物語 1 フォルダ
（フォルダの名前が物語の id。中に物語のファイル `story.txt` と、話のファイル）。**フォルダを置けば、物語を選ぶ場面に並ぶ**（下の「物語を 1 つ足す」）。

- 人はその物語の軍で話を進める。話をクリアすると、その物語で雇える駒・持ち物・コスト上限が増える（下の「解放」）。
- クリアの記録、出撃準備で選んだ部隊、雇える駒は、物語ごと（下の「クリアの記録」）。
- いまの物語は 3 つ: ベルク連邦の物語（MILITARY。`game/story/military/`）、リュエル騎士領の物語（FANTASY。`game/story/fantasy/`）、
  番外の短い物語「縫い代の見回り」（MILITARY。`game/story/berk_patrol/`。下の「番外の物語」）。
- 話の無い物語は、物語を選ぶ場面に「準備中」の札で並ぶ（選べない）。

部隊編成の画面のストーリー用の一覧は、物語ごと（物語の `rules` の決まり。出撃準備の「部隊編成」は、その話の物語の一覧を開く。`docs/deck-screen.md`）。

## 物語を選ぶ

`campaign_list_screen.gd`。物語をカードで並べる: 顔（その物語で人が使う軍の、将と最初から雇える駒のアイコン。青）、物語の名前、軍、紹介の 1 行（物語のファイルの `intro`。遊ぶ人が誰として、何をする物語か。カードの幅で語の途中を切らずに折り返す。3 行まで）、状態（「全 N 話」「M / N 話クリア」「全 N 話クリア」「準備中」）。
顔の並びは決まった幅の欄に収める（多ければ重ねを深くし、5 体より多い駒は「ほか N 体」。カードの中身は左右の真ん中）。

- 紹介の 1 行は、人間の言葉「ドーソンとハーデンの会話の意味が分からない、誰がどういう立ち位置なんだ」（11/21）から。最初の話を読む前に、遊ぶ人が誰なのかを渡す。

- 遊べる物語が 1 つでも、この場面は飛ばさない（物語が増えていくことを、準備中の札で見せる）。
- カードのクリック（キーボードでは、左右の矢印で選んで Enter。1〜9 のキーでも）で、その物語を選んで話の一覧へ。準備中のカードは暗く、押せない。
- カードの下の「部隊編成」で、その物語のストーリー用の部隊を組む（寄り道。「物語選択へ戻る」で、ここへ戻る）。準備中の物語には出さない。
- 「タイトルへ戻る」（右クリック・Esc でも）でタイトルへ。

## 流れ

```
タイトル ─「ストーリー」→ 物語を選ぶ ─物語→ 話の一覧 ─話→ 出撃準備 ─「出撃」→ 会話（前）→ 対戦 ─ 決着の画面 ─「次へ」（勝ったとき）→ 会話（後）─┬「次の話へ」→ 次の話の出撃準備
                              ↑                     │ ↑ └「話の一覧へ戻る」┐                ├─「同じマップで再戦」→ 対戦（何度でも）└「話の一覧へ」→ 話の一覧
                              │   「部隊編成」↓ │「出撃準備へ戻る」   │                ├─「部隊変更」→ 出撃準備（会話は飛ばす）
                              │               部隊編成（ストーリー用）    │                └─「話の一覧へ」（負けたとき）→ 話の一覧
                              └──────────────────────────────────────┘
```

- 話は物語の中で一本道。遊べるのは、並びの最初の話と、1 つ前の話をクリアした話（`is_available`）。クリアした話は、何度でも遊び直せる。
  遊べる物語の話を全部クリアしたら、タイトルのボタンは「ストーリー（クリア済み）」になる。
- 場面の並びは流れ（`docs/scene-flow.md` の「流れ」）。話は**場面の列**（下の「場面の列」）で持ち、`story.gd` の `run_of(話)` がその列を順に流れへ並べる。
  `[before]`・`[after]` で書いた話は、どれも 出撃準備・会話（前）・対戦・会話（後）。場面の節で書いた話は、書いた順（会話をいくつでも。対戦の無い話も。下の「場面の節」）。列を終えたら話の一覧。
- 会話（前）は、出撃してから対戦の前に出す（背景は話の盤。マップを選んでいきなり会話を読ませない）。1 度通ったら、その流れの中ではもう出さない
  （決着の画面の「同じマップで再戦」も「部隊変更」→「出撃」も、会話を通らずに対戦へ。見たければ話の一覧から入り直す）。
- 負けても失うものは無い。決着の画面の「同じマップで再戦」で、何度でもやり直せる。「部隊変更」で、出撃準備へ戻って部隊を替えられる。
  「話の一覧へ」で話の一覧へ（決着の画面に「タイトルへ」は出さない）。
- 負けた決着の画面には、話し手のひとこと（話のファイルの `[lost]`）を、戦績の左の板に出す（話し手のアイコンと名前の札、文。戦績と一緒に出てくる）。
  会話の場面は挟まない（再戦の手間を増やさない）。見出しの真下は、戦績が 5 行のときに縦の余りが無いので、左に置いた（人の軍の話し手は、会話の場面でも左に立つ）。
- 勝ったら「次へ」で会話（後）。勝った決着の画面には「話の一覧へ」を出さない（あとの会話を読まずに抜けないように）。読み終えたら「次の話へ」（物語の次の話の出撃準備。Enter でも）か「話の一覧へ」を選ぶ（右クリックで最後の文へ戻る。2 つのボタンは縦に積み、左右の話し手に重ねない）。選ぶ間は「スキップ」と下の案内（キーの印の並び。「クリック 次へ」）を出さない。
  物語の最後の話なら、選ばずに話の一覧へ。
- 出撃準備・会話・対戦の途中は、システムメニューの「話の一覧へ戻る」で話の一覧へ、「タイトルへ戻る」でタイトルへ抜けられる
  （流れは捨てる。決着していない対戦は確かめる）。

## 話の一覧

選んだ物語の話を、並びの順にカードで並べる（`episode_list_screen.gd`）。見出しは物語の名前。

- 見出しの下に、主な人物の欄（物語のファイルの `[cast]`。1 人ずつ、姿の額（人の軍の色。縁は国の色）・名前・立ち位置を横に並べる）。書いていない物語は「話の選択」の小見出し。

- カード: 「第 N 話」、話の名前、盤の縮図（`map_card.gd`。両軍の駒の初期位置に、陣営の色の点。右下に、その話の顔として敵の話し手の姿のアイコン（話のファイルの `[cast]` の姿。骸骨の将も））、状態（「クリア済み」「未クリア」「第 N 話クリアで開放」）、「クリア報酬」（クリアで増えるもの）。
  チュートリアルの話（`lesson` のある話）は、番号に「（演習）」が付く。
- カードは横に 1 段。幅に収まれば真ん中に寄せ、収まらなければ横に送れる。左右の端には、マップ選択と同じ余白（`UiTheme.SCROLL_ROW_EDGE`）を置き、送り切ってもカードが画面の端に付かない。開いたときは、次に遊ぶ話のカードが見えるところまで送る。
- 遊べない話のカードは暗く、押せない。話の名前と縮図（顔も）を「？？？」で伏せる（遊べるようになるまで中身を見せない）。番号・開く条件・「クリア報酬」は見せる。
- カードのクリック（キーボードでは、左右の矢印で選んで Enter。最初の矢印で次に遊ぶ話が選ばれ、遊べない話は飛ばす。1〜9 のキーでも、1〜9 話目）で、その話の出撃準備から始める。
- 下の欄に、いま雇える駒・持ち物・コスト上限（下の「解放」）。
- 「部隊編成」で、この物語のストーリー用の部隊を組む（寄り道。「話の一覧へ戻る」で、ここへ戻る）。取っておいた部隊は、出撃準備で選ばれている。
- 「物語選択へ戻る」（右クリック・Esc でも）で物語を選ぶ場面へ。

## 出撃準備

話の流れの最初の場面（`sortie_screen.gd`。「出撃」のあとに前の会話、そのあと対戦）。流れが、話と、話の対戦（`story_battle.gd`）を渡す。

- 左: **初期位置**（`game/deploy_map.gd`）。盤の縮図に、置けるマス（`Deployment.zone`。話の `deploy` か、本陣の前の 2 行。`docs/player-loadout.md`）を青で縁取り、
  味方の駒はアイコン、敵と中立の駒は点で出す。味方の駒を押して選び（金の縁）、縁取りのマスを押すとそこへ動かす（駒を押せば入れ替え。選んだ駒をもう一度押すか右クリックでやめる）。
  使い方の案内の文は出さない。押せるマス（味方の駒、選んだ駒の行き先）の上では、カーソルが指の形になる。
  選んだ駒は大きく描いて金の縁で囲み、縮図の上に名前の札を出す。マウスを乗せた駒にも名前の札を出す。
  縮図の下の**駒の欄**（`game/deploy_note.gd`）に、選んでいる駒（選んでいなければマウスを乗せた駒）の額（役割の印つき）・名前・役割（始めのレベルが 1 でなければレベルも）・
  能力値（HP・攻撃・移動・射程。持ち物と始めのレベルを含んだ値）を出す。アイコンだけで誰を動かすかを当てなくてよいように。
  縮図は、下の欄とボタンが画面に収まるよう、高さが 380 px を超えるマップ（`sortie_screen.gd` の `MAP_MAX_HEIGHT`）では 1 マスを小さく描く。
  何もしなければ、いつもの置き方（おまかせ）で始まる。「おまかせ」で戻す。部隊を選び替えたら、おまかせに戻る。
  決めた置き方は話の対戦（`StoryBattle.placement`）が持ち、「同じマップで再戦」でも同じ。「部隊変更」で戻ってきたときも残る（同じ数の部隊なら）。
  部隊も位置も決まっている話（演習。話に人の `unit` と `deploy` がある）は、見せるだけで動かせない（「この話の初期位置は固定」）。
- 見出しの右: この話で覚えること（話の `lesson`。チュートリアルだけ。決まった大きさの札に 2 行まで。`LESSON_SIZE`）。
  見出しの段に置くので、下の枠は、**どの話でも同じ場所・同じ大きさ**（`tests/game/test_steady_frames.gd` が、演習・ふつうの話・敵の多い話で比べる）。
- 右: 勝利条件（対戦の始めの「対戦ルール」と同じ札を 1 列に、欄の真ん中に寄せて。`rule_card.gd`、`BattleTexts.goal_cards`。負け方は出さない）、
  敵の部隊（文は、いつも 2 行ぶんの高さ）、出撃する部隊（見出しのすぐ下に選んだ部隊のアイコンと中身、その下に選べる部隊の並び）。
  札は 3 枚まで（`sortie_screen.gd` の `GOAL_CARDS`。右の欄の幅は 3 枚が入る幅）で、どの話も収まることをテストが確かめる。勝利条件と敵の部隊は、対戦と同じ話の戦いの定義（`StoryBattle.scenario()`。種に依らない）から読む。
  右の欄の文は `game/text_wrap.gd` で折り返す（駒や持ち物の名前を、語の途中で切らない）。
- 部隊は「既定の編成」（下の「既定の編成」）と、取っておいた、その物語の部隊（決まりの名前が物語の `rules`。`docs/deck-screen.md`）から選ぶ。
  出せない部隊（まだ解放していない駒がいる、など）は、理由つきで押せない。対戦用の部隊は並ばない。
  敵の部隊と出撃する部隊は、駒の額（将から並びの順。額の下に持ち物の印）で見せ、文では並べない。額に乗せると名前と持ち物、押すとその駒の詳しい説明（`docs/deck-screen.md` の「駒の詳細」）。
  額の並びの高さは決まっている（選び替えても、ほかの部品が動かない。テストが確かめる）。
- 「部隊編成」で、部隊編成（ストーリー用だけ）へ寄り道する。「出撃準備へ戻る」（右クリック・Esc でも）で、ここへ戻る。
  寄り道の間に取っておいた部隊が、戻ったときに選ばれている。
- 「出撃」で、選んだ部隊を話の対戦に持たせて対戦へ。選んだ部隊は覚えておき（下の「クリアの記録」）、次に出撃準備を開いたとき（次に起動したときも）選ばれている。
  覚えた部隊が無くなったか出せなくなったら、既定の編成。
- **部隊が決まっている話**（話の `[ally]` に `unit` がある。チュートリアル）は、選択肢が「この話の部隊」の 1 つだけで、「部隊編成」も出さない。
  その部隊で出撃しても、覚えている部隊（`squad`）は変えない。決着の画面の「部隊変更」も出さない。
- 「話の一覧へ戻る」（右クリック・Esc でも）で話の一覧へ（流れは捨てる）。
- 負けて「同じマップで再戦」なら、同じ部隊でやり直す。決着の画面の「部隊変更」なら、ここへ戻る（前の会話は飛ばす）。

### 既定の編成

初めて遊ぶ人が出撃準備で見て納得できる、素直な形にする（`story.gd` の `default_deck`）。CPU の編成の組み方（`CpuDeck`）は使わない
（余ったコストを前衛の盾に積むので、「シールドトルーパーに盾 3 つ ×2」のように偏る）。

1. いま雇える駒を、役割の順（前衛・後衛・奇襲・回復）に 1 体ずつ、数の上限まで繰り返して雇う（コスト上限に収まるかぎり）。
2. 余ったコストで、役割ごとの持ち物を、1 体に 1 つまで持たせる（`DEFAULT_ITEMS`。持たせられる持ち物だけ。後衛と回復は持たない）:
   前衛は古竜の鱗かアイアンシールド、奇襲は試作ジェットパックかスピードブーツ（前にあるほうを、解放していれば）。ほかの新しい持ち物は持たせない
   （どの駒に何を持たせるかは人が選ぶ。遠眼鏡を後衛に持たせると、岩山の掃討の既定の編成の 1 局が負けに変わった）。
3. 並びは役割の順（同じ種類はまとめる）。並びの順に初期位置へ置かれるので、前衛が前に出る。

どの時点で何になるかは、そのときの解放（下の「解放」）から決まる。出撃準備で「既定の編成」を選ぶと見える。

## 会話

背景に話の盤（対戦と同じ景色。`backdrop.gd`。少し暗く沈め、足元は下から夜の藍へさらに沈めて、話し手の姿を舞台に立たせる。四隅も沈める）。盤には駒を立たせる（`StoryBattle.talk_battle`）: 前の会話は、出撃準備で決めた初期位置の味方と、話の並びの敵。あとの会話は、勝ったときの盤（生き残った駒。決着していなければ初期位置の味方だけ）。駒は敵の本陣のほうを向き、HP の棒は出さない。見る中心は、盤の真ん中から味方の本陣のほうへ寄せる（`TOWARD_FRIENDS`。手前の味方が文の枠に隠れない）。下に文の枠と、話し手の名前の札（陣営の色の、角を落とした札。人の軍は青、敵は赤）。
文の枠は影の付いた板で、縁を話し手の陣営の色にする（札とつながって見え、話し手が替わると色も替わる）。話の名前は、左上に明朝で出す。
その上に、**話し手の姿**を立たせる（`talk_figure.gd`）。

- 絵は描かない。盤の駒の 3D の形（`unit_view.gd`。いまの駒の見た目の組の形で、陣営の色、進化後の金の輪も同じ）を、会話の場面の中の小さい 3D の枠（SubViewport、透明な地）に立たせる。
  どの姿にするかは、話のファイルの `[cast]` の姿（下の表。書かなければ、その陣営の将）。
- 立つ所は左右に 1 つずつ。人の軍の話し手は左、敵の軍の話し手は右。文の枠の左端・右端にそろえ、見出しと名前の札の間の高さいっぱいに立たせる（名前の札・文の枠・「スキップ」とは重ねない）。
- **話し手は、陣営ごとに何人いてもよい**（話のファイルの `[cast]`）。同じ所に立つ話し手が何人かいれば、いちばん近くに話した人が立つ（まだ誰も話していなければ、次に話す人）。
  話し手が替わると、その所の姿が入れ替わる。名前の札の色は陣営の色のまま。
  名前の札の幅は決まっていて（`TalkScreen.PLATE_WIDTH`）、名前の長さで変わらない（名前は真ん中。`docs/ui-theme.md` の「枠の大きさ」）。
  対戦の途中の台詞の帯（`battle_talk.gd`）も、名前の札の幅（`BattleTalk.PLATE_WIDTH`）と帯の高さ（2 行ぶん）を変えない。
- **敵の軍が出てこない会話**は、最初に話す人が左、ほかの人が右に立つ（味方どうしが向き合って話す。色はどちらも人の軍の色）。話し手が 1 人だけなら、左だけ。
- 話している人は明るく大きく、話していない人は暗く小さく（暗さに陣営の色を混ぜる。同じ騎士の形が向き合っても、どちらの側か分かる）。知らせの行（下の「解放」）と地の文では、両方とも暗い。
- **地の文**（話し手のいない行）は、名前の札を出さず（札の場所は空けたまま。文の枠が上下に動かない）、文を枠の真ん中に明朝で出す。枠の縁は陣営の色にしない。ログでも、札を出さずに明朝で並べる。
- 立っている間は待つ動き（駒の立ち姿のアニメーション）。黙っていた側が話し始めると、小さな身振り（`UnitView.play_gesture`）をする。

- クリック・Enter・Space で次の文へ。文は 1 文字ずつ出る（速さは `talk_screen.gd` の `CHARS_PER_SECOND`）。出きる前に送ると、出しきるだけ。
- 選ばせる行（下の「選択肢」）では、答えを選ぶまで進まない。
- 右クリックで 1 つ前の文へ。Esc はシステムメニュー（ほかの場面と同じ。閉じるボタンは「会話へ戻る」）。
- 「スキップ」で、残りを読まずに次の場面へ。ただし、この先に知らせの行（下の「解放」）があれば、そこで止まる。
- 「ログ」（ホイールを上へ・L でも）で、会話のログの窓を開く（`game/talk_log.gd`）。これまでに出した文（いまの文まで）を、話し手の名前の札（陣営の色）と文で並べる。
  窓の見た目はほかの窓と同じ（`docs/ui-theme.md` の「窓」）。ホイール・上下の矢印（W/S でも）・PageUp/PageDown・Home/End で遡る。
  右クリック・Esc・L・「閉じる」・板の外のクリックで閉じる。いちばん下でホイールを下へ回しても閉じる。開いている間は、会話を送らない。
  対戦の途中の台詞は、対戦のログ（`docs/battle-log.md`）に残るので、対戦の「ログ」で遡る。
- 最後の文を送ると、次の場面へ（流れの `Run.NEXT`）。
- 曲は、話のファイルの `before_music`（前の会話）と `after_music`（あとの会話）。無ければ、前の会話はその話の対戦の曲（小さく鳴らし、そのまま対戦へつながる）、あとの会話は落ち着いた曲（`docs/sound.md`）。

## 話の対戦

`story_battle.gd`（対戦の画面に渡すもの）が、話（`episode.gd`）から対戦設定を作る。

- 盤は、話のマップ（手で作ったマップ。`docs/hand-map.md`）。見た目（景色）はマップが決める（マップのファイルの `look`）。話が `look` を書けば、その話だけ別の見た目にできる（`stage_look.gd` のテーマ）。
- 初期位置は話が選べる（`deploy`。戦いの定義の初期位置。`docs/scenario.md`）。同じマップを、初期位置を変えて使い回せる。
- 人はいつもプレイヤー1（先手）で、出撃準備で選んだ部隊。話が人の部隊を決めていれば（`[ally]` の `unit`）、その部隊（戦いの定義の決め打ちの部隊。`docs/scenario.md`）。
- 話が `start_gauge` を持てば、人の必殺技のゲージをその量から始める（戦いの定義の `start_gauge`。必殺技を教える話だけ）。
- 敵はプレイヤー2 で、CPU が動かす。部隊は話が決め打ちにする（`[enemy]` の `unit`。編成の決まりの検査は通さない。`docs/scenario.md`）。
- 勝ち方は、ふつうは対戦と同じ（将の撃破、本陣の占拠）。話が `hold_turns` を持てば、人はそのターン数を守り切っても勝てる
  （戦いの定義の `hold_for`。`docs/win-conditions.md` の「守り切る」）。話が `wins` を持てば、人の勝ち方はその列だけになる
  （戦いの定義の `set_win_conditions`。たとえば全滅だけなら、敵の将を倒しても終わらない）。敵はいつもの勝ち方で攻める。
- 選び直す入口（F1〜F4、対戦設定のパネル、決着の画面の「新しいマップ」「対戦設定へ」）は出さない。部隊だけは、決着の画面の「部隊変更」で選び直せる。
- 人が勝つと、決着の画面に「次へ」が出る（Enter でも）。負けたときの Enter は「同じマップで再戦」。決着の画面が出た時点で、話をクリアしたと書く（「次へ」を押す前に抜けても、クリアは残る）。

## 話のファイル

物語のフォルダ（`game/story/<物語>/`）に 1 話 1 ファイル（テキスト。ファイルの名前が話の id）。物語のファイル（`story.txt`）の `[episodes]` に id を並べた順が、話の並び。
欄の説明つきの見本は `game/story/_template/first_battle.txt` と、場面をいくつも並べる書き方の `scenes.txt`（物語の一覧には並ばない。テストがそのまま読めることを確かめる）。

人間の言葉「物語は人間が読みやすいようなフォーマットで取り込めるようになっていないと、別で人が用意したストーリーとかも組み込みづらい」から、
**話のファイル 1 つが、上から読める台本で、人がエディタで書けて、そのままゲームが読む**形にした（別に作った台本は置かない。下の「台本」）。
上の半分が台本（話の名前、話し手、会話を出る順に）、線より下の半分が戦いの設定（部隊、初期位置、クリアで増えるもの）。
節の順は読む順にそろえているだけで、読み込みは順に依らない。

```
[episode]
title = 尾根の籠城
map = ridge_path
hold_turns = 10

[cast]
ハーデン = ally
ドーソン = ally, shield_trooper evolved
ヴァルト = ally, sniper evolved
セリス = enemy, spellblade

[before]
ハーデン: ヴァルト少佐の本隊へ伝令は出した。着くまで、ここで持たせる。
ドーソン: 聞いたな。少尉と旗を守って、立ってろ。
セリス: 尾根ごと、押しつぶしてあげる。

[cues]
(turn 8) ハーデン: 本隊は近い。あと少しだ、持ちこたえろ。

[after]
ドーソン: よく立ってた。もう、ひよっこじゃないな。

# ---- ここから下は、戦いの設定（部隊・初期位置・クリアで増えるもの） ----

[enemy]
army = fantasy
unit = paladin + iron_shield
unit = sorcerer
deploy = 8,9  5,9  11,9

[unlock]
budget = 2
```

- 書式（`story_file.gd`）: 空の行と `#` で始まる行は読み飛ばす。`[名前]` の行で節を始める。値の節は「キー = 値」（`unit`・`item`・`deploy` は何行でも書けて、その順の列になる）。
  話し手の節（`[cast]`）は 1 行に 1 人で「名前 = 陣営, 姿」。会話の節は 1 行が 1 つの文で「話し手: 文」（全角の「：」でもよい）。話し手は `[cast]` に書いた名前（陣営で、名前の札の色と立つ側が決まる）。
  頭に `>`（全角の「＞」でもよい）を付けた行は**地の文**（話し手のいない行。「> 演習を終えた偵察隊は、縫い目の土地の尾根に着いた。」）。`[before]`・`[after]` に書ける（`[lost]` と `[cues]` には書けない。下の「会話」「会話の書き方」）。
- 駒・持ち物・軍・勝ち方は、列挙の名前を小文字で書く（`UnitKind.Id`、`Equipment.Id`、`UnitKind.Army`、`GameWonEvent.Reason`）。マスは `x,y` を空白で区切る。
- **書き間違いは、読み込みが「ファイル:行: 何がおかしいか」で弾く**（`episode.gd`、`campaign.gd`）。起動したときはエラーの出力に出し、書き間違いのある話は並べない。
  検査（`tests/game/test_episode_data.gd`）は、全部のファイルが書き間違いなく読めることと、わざと壊した文を正しい行で弾くことを確かめる。
  弾くもの: 知らない節・キー、キーの重なり、無い駒・持ち物・軍・マップ・見た目・曲、将を書いた、置けないマス・重なるマス・足りないマス、
  勝ち方の矛盾（`hold_turns` と `wins` の `turns_held`）、将のいない群れの矛盾（下の「将のいない群れ」）、知らない話し手・陣営・姿、話し手の名前の重なり、どちらかの陣営の話し手がいない、きっかけの値、長さ（下の表）、物語の軍でない駒の解放・決まった部隊、同じものの 2 度目の解放、持ち物を持てない駒（魔物）の持ち物、軍の無い敵（`army = none`）に置いた軍の駒。
- **話のファイルの頭（`[episode]` より上のコメント）に、その話の背骨を 3 行で書く**: `# 起きること:` `# 伝わること:` `# 知る・変わる:`（`docs/story-outline.md` のその話の写し。ゲームは読まない）。
  台詞の仕上げをほかの書き手に頼むとき、話のファイル 1 つを渡せば、その場面で何が起きるかが一緒に渡る（`docs/story-writer-brief.md`）。
  筋の文書と同じ文であることを、検査（`tests/game/test_story_notes.gd`）が見る。話を足したら、筋の文書に 3 行を書いて、同じ文を写す。
- 読む側（画面、道具、テスト）は、読んだ話（`episode.gd` の値）をそのまま使う。無い欄の値（0、空）も `episode.gd` が決める。
- ルール（`rules/`）はファイルを読まない。`story_battle.gd` が、読んだ話から戦いの定義（`Scenario`）を組んで渡す。
- 書き出した exe に入れるため、`export_presets.cfg` の `include_filter` に `game/story/*`（と `game/maps/*`）がある（テキストは、書かないと exe に入らない）。

### 始めのレベル

駒の行の「,」のあとに、その駒の始めのレベルと経験値を書ける（`unit = sorcerer + iron_shield, level 2, exp 110`。どちらか片方でもよい）。
書かなければ、いつもどおりレベル 1・経験値 0。戦いの定義の始めのレベル（`docs/scenario.md`）へ写す。

- 進化の選び方を教える話が、あと少しで進化する駒から始めるのに使う。進化は対戦の中で選ぶので、
  `level` は上限（`Growth.MAX_LEVEL`）の 1 つ手前まで、`exp` は 1 レベルに要る量（`Growth.EXPERIENCE_PER_LEVEL`）の 1 つ手前まで。超えたら読み込みが弾く。
- 育たない駒（中立の駒）には書けない。
- 出撃準備では、始めのレベルが 1 でない駒に、レベルを出す（部隊の中身の文の名前の後ろ「パラディン Lv2」と、駒のアイコンの右下。敵の部隊の文も）。
  人の側は部隊が決まっている話だけ（選んだ部隊には当てないので）。

### 場面の節

話のファイルの書き方は 2 つ。**どちらで書いてもよく、いまある話は書き直さなくてよい。**

- **`[before]`・`[after]` の書き方**（上の例）: 「出撃準備 → 会話 → 対戦 → 会話」の決まった形。
- **場面の節の書き方**: 会話の場面 `[talk 名前]` をいくつでも書き、`[sortie]`（出撃準備）と `[battle]`（対戦）を挟む。**節を書いた順が、場面の順。**
  見本は `game/story/_template/scenes.txt`（読み込みは `game/episode/episode_scenes.gd`）。

```
[talk 練兵場]
place = drill_field
music = talk
> 出発の前の晩。練兵場には、まだ灯りが残っていた。
新兵: 少尉、明日は尾根ですね。

[sortie]

[talk 盤の前]
music = talk
敵将: かかってこい。

[battle]

[talk 勝ったあと]
music = talk_bright
少尉: 見本の話は、ここまで。
```

- `[talk 名前]`: 会話の場面。名前は話の中で重ならなければ何でもよい（台本の見出しに出る。画面には出ない）。8 つまで（`episode_base.gd` の `TALK_SCENES_MAX`）。
  会話の行の書き方と長さは `[before]` と同じ（1 から 10 行、1 行は 60 字まで）。頭に、設定を「キー = 値」で書ける（会話の行より前）:

  | 設定 | 中身 |
  | --- | --- |
  | `place` | 無くてよい。背景にする別の場所（マップの id）。その場所の景色だけを映す（兵は立たない。マス目の線・本陣の旗と地面の陣営の色・拠点の印も出さない。`BoardView.scenery_only`）。書かなければ、話の盤（対戦の前は初期位置の兵、あとは生き残った兵） |
  | `look` | 無くてよい。`place` の景色を替える（`stage_look.gd` の名前）。`place` と組で書く |
  | `music` | 曲。読み込みは無くてよいとしているが、検査が、どの会話にも求める。対戦の曲を書けるのは、対戦より前の会話に、その話の対戦の曲だけ。書かなければ、対戦より前で話の盤を前にした会話は対戦の曲、ほかは落ち着いた曲 |

  立つ人物は、その場面で話す人（`[cast]` の姿。話の中で共通）。
- `[cut 名前]`: カットシーン（地の文だけの場面。下の「カットシーン」）。
- `[board 名前]`: 盤のカットシーン（盤の上で兵が台本どおりに動く場面。下の「盤のカットシーン」）。
- `[sortie]`・`[battle]`: 場面の順の印（中には何も書かない）。対戦は 1 つの話に 1 つまで。`[sortie]` は `[battle]` より前。書かなければ、出撃準備は話の最初。
  対戦より前の会話は、どれも 1 度だけ出す（決着の画面の「部隊変更」で戻る先は出撃準備。会話は読み直さない）。
- `[cues]`・`[lost]`・`[ally]`・`[enemy]`・`[unlock]`・`[cast]`・`[episode]` は、どちらの書き方でも同じ（場面の順には入らない）。
  場面の節で書く話には、`[before]`・`[after]`・`before_music`・`after_music` を書かない（読み込みが弾く）。
- **対戦の無い話**: `[battle]` を書かない。`[sortie]`・`[cues]`・`[lost]`・`[ally]`・`[enemy]` を書かず、`[cast]` に `enemy` の話し手がいなくてよい。
  `map` は書く（`place` の無い会話の背景と、話の一覧のカードの絵。カードに兵の点と敵の顔は出ない）。**最後の会話を読み終えたら、クリア**（解放の知らせと「次の話へ」も、そこで出る）。

### カットシーン

地の文だけの場面（Issue #49 の 11/26「カットシーンとかも挟めるといいんだろうな」）。場面の節の書き方で、`[cut 名前]` と書く。
文の枠も話し手の姿も見出しも出さず、背景の上に、文を 1 行ずつ画面の真ん中に明朝で出す（上下に黒い帯）。時間や場所が大きく飛ぶ所、物語の節目に使う。

```
[cut 夜の行軍]
color = night
music = talk_calm
隊は、夜のうちに谷を抜けた。
だれも、口をきかなかった。
```

- **絵は描かない。** 背景は、いまある素材から選ぶ: 場所の景色（`place`。`look` で替えられる。`[talk 名前]` と同じ）、色の幕（`color`。`black` = 黒、`night` = 夜の藍。`StoryScene.COLORS`）、
  どちらも書かなければ話の盤の景色（兵は立たせない）。`color` と `place` は、どちらかだけ。景色は、会話の `place` と同じく、マス目の線も本陣の旗も出さない。
- 「ログ」「スキップ」は薄くして、会話の場面と同じ所（下の文の枠があるはずの所の右上）に置く。真ん中の文には重ならず、場面が替わっても動かない。
- 行は、どれも地の文（頭の `>` は、あっても無くてもよい）。1 から 6 行（`episode_base.gd` の `CUT_MAX_LINES`）、1 行は 60 字まで。`{hero}` は書ける。台詞・選択肢・条件は書けない。
- 話の最後の場面にはしない（クリアの知らせと「次の話へ」は、最後の会話に出すので。読み込みが弾く）。会話の場面と合わせて 8 つまで。
- 操作は会話と同じ（クリックで次へ、右クリックで戻る、ログ、スキップ）。曲は `music`（どの場面にも書く）。
- コードの形: 会話の場面の型の 1 つ（`StoryScene.cut` が真、`color`）。流れは、会話の場面（`talk_screen.gd`）に `"cut"`・`"color"` を渡す。
  台本・声・折り返しの道具、通しの点検は、会話の場面として読む（台本の見出しは「カットシーン「名前」」）。
- 盤の上で兵が動く型は、次の「盤のカットシーン」。

### 盤のカットシーン

盤の上で、兵が台本どおりに動く場面。場面の節の書き方で、`[board 名前]` と書く。見本は `game/story/_template/scenes.txt` の `[board 尾根の朝]`。

```
[board 尾根の朝]
music = talk_calm
unit レオ ally king 8,19
unit 骸骨 enemy skeleton 7,12
camera 8,17
> 霧の向こうで、何かが動いた。
move 骸骨 7,16
face レオ 骸骨
レオ: 撃て。
attack レオ 骸骨 20
> 骸骨は崩れて、動かなくなった。
```

- 台本の行（`unit`・`move` など。座標は「x,y」で左上が 0,0）と、文の行（「話し手: 文」「> 地の文」）を、**書いた順に**並べる。
  行の書き方の全部は見本の頭の説明と `docs/battle-view.md` の「盤のカットシーン」（読むのは `game/cut_script.gd`）。
  兵の名前が `[cast]` の話し手と同じなら、その人の形（人物の形か将の姿）で立つ。
- **兵が動いている間は文を出さず、文を読んでいる間は盤が止まる**。文の前に台本の行があれば、その動きを見せてから文を出す。最後の文のあとの動きは、見せてから場面を終える。
  動いている間は、文の枠と名前の札を消す（「ログ」「スキップ」は会話の場面と同じ所に残る）。クリックでは進まない。
- 背景は `place`（書かなければ話の盤）の景色で、立つのは台本の兵だけ。話し手の姿・見出しは出さない。マス目の線と本陣の旗も出さない。カメラは手で動かさない。
- 「スキップ」は、残りの動きを見せずに終わりの盤まで済ませてから、場面を終える。右クリックで前の文へ戻れるのは、間に盤の動きが無いときだけ（盤は戻せないので）。ログには、読んだ文が残る。
- 設定は `place`・`look`・`music`（`[talk 名前]` と同じ）。文の行は 1 から 10 行（1 行は 60 字まで）。選択肢と条件は書けない。台本の行が 1 つも無い節は弾く（文だけなら `[talk 名前]` か `[cut 名前]`）。
  話の最後の場面にはしない（`[cut 名前]` と同じ）。会話の場面と合わせて 8 つまで。
- 書き損じ（知らない行・兵・種類・状態・話し手、行けないマス、もういない兵）は、読み込みが行の番号と直し方の文で弾く。
- 対戦の前のカットシーンの盤は、対戦の始めの配置とはつながらない（別の盤。兵の位置も数も、対戦とは関係が無い）。
- コードの形: 会話の場面の型の 1 つ（`StoryScene.board_cut` に読んだ台本、`beats` に文の前ごとの出来事の塊）。流れは、会話の場面に `"cut_board"`・`"beats"`・`"looks"` を渡す（`talk_screen.gd` と `talk_screen/talk_board.gd`）。
  台本・声・折り返しの道具、通しの点検は、会話の場面として読む（文の行だけ）。
  作るときは、`[cut 名前]` に台本の行（兵の動き）を足す形にできる（場面の列・流れ・道具は、いまの `cut` の口をそのまま使える）。

### 選択肢

会話の途中で、遊ぶ人に 2〜3 の答えから選ばせる（Issue #49 の 11/26「選択肢はあったほうが面白そう」。どの話に入れるかは、話を書く側が決める）。
会話の節（`[before]`・`[after]`・`[talk 名前]`）に、括弧で始まる指示の行で書く。`[cues]`・`[lost]` には書けない。

```
新兵: 少尉、どちらから登りますか。
(choice template_route)
(answer left) 左の岩場から行く
少尉: 左だ。岩場なら、身を隠せる。
(answer right) 右の坂を急ぐ
少尉: 右だ。日が高くなる前に登りきる。
新兵: 走るんですね……。
(end)
少尉: ここから先は、声を落とせ。
```

| 行 | 中身 |
| --- | --- |
| `(choice 名前)` | ここで選ばせる。**すぐ前の行が問い**（文の枠に出たまま、答えを出す）。名前（英小文字・数字・`_`）で答えを覚える。物語の中で重ねない |
| `(answer 鍵) 画面の文` | 答え。2 つか 3 つ。画面の文は 22 字まで（`episode_base.gd` の `OPTION_MAX_CHARS`。ボタンに 1 行で収まる）。次の `(answer)`・`(end)` までの行は、この答えを選んだときだけ出す（無くてよい） |
| `(end)` | 選択肢の終わり。ここから元の流れ |
| `(if 名前 = 鍵) 行` | その選択肢でその答えを選んでいたときだけ出す行。`!=` なら、選んでいなかったとき（まだ選んでいないときも）。同じ会話のあと、あとの場面、**あとの話**で書ける |

- 行の数（10 行まで）は、1 度に読む数で数える（選択肢は、いちばん長い答えの行の数）。選択肢の中に選択肢・`(if …)` は書けない。
- 条件に書けるのは、その行までに選ばせた選択肢と、その答えの鍵（物語の読み込み `campaign.gd` が確かめる）。
- **画面**（`game/talk_screen/talk_ask.gd`）: 問いの行を出しきると、舞台の真ん中に答えの枠を出す。枠は、いつも答え 3 つぶんの大きさ（答えの数と長さで変えない。
  `TalkScreen.OPTION_SIZE`・`OPTION_SLOTS`。テストが確かめる）。
  左右の話し手の姿は、枠の幅（`OPTIONS_WIDTH`）を真ん中に空けて立つので、枠は姿に重ならない（`FIGURE_MAX_WIDTH`。縦長の窓でも）。
  問われている人は、答えを選ぶ前から立っている（その人の行が、答えのあとにしか無くても）。クリックか、上下の矢印（W/S）で選んで Enter・Space、数字のキー（1〜3）で選ぶ。
  選ぶまで先へ進まない（クリックでも「スキップ」でも。「スキップ」は、この先の選ばせる行で止まる）。右クリックで前の文へ戻れる。選んだあとに問いの行へ戻れば、選び直せる（覚えた答えは上書き）。
- **ログ**: 問いの行のあとに、選んだ答えを 1 行で残す（札は「選択」）。
- **セーブ**: 選んだ答えは、物語ごとの記録の `answers`（選択肢の名前 → 答えの鍵。`Story.choose_answer`・`answer_of`。版 3。`docs/save-slots.md`）。
  確かめ用の解放（F5）の間に選んだ答えは、覚えるが、その場ではファイルに書かない。
- コードの形: 問いの行（`TalkLine`）が `choice`（名前）と `options`（`{"key", "text"}` の列）を持ち、答えごとの行と `(if …)` の行が、出す条件
  `when_choice`・`when_answer`・`when_not` を持つ（`TalkLine.holds(答えを返す関数)` で、出すかを決める）。会話の場面へは、行の `"choice"` と `"when"` で渡る（`Story.talk_of`）。

### 主人公の名前

遊ぶ人は、物語の将（連邦のハーデン、騎士領のイェルダ）の立場に入り、**名前を変えられる**（Issue #49 の 11/26 の A の形。主人公はしゃべる）。
決まりは `game/hero_name.gd`、窓は `game/hero_name_window.gd`、記録は `Story.hero_name`・`name_hero`。テストは `tests/game/test_hero_name.gd`。

- **書き方**: 物語のファイルの `[campaign]` に `hero = ハーデン`（既定の名前。話の `[cast]` の同じ名前の話し手が主人公）。
  **文の中の主人公の名前は、差し込みの印 `{hero}` で書く**（「{hero}少尉、後ろの二人はどうします。」。会話・地の文・途中の台詞・負けの台詞・答えの文・物語の `intro`）。
  話し手の側（`ハーデン: …` と `[cast]` の `ハーデン = ally`）は、既定の名前のまま書く（画面の札では、付けた名前に替わる）。
  文に既定の名前をそのまま書くと、検査が落ちる（名前を変えたときに、前の名前が残るので）。
- **長さ**: 全角 5 字ぶんの幅まで（`HeroName.MAX_CHARS`。半角の字は幅が狭いぶん多く入る。字の数は 10 まで）。名前の出る枠で決めた:
  会話の名前の札（`TalkScreen.PLATE_WIDTH`）、対戦の途中の台詞の札（`BattleTalk.PLATE_WIDTH`）、会話のログの札。いちばん広い名前でも入ることを、テストが見る。
  文の長さの上限（60 字など）は、`{hero}` を 5 字と数える。
- **使えない文字**: 改行などの制御文字、波括弧（差し込みの印）、画面の字（本文・太字・見出しのフォント）に無い文字（絵文字など）。
  打った所で落とす（`HeroName.clean`）。前後の空白も落とす。空で決めると、既定の名前。
- **付ける所**: 物語選択で、その物語を初めて選んだとき、名前の窓を出す（既定の名前が入っている。そのまま Enter・「決定」で進める。右クリック・Esc でも、既定の名前で進む）。
  あとからは、話の一覧の主な人物の欄の「名前を変える」。検査とスクリーンショットでは、窓を出さずに既定の名前のまま進む。
- **出る所**: 会話の話し手の札と文、選択肢の答え、対戦の途中の台詞、負けの台詞、会話と対戦のログ、物語のカードの紹介の 1 行、話の一覧の主な人物の欄。
  出撃準備と対戦の上の帯は、人の名前を出していない（兵の種類と陣営の呼び名）。
- **セーブ**: 記録の `heroes`（既定の名前 → 付けた名前。版 4）。**既定の名前ごとに 1 つ**なので、同じ主人公の物語（連邦の本編と番外）で共通。
  使えない名前の記録（手で書き換えたファイル）は読み飛ばし、既定の名前に戻る。
- コードの形: 会話の行（`TalkLine`）が既定の名前 `hero` を持ち（物語の読み込みが `Episode.set_hero` で入れる）、`shown_text(付けた名前)`・`speaker_in(speakers, 付けた名前)` で出す。
  付けた名前は、流れ（`Story.run_now` → `run_of`）が会話と話の対戦（`StoryBattle.hero`）へ渡す。台本・声・折り返しの道具は、既定の名前で読む。

### 場面の列

話は、場面の列 `Episode.scenes`（`game/episode/story_scene.gd` の `StoryScene` の列）で持つ（`game/episode/episode_scenes.gd` の `_build_scenes` が組む）。
`[before]`・`[after]` の話は、どれも次の 4 つ。場面の節の話は、書いた順。

| 場面 | 種類（`StoryScene.Kind`） | 中身 |
| --- | --- | --- |
| 出撃準備 | `SORTIE` | 部隊と初期位置 |
| 会話（前） | `TALK` | `[before]` の行、曲 `before_music`、1 度だけ（`once`） |
| 対戦 | `BATTLE` | 決着の画面を含む。途中の台詞 `[cues]` と負けたときの台詞 `[lost]` は、この場面のもの |
| 会話（後） | `TALK` | `[after]` の行、曲 `after_music` |

- 会話の場面が持つもの: 行 `lines`、曲 `music`（話のファイルが選んで書いたか `music_written`）、1 度だけか `once`、どの節から来たか `part`、
  場面の名前 `name`、背景の場所 `place`（null なら話の盤）と見た目 `look`。
- 列を読む所: 流れ（`Story.run_of`。種類ごとに流れのどの場面にして何を渡すかは、ここだけ）、決着のあとの曲（`StoryBattle.after_result_music`。対戦の次の場面が会話なら、その曲）、
  台本（`tools/story_script.gd`）、声の点検（`tools/voice_check.gd`）、折り返しの点検（`tools/wrap_audit_lib.gd`）、通しの点検（`game/autoplay_sweeps.gd`。列を順に通す）、テスト。
- 対戦のあとの会話かどうかは、列の位置で決まる（対戦の場面より後ろで、`place` の無い会話は、背景の盤に決着したときの兵を立たせる）。
  最後の場面が会話なら、その最後にクリアで増えるものの知らせを足し、「次の話へ」を選ばせる。最後が会話でなければ、そのまま話の一覧へ。
- **クリアの記録**: 対戦のある話は、対戦に勝ったとき（`StoryBattle.record_win`。決着の画面が出た時点）。対戦の無い話（`Episode.has_battle()` が偽）は、
  最後の会話を読み終えたとき（流れが会話に `"clears"` で話の id を渡し、`talk_screen/talk_choice.gd` の `_end` が書く）。
- 話の台詞の全部は `Episode.all_lines()`（場面の順に会話の行と途中の台詞、最後に負けたときの台詞）。
- **場面の種類を足すとき**（カットシーンなど）: `StoryScene.Kind` に足し、作る関数を足し、`episode_scenes.gd` に節の読み方を、`Story.run_of` の `match` に流れの場面を足す。
  台本・声・折り返しの道具は、会話の場面と対戦の場面しか見ないので、台詞を持つ種類なら道具にも足す。
- **試しの 1 話**: 連邦の第 1 話「はじめの一歩」（`game/story/military/drill_first_steps.txt`）は、場面の節で書いた厚い版。
  カットシーン（色の幕）→ 会話（峠の駐屯地）→ 会話（ふもとへの道。選択肢 `military_first_wish`）→ 出撃準備 → 会話（盤の前）→ 対戦 → あとの会話（選んだ答えで 1 行替わる）。
  ほかの話は `[before]`・`[after]` のまま。書き方の実例として読める。
- 列にまだ寄っていない所:
  - 自動の対戦の `story`（`game/autoplay/story_checks.gd`）は、通す話（本編の最初の話・2 つ目の物語の最初の話）が 出撃準備 → 会話 → 対戦 → 会話 の順である前提で画面を押す。
    スクリーンショットの場面（`tools/shots/`）は、話を始めたら出撃準備より前の場面を飛ばす（`_skip_to_sortie`）。通しの点検（`autoplay_sweeps.gd`）は列を順に通す。
  - 実測（`tools/cpu_matches.gd`）と出撃準備は、対戦のある話だけを相手にする（`Story.first_battle`）。対戦は 1 つの話に 1 つまで。

### 会話の 1 行（コードの形）

読んだ会話の 1 行は `game/episode/talk_line.gd`（`Episode.TalkLine`）。`[before]`・`[after]`・`[lost]` は、その列。
`[cues]` の 1 行は `game/episode/talk_cue.gd`（`Episode.TalkCue`。きっかけ `trigger`・値 `value`・言うこと `line`）。

| 欄 | 中身 |
| --- | --- |
| `kind` | 行の種類（`SPEECH` 台詞、`NARRATION` 地の文） |
| `side` | 話し手の陣営（0 人の軍、1 敵の軍。地の文は `NARRATION_SIDE`） |
| `text` | 文（ファイルに書いたまま） |
| `who` | 話し手（`speakers` の番号。地の文は -1） |

- 読む側（会話の場面へ渡す `Story.talk_of`、途中の台詞 `BattleCues.line_of`、台本・声・折り返しの道具、自動の対戦、テスト）は欄を名前で読み、
  話し手の名前は `speaker_in(speakers)`、画面に出す文は `shown_text()` で取る。
- 行の種類を足すときは、`Kind` に足し、作る関数（`speech`・`narration` と同じ形）を足し、読む側で `kind` を見る。
- 選択肢は、行の種類ではなく、行に付く欄（`choice`・`options`、出す条件の `when_choice`・`when_answer`・`when_not`。上の「選択肢」）。
  台本・声・折り返しの道具とテストは、条件に依らず全部の行を読む。
- 文に差し込むもの（主人公の名前。上の「主人公の名前」）は `shown_text()` が入れる。文の長さの検査（`TALK_MAX_CHARS` など）は、差し込みの印をいちばん長い名前で数える（`longest()`）。

### 話を 1 つ足す

1. `game/story/_template/first_battle.txt`（会話の場面をいくつも書くなら `scenes.txt`。下は `[before]`・`[after]` の書き方で説明する。違いは「場面の節」）を、物語のフォルダに `<id>.txt` の名前で写す（`<id>` は英小文字と `_`。クリアの記録に書くので、配ったあとは変えない。ほかの物語の話とも重ねない）。
2. 筋（`docs/story-outline.md`）に、その話の見出しと背骨の 3 行を書き、同じ 3 行を話のファイルの頭に写す（上の「話のファイル」。テストが同じ文かを確かめる）。
3. 欄を直す（使わない欄は消す）。上の半分（話の名前、話し手、会話）から書き、線より下（敵の部隊など）をあとで埋めてよい。
   読み込みは無くてよいとしているが、**検査が求める欄**がある: `[lost]`（1〜3 行）、`before_music` と `after_music`（あとの会話に戦いの曲は置かない）。
   対戦の曲は、同じ物語の隣の話と変える。MILITARY の物語の最後の話にするなら、`climax_music` も既定から変える。
4. 新しい話し手を出すなら、口調の表（`game/story/voices.txt`）に節を足す。
5. 物語のファイル（同じフォルダの `story.txt`）の `[episodes]` の、遊ばせたい位置に `<id>` を 1 行足す（話のファイルはフォルダから探さない。ここに書いた順に並ぶ）。
6. `tools/check.sh` か、テストだけ（`godot --headless --path . -s res://tools/run_tests.gd -- --only=test_episode_data,test_sound,test_story,test_voice_check,test_wrap_audit`）を回す。
   書き間違いは「ファイル:行: 何がおかしいか」で出る。
7. 目次を作り直す（`tools/write_story_script.sh <godot>`。下の「台本」）。
8. 敵の強さを測る（`tools/cpu_matches.gd -- --episode=<id>`、部隊を変えるなら `--squads=random`。下の「敵の強さ」）。

足し忘れても検査が落ちない所:

- 書き間違いのある話は、画面では話の一覧から消えるだけ（検査では落ちる）。
- 口調の表に節の無い話し手は、口調を見られない。会話に仕組みの言葉（マス、ターン、コストなど。下の「会話の書き方」）を書いても、話し手の `avoid` に入れた語のほかは拾わない。
- 通しの点検（`--story-all`。`game/autoplay_sweeps.gd`）は、物語ごとに頭から `STORY_EPISODES` 話まで。それより後ろに足した話は通らない。
- 敵の強さは、検査では測らない。

### 物語を 1 つ足す

ほかの人が書いた物語を、コードを知らずに組み込めるようにしてある。**物語のフォルダを `game/story/` に置けば、物語を選ぶ場面に並ぶ**（どこにも登録しない）。
ただし、検査のいくつかが、いまの 3 つの物語の並びを決め打ちしている（`test_episode_data.gd` の `test_story_folders_are_found_in_order`、
2 つ目の物語を FANTASY として読む `test_story_records.gd`・`test_scene_flow.gd`・`tools/shots/story_menu_scenes.gd`）。物語を足したら直す。`order` は、いまの物語の後ろにする。

1. `game/story/_template/` を、`game/story/<物語の id>/` に写す（英小文字と `_`。フォルダの名前が物語の id で、クリアの記録に書く。配ったあとは変えない）。
   `_` で始まるフォルダはゲームが読まない（見本と、書きかけの下書きを置ける）。
2. `story.txt`（物語のファイル。下）を直す: 物語の名前、軍、部隊の決まりの名前（`rules`。ほかの物語と重ねない。物語の id と同じでよい）、最初のコスト上限、最初から雇える駒、
   紹介の 1 行（`intro`）と主な人物（`[cast]`。名前・姿・立ち位置）。
3. 話のファイルを同じフォルダに書き（上の「話を 1 つ足す」）、`story.txt` の `[episodes]` に遊ぶ順に並べる。
4. 検査を回す（`tools/check.sh`）。物語か話に書き間違いがあれば、「ファイル:行: 何がおかしいか」が日本語で出る。書き間違いのある話は並ばない（ほかの話は遊べる）。
5. 目次を作り直す（`tools/write_story_script.sh <godot>`）。

- 物語を選ぶ場面での並びは、`story.txt` の `order` の小さい順（書かなければ、順を書いた物語の後ろに id の順）。
- 物語のカードの顔（アイコン）、話の一覧、出撃準備、部隊編成の物語ごとのタブ、クリアの記録は、物語のファイルから自動で出る。
- 使える素材はいまあるものだけ: マップは `game/maps/`（足し方は `docs/hand-map.md`）、駒と持ち物は `docs/unit-roster.md`・`docs/player-loadout.md`、曲は `docs/sound.md`。
- 会話に地の文（話し手のいない行。頭に `>`）も書けるが、使うのは数か所だけ（下の「会話の書き方」）。状況は、なるべく話し手の台詞で見せる。
- 書き出した exe には、`export_presets.cfg` の `include_filter` の `game/story/*` で、フォルダごと入る。

  （説明の台詞を足さない）。初めて出る人物は、出た話で名乗るか、まわりが役目で呼ぶ。

### 口調の見本

人間の言葉（11/22、Issue #49）から: 「ウルが喋ったあと『導師の前では〜』と突然言い出すので、ウルが導師と呼ばれているんだと認識するまで時間差がある」
「イェルダの口調が文体すぎる。口語に見えない」「この会話自体が師匠と弟子っぽくない」「（ベルクの 1 話は）口調が立場に対して違和感がある」。
台詞を書く前に、人物ごとの口のきき方をここで決め、台詞はこれに合わせる。**ここは人間が直してよい所**で、直したら台詞のほうを合わせる。
いまの台詞は、全 30 話が呼び方の表どおり（検査が全部の話に掛かる）。文体は下書きで、仕上げは別の書き手に頼む（`docs/story-writer-brief.md`）。

決まり:

- **呼び方は、初めて出るとき名前と一緒に言う。** 肩書き（少尉、曹長、少佐、騎士長、導師、先生）だけで呼ぶのは、同じ物語の中で、その肩書きと名前が 1 度結びついたあと
  （「ウル導師」「ハーデン少尉」「ドーソン曹長」のように名前つきで呼ぶか、本人が名乗る）。
- **連邦の人物は、互いを階級で呼ぶ**（人間の言葉「普通、階級で揃えるだろうな」11/22）。少佐 ＞ 少尉 ＞ 曹長。ハーデンは「ハーデン少尉」「少尉」で、**「隊長」とは呼ばない**
  （表の `avoid` に入れてあり、検査が落とす）。騎士領の者は、ハーデンを名前か「連邦の将」と呼ぶ。
- **1 人の中で、敬語の段と語尾をそろえる。** 相手で段が変わる人は、どの相手にどの段かを下に書く。1 つの台詞の中で、同じ相手への段を混ぜない。
- **2 人の関係が、口のきき方に出ること。** だれがだれを何と呼ぶかは、呼び方の表（`game/story/voices.txt`）が正。表に無い呼び方と一人称は、検査（`tests/tools/test_voice_check.gd`）が落とす。
- **姿は人物像に合わせる。** 会話に立つ姿と盤の駒は、人物ごとの「見た目」の行（年ごろ、男女、体つき、装い）に合う形を選ぶ。どの組でも合わない所と、足りない形は Issue #46。
- **声に出して読める言葉で書く。** 書き言葉の「〜である」は、名乗りと号令のような場面だけ。
  字で読めば通るが、口で言うと痩せて聞こえる 1 字の言葉は言い換える: **魔法の火は「炎」**（「ぼくの炎」「いい炎だ」）、師は「導師」。
- **引用と伝聞を混ぜない。** 人の言葉を伝えるときは、言ったとおりに言う（「……と」で受ける）か、伝聞の形（「〜と言われている」「〜だそうだ」）にする。
  伝聞の中の呼び方は、伝える人から見た呼び方にする（少佐の命令を曹長に伝えるなら「ドーソン曹長に鍛えてもらえと言われている」。「あんたに鍛えてもらえ」は、どちらでもない）。

#### ベルク連邦（MILITARY）

連邦の隊の形（だれがどれだけ偉いか）:

- **ヴァルト少佐**: 本隊（数百人）の長。縫い目の土地にいる連邦の兵の、いちばん上。
- **ハーデン少尉**: 本隊の下にある偵察隊（十数人）の長。呼ばれ方は階級の「少尉」。
- **ドーソン曹長**: 偵察隊の兵のいちばん上で、少尉の次。兵をまとめ、少尉を支える。

士官学校を出た者は少尉になり、着任したその日から、兵からたたき上げた曹長の上官になる。
**新任の少尉を一人前にするのは、古参の曹長の仕事**。ハーデンとドーソンはこの形。
ハーデンは良い所の出だが（下）、曹長の上に立つのは家柄のためではなく、士官学校を出た少尉だから。
その下: 教導隊員（軍曹）・マルタ（衛生兵。伍長）＞ ピップ（上等兵）＞ ノエ（二等兵）。

**ハーデン**（22 歳。少尉。偵察隊を率いる）

- 経歴: 先月、士官学校を出た。初めての隊が、この偵察隊（十数人）。
  **良い所の出。** 山の州の州都の、代々将校を出してきた家の子（仮: 父は最初の冬に配給を回した将校の 1 人で、いまは議会に席がある）。

  実戦の経験は、まだ無い。隠しはしないが、**卑下もしないし、無知をひけらかしもしない。自分の未熟を口にするときは、これからどうするかと一緒に、前向きに言う。**
  知らないことを並べない。分からないことは、見て確かめるか、短く尋ねる。育ちが良く、年上の部下にも礼を欠かさない。

  少佐には「です／ます」。敵にも言い切り。
- 癖: ひとことで返す。見たものと決めたことだけを言う。礼と詫びは短く口に出す（「助かった」「すまん」）。改まって頼むときは「頼む」だけでなく「よろしく頼む」。

### 会話の書き方

人間の言葉「とにかく説明口調なのが気になる」「もっとキャラの個性出しながら説明もしていくもんじゃない？」（Issue #49）から。

- **説明は掛け合いの中で、その人の言い方で。** 状況・地形・勝ち方・遊び方を 1 人にまとめて言わせない。誰に向けたか分からない宣言を書かない。
- **地の文は、効く所に数か所だけ**（入れすぎない）: 話の頭の場面（どこに着いたか）、時間が飛んだとき、物語の最後の締め。1 行で、説明はしない（勝ち方・遊び方・人物の紹介を地の文に書かない）。
  **物語の最初の話の頭だけは 2〜3 行**: 遊ぶ人が「ここはどんな世界で、自分はだれか」をつかめるように（MILITARY のはじめの一歩が 3 行、FANTASY の少数精鋭が 2 行）。
  ほかにあるのは、MILITARY の尾根の小道・もう一人の番人の頭と縫い目の発破の締め、FANTASY の岩山越えの頭と墓守の眠りの締め。
- **画面に見えるとおりに呼ぶ。** 書く前に、その話の盤を絵で見る（`tools/screenshots.sh`）。岩山、石壁、樽、森、結晶泉、旗（本陣）、光る輪（ポータル）、緑の印の泉（回復の泉）。
  画面に無い物（橋、霧、夜）を書かない。駒の姿は、見た目の組（`docs/battle-view.md`）が替わっても通る言い方にする（武器や服の種類を言い切らない）。
- **遊び方の案内は残す。** 演習の教えることと、勝ち方が特別な話の「何をすれば勝ちか」は、台詞の中で必ず伝わるように。
  ボタン・スキル・駒の名前を「」で括るときは、画面の名前と一字一句同じに（`tests/game/test_episode_data.gd` が見張る。「」は画面の名前にだけ使う）。
- **ゲームの仕組みの言葉を、そのまま言わせない**（人間の言葉「『旗の下に誰もいません』とかは、だいぶメタい」11/21）。
  台詞に書かない言葉: マス、ターン、ゲージ、コスト、駒、レベル、スキル、クリック、メニュー、ボタン、中ボス、HP。
  世界の中の言い方にする（「青く光る所まで歩ける」「隊の士気が満ちた」「本隊が着くまで持たせる」「番人」「得意技」）。
  数（何ターン守るか、何マス届くか）は、出撃準備の「この話で覚えること」（`lesson`）と勝ち方の札が出すので、台詞では言わない。
  「将」「本陣」「旗」「聖遺物」は世界の中にもある言葉なので使ってよい（MILITARY の人は自分の将を階級で「少尉」と呼ぶ）。
  演習の途中の台詞は、教官が見えているもの（光る色、相手、泉）を指して言う。
- **負けたときの台詞（`[lost]`）は、次にどうすればよいかの手掛かり**を、世界の中の言葉で 1〜2 行（「旗を空けすぎた」「杖持ちを先に黙らせろ」）。
  とくに守り切る話と演習は、負け方の手掛かりにする。対戦の前の会話で言ったことを、短く言い直すとよい。敵のひとことを 1 行目に置いてもよい。
- **あとの会話は 4 行以上**（2〜4 往復）。話を進めるのは、あとの会話。途中の台詞は、戦いの山場に 1〜3 つ。
- **短く。** 対戦の前は 6〜7 行をめやすに（上限は 10 行）、1 行は文の枠に 2 行まで（60 字）。途中の台詞は 40 字まで。話を進めるのは、あとの会話。
- **対戦の前の会話は、出撃のあと、盤を前にして話している。** 見えている地形や敵を指して話してよい。
- **1 行ずつ確かめる。** 書いた台詞は、1 行ごとに次の 7 つを見る（上の「口調の見本」と照らす）。
  1. だれが、だれに言っているか（上官にか、兵にか、敵にか、独り言か）。1 行の中で相手が替わるなら、呼びかけで分かるようにする。
  2. 呼び方は表（`game/story/voices.txt`）どおりか。肩書きだけの呼び方は、その物語で名前と結びついたあとか。
  3. 敬語の段と語尾は、その人の見本どおりか（その相手への段になっているか）。
  4. 引用と伝聞が混ざっていないか。
  5. 声に出して読めるか（書き言葉の語尾、説明の調子になっていないか）。
  6. 前の行を受けているか（前の人の言ったことに答えているか、同じものを見て話しているか）。
  7. **その出自と立場の人が、その相手に言うことか**（人間の言葉、11/23: 士官学校を出た良い所の出の少尉が「実戦は、まだ知らない」と無知をひけらかすのは「どう考えてもおかしい」。意味が通っていても、人物に合わない台詞は駄目）。
     新任でも将校は基本を知っている。騎士長は、20 年前から出ている物を初めて聞くようには尋ねない。部下は上官を値踏みしない。
  2 と、一人称・「言わないこと」の一部は、道具が見る（`tools/voice_check.gd`。`tests/tools/test_voice_check.gd` が全部の話に掛ける）。ほかは、読んで確かめる。
- 書いたら通しの台本（下）を手元で作って通しで読み、同じ言い回しの繰り返し・口調のぶれ・話のつながりを直す。

### 台本

人間の言葉「テキストで読み物として読むだけでもある程度評価できる」（11/17）、
「`docs/story-script` は読みやすいけど、二重更新が必要では。設定ファイルか何かに取り出して、それが人間にも読みやすければいい」（11/21）から。

- **会話の正は話のファイルで、写しはコミットしない。** 読むのも話のファイル（`[before]`・`[cues]`・`[after]`・`[lost]` が、そのまま台本の形）。
- **目次は `game/story/README.md`**（GitHub で `game/story/` を開くと出る）。物語ごとに、話の順に、話の名前と話のファイルへのリンクを並べる。
  持つのは話の並びと名前だけ。**台詞や敵を直しても、作り直しは要らない。** 話を足す・並べ替える・名前を変えたときだけ
  `tools/write_story_script.sh <godot>` で作り直す（`tools/story_script.gd` の `index_text`。手で書かない）。
  作り直し忘れると、テスト（`tests/tools/test_story_script.gd`）が落ちる。
- **通しで 1 本に読みたいとき**は、同じ道具が `build/story-script/<物語の id>.md` に書き出す（コミットしない。`.gitignore` の `/build/`）。
  話の順に、話の名前、マップ、勝ち方、敵、（演習なら）覚えること、対戦の前の会話、途中の台詞（いつ出るか）、対戦のあとの会話、負けたときの台詞、クリアで増えるもの。
  テストは、これが作れて、全部の文を話の順に持つことを確かめる。

## 物語のファイル

物語のフォルダ（`game/story/<物語の id>/`）の `story.txt`（フォルダの名前が物語の id。クリアの記録に書く）。書式は話のファイルと同じ。
欄の説明つきの見本は `game/story/_template/story.txt`。

```
[campaign]
title = ベルク連邦の物語
army = military
rules = story
budget = 20
order = 1
intro = 山の国の新任少尉{hero}として偵察隊を率い、縫い目の土地の尾根を越える。
hero = ハーデン

[start]
unit = shield_trooper
unit = sniper

[cast]
ハーデン = king, 偵察隊の新任少尉
ドーソン = shield_trooper evolved, 古参の曹長。教官

[episodes]
drill_first_steps
ridge_path
```

| 節 | キー | 中身 |
| --- | --- | --- |
| `[campaign]` | `title` | 物語を選ぶ場面と、話の一覧の見出しに出す名前 |
| | `army` | 人が使う軍 |
| | `rules` | この物語の編成の決まりの名前（取っておく部隊に書く。物語ごと・対戦と違う名前。取っておいた部隊が外れるので、配ったあとは変えない） |
| | `budget` | 最初のコスト上限 |
| | `order` | 無くてよい。物語を選ぶ場面での並びの順（小さいほうが先。書かなければ、順を書いた物語の後ろに id の順） |
| | `intro` | 無くてよい（遊べる物語には書く。検査が見る）。物語を選ぶ場面のカードに出す紹介の 1 行（40 字まで。`campaign.gd` の `INTRO_MAX_CHARS`）。遊ぶ人が誰として、何をする物語か。主人公の名前は `{hero}` で書く（5 字と数える） |
| | `hero` | 無くてよい（遊べる物語には書く。検査が見る）。主人公の既定の名前（上の「主人公の名前」）。話の `[cast]` の同じ名前の話し手が主人公 |
| `[cast]`（無くてよい。遊べる物語には書く） | （1 行に 1 人） | 主な人物「名前 = 姿, 立ち位置」（話の一覧の頭に出す）。姿は話のファイルの `[cast]` と同じ書き方。立ち位置は 10 字まで、6 人まで（`campaign.gd` の `ROLE_MAX_CHARS`・`CAST_MAX`）。遊ぶ人の将と隊の人を書く。名前と姿は、話の `[cast]` の人の軍の話し手と同じにする（検査が見る） |
| `[start]` | `unit`、`item` | 最初から雇える駒（その物語の軍の駒）と、持たせられる持ち物（何行でも） |
| `[episodes]` | （1 行に 1 つ） | 話の並び（一本道。同じフォルダの話のファイルの名前。`.txt` を除く） |

いまある話は、物語のファイル（`game/story/<物語>/story.txt`）の `[episodes]` の並びと、同じフォルダの話のファイル
（盤、見た目、勝ち方、敵の部隊と初期位置、クリアで増えるもの）が正。ここには写さない。

- MILITARY の物語: 人は MILITARY、敵は FANTASY か、軍に属さない魔物の群れ（下の「魔物の群れの話」）。
  頭の話（`drill_` で始まる話）がチュートリアル（下の「チュートリアル」）、残りが本編。
- FANTASY の物語: 人は FANTASY、敵は MILITARY か魔物の群れ。頭の話（`trial_` で始まる話）がチュートリアル（下の「FANTASY の演習」）。
  話の id はクリアの記録に書くので、物語をまたいで重ならないよう、物語ごとに頭の言葉を分けた。

MILITARY の物語の本編は、対戦モードと同じ手で作ったマップ（`docs/hand-map.md`）を、初期位置と勝ち方を変えて使い回す（敵が中ほどで待ち伏せる話、守り切る話、全滅させる話）。
本編の 5・6 話目は、魔物の群れの話（ストーリー用のマップ「古戦場」を、勝ち方と敵の初期位置を変えて 2 回使う）。
7 話目から（森のあとの筋）は、MILITARY の物語でまだ使っていない盤と遊びにした:

| 話 | マップ | 勝ち方 | 敵 |
| --- | --- | --- | --- |
| もう一人の番人 | 大岩の峠 | 中ボスの撃破だけ（本編では初めて） | 将のいない魔物の群れ（骸骨術師と骸骨鼓手。番人のまわりから始まる） |
| 最後の演習 | 結晶の祠（演習の盤を、本編の部隊で） | いつもの勝ち方 | 教導隊（FANTASY。3 体だけで、前衛と後衛が始めからレベル 2） |
| 縫い目の発破 | 結晶の採掘場（`game/maps/crystal_quarry.txt`。MILITARY の物語のために足した、起爆樽の多い盤） | いつもの勝ち方。**味方が正面と西の脇に分かれて始まる** | MILITARY（ヴァルト少佐の本隊。連邦どうし） |

- 縫い目の発破は、MILITARY の物語の最後の話。分かれて始まる形は FANTASY の「岩山の合流」（取り残された隊を迎えに行く）と向きを変え、こちらから 2 手に分かれて挟む。
  樽は撃つと周りごと吹き飛ぶ。スナイパーの射程で、敵のそばの樽を撃てる（敵のスナイパーも、こちらのそばの樽を撃つ）。

FANTASY の物語の本編（9 話）は、MILITARY の物語の本編と**違う遊び**にした。同じマップを使う話も、勝ち方と敵を変えた:

| 話 | マップ | 勝ち方 | 敵 |
| --- | --- | --- | --- |
| 岩山越え | 結晶の岩山 | いつもの勝ち方 | MILITARY（少数） |
| 岩山の合流 | 結晶の岩山 | いつもの勝ち方。**味方が岩山の南と北に分かれて始まる**（`deploy` を 2 か所に書く） | MILITARY（北の隊のそばで待つ） |
| 尾根の砦 | 尾根の小道 | 本陣の占拠か、全滅させる（将を倒しただけでは終わらない。MILITARY の物語の本編に無い） | MILITARY（本陣の前で待つ） |
| 古戦場の祈り | 古戦場 | 守り切る（8 ターン） | 混成（MILITARY の軍と魔物。軍があるので必殺技も使う） |
| 亡者の太鼓 | 結晶の岩山 | 全滅させる | 将のいない魔物の群れ（骸骨鼓手が周りの亡者を突撃させる） |
| 峠の番人 | 大岩の峠（対戦モードのマップ） | 中ボスの撃破だけ（本編では初めて） | MILITARY |
| リュエルの森 | リュエルの森（`game/maps/mist_forest.txt`。FANTASY の物語のために足した森の多い盤） | いつもの勝ち方 | MILITARY の本隊 |
| 尾根の亡者 | 尾根の小道（「尾根の砦」で奪った砦を、今度は守る） | 守り切るだけ（10 ターン。倒す将がいない） | 将のいない魔物の群れ（骸骨鼓手 2・骸骨術師。尾根の中ほどの左右の道から始まる） |
| 墓守の眠り | 縫い目の谷（`game/maps/seam_vale.txt`。FANTASY の物語のために足した、ポータルの多い盤） | 将の撃破だけ（旗を取っても終わらない） | 将（墓守）のいる魔物の群れ（骸骨術師・骸骨鼓手つき） |

- 岩山の合流は、人間の言葉「2 分隊に分かれてスタートするようなストーリーを用意してもいい」（11/17、Issue #46）から。
  将のいる南の隊は本陣のそば、北の隊は岩山（越えられない）の向こうの台地で、敵の陣地に近い。北の隊は敵に狙われながら耐えるか、近い敵の本陣を突き、
  南の隊は西の端の回り道かポータルで回り込んで挟む。どの駒をどちらに置くかは出撃準備の初期位置で選ぶ（置けるマスが 2 か所に出る。書いた順が交互なので、選ばなければ半分ずつ）。
  クリアで増えるものは置かない（あとの話を初めて遊ぶときの部隊と難しさを、足す前と変えないため）。
- 尾根の亡者と墓守の眠りは、森のあとの筋（`docs/story-outline.md`）。守り切るだけの話は、敵に将がいないので、倒して早く終わらせる道が無い（古戦場の祈りは、将を倒しても勝てた）。
  墓守の眠りは、群れを減らしきれない（術師が増やす）ので、ポータルで墓守の脇へ跳ぶか、正面から道を開けるかを選ぶ。亡者も同じポータルで人の本陣へ来る。
- リュエルの森は、森（入るのに手間が掛かり、中で受けるダメージが減る）で、遠くから撃つ側が当てにくい盤。近くで戦う FANTASY の側の物語の締めにした。

### 魔物の群れの話

人間の言葉「ストーリーなら、敵は FANTASY とかほかのクラスなこともあれば、全然別のモンスターとか、特に軍とかない特殊なユニットとかいていい」
「ストーリーも色んな種類あったほうが深みが出る」から。敵は軍に属さない魔物（`docs/unit-roster.md` の「魔物」）で、話のファイルの `[enemy]` に `army = none` と書く。

- 将のいる群れでは、敵の将は骸骨の将の姿（`king_figure = skeleton_mage`。見た目だけで、ルールの上では将のまま）。混成の敵の「古戦場の祈り」と、FANTASY の演習「火球」（亡者の群れ）も同じ。
- 敵に必殺技もゲージも無い。かわりに数が多い（9〜11 体。骸骨兵で数を、骸骨射手で射程を、骸骨重兵で堅さを出す）。
- MILITARY の物語の 5 話目（古戦場の亡者）は**将のいない群れ**（下）を全滅させる話。骸骨術師が骸骨兵を起こして群れを増やすので、術師を先に狙う。
  6 話目（墓守）は将のいる群れで、いつもの勝ち方（群れを相手にせず、群れを率いる「墓守」を狙える）。5 話目の終わりに、墓守の名が出る（連邦の隊は、亡者を起こして従える者だと思い違える。ほんとうは、亡者を谷に留めている番人。`docs/story-outline.md`）。
- FANTASY の物語の「亡者の太鼓」も将のいない群れ。骸骨鼓手が太鼓を鳴らすと周りの亡者が突撃してくるので、鼓手を先に狙う。勝ち方は全滅させる。
  クリアで増えるものは置かない（あとの話の既定の編成と難しさを、足す前と変えないため）。
- スキルを持つ魔物（骸骨術師、骸骨鼓手）は、将のいない群れの話に置いた。群れに頭が無いぶん、「どれを先に倒すか」を魔物の側で作る。
- 盤は、道を 1 本に絞らない見通しのよい盤（`game/maps/old_battlefield.txt`）。数で押す敵が横へ広がって回り込める。

#### 番外の物語

`game/story/berk_patrol/`（「番外　縫い代の見回り」）。本編の外の、5 話だけの短い物語（筋は `docs/story-outline.md` の「番外」）。
新しい魔物（`docs/monsters.md`）、縫い目の様子（`signs`）、番人の名前（`boss`）を 1 つずつ使ってみせる、話の書き方の見本を兼ねる。

- 物語のフォルダを足すだけの形（上の「物語を 1 つ足す」）。本編の 30 話の敵は変えていない（難しさと、敵に触れる台詞に響くので）。
- 人は MILITARY（ハーデンの偵察隊。墓守のあとの見回り）。最初から 4 種類の駒と持ち物 4 つを雇え、コスト上限は 22（対戦より 2 低い）。話ごとに 2 上がる。
- 1 話目「岩山の蝙蝠」: 大蝙蝠（支配領域で止まらない速い群れ）。2 話目「ほつれた野」: ほつれと骸骨旗手（倒れると何か起きる）と、縫い目の様子「天裂の名残り」。
  3 話目「針の峠」: 糸針（動かず遠くまで撃つ）と、番人の名前「針の番人」。
  4 話目「石喰いの採掘場」: 骸骨でない魔物の糸喰い（倒れると弾ける）と糸蜘蛛（当てた相手を動けなくする）。台詞は下書き。
  5 話目「迎えを待つ谷」: 骸骨でない魔物の殻蟹（離れた所からは狙えない）と糸茸（周りの敵の攻撃を弱める）。勝ち方は守り切るだけ。台詞は下書き。

#### 将のいない群れ

人間の言葉「全然別のモンスターとか、特に軍とかない特殊なユニット」から。`[enemy]` に `king = none` と書くと、敵の将を置かない（本陣は空のまま）。

- 人の勝ち方は `wins` に書く（全滅 `routed`、中ボスの撃破 `boss_slain`、守り切る `turns_held`）。将の撃破と本陣の占拠は書けない
  （倒す将がいない。空の本陣に乗るだけで勝ててしまう）。読み込みが弾く。
- 敵の勝ち方はいつもどおり（人の将を倒す、人の本陣を占拠し続ける）。
- 敵の将がいないので、`king_figure` と、敵の将の HP のきっかけ（`king_half enemy`）は書けない。敵の話し手には、`[cast]` で将でない姿を書く
  （話の一覧のカードの顔と、会話の姿）。
- 画面: 出撃準備の敵の部隊に将を並べない。勝ち方の文に「将を倒しても終わらない」を言い添えない。

### チュートリアル

人間の言葉「ストーリーモードの序盤はチュートリアルみたいになってるのがよい。各軍の種類ごとの特徴も分かるようになってるとなおよい」から。
どの物語も、頭の話がチュートリアル（MILITARY の物語は `drill_`、FANTASY の物語は `trial_` で始まる話）。**1 つの話で教えるのは 1〜2 個**。小さい盤、少ない駒、決まった部隊（`[ally]` の `unit`）、まず負けない敵。
教え方は、いまある仕組みだけ: 出撃準備の「この話で覚えること」（`lesson`。1 行）、前の会話（短く）、対戦の途中の台詞（`[cues]`。触っている最中に 1 行ずつ）。
長い説明の文は読ませない（操作は触れば分かる形にし、台詞は「どこを押すか」「なぜそうするか」を 1 行で）。
話の一覧のカードの番号に「（演習）」を付ける（`lesson` のある話）。

- MILITARY の物語の教える順（教えるのは、曹長のドーソンと、演習ごとに隊へ加わる部隊の人たち。相手は連邦の教導隊）: 駒を動かして攻撃する（将を倒せば勝ち）→ 射程と前衛・後衛 → 回復（衛生兵と回復の泉）→ スキルと必殺技（ゲージを途中から始める。`start_gauge`）
  → 中立の駒と聖遺物（勝ち方は中ボスの撃破だけ。将を倒しても終わらないので、狩らずには終われない。`wins = boss_slain`）
  → 本陣の占拠（将を倒しても終わらない。`wins`）。話ごとに教えることは、話のファイルの `lesson`。
- **軍略**（`docs/troop-traits.md`。人間の言葉「軍略はストーリーにもいれ、チュートリアルもいれるべき」）: 演習の話を足さず、いまある演習に 1 つずつ重ねた
  （話の数と番号を変えないため。教えることが 1 つ増えるが、軍略はその演習で教える兵種の使い方と同じ所に効く）。
  話のファイルの `[ally]` の `trait` で教える軍略を持たせ、`lesson` に効き方を 1 文で足し、効いた瞬間に途中の台詞（`[cues]` の `trait ally`）で名前を言う。クリアの `[unlock]` の `trait` で、自分で組む部隊が選べるようになる。
  - MILITARY: 撃ち合い → 集中砲火（スナイパー 2 体で 1 体を撃つ）、手当て → 補給線（衛生兵の隣から始まる `deploy`）、本陣を取れ → 隊列（盾 2 枚で居座る）。
    あいだの演習も、教わった軍略を持つ（スキルと必殺技は集中砲火、結晶の番人は集中砲火）。本編（尾根の小道から）は、自分で組む部隊で 3 つから選ぶ。
  - FANTASY: 盾と祈り → 守護（パラディン 2 体とプリーストで守り切る）、影渡り → 誓い（スペルブレード 2 体を結ぶ）、魔力解放 → 仇討ち
    （敵の狙撃を 3 体にして前へ出した。倒される味方が出ないと仇討ちが効かないため）。分かれ道は守護。本編（岩山越えから）は 3 つから選ぶ。
  - 番外の物語は、本編を終えた偵察隊なので、最初から 3 つとも選べる（`[start]` の `trait`）。
  - 人の側を CPU に持たせて、どの演習も勝ち、教える軍略が 1 局に 2 回以上効くことを確かめた（集計の道具の `TRAIT` 行）。
- **MILITARY の特徴**（`docs/unit-roster.md` の「軍の釣り合い」）が遊んで分かるように並べた: 堅い前衛（シールドトルーパーと盾）、長い射程と脆さ（スナイパー）、
  数と回復で粘る（衛生兵、泉）、総員突撃。コマンドー（奇襲）は本編のクリアで増える。
- 盤は、教えることだけが起きるよう、チュートリアルのための小さい盤（`game/maps/drill_field.txt` 練兵場: 中立の駒が無い。
  `game/maps/shrine_hollow.txt` 結晶の祠: 中立の駒を教える。中身はファイルの頭の説明）。
- 物語の最初に雇える駒は少なくする（チュートリアルの部隊は決まっているので、組むのは本編から）。チュートリアルのクリアで、本編の最初に要る駒と持ち物がそろう。
- 敵の強さ: 人の側を CPU に持たせて、どの話も人の側が勝つ（チュートリアルの盤は中立の駒の湧き直しが無く、どの種でも同じ 1 局になる）。
  敵は教えることに要る最小限にする（1 体増やすだけで人の側が負ける話がある）。
- **教えていることを、やらずに勝てる話にしない**（MILITARY の演習 5 は、中ボスを狩らずにも勝てたので、勝ち方を中ボスの撃破だけにした）。
  勝ち方・敵・盤で、自然にそれをやる流れにし、人の側を CPU に持たせて、その手を使って勝つことを確かめる（集計の道具の、スキル・必殺技を使った回数）。

#### FANTASY の演習

FANTASY の物語の頭の 6 話（`trial_` で始まる話）。基本の操作（動かす・攻撃する）は MILITARY の演習と同じなので 1 話で済ませ、残りは **FANTASY ならでは**に割いた
（`docs/unit-roster.md` の「軍の釣り合い」: 少数で 1 体が強い、ファイアボール、魔力解放）。教えるのは導師のウルと、演習ごとに加わる部隊の人たち（相手は、ウルが糸で編む幻の兵と、修練場の裏の縫い代から上がってくる亡者）。盤はどれも練兵場（見た目は修練場 `trial_court`。石畳と白い石の壁の庭）。

| 話 | 教えること | 勝ち方と敵（教えることをやる流れ） |
| --- | --- | --- |
| 少数精鋭 | 動かして攻撃する、ソーサラーの射程 2。数が少なく 1 体が強いこと（会話） | いつもの勝ち方。敵は 2 体 |
| 火球 | ファイアボール（十字の範囲、壁越し） | 全滅だけ。敵は軍に属さない骸骨兵の群れ（脆く、固まって来るので、範囲で巻き込むのがいちばん早い） |
| 盾と祈り | パラディンのバリア（ディバインシールド）、プリーストの回復と聖域（セイントプレイス） | 守り切るだけ（攻めて勝つ道が無い）。敵はスナイパー 2 体と盾役 |
| 影渡り | スペルブレードのシャドウステップ（跳ぶ、入れ替わる、続けて斬る） | 将の撃破だけ。敵の将は盾役 2 体に前と横をふさがれて始まる（`deploy`） |
| 魔力解放 | FANTASY の必殺技（スキルの待ち時間が消える。行動は戻らないので、駒を動かす前に使う） | いつもの勝ち方。部隊は 4 種類 1 体ずつ（どれもスキルを持つ）、ゲージは手前から（`start_gauge`） |
| 分かれ道 | 進化の選び方（レベル 3 に上がった駒は、2 つの進化先から 1 つを選ぶ。`docs/branch-evolution.md`） | いつもの勝ち方。パラディンとソーサラーが、あと 1 撃でレベル 3 のところから始まり（駒の行の `level`・`exp`。上の「始めのレベル」）、敵の盾役が手の届く所で待つので、最初の番に 2 回選ぶ |

- 最初に雇える駒は、演習で教える順に合わせた: パラディンとソーサラーから始め、「盾と祈り」でプリースト、「影渡り」でスペルブレード、「魔力解放」でアイアンシールド。
  演習を終えると、4 種類の駒がそろう。
- 分かれ道の敵は、どちらの進化先を選んでも違いが直後の数手で出る顔ぶれにした: 速いコマンドーが後ろへ跳び込んでくる（エンチャンターの支配領域が止める。クルセイダーは追える）、
  スナイパーが壁の陰から撃ってくる（アークメイジの射程 3 なら前へ出すぎずに撃ち返せる。セイクリッドの再生は削られても戻る）。
  人の側を CPU に持たせ、進化先の 4 通りの組み合わせのどれでも人の側が勝つ（決着のターンと残りの HP が、選んだ型で変わる）。
- MILITARY の演習には、進化の話を足していない。MILITARY の進化先は能力値が尖るだけで（特性は浸透の 1 つ）、選ぶ画面のボタンに出る増減で違いが読める。
  FANTASY の進化先は性質が変わる（再生、支配領域、森歩き。`docs/branch-evolution.md` の「軍の色」）ので、触って確かめる演習を置いた。

### 敵の強さ

**人間が遊んで「ストーリーの難易度は結構高めに感じた」と言った（11/16）。CPU の実測は、人が遊んだ手応えより甘く出る**（CPU は人より上手に駒を並べる）。
そこで、めやすを上へ寄せた。人が遊んだ手応えはまだ測れないので、**人の側も CPU に持たせて回したときの、人の側の勝率**を目安にする（集計の道具の `--episode`）:

| 話 | めやす |
| --- | --- |
| チュートリアル | 人の側が勝つ（上の「チュートリアル」。盤に乱数が無く、どの種でも同じ 1 局） |
| 本編の 1 話目 | 90% 以上（まず負けない） |
| 本編の 2 話目 | 85% 前後 |
| 本編の 3 話目から | 75〜85% |

- 人の側は 2 通りで測り、両方を見る: その話を初めて遊ぶときの既定の編成（`story.gd` の `first_battle`）と、局ごとに変えた部隊（`--squads=random`）。
  手で作ったマップは盤の上の乱数が少なく、既定の編成だけでは同じような局を数えることになる（`docs/hand-map.md` の「マップを作るときのめやす」）。
- 最後は人間が遊んで決める（CPU どうしの勝率は、人が遊んだときの手応えとは違う。勝ち方が話ごとに違うので、話どうしの勝率を並べて比べることもしない）。

**軍略を入れたあと**（`docs/troop-traits.md`）: 人の側は自分で組む部隊の軍略（教わったものから）、軍の敵は話の筋に合う軍略を持つ。魔物の群れと亡者は持たない。
人の側の軍略で勝率が上がった話は、敵の顔ぶれ・初期位置か、敵の軍略の選び方で寄せた（測った数は `docs/cpu-ai.md` の「いまの集計」）。

| 物語 | 話 | 敵の軍略 | 選んだ理由 |
| --- | --- | --- | --- |
| MILITARY | 尾根の小道 | 仇討ち | 初めて会う騎士の隊。騎士領の既定 |
| MILITARY | 尾根の待ち伏せ | 守護 | 盾を 2 つ持つパラディンが、後衛と回復役の前に立つ |
| MILITARY | 尾根の籠城 | 誓い（パラディンとソーサラーを 2 組） | 騎士長の隊が、組で 1 体ずつ落としに来る |
| MILITARY | 岩山の掃討 | 守護 | 退く隊の殿（しんがり）。仇討ちでは人の側が勝ちすぎた |
| MILITARY | 最後の演習 | 仇討ち | 教導隊が騎士の戦い方を真似る。守護では人の側が勝ちすぎた |
| MILITARY | 縫い目の発破 | 隊列 | 少佐の隊は並びを崩さない。集中砲火では人の側が勝ちすぎた |
| FANTASY | 岩山越え | 集中砲火 | ハーデンの偵察隊。連邦の既定 |
| FANTASY | 岩山の合流 | 補給線 | 衛生兵のいる北の隊。集中砲火では人の側が勝ちすぎた |
| FANTASY | 尾根の砦 | 集中砲火 | 狙撃 2 体で 1 体ずつ |
| FANTASY | 古戦場の祈り | 隊列 | 骸骨兵が並んで押す（連邦の旗の下の混成）。集中砲火では人の側が勝ちすぎた |
| FANTASY | 峠の番人 | 集中砲火 | 補給線では人の側が負けすぎた |
| FANTASY | 森の守り | 隊列 | 盾 2 枚・狙撃 2 体が並ぶ。補給線・集中砲火では人の側が勝ちすぎた |

- 亡者の話（古戦場の亡者・墓守・もう一人の番人）は、人の側の軍略だけ効く。古戦場の亡者は骸骨射手と骸骨兵を 1 体ずつ、もう一人の番人は骸骨兵を 1 体（番人の奥、`5,9`）足した
  （足さないと、人の側が 95% と 88% 勝つ）。骸骨重兵を 1 体足すと、古戦場の亡者は 61% まで落ちる。
- 亡者の太鼓は骸骨兵を 1 体足した（足さないと 90%）。岩山の合流は、4 体目（狙撃でも盾でも）を足すと 53〜66% に落ちるので、3 体のまま（めやすより少し易しい）。

MILITARY の物語の本編の敵の形と、その理由（敵の部隊は話のファイルの `[enemy]`）:

- 1 話目: 前衛（パラディン。盾なし）と後衛の 2 体。コスト上限どおりの編成（6 体）よりずっと少なく、駒の数で人の側が大きく有利。
  奇襲の駒は入れない（人の側にまだ奇襲の駒が無く、奇襲の駒の有る無しで勝率が大きく動く）。
- 2 話目: 敵は尾根の中ほどから始まる（人の本陣に近く、左右どちらの道へもすぐ出られる）。盾を 2 つ持つパラディン・後衛・回復の 3 体。
  4 体目（後衛でも奇襲でも）を足すと、人の側の勝率が大きく落ちる。
- 3 話目（守り切る）: 6 体（前衛 2・後衛 2・奇襲 1・回復 1）で数で押す。人は敵を倒しきらなくても、10 ターン持ちこたえれば勝てる。
  守り切る話は、敵の数と顔ぶれで勝率が大きく跳ね（1 体の違いで、人の側がほぼ勝つ ⇔ ほぼ負ける）、ターン数を 1〜2 動かしても少ししか変わらない。
  既定の編成ではほぼ勝ち、部隊を変えると負けることがある（守りに向かない組み合わせ）。
  敵は尾根の奥（敵の本陣の前）から始まる。尾根の中ほどから始めると、人の本陣に早く届いて押す時間が長く、部隊を変えた人の側がめやすを下回った
  （2 行下げただけでは、まだ下の端の外）。
- 4 話目（全滅させる）: パラディン（盾なし）・後衛・回復の 3 体。このマップは中立の駒の湧き直しが起きず、盤の上に乱数が無い（どの種でも同じ 1 局になる）ので、
  人の部隊を局ごとに変えて測る（`--squads=random`）。

- 5 話目（将のいない魔物の群れ、全滅させる）: 骸骨術師 2・骸骨重兵 1・骸骨射手 4・骸骨兵 4（軍略を入れたときに射手と兵を 1 体ずつ足した）。術師が骸骨兵を 2 体ずつ起こすので、倒す数は最大 15。
  将のいた形（骸骨重兵 2・骸骨射手 4・骸骨兵 4）に術師を足すと、部隊を変えた人の側が大きく負け越した。骸骨重兵を 1 体にして、めやすに戻した
  （骸骨重兵の数がいちばん効く。術師を 1 体に減らして骸骨重兵を 2 体残すより、術師 2・骸骨重兵 1 のほうが人の側の勝率が高い）。
  既定の編成はスナイパー 2 体の射程で骸骨射手より先に撃てるので、ほぼ勝つ。
- 6 話目（魔物の群れ、いつもの勝ち方）: 骸骨重兵 2・骸骨射手 3・骸骨兵 4 が、霊廟のまわりから始まる。人の本陣に近いので、骸骨兵（速い奇襲）が本陣の占拠を狙ってくる。
  既定の編成の勝率は、敵の顔ぶれを 1 体変えるだけで大きく跳ねる（盤の上の乱数が少なく、似た局を数えるため）。
  後ろの骸骨兵 2 体は、盤の左右の端から始まる。回復役が攻撃できるようになって、将の前に置いた形では人の側がめやすより易しくなった。
  将を守る骸骨重兵と骸骨射手を、本陣の前に固めると、めやすの下の端まで下がる。
- 7 話目（もう一人の番人。中ボスの撃破だけ、将のいない魔物の群れ）: 骸骨重兵 2・骸骨兵 5（5 体目は軍略を入れたときに番人の奥へ）・骸骨射手 2・骸骨術師 1・骸骨鼓手 1 が、人の本陣に近いほうの番人のまわりから始まる。
  群れを本陣の前（いつもの初期位置）に置くと遠すぎて、番人を狩り終えるまで届かない。骸骨兵の 1 体は人の本陣のそばに置き、狩りに出た隊の背中を突かせた。
  骸骨重兵を 2 体・骸骨射手を 3 体にすると、部隊を変えた人の側がめやすを大きく下回り、人の側の CPU が群れに足を取られて打ち切りになる局も増える。
  骸骨重兵 1・骸骨兵 5 では、回復役も攻撃するいまの人の側には易しすぎた。骸骨射手を足しても、まだ易しい。骸骨兵 1 体を骸骨重兵にして、めやすに寄せた。
  敵に将がいないので、群れを全部倒しても終わらない（術師が増やす）。番人を倒すまで、群れは払うだけ。
- 8 話目（最後の演習。いつもの勝ち方）: パラディンとソーサラー（どちらも始めからレベル 2）とプリーストの 3 体。小さい盤（結晶の祠）で、数の少ない強い駒を囲む話。
  盾を持たせてスペルブレードを足し、4 体ともレベル 2 にすると、既定の編成でも人の側が大きく負け越した。レベルを付けずに 4 体（スペルブレード入り）でも、めやすを少し下回る。
- 9 話目（縫い目の発破。分かれて始まる、いつもの勝ち方）: 盾持ちのシールドトルーパー・スナイパー 2・衛生兵の 4 体。
  コマンドーとシールドトルーパーを足した 6 体では、部隊を変えた人の側がめやすを大きく下回る。衛生兵を 2 体にしても、盾を外してシールドトルーパーを 2 体にしても、めやすを下回る。
  脇の組の初期位置がよく効く: 敵の陣地のそば（西の端の北寄り）に置くと、合流の前に敵のスナイパーに撃たれ、敵を弱くしても既定の編成が負ける局が出た。
  西の端の中ほどへ下げて、正面の組と同じころに敵へ届くようにした。

FANTASY の物語の本編の敵の形と、その理由:

- 1 話目（いつもの勝ち方）: シールドトルーパーとスナイパーの 2 体。人の側は 4 種類 1 体ずつで、まず負けない。
- 2 話目（岩山の合流。分かれて始まる）: 盾持ちのシールドトルーパー・スナイパー・衛生兵の 3 体（北の隊のそば）。コマンドーを足した 4 体では、部隊を変えた人の側がめやすを下回る
  （速い奇襲が、取り残された北の隊を先に崩す）。盾を外してシールドトルーパーを 2 体にしても下回る。
  回復役が攻撃できるようになって、北の隊が耐えながら削れるぶん易しくなりすぎた。敵を北の隊へ寄せて始めると、めやすの上の端に戻る
  （隣り合わせまで寄せると、北の隊が一度に囲んで、かえって易しい。3 体とも敵の本陣のそばへ下げると、めやすを大きく下回る）。
- 3 話目（本陣の占拠か、全滅させる）: 盾持ちのシールドトルーパーとスナイパー 2 体。砦を落とす話なので、将を倒しただけでは終わらない。
  勝ち方が占拠だけで、敵に衛生兵がいたときは、人の側の CPU が攻めあぐねて打ち切りになる局が出た
  （敵の将は本陣の旗のマスに立つので、占拠するには先に将を倒す。火力の低い部隊では、衛生兵の回復を上回れない）。
  全滅でも勝てるようにし、回復する敵を置かない形にして、打ち切りを無くした。スナイパーを 1 体にすると易しすぎ、盾役を足すとめやすを大きく下回る。
  （占拠だけのまま衛生兵を外したときの打ち切りは、敵を全滅させたあと、追う敵のいない CPU が自分の本陣へ戻っていたため。
  CPU を直した（`docs/cpu-ai.md` の「勝ちの条件」）。いまの勝ち方では全滅で終わるので、この話の局は変わらない。）
- 4 話目（守り切る、8 ターン）: 敵は MILITARY の軍に魔物を混ぜた混成（骸骨兵 6・骸骨射手 2・骸骨重兵 1・コマンドー 1）。軍があるので、敵は総員突撃も使う。
  骸骨兵の数で押し、コマンドーと骸骨兵が将と本陣を狙う。数が多いぶん、ファイアボールがよく当たる。
  敵は本陣の前の左右へ広く分かれて始まり、骸骨重兵だけが将の前に立つ。回復役が攻撃できるようになって、本陣の前に固めた形では人の側がめやすより易しくなった。
  骸骨重兵を脇から前に出すと、既定の編成が大きく負け越す（部隊を変えた人の側は、ほとんど変わらない）。
- 5 話目（亡者の太鼓。将のいない魔物の群れ、全滅させる）: 骸骨兵 5（5 体目は軍略を入れたときに足した）・骸骨重兵 2・骸骨射手 2・骸骨鼓手 1。鼓手を 2 体にすると、部隊を変えた人の側がめやすを大きく下回る
  （突撃した骸骨兵が一度に将へ届く）。並びの順（初期位置）だけで、既定の編成が勝つか負けるかが入れ替わる（盤の乱数が少なく、1 局がほぼ決まる）。
  既定の編成が勝つ並びのうち、部隊を変えた人の側がめやすより少し易しい形を選んだ（迷ったら易しいほう）。
  骸骨兵 5・骸骨重兵 1 では、回復役も攻撃するいまの人の側には易しすぎた。骸骨射手を足しても易しいまま。骸骨兵 1 体を骸骨重兵にして、めやすに寄せた（既定の編成は勝つまま）。
- 6 話目（中ボスの撃破だけ）: シールドトルーパー・スナイパー 2・コマンドー・衛生兵。敵はいつもの勝ち方で攻めてくるので、狩りに出た人の側の本陣と将が空く。
  シールドトルーパーをもう 1 体足すと、部隊を変えた人の側がめやすを大きく下回る。
- 7 話目（いつもの勝ち方。森の多いマップ「リュエルの森」）: シールドトルーパー 2・スナイパー 2・衛生兵の 5 体。コマンドーを足した 6 体では、部隊を変えた人の側がめやすより厳しかった。
  人の側の CPU の勝率は人が遊んだ手応えより高く出る（上）ので、迷ったら易しいほうにした。

- 8 話目（尾根の亡者。守り切るだけ、10 ターン、将のいない魔物の群れ）: 骸骨重兵 2・骸骨兵 5・骸骨射手 2・骸骨術師 1・骸骨鼓手 2 が、尾根の中ほどから始まる。
  鼓手が 1 体だと部隊を変えた人の側がめやすより易しく、骸骨射手や骸骨兵を足すと、かえって易しくなる（道が詰まって届かない）。
  いつもの初期位置（敵の本陣の前）では、砦へ届くまでに何ターンも掛かる。同じ群れを尾根の中ほどに置くと、既定の編成がめやすの中に入った（遠くに置くと、ほぼ勝つ）。
  ターン数を 12 に延ばしても、めやすの下の端まで下がる。始めから戦いになるほうを選んだ。
  群れは左右の道に半分ずつ分ける。回復役が攻撃できるようになって、真ん中に固めた形では人の側がめやすより易しくなった（守りながら削れる）。
  分けると、両方の道を守ることになり、めやすに戻る。前に出しても、左の道に寄せても易しいまま。
- 9 話目（墓守の眠り。将の撃破だけ、将のいる魔物の群れ）: 骸骨重兵 2・骸骨射手 1・骸骨兵 4・骸骨術師 1・骸骨鼓手 1。
  骸骨射手を 2 体にすると、部隊を変えた人の側がめやすを下回る。骸骨重兵を 1 体にすると易しすぎる。骸骨兵を 1 体減らすと、既定の編成が負ける局が出た
  （顔ぶれを 1 体変えるだけで、勝つ側が入れ替わる。盤の乱数が少ない）。物語の締めなので、迷ったら易しいほうにした。
  骸骨兵 4 体は、墓守の左右の翼に分かれて始まる。回復役が攻撃できるようになって、本陣の前に固めた形では人の側がめやすより易しくなった。

番外の物語（`berk_patrol`）の敵の形と、その理由（めやすは、1 話目を本編の 1 話目、2 話目を 2 話目、3 話目を 3 話目からと同じに見た）:

- 1 話目（岩山の蝙蝠。全滅させる）: 大蝙蝠 6・骸骨射手 3。大蝙蝠を 7 体・骸骨射手を 2 体にすると、既定の編成が本陣を占拠されて大きく負け越す（大蝙蝠は支配領域で止まらず、本陣へ飛ぶ）。
  骸骨重兵 1 体を入れた形は、部隊を変えた人の側が 1 話目のめやすを下回った。骸骨重兵を抜くと、めやすに届く（骸骨射手を 1 体抜くよりよく効き、大蝙蝠を 1 体抜くと、かえって下がる）。
  群れは大蝙蝠と、それに守られて撃つ骸骨射手だけになり、盾の脇を越えてくる大蝙蝠がこの話の主役のまま。
- 2 話目（ほつれた野。全滅させる。天裂の名残り）: ほつれ 3・骸骨旗手 3・骸骨兵 3・骸骨射手 2。旗手 2 体の形は、部隊を変えた人の側が 2 話目のめやすより易しかった。
  旗手を 1 体足して寄せた（倒れたときの奮起が増え、どこで旗手を倒すかが効く）。ほつれを 1 体足すと、めやすを大きく下回る。
- 3 話目（針の峠。番人の撃破だけ）: 糸針 5・骸骨重兵 1・骸骨射手 2・大蝙蝠 4。群れは番人を狙わない（`spare_boss`。群れの側が番人を 2 体とも倒すと、人の側が勝てなくなるため）。
  糸針は、人の本陣から番人へ向かう道に 4 本（左の道の下と中ほど、右の道の中ほど、手前の番人の右下）と、奥の番人の左に 1 本。
  群れが番人を狙わないと、群れの手が人の側へ向くので、前の顔ぶれ（糸針 4・大蝙蝠 5）では難しすぎた。大蝙蝠を 1 体抜くとやや易しく、
  骸骨射手を 1 体足すと難しすぎ、手前の番人への道に糸針を足すと長引く。奥の番人の脇に糸針を足して、めやすに寄せた。
- 4 話目（石喰いの採掘場。全滅させる）: 糸喰い 3・糸蜘蛛 4・大蝙蝠 2・糸針 1。初期位置はいつもの「本陣の前」。起爆樽の多い盤で、樽と糸喰いの弾けるのが重なる。
  糸喰い 2・糸蜘蛛 3 では、部隊を変えた人の側がめやすより易しかった。1 体ずつ足して寄せた。
- 5 話目（迎えを待つ谷。守り切る、8 ターン）: 殻蟹 4・糸茸 4・糸蜘蛛 2・大蝙蝠 2。群れは谷の上の段（いつもの「本陣の前」より 3 行、人の側へ寄った所）から始まる。
  群れはいつもの勝ち方（将の撃破、本陣の占拠）で攻めてくる。ポータルが人の本陣の脇と群れの陣地を結ぶので、跳んでくる群れも防ぐ。
  めやすは 70〜80%（番外の最後の話）。負けはほとんど迎えの直前の押し（7〜8 ターン目）。
  殻蟹 3・糸茸 3 で本陣の前から始めると、回復役も攻撃するいまの人の側には易しすぎた。殻蟹か糸蜘蛛を 1 体足しても、大蝙蝠を足しても、ほとんど動かない。
  群れを前へ出し、殻蟹と糸茸を 1 体ずつ足して寄せた（殻蟹を 5 体にすると、めやすを下回る）。
  既定の編成は、部隊を変えたほうより勝率が低い（盤の乱数が少なく、局は 4 通り。負ける 1 通りが 24 局のうち 9 局）。
- 大蝙蝠と糸針の HP と攻撃力は、敵の数を増やしてもダメージが届く値にしてある（`docs/unit-roster.md`）。

前衛に盾を持たせると、勝率が下がり、対局が長くなる（決着まで粘る）。CPU どうしの対局は、敵の形でほぼ勝ち負けが決まり、シードを替えても勝率が大きくは動かない。
実測は `docs/cpu-ai.md` の「いまの集計」（選んだ形のもの）。選ばなかった形と比べた数字は、それぞれの PR の本文にある。数値か CPU か話のファイルを変えたら、取り直す。

## 対戦の途中の会話

コード: `game/battle_cues.gd`（いつ出すか。ノードに依存しない）、`game/battle_talk.gd`（札）。テスト: `tests/game/test_battle_cues.gd`。

話のファイルの `[cues]` に「いつ・だれが・何と言うか」を書くと、対戦の途中に短い台詞が出る。**出ている間は盤を止め、クリック・Enter・Space で送る**。

帯の見た目は、会話の画面の文の枠と同じ向き: 上の縁が太く、話し手の陣営の色。話し手のアイコンは、陣営の色の縁の小さな額に入れ、名前の札は陣営の色の地に明るい縁。

- きっかけ（`BattleCues` の定数。話のファイルには小文字で書く。陣営は `ally`（人の軍）か `enemy`（敵の軍）。話で使うものだけ作った）:

  | きっかけ | 値 | 出すとき |
  | --- | --- | --- |
  | `TURN` | ターン N | ターン N の、人の番（プレイヤー1 のフェーズ）の始め。ターン 1 は対戦の始め |
  | `KING_HALF` | 陣営（`ally` か `enemy`） | その陣営の将の HP が半分を切った |
  | `FALLEN` | 陣営（`ally` か `enemy`） | その陣営の駒（将を除く）が初めて倒れた |
  | `ULT_READY` | 陣営（`ally` か `enemy`） | その陣営の必殺技のゲージがたまった（`UltReadyEvent`） |
  | `RELIC` | 陣営（`ally` か `enemy`） | その陣営が聖遺物を受け取った（中ボスを倒した。`RelicGainedEvent`） |
  | `TRAIT` | 陣営（`ally` か `enemy`） | その陣営の軍略が初めて効いた（`TraitTriggeredEvent`。補給線は `SupplyHealedEvent`）。軍略を教える演習が、効いた瞬間に名前を言うのに使う |

- ルール（`rules/`）には入れない。画面が、行動ごとにルールが返した出来事の列（`BattleEvent`）と盤の状態を `BattleCues` に渡して、出す台詞を聞く。
  聞くのは、その行動の演出を見せ終えたあと（演出と重ねない）。
- どの台詞も、1 回の対戦で 1 度だけ。「同じマップで再戦」なら、また出る。同時にいくつか当たったら、`[cues]` の並びの順に、1 つずつ出す。
- **決着した行動のあとは出さない**（決着の画面と重ねない）。決着の画面が出たら、出ている台詞も消す。
- 出し方: 上の帯のすぐ下の真ん中に、細く横長の帯（幅 `BattleTalk.WIDTH`。話し手のアイコン（話のファイルの `[cast]` の姿の、胸から上。`UnitIcons.bust`）、名前の札（陣営の色）、文を 1 行に並べる。長い文は 2 行）で出す。地は半透明。帯の右に、送りの印（▼）を明滅させる。下の帯の案内は、台詞の間は出さない（送りの印で分かる）。
  画面の真ん中の「ターン N」の帯が出ている間は、出し始めずに待つ（対戦の始めとターンの始めの台詞が、帯に紛れないように）。出し始めてすぐ（フェードの途中）は送らない（押した勢いで、読む前に消さない）。
- **送られるまで消さない**（`BattleTalk.hold`）。その間は盤を止める: 人の操作（盤のクリック、帯のボタン、キー）は台詞を送るのに使い、CPU の番・中立の番・おまかせも次の行動へ進まない。
  敵の番の早送りとスキップの途中に出た台詞でも止まる（スキップは続き、台詞の所でだけ止まる）。Esc はシステムメニュー（メニューの右上のボタンも押せる）。
- 検査とスクリーンショットでは送らずに済むよう、数秒（`BattleTalk.SHOW_BASE` 秒 + 1 文字 `BattleTalk.SHOW_PER_CHAR` 秒）で消す（自動の対戦の `story` は、送る形も 1 度確かめる）。
- 盤の大事な所（選んだ駒、動けるマス）を隠しにくいよう、駒のそばのメニュー・予測のパネル・進化先の選択肢（同じ上の真ん中に出る）が重なっている間は薄くする（数秒で消す形では、マウスが乗っている間も）。
  左の勝ち方の札、右の視点の案内・ミニマップとは重ならない（自動の対戦の `story` が、いちばん長い台詞で確かめる）。
  帯・駒のそばのメニュー・予測のパネル・進化の選択より下に描く（重なったら、そちらが見える）。送られるのを待つ間は、その上に透明な幕を張ってクリックを受ける。
- ログ（`docs/battle-log.md`）にも「話し手「文」」の 1 行で残す（話し手の陣営の色）。読み逃しても、あとで読める。

いまの台詞は、話のファイルの `[cues]`（使い方の例にもなる。チュートリアルは操作の案内、本編は待ち伏せの知らせや、守り切る話の残りのターンなど）。

## 解放

ストーリーを進めると、その物語で使えるものが増える（Issue #49。人間の言葉「それぞれのストーリーで、それぞれの軍の種類のユニットが解放されていく」
「ストーリーモードなら部隊のコスト上限とかあげられてもよさそう」）。対戦モードの編成には影響しない（決まりが別）。

増えるものは 4 つ。どれも**その物語の中だけ**で、物語ごとに別に数える。

| 増えるもの | 物語の最初 | 話のクリアで増える |
| --- | --- | --- |
| 雇える駒の種類 | `[start]` の `unit` | 話の `[unlock]` の `unit`（その物語の軍の駒だけ。読み込みが確かめる） |
| 持たせられる持ち物 | `[start]` の `item` | 話の `[unlock]` の `item` |
| コスト上限 | `[campaign]` の `budget` | 話の `[unlock]` の `budget` だけ上がる（対戦のコスト上限を超えてよい） |
| 選べる軍略（`docs/troop-traits.md`） | `[start]` の `trait` | 話の `[unlock]` の `trait`（その物語の軍の軍略だけ。何行でも） |

- **軍略は、教わってから使う**（人間の言葉「軍略はストーリーにもいれ、チュートリアルもいれるべき」。Issue #47 の 11/26）。
  教えるのは演習の話（下の「チュートリアル」）で、その話は部隊が決まっていて、話のファイルの `[ally]` の `trait` が教える軍略を持たせる。クリアで `[unlock]` の `trait` が、その軍略を選べるようにする。
  自分で部隊を選ぶ話では、選んだ部隊の軍略（ストーリー用の部隊の軍略。部隊編成で、教わった軍略から選ぶ）がそのまま効く（`StoryBattle.trait_of_deck`、`DeckRules.trait_for`）。
  選んだ軍略をまだ教わっていなければ、その軍の既定、それも教わっていなければ教わった最初の 1 つ。1 つも教わっていなければ、軍略なし（出撃準備の見出しの札も出ない）。
  既定の編成は、教わった軍略から CPU の選び方で選ぶ（`CpuDeck.pick_trait`）。

- いま使えるものは、クリアの記録から、その場で求める（`story.gd` の `Unlocked`、`unlocked()`。記録には書かない）。
  話を初めて遊ぶときに使えるもの（並びで前の話の解放まで）は `unlocked_before(話)`。
- ストーリーの編成の決まり（`DeckRules`。名前は物語の `rules`）は、いま使えるものから作る（`deck_rules()`、`rules_of(使えるもの)`）。
  数の上限は対戦と同じ。まだ持たせられない持ち物を持った部隊は出せない（`Deck.Problem.ITEM_NOT_ALLOWED`。`docs/deck-building.md`）。
  名前が `versus` とも、ほかの物語とも違うので、取っておく部隊は対戦用と物語ごとに分かれる。
  取っておいた部隊を読むときは、決まりの名前から、その物語の進み具合の決まりを引く（`rules_by_id`。`app_context.gd`）。
- 雇えない駒や持たせられない持ち物のいる、取っておいた部隊（ファイルを手で書き換えた部隊など）は、消さずに、理由つきの「出撃不可」で一覧に残る。
  出撃準備で覚えていた部隊が出せなければ、既定の編成を選ぶ。
- 話を初めてクリアすると、あとの会話の最後に「知らせ」の行（金の縁の札。文の枠の縁も金。増えた駒・持ち物は、文の左の金の縁の額に出す。駒の額には役割の印）で、増えたものを 1 つずつ知らせる（「新しい兵種「…」を雇えるようになりました。」
  「新しい持ち物「…」（効果）を持たせられるようになりました。」「コスト上限が N に上がりました。」「軍略「…」を選べるようになりました（文）。」）。駒・持ち物・軍略の知らせは、文の左にアイコンか持ち物・軍略の印を出す。クリア済みの話を遊び直したときは出さない。
- 話の一覧のカードに「クリア報酬: …」、下の欄に、いま雇える駒・持ち物・コスト上限。

いまの解放の順は、物語のファイルの `[start]`・`[campaign]` の `budget` と、並びの順の話のファイルの `[unlock]` が正（ここには写さない）。
どの物語も、最初のコスト上限は対戦のコスト上限より低く、物語の終わりには軍の駒が全部そろい、コスト上限が対戦のコスト上限を超える（`tests/game/test_story.gd` が確かめる）。
FANTASY の物語は駒の数が少なく 1 体のコストが高いので、最初のコスト上限は、対戦のコスト上限から MILITARY の物語と同じだけ（4）下げた所にした（演習を終えたとき、4 種類 1 体ずつに盾 1 つ）。
本編の 1 話目でスピードブーツ、2 話目（岩山の合流）は何も増えず、3〜6 話目で 2 ずつ上がる（物語の終わりには、対戦のコスト上限より 4 高い）。
2 ずつにしたのは、FANTASY の駒 1 体のコスト（3〜4）より小さく、話ごとに「1 体増える」より「持ち物か、次の話で 1 体」の歩みにして、数が少なく 1 体が重い形を長く残すため
（既定の編成は、本編の頭で 4 体、終わりの話で 6 体）。
軍の駒の種類はすぐ尽きるので、駒のあとは持ち物とコスト上限で進み具合を出す（人間の言葉「持ち物の種類も増やしてもよさそう」「ストーリーモードなら特殊なアイテムを持たせたりできても面白そう」）。
本編の 3 話目から、話ごとに持ち物を 1 つずつ（コスト上限の上がりと一緒に）解放する。持ち物の中身は `docs/player-loadout.md` の「装備」。

- **物語ごとに顔ぶれを変えた**: MILITARY の物語は能力値が尖る持ち物（遠眼鏡、力の籠手、軍旗）、FANTASY の物語は性質が変わる持ち物（再生の護符、獣道の地図、隠れ蓑）。
  進化先の「軍の色」（`docs/branch-evolution.md`）に合わせた。獣道の地図は、FANTASY の物語の締めのリュエルの森（森の多い盤）の 2 つ前に出す。
- **ストーリー専用の持ち物**は、物語に 1 つずつ、森の話までの筋の終わりの 1 つ前の話のクリアで手に入る（墓守・森の守りで使える）: MILITARY は試作ジェットパック、FANTASY は古竜の鱗。
  対戦モードには出ない（`DeckRules.VERSUS_ITEMS` に無い）。
- **森のあとの話は、コスト上限を動かさない**（物語の終わりのコスト上限は、森の話までで決めた値のまま）。かわりに、両国が手を組んでいく印に、
  相手の物語の持ち物を 1 つ渡す（MILITARY の物語の「もう一人の番人」で獣道の地図、FANTASY の物語の「尾根の亡者」で遠眼鏡）。既定の編成はこの持ち物を使わないので、あとの話の測り方は変わらない。
- 部隊編成と出撃準備は、その物語でいずれ持たせられる持ち物を最初から並べる（まだのものは「未解放」。`offered_items`）。

## クリアの記録

いまのセーブデータ（スロット）の中のまとまり `story`（版 4。`docs/save-slots.md`）。中身は `{"campaign": 最後に選んだ物語の id, "campaigns": {物語の id: {"cleared": [話の id, …], "squad": 部隊の id, "answers": {選択肢の名前: 選んだ答えの鍵}}}, "heroes": {主人公の既定の名前: 付けた名前}}`。
ファイルに書くのは、オートセーブの区切り（話の流れを抜けたときなど）だけ。クリアしたときは覚えておくだけ（`docs/save-slots.md` の「保存する所」）。

- 書くのは、物語ごとの、クリアした話の id と、出撃準備で最後に選んだ部隊の id（`squad`。既定の編成なら書かない）だけ。
  クリアも部隊も無い物語は書かない。使える駒など、ほかのものは書かない（話のファイルを後で変えても、記録と食い違わない）。
  最後に選んだ物語（`campaign`）は、セーブデータ選択のカードに出すためだけに書く（ストーリーに入るたびに選ぶのは同じ）。
- **版 1**（`{"cleared": [...], "squad": ...}`）は、版の番号を見て MILITARY の物語の記録として読み替える（`Story._migrate`）。次に書くときは、いまの版の形。
- **版 3** で `answers`（会話の選択肢で選んだ答え。上の「選択肢」）を足した。選んでいなければ書かない。版 2 の記録は、答えが無いだけ。
- **版 4** で `heroes`（主人公に付けた名前。上の「主人公の名前」）を足した。
- 欄を足すとき（選んだ答え、主人公の名前など）は版を上げる。古い exe は、新しい版の記録の知らない欄を残して書き戻す（`docs/save-slots.md` の「版と、知らない欄」）。
- 話は物語の中で一本道なので、**クリアした話より前の話は、どれもクリアしたものとして読む**（`_fill_earlier_clears`）。
  物語の頭や途中に話を足しても、先へ進んでいた人が、足された話のぶんの解放や先の話を失わない。
- `squad` の無い記録もそのまま読める（既定の編成）。形の違う `squad` も既定の編成として読む。
- 壊れたファイルは「何もクリアしていない」として読む。知らない id（後の版の話や物語）は、消さずに残して書き戻す。
- 検査とスクリーンショットは、ファイルを読み書きしない（スロットの取っておく先が無い。覚えておくだけ）。
- スロットの前の `user://story.json` は、起動したときに 1 番のスロットへ移す（`docs/save-slots.md` の「前の置き方からの移し替え」）。

## 確かめ用の解放

動作の確かめのために、クリアの記録を進めずに先の話を遊べるようにする鍵（人間の言葉「ストーリーのクリア状態を進めないとテストできないのは、今の動作確認では困る。
自由に解放できてしまうのはゲーム性としておかしいが」）。ふつうの画面には入口を出さない（対戦の F1〜F4 と同じく、鍵だけ。`README.md` に書く）。

- **F5** で、全部の物語の全部の話と解放（駒・持ち物・コストの上限）を開く。もう一度 F5 で元に戻す（`Story.open_all`。`game/open_all_key.gd`）。
- その起動のあいだだけ。**記録には書かない**。開いている間に勝った話のクリアは、その起動のあいだだけ覚え、戻すと捨てる
  （一本道の読み方（上の `_fill_earlier_clears`）で、先の話のクリアが前の話を全部クリアにしてしまわないように）。
  開いて始めた、記録どおりではまだ遊べない話は、途中で F5 を戻してから勝っても記録に書かない（その起動のあいだ。ほかのセーブデータを読むまで）。
- 開いているかはセーブデータを替えても続く（起動のあいだの鍵なので）。開いている間のクリアと、開いて始めた話は、セーブデータを読み直すと捨てる（ほかのセーブデータへ持ち越さない）。
- 開いている間は、画面の左下の隅に「確かめ用: 全部の話を開いている（F5 で戻す）」を出す。
- タイトル・物語選択・話の一覧で押したら、その場面を作り直してカードに効かせる。ほかの場面では、次に開く場面から効く。
- あとの会話の「増えたものの知らせ」は、開いていても記録どおりの進み具合で出す（知らせの出方も確かめられるように）。

## 検査

- 自動の対戦（`--autoplay` の `story`。操作の決まりのまとまり `ui` に入る）が、タイトルの「ストーリー」から 1 話を通す:
  セーブデータ選択（はじめから）→ 物語を選ぶ（準備中は押せない）→ 話の一覧 → 出撃準備から編成へ寄り道して部隊を組み、戻ると選ばれている →「出撃」→ 前の会話（送る、戻る、スキップ）→ 話の対戦（話のマップで、選び直す入口が無く、敵を CPU が動かす）→ 小さな盤に替えて 1 手で勝つ
  → クリアを書く・決着の画面に「次へ」→「部隊変更」で出撃準備へ戻り、もう一度勝つ → あとの会話を最後まで送る → 話の一覧（オートセーブで書いて保存の印、最後に保存した所、済みの印、次の話が選べる、雇える駒が増えた）→ 物語を選ぶ（クリアした話の数）→ タイトル（済みの印）。
- 続けて、2 つ目の物語（FANTASY の物語）の頭の演習を通す: 前の物語の記録があり、この物語の記録が無いところから（古いセーブから起動したときと同じ形）、
  セーブデータ選択（つづきから。コピー・上書きの確かめ・削除も）→ 物語を選ぶ → 話の一覧（最初の話だけ選べる。最初から雇える駒）→ 会話を飛ばす → 出撃準備（決まった部隊だけ）→ 勝つ（「部隊変更」が無い）→ あとの会話 → 話の一覧（次の話が選べる）→ 物語を選ぶ（クリアした話の数。前の物語の記録はそのまま）→ タイトル。
- スクリーンショットの場面は `story_` で始まる（`docs/screenshots.md`）。
