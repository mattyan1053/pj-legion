# ストーリー

コード: `game/story.gd`（話の並び、進み具合、話の流れ）、`game/story_battle.gd`（話の対戦。`docs/battle-source.md`）、
`game/talk_screen.gd`（会話の場面）、`game/episodes/`（話のデータ。1 話 1 ファイル）。
テスト: `tests/game/test_story.gd`、自動の対戦の `story`（下の「検査」）。

ストーリーモードの最初の形（Issue #49）。タイトルの「ストーリー」から、1 話を「会話 → 対戦 → 会話」と通す。
**話の中身（世界、登場人物、会話の文）は仮のもの。** 人間が決めたら、話のデータを差し替える。

## 流れ

```
タイトル ─「ストーリー」→ 会話（前）→ 対戦 ─ 決着の画面 ─「次へ」（勝ったとき）→ 会話（後）→ タイトル
                                              ├─「同じ盤面でもう一度」→ 対戦（何度でも）
                                              └─「タイトルへ」→ タイトル
```

- 話は一本道。「ストーリー」は、まだクリアしていない最初の話を始める。全部クリアしていたら、最初の話をもう一度遊ぶ。
  全部クリアしたら、タイトルのボタンは「ストーリー（クリア済み）」になる。
- 場面の並びは流れ（`docs/scene-flow.md` の「流れ」）。`story.gd` の `run_of(話)` が、会話（前）・対戦・会話（後）を並べる。列を終えたらタイトル。
- 負けても失うものは無い。決着の画面の「同じ盤面でもう一度」で、何度でもやり直せる。
- 対戦の途中と会話の途中は、システムメニューの「タイトルへ戻る」で抜けられる（流れは捨てる。もう一度「ストーリー」で、前の会話から）。

## 会話

立ち絵は無い。背景に話の盤（対戦と同じ景色。`backdrop.gd`）、下に文の枠と、話し手の名前の札（陣営の色。人の軍は青、敵は赤）。

- クリック・Enter・Space で次の文へ。文は 1 文字ずつ出る（速さは `talk_screen.gd` の `CHARS_PER_SECOND`）。出きる前に送ると、出しきるだけ。
- 右クリックで 1 つ前の文へ。Esc はシステムメニュー（ほかの場面と同じ）。
- 「飛ばす」で、残りを読まずに次の場面へ。
- 最後の文を送ると、次の場面へ（流れの `Run.NEXT`）。
- 曲はタイトルと同じ（`menu`）。

## 話の対戦

`story_battle.gd`（対戦の画面に渡すもの）が、話のデータから対戦の設定を作る。

- 盤は、話のマップ（手で作ったマップ。`docs/hand-map.md`）。見た目は話が選ぶ（`LOOK`。`stage_look.gd` のテーマ）。
- 人はいつもプレイヤー1（先手）で、人の軍の既定の編成（`MatchSetup.default_deck`）。部隊を選ぶ入口は、まだ無い。
- 敵はプレイヤー2 で、CPU が動かす。部隊は話が決め打ちにする（`ENEMY`。編成の決まりの検査は通さない。`docs/scenario.md`）。
- 勝ち方は対戦と同じ（将の撃破、本陣の占拠）。
- 選び直す入口（F1〜F4、対戦の設定のパネル、決着の画面の「新しい盤面」「対戦の設定へ」）は出さない。
- 人が勝つと、決着の画面に「次へ」が出る（Enter でも）。勝った時点で、話をクリアしたと書く（「次へ」を押す前に抜けても、クリアは残る）。

## 話のデータ

`game/episodes/` に 1 話 1 ファイル。並びは `story.gd` の `EPISODES`。GDScript の定数にしているのは、マップと同じ理由（exe に同梱する設定が要らない、PR で読める）。

| 定数 | 中身 |
| --- | --- |
| `ID` | 話の id（クリアの記録に書く。変えると記録が外れる） |
| `TITLE` | 会話の見出し |
| `MAP`、`LOOK` | 盤（`rules/maps/` のマップ）と、その見た目 |
| `HUMAN_ARMY`、`ENEMY_ARMY` | 人の軍と敵の軍 |
| `ENEMY` | 敵の部隊（将を除く）。`[駒の種類, [装備, …]]` の列。並びの順に、本陣の前へ置く |
| `SPEAKERS` | 話し手の名前（0 = 人の軍、1 = 敵の軍） |
| `BEFORE`、`AFTER` | 対戦の前と後の会話。`[話し手（0 か 1）, 文]` の列。どちらも 6 行まで（テストが確かめる） |

いまある話は 1 つ（「尾根の小道」。`rules/maps/ridge_path.gd` のマップ、石の壁の見た目（迷宮回廊のテーマ）、人は MILITARY、敵は FANTASY）。

### 敵の強さ

最初の話は「ふつうに遊べば勝てるが、雑に突っ込むと負ける」くらいを狙う。人が遊んだ手応えはまだ測れないので、
**人の側も CPU に持たせて回したときに、人の側が 65〜80% 勝つ**ことを目安に、敵の部隊を決めた（集計の道具の `--episode`。`docs/cpu-ai.md`）。
いまの敵は 4 体（予算どおりの編成は 6 体）で、駒の数で人の側が有利になる形にした。前衛に盾を持たせると、勝率はほぼ同じまま対局が長くなる（決着まで粘る）ので、持たせた。
実測は `docs/cpu-ai.md` の「いまの集計」。数値か CPU か話のデータを変えたら、取り直す。

## クリアの記録

`user://story.json`（`save_store.gd`。名前 `story`、版 1）。中身は `{"cleared": [話の id, …]}` だけ。

- 書くのはクリアした話の id だけ。使える駒など、ほかのものは書かない（話のデータを後で変えても、記録と食い違わない）。
- 壊れたファイルは「何もクリアしていない」として読む。知らない id（後の版の話）は、消さずに残して書き戻す。
- 検査とスクリーンショットは、ファイルを読み書きしない（`context.story.store` が無い）。

## 検査

- 自動の対戦（`--autoplay` の `story`。操作の決まりのまとまり `ui` に入る）が、タイトルの「ストーリー」から 1 話を通す:
  前の会話（送る、戻る、飛ばす）→ 話の対戦（話のマップで、選び直す入口が無く、敵を CPU が動かす）→ 小さな盤に替えて 1 手で勝つ
  → クリアを書く・決着の画面に「次へ」→ あとの会話を最後まで送る → タイトル（済みの印）。
- スクリーンショットの場面は `story_` で始まる（`docs/screenshots.md`）。
