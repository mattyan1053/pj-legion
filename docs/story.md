# ストーリー

コード: `game/story.gd`（物語と話の並び、進み具合、話の流れ）、`game/story_battle.gd`（話の対戦。`docs/battle-source.md`）、
`game/campaigns/`（物語のデータ。1 物語 1 ファイル）、`game/campaign_list_screen.gd`（物語を選ぶ）、`game/episode_list_screen.gd`（話の一覧）、`game/sortie_screen.gd`（出撃の準備）、`game/talk_screen.gd`（会話の場面）、`game/episodes/`（話のデータ。1 話 1 ファイル）。
テスト: `tests/game/test_story.gd`、`tests/game/test_episode_data.gd`（話のデータの書き間違い）、`tests/game/test_battle_cues.gd`（対戦の途中の会話）、自動の対戦の `story`（下の「検査」）。

タイトルの「ストーリー」から物語を選び、その物語の話の一覧へ進み、選んだ話を「会話 → 出撃の準備 → 対戦 → 会話」と通す。
**物語と話の中身（世界、登場人物、会話の文）は仮のもの。** 人間が決めたら、物語と話のデータを差し替える。

## 物語

物語（Issue #49 の「ストーリーは軍の種類ごとにあっていい」）は、**軍 1 つと話の列**。`game/campaigns/` に 1 物語 1 ファイル、並びは `story.gd` の `CAMPAIGNS`。

- 人はその物語の軍で話を進める。話をクリアすると、その物語で雇える駒・持ち物・コストの上限が増える（下の「解放」）。
- クリアの記録、出撃の準備で選んだ部隊、雇える駒は、物語ごと（下の「クリアの記録」）。
- いまの物語は 2 つ: MILITARY の物語（下の 4 話）と、FANTASY の物語（**準備中**。話がまだ無い）。
- **物語を 1 つ足すのは、`game/campaigns/` に 1 ファイルと `CAMPAIGNS` に 1 行、話のファイル**（`game/episodes/`）。
  話の無い物語は、物語を選ぶ場面に「準備中」の札で並ぶ（選べない）。

| 定数 | 中身 |
| --- | --- |
| `ID` | 物語の id（クリアの記録に書く。変えると記録が外れる） |
| `TITLE` | 物語を選ぶ場面と、話の一覧の見出しに出す名前 |
| `ARMY` | 人が使う軍 |
| `RULES_ID` | この物語の編成の決まりの名前（取っておく部隊に書く。物語ごとに違う名前。MILITARY の物語は、物語が 1 つだったころの `story`） |
| `STARTING_KINDS` | 最初から雇える駒の種類（その物語の軍の駒） |
| `STARTING_ITEMS` | 最初から持たせられる装備 |
| `STARTING_BUDGET` | 最初の部隊のコストの上限 |
| `EPISODES` | 話の並び（一本道。`game/episodes/` の話のファイル） |

部隊の編成の画面の「ストーリー用」は、いま MILITARY の物語の決まり（`Story.RULES_ID`）で組む。物語が 2 つ遊べるようになったら、編成の画面に物語を選ぶ入口が要る。

## 物語を選ぶ

`campaign_list_screen.gd`。物語をカードで並べる: 物語の名前、使う軍、状態（「全 N 話」「M / N 話クリア」「全 N 話クリア」「準備中」）。

- 遊べる物語が 1 つでも、この場面は飛ばさない（物語が増えていくことを、準備中の札で見せる）。
- カードのクリック（1〜9 のキーでも）で、その物語を選んで話の一覧へ。準備中のカードは暗く、押せない。
- 「タイトルへ戻る」（右クリック・Esc でも）でタイトルへ。

## 流れ

```
タイトル ─「ストーリー」→ 物語を選ぶ ─物語→ 話の一覧 ─話→ 会話（前）→ 出撃の準備 ─「出撃」→ 対戦 ─ 決着の画面 ─「次へ」（勝ったとき）→ 会話（後）→ 話の一覧
                              ↑                     │ ↑ └「話の一覧へ戻る」┐     ├─「同じ盤面でもう一度」→ 対戦（何度でも）
                              │   「部隊を編成する」↓ │「出撃の準備へ戻る」   │     ├─「部隊を選び直す」→ 出撃の準備
                              │               部隊の編成（ストーリー用）    │     └─「タイトルへ」→ タイトル
                              └──────────────────────────────────────┘
```

- 話は物語の中で一本道。遊べるのは、並びの最初の話と、1 つ前の話をクリアした話（`is_available`）。クリアした話は、何度でも遊び直せる。
  遊べる物語の話を全部クリアしたら、タイトルのボタンは「ストーリー（クリア済み）」になる。
- 場面の並びは流れ（`docs/scene-flow.md` の「流れ」）。`story.gd` の `run_of(話)` が、会話（前）・出撃の準備・対戦・会話（後）を並べる。列を終えたら話の一覧。
- 負けても失うものは無い。決着の画面の「同じ盤面でもう一度」で、何度でもやり直せる。「部隊を選び直す」で、出撃の準備へ戻って部隊を替えられる。
- 対戦の途中と会話の途中は、システムメニューの「タイトルへ戻る」で抜けられる（流れは捨てる。もう一度「ストーリー」で、前の会話から）。

## 話の一覧

選んだ物語の話を、並びの順にカードで並べる（`episode_list_screen.gd`）。見出しは物語の名前。

- カード: 「第 N 話」、話の名前、盤の縮図（`stage_card_map.gd`。両軍の駒の初期位置に、陣営の色の点）、状態（「クリア済み」「未クリア」「第 N 話をクリアすると遊べる」）、クリアで増える駒。
- 遊べない話のカードは暗く、押せない。カードのクリック（1〜9 のキーでも）で、その話の前の会話から始める。
- 下の欄に、いま雇える駒・持ち物・コストの上限（下の「解放」）。
- 「物語を選び直す」（右クリック・Esc でも）で物語を選ぶ場面へ。

## 出撃の準備

前の会話と対戦のあいだ（`sortie_screen.gd`）。流れが、話と、話の対戦（`story_battle.gd`）を渡す。

- 左: 盤の縮図。両軍の駒の初期位置に陣営の色の点（選んだ部隊で置き直す）。
- 右: 勝ち方（話の勝ちの条件から作った文。`win_text.gd`）、敵の部隊、出撃する部隊。勝ち方と敵の部隊は、対戦と同じ話の戦いの定義（`StoryBattle.scenario()`。種に依らない）から読む。
  右の欄の文は `game/text_wrap.gd` で折り返す（駒や装備の名前を、語の途中で切らない）。
- 部隊は「既定の編成」（下の「既定の編成」）と、取っておいた、その物語の部隊（決まりの名前が物語の `RULES_ID`。`docs/deck-screen.md`）から選ぶ。
  出せない部隊（まだ解放していない駒がいる、など）は、理由つきで押せない。対戦用の部隊は並ばない。
- 「部隊を編成する」で、部隊の編成（ストーリー用だけ）へ寄り道する。「出撃の準備へ戻る」（右クリック・Esc でも）で、ここへ戻る。
  寄り道の間に取っておいた部隊が、戻ったときに選ばれている。
- 「出撃」で、選んだ部隊を話の対戦に持たせて対戦へ。選んだ部隊は覚えておき（下の「クリアの記録」）、次に出撃の準備を開いたとき（次に起動したときも）選ばれている。
  覚えた部隊が無くなったか出せなくなったら、既定の編成。
- 「話の一覧へ戻る」（右クリック・Esc でも）で話の一覧へ（流れは捨てる）。
- 負けて「同じ盤面でもう一度」なら、同じ部隊でやり直す。決着の画面の「部隊を選び直す」なら、ここへ戻る（前の会話は飛ばす）。

### 既定の編成

初めて遊ぶ人が出撃の準備で見て納得できる、素直な形にする（`story.gd` の `default_deck`）。CPU の編成の組み方（`CpuDeck`）は使わない
（余った予算を前衛の盾に積むので、「シールドトルーパーに盾 3 つ ×2」のように偏る）。

1. いま雇える駒を、役割の順（前衛・後衛・奇襲・回復）に 1 体ずつ、数の上限まで繰り返して雇う（予算に収まるかぎり）。
2. 余った予算で、前衛にアイアンシールド、奇襲にスピードブーツを、1 体に 1 つまで持たせる（`DEFAULT_ITEMS`。持たせられる持ち物だけ。後衛と回復は持たない）。
3. 並びは役割の順（同じ種類はまとめる）。並びの順に初期位置へ置かれるので、前衛が前に出る。

| いつ（雇える駒・持ち物・コストの上限） | 既定の編成 |
| --- | --- |
| 最初（シールドトルーパー・スナイパー・衛生兵、盾、20） | シールドトルーパー ×2、スナイパー ×2、衛生兵 ×2（予算が尽きて盾は持たない） |
| 第 1 話のあと（+ コマンドー） | シールドトルーパー ×2、スナイパー ×2、コマンドー、衛生兵 |
| 第 2 話のあと（+ ブーツ、22） | シールドトルーパー（盾）×2、スナイパー ×2、コマンドー、衛生兵 |
| 第 3 話のあと（24） | シールドトルーパー（盾）×2、スナイパー ×2、コマンドー（ブーツ）、衛生兵 |

## 会話

立ち絵は無い。背景に話の盤（対戦と同じ景色。`backdrop.gd`）、下に文の枠と、話し手の名前の札（陣営の色。人の軍は青、敵は赤）。

- クリック・Enter・Space で次の文へ。文は 1 文字ずつ出る（速さは `talk_screen.gd` の `CHARS_PER_SECOND`）。出きる前に送ると、出しきるだけ。
- 右クリックで 1 つ前の文へ。Esc はシステムメニュー（ほかの場面と同じ。閉じるボタンは「会話へ戻る」）。
- 「飛ばす」で、残りを読まずに次の場面へ。ただし、この先に知らせの行（下の「解放」）があれば、そこで止まる。
- 最後の文を送ると、次の場面へ（流れの `Run.NEXT`）。
- 曲はタイトルと同じ（`menu`）。

## 話の対戦

`story_battle.gd`（対戦の画面に渡すもの）が、話のデータから対戦の設定を作る。

- 盤は、話のマップ（手で作ったマップ。`docs/hand-map.md`）。見た目は話が選ぶ（`LOOK`。`stage_look.gd` のテーマ）。
- 初期位置は話が選べる（`DEPLOY`。戦いの定義の初期位置。`docs/scenario.md`）。同じマップを、初期位置を変えて使い回せる。
- 人はいつもプレイヤー1（先手）で、出撃の準備で選んだ部隊。
- 敵はプレイヤー2 で、CPU が動かす。部隊は話が決め打ちにする（`ENEMY`。編成の決まりの検査は通さない。`docs/scenario.md`）。
- 勝ち方は、ふつうは対戦と同じ（将の撃破、本陣の占拠）。話が `HOLD_TURNS` を持てば、人はそのターン数を守り切っても勝てる
  （戦いの定義の `hold_for`。`docs/win-conditions.md` の「守り切る」）。話が `WINS` を持てば、人の勝ち方はその列だけになる
  （戦いの定義の `set_win_conditions`。たとえば全滅だけなら、敵の将を倒しても終わらない）。敵はいつもの勝ち方で攻める。
- 選び直す入口（F1〜F4、対戦の設定のパネル、決着の画面の「新しい盤面」「対戦の設定へ」）は出さない。部隊だけは、決着の画面の「部隊を選び直す」で選び直せる。
- 人が勝つと、決着の画面に「次へ」が出る（Enter でも）。負けたときの Enter は「同じ盤面でもう一度」。決着の画面が出た時点で、話をクリアしたと書く（「次へ」を押す前に抜けても、クリアは残る）。

## 話のデータ

`game/episodes/` に 1 話 1 ファイル。並びは `story.gd` の `EPISODES`。GDScript の定数にしているのは、マップと同じ理由（exe に同梱する設定が要らない、PR で読める）。

話のファイルは定数だけを持つ（敵の部隊を組むのも、無くてもよい定数を読むのも `story_battle.gd`）。**話を 1 つ足すのは、`game/episodes/` に 1 ファイルと、物語の `EPISODES` に 1 行。**
物語の書き間違い（id や決まりの名前の重なり、最初の駒がほかの軍の駒、1 つの話が 2 つの物語に入る）も `test_episode_data.gd` が弾く。
書き間違い（知らない定数の名前、無い駒・装備、置けないマス、勝ち方の列の矛盾、きっかけの値）は `tests/game/test_episode_data.gd` が起動の前に弾く。
無くてもよい定数（`HOLD_TURNS`、`WINS`、`CUES`、`UNLOCK_ITEMS`、`BUDGET_UP`、`MUSIC`、`TALK_MUSIC`）は、名前を書き間違えると黙って「無い話」になるので、知らない名前はテストが落とす。
読む側（画面、スクリーンショットの道具、テスト）は、定数の有る無しを自分で調べず、`StoryBattle.hold_turns_of`・`wins_of`・`cues_of`・`unlock_items_of`・`budget_up_of`・`music_of`・`talk_music_of` を通す（無い話の値もそこだけに持つ）。

| 定数 | 中身 |
| --- | --- |
| `ID` | 話の id（クリアの記録に書く。変えると記録が外れる） |
| `TITLE` | 会話の見出し |
| `MAP`、`LOOK` | 盤（`rules/maps/` のマップ）と、その見た目 |
| `UNLOCKS` | クリアで新しく雇えるようになる駒の種類の列（下の「解放」）。その物語の軍の駒だけ |
| `UNLOCK_ITEMS` | あれば、クリアで新しく持たせられるようになる装備の列 |
| `BUDGET_UP` | あれば、クリアで部隊のコストの上限が上がる量（1 以上） |
| `ENEMY_ARMY` | 敵の軍（人の軍は、話の物語の `ARMY`） |
| `ENEMY` | 敵の部隊（将を除く）。`[駒の種類, [装備, …]]` の列。並びの順に、初期位置へ置く |
| `HOLD_TURNS` | あれば、人（プレイヤー1）がこのターンの終わりまで守り切れば勝ち。無い話は、勝ち方が対戦と同じ |
| `WINS` | あれば、人（プレイヤー1）の勝ち方の列（`GameWonEvent.Reason`）。無い話は、いつもの勝ち方（将の撃破、本陣の占拠） |
| `DEPLOY` | 初期位置。`[プレイヤー1 のマスの列, プレイヤー2 のマスの列]`。空の列は、いつもの「本陣の前」。マスは歩けて、重ならず、本陣でなく、部隊の数以上（テストが確かめる） |
| `SPEAKERS` | 話し手の名前（0 = 人の軍、1 = 敵の軍） |
| `CUES` | あれば、対戦の途中の会話（下の「対戦の途中の会話」）。`[きっかけ, 値, 話し手（0 か 1）, 文]` の列。3 つまで、文は 40 字まで（テストが確かめる） |
| `BEFORE`、`AFTER` | 対戦の前と後の会話。`[話し手（0 か 1）, 文]` の列。どちらも 6 行まで（テストが確かめる） |
| `MUSIC` | あれば、対戦の曲（`sound_catalog.gd` の `MUSIC` の名前。`docs/sound.md`）。無い話は、盤の見た目（`LOOK`）の曲 |
| `TALK_MUSIC` | あれば、対戦の前と後の会話の曲。無い話は、会話の場面の曲（`talk`） |

| 話 | id | 初期位置 | クリアで増えるもの |
| --- | --- | --- | --- |

| 第 2 話「尾根の待ち伏せ」 | `ridge_ambush` | 人は本陣の前。敵は尾根の中ほど（中央の岩の上側と、左右の道の入り口） | スピードブーツ、コストの上限 +2 |
| 第 3 話「尾根の籠城」 | `ridge_hold` | 人は本陣の前。敵は尾根の中ほど（2 話より 1 列多い）。人は 10 ターン守り切れば勝ち | コストの上限 +2 |
| 第 4 話「渓谷の掃討」 | `gorge_rout` | どちらも本陣の前（結晶の渓谷の対角）。人は敵を全滅させれば勝ち（将を倒しても終わらない） | コストの上限 +2 |

### 敵の強さ

**人間が遊んで「ストーリーの難易度は結構高めに感じた」と言った（11/16）。CPU の実測は、人が遊んだ手応えより甘く出る**（CPU は人より上手に駒を並べる）。
そこで、めやすを上へ寄せた。人が遊んだ手応えはまだ測れないので、**人の側も CPU に持たせて回したときの、人の側の勝率**を目安にする（集計の道具の `--episode`）:

| 話 | めやす |
| --- | --- |
| 1 話 | 90% 以上（まず負けない） |
| 2 話 | 85% 前後 |
| 3・4 話 | 75〜85% |

- 人の側は 2 通りで測り、両方を見る: その話を初めて遊ぶときの既定の編成（`story.gd` の `first_battle`）と、局ごとに変えた部隊（`--squads=random`）。
  手で作ったマップは盤の上の乱数が少なく、既定の編成だけでは同じような局を数えることになる（`docs/hand-map.md` の「マップを作るときのめやす」）。
- 最後は人間が遊んで決める（CPU どうしの勝率は、人が遊んだときの手応えとは違う。勝ち方が話ごとに違うので、話どうしの勝率を並べて比べることもしない）。

- 1 話: 前衛（パラディン。盾なし）と後衛の 2 体。予算どおりの編成（6 体）よりずっと少なく、駒の数で人の側が大きく有利。
  奇襲の駒は入れない（人の側にまだ奇襲の駒が無く、奇襲の駒の有る無しで勝率が大きく動く）。
- 2 話: 敵は尾根の中ほどから始まる（人の本陣に近く、左右どちらの道へもすぐ出られる）。盾を 2 つ持つパラディン・後衛・回復の 3 体。
  4 体目（後衛でも奇襲でも）を足すと、人の側の勝率が半分ほどに落ちる。
- 3 話（守り切る）: 8 体（前衛 2・後衛 3・奇襲 2・回復 1）で数で押す。人は敵を倒しきらなくても、10 ターン持ちこたえれば勝てる。
  守り切る話は、敵の数と顔ぶれで勝率が大きく跳ね（1 体の違いで、人の側がほぼ勝つ ⇔ ほぼ負ける）、ターン数を 1〜2 動かしても少ししか変わらない。
  既定の編成ではほぼ勝ち、部隊を変えると負けることがある（守りに向かない組み合わせ）。
- 4 話（全滅させる）: パラディン（盾なし）・後衛・回復の 3 体。このマップは中立の駒の湧き直しが起きず、盤の上に乱数が無い（どの種でも同じ 1 局になる）ので、
  人の部隊を局ごとに変えて測る（`--squads=random`）。

前衛に盾を持たせると、勝率が下がり、対局が長くなる（決着まで粘る）。CPU どうしの対局は、敵の形でほぼ勝ち負けが決まり、シードを替えても勝率が大きくは動かない。
実測は `docs/cpu-ai.md` の「いまの集計」。数値か CPU か話のデータを変えたら、取り直す。

## 対戦の途中の会話

コード: `game/battle_cues.gd`（いつ出すか。ノードに依存しない）、`game/battle_talk.gd`（札）。テスト: `tests/game/test_battle_cues.gd`。

話のデータの `CUES` に「いつ・だれが・何と言うか」を書くと、対戦の途中に短い台詞が出る。対戦は止めない。

- きっかけ（`BattleCues` の定数。話で使うものだけ作った）:

  | きっかけ | 値 | 出すとき |
  | --- | --- | --- |
  | `TURN` | ターン N | ターン N の、人の番（プレイヤー1 のフェーズ）の始め。ターン 1 は対戦の始め |
  | `KING_HALF` | 陣営（0 か 1） | その陣営の将の HP が半分を切った |
  | `FALLEN` | 陣営（0 か 1） | その陣営の駒（将を除く）が初めて倒れた |

- ルール（`rules/`）には入れない。画面が、行動ごとにルールが返した出来事の列（`BattleEvent`）と盤の状態を `BattleCues` に渡して、出す台詞を聞く。
  聞くのは、その行動の演出を見せ終えたあと（演出と重ねない）。
- どの台詞も、1 回の対戦で 1 度だけ。「同じ盤面でもう一度」なら、また出る。同時にいくつか当たったら、`CUES` の並びの順に、1 つずつ出す。
- **決着した行動のあとは出さない**（決着の画面と重ねない）。決着の画面が出たら、出ている台詞も消す。
- 出し方: 上の帯のすぐ下の真ん中に、細く横長の帯（幅 `BattleTalk.WIDTH`。話し手の名前の札（陣営の色）と文を 1 行に並べる。長い文は 2 行）で、
  数秒（`BattleTalk.SHOW_BASE` 秒 + 1 文字 `BattleTalk.SHOW_PER_CHAR` 秒）出して消す。地は半透明。
  盤の大事な所（選んだ駒、動けるマス）を隠しにくいよう、マウスが乗っている間と、駒のそばのメニュー・予測のパネルが重なっている間は薄くする。
  左の勝ち方の札、右の視点の案内・ミニマップとは重ならない（自動の対戦の `story` が、いちばん長い台詞で確かめる）。
  クリックは受けない（盤の操作を邪魔しない）。帯・駒のそばのメニュー・予測のパネル・進化の選択より下に描く（重なったら、そちらが見える）。出す長さは実際の時間で測る（CPU の番の早送りや、自動の対戦の速さで縮めない。メニューで止めている間は進めない）。
- ログ（`docs/battle-log.md`）にも「話し手「文」」の 1 行で残す（話し手の陣営の色）。読み逃しても、あとで読める。
- 止めてクリックで送る形にしなかったのは、台詞が 1〜2 行で短く、CPU の番の途中にも出るため（止めると、早送りや決着の手前で、送る手間だけが増える）。

いまの台詞（どの話も 1〜2 つ。使い方の例）: 1 話は敵の将が弱ったとき、2 話は始め（敵が待ち伏せを知らせる）と味方が初めて倒れたとき、
3 話はターン 8 と 10 の始め（残りのターン）、4 話は敵が初めて倒れたときと敵の将が弱ったとき（全滅させる話なので「残りも逃がすな」）。

## 解放

ストーリーを進めると、その物語で使えるものが増える（Issue #49。人間の言葉「それぞれのストーリーで、それぞれの軍の種類のユニットが解放されていく」
「ストーリーモードなら部隊のコスト上限とかあげられてもよさそう」）。対戦モードの編成には影響しない（決まりが別）。

増えるものは 3 つ。どれも**その物語の中だけ**で、物語ごとに別に数える。

| 増えるもの | 物語の最初 | 話のクリアで増える |
| --- | --- | --- |
| 雇える駒の種類 | `STARTING_KINDS` | 話の `UNLOCKS`（その物語の軍の駒だけ。テストが確かめる） |
| 持たせられる持ち物（装備） | `STARTING_ITEMS` | 話の `UNLOCK_ITEMS` |
| 部隊のコストの上限（予算） | `STARTING_BUDGET` | 話の `BUDGET_UP` だけ上がる（対戦の予算を超えてよい） |

- いま使えるものは、クリアの記録から、その場で求める（`story.gd` の `Unlocked`、`unlocked()`。記録には書かない）。
  話を初めて遊ぶときに使えるもの（並びで前の話の解放まで）は `unlocked_before(話)`。
- ストーリーの編成の決まり（`DeckRules`。名前は物語の `RULES_ID`）は、いま使えるものから作る（`deck_rules()`、`rules_of(使えるもの)`）。
  数の上限は対戦と同じ。まだ持たせられない持ち物を持った部隊は出せない（`Deck.Problem.ITEM_NOT_ALLOWED`。`docs/deck-building.md`）。
  名前が `versus` とも、ほかの物語とも違うので、取っておく部隊は対戦用と物語ごとに分かれる。
  取っておいた部隊を読むときは、決まりの名前から、その物語の進み具合の決まりを引く（`rules_by_id`。`app_context.gd`）。
- 雇えない駒や持たせられない持ち物のいる、取っておいた部隊（前の版でほかの軍の駒を解放していたころの部隊など）は、消さずに、理由つきの「出せない」で一覧に残る。
  出撃の準備で覚えていた部隊が出せなければ、既定の編成を選ぶ。
- 話を初めてクリアすると、あとの会話の最後に「知らせ」の行（灰色の札）で、増えたものを 1 つずつ知らせる（「新しい駒「…」を雇えるようになった。」
  「新しい持ち物「…」を持たせられるようになった。」「部隊のコストの上限が N になった。」）。クリア済みの話を遊び直したときは出さない。
- 話の一覧のカードに「クリアで増える: …」、下の欄に、いま雇える駒・持ち物・コストの上限。

MILITARY の物語のいまの解放の順:

| いつ | 雇える駒 | 持ち物 | コストの上限 |
| --- | --- | --- | --- |
| 最初 | シールドトルーパー・スナイパー・衛生兵 | アイアンシールド | 20 |
| 第 1 話のあと | + コマンドー | | |
| 第 2 話のあと | | + スピードブーツ | 22 |
| 第 3 話のあと | | | 24（対戦と同じ） |
| 第 4 話のあと | | | 26 |

MILITARY の駒は 4 種で尽きるので、駒のあとは持ち物とコストの上限で進み具合を出す。新しい持ち物（ストーリー専用のものを含む）は、まだ無い（Issue #49）。

## クリアの記録

`user://story.json`（`save_store.gd`。名前 `story`、版 2）。中身は `{"campaigns": {物語の id: {"cleared": [話の id, …], "squad": 部隊の id}}}`。

- 書くのは、物語ごとの、クリアした話の id と、出撃の準備で最後に選んだ部隊の id（`squad`。既定の編成なら書かない）だけ。
  クリアも部隊も無い物語は書かない。使える駒など、ほかのものは書かない（話のデータを後で変えても、記録と食い違わない）。
  いま選んでいる物語も書かない（ストーリーに入るたびに選ぶ）。
- **版 1 の形**（物語が 1 つだったころの `{"cleared": [...], "squad": ...}`）は、MILITARY の物語の記録として読む。次に書くときは版 2 の形。
- `squad` の無い記録もそのまま読める（既定の編成）。形の違う `squad` も既定の編成として読む。
- 壊れたファイルは「何もクリアしていない」として読む。知らない id（後の版の話や物語）は、消さずに残して書き戻す。
- 検査とスクリーンショットは、ファイルを読み書きしない（`context.story.store` が無い）。

## 検査

- 自動の対戦（`--autoplay` の `story`。操作の決まりのまとまり `ui` に入る）が、タイトルの「ストーリー」から 1 話を通す:
  物語を選ぶ（準備中は押せない）→ 前の会話（送る、戻る、飛ばす）→ 出撃の準備から編成へ寄り道して部隊を組み、戻ると選ばれている → 話の対戦（話のマップで、選び直す入口が無く、敵を CPU が動かす）→ 小さな盤に替えて 1 手で勝つ
  → クリアを書く・決着の画面に「次へ」→「部隊を選び直す」で出撃の準備へ戻り、もう一度勝つ → あとの会話を最後まで送る → 話の一覧（済みの印、次の話が選べる、雇える駒が増えた）→ 物語を選ぶ（クリアした話の数）→ タイトル（済みの印）。
- スクリーンショットの場面は `story_` で始まる（`docs/screenshots.md`）。
