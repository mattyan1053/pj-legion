# docs/

## 置き方

- **機能ごとに 1 ファイル**。ファイル名は機能の名前にする（例: `combat.md`、`turn-phase.md`）。**連番は振らない。**
- 書くのは**いまの仕様**だけ。経緯や議論は PR の本文に書き、ここには残さない。
- **全 PR が書き足すファイルは作らない**（進捗の記録、変更履歴、目次など）。
  この README にも一覧は置かない。一覧が要るならディレクトリを見る。
- 仕様の正しさは**テストで固定する**。文書とテストが食い違ったら、テストが正で、文書を直す。

機能を 1 つ入れる PR は、ふつう「その機能の文書 1 つ + コード + テスト」になる。
他の機能の文書には触らないので、並行する PR が衝突しない。

## テスト

`tests/` の下に `test_*.gd` を置く。書き方は `tests/base_test.gd` の先頭に書いてある。
`tools/check.sh` が全部を実行する（CI も同じ）。テストだけなら次で動く。

    godot --headless --path . -s res://tools/run_tests.gd
