# コードの健康診断

コード全体を通しで読んで、継ぎ足しで歪んだ所が無いか、これから入る大きいものを足せる形かを見た記録。2 回目。
基準は 2026-11-28 の main（`e5599e7`。#536 まで）。読んで測っただけで、コードは変えていない。
前の診断は 11/26（`701c8c8`。#489）。そのあと main に 50 本ほど入った（前の「直す順」の ①〜⑬ の全部と、話の新しい書き方）。
次の診断では、この文書を書き直す（書き足さない。前の版は `git log` に残る）。手順は `code-health` のスキル。

## 全体の診断

1. **対戦の土台は、前より健康になった。** 前の診断の「足し忘れても誰も気付かない所」は、見張りのテストでふさがっている。
   わざと壊して確かめた（下の「前の直しが効いたか」）: 効果の順を入れ替えると 4 つ、新しい出来事を足すと読む所 8 つの全部が落ちる。
2. **心配は、話の流れの側へ移った。** 2 日で場面の種類・選択肢・名前・盤のカットシーンが入り、書かれた話も厚くなったが、
   **自動の点検は厚くなったぶんを通っていない。** 対戦のあとの場面（会話の場面 92 のうち 42、行で 580 のうち 269）と、選択肢 8 つのうち 6 つは、
   どの自動の点検でも画面に出ない。放っておくと「書き間違いは無いのに、遊ぶと止まる・崩れる」を人間が exe で見つけることになる。
3. **PR ごとの点検が、特定の話の形に結び付いている。** 連邦 第 7 話と騎士領 第 1 話が「出撃準備 → 会話 → 対戦 → 会話」でないと落ちる。
   話を書く側が、その 2 話だけ形を変えられない。話が増えるほど、こういう「触れない話」が邪魔になる。
4. **測る道具は、打ち間違えた引数を黙って受ける。** `--trait=none`（正しくは `--traits`）でも止まらず、既定のまま回って数字が出る。
   集中砲火の件と同じ「測っているつもりで測れていない」が、また起きる形のまま。
5. **いますぐ直すべき壊れは無い。** CI の `check` は 57〜64 秒（めやす 90 秒）。ただし 2 日で手元が 4〜10 秒伸びた。
   いまの速さで足し続けると、1〜2 週間でめやすに届く（伸びているのは、足したテストが全部入る既定の組）。
