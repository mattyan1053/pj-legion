# 環境オブジェクト（起爆樽、回復の泉、ポータル、砲台、拠点）

コード: `rules/map_object.gd`（種類と、効果の計算）、`rules/board.gd`（どこに何があるか）、
`rules/board_generator.gd`（マップごとの配置）、`rules/actions/attack_barrel_action.gd`、
`rules/events/`（`barrel_exploded_event.gd`、`explosion_damaged_event.gd`、`spring_healed_event.gd`、`unit_warped_event.gd`、
`game_drawn_event.gd`）。
泉の回復は `rules/actions/end_phase_action.gd`、ポータルは `rules/movement.gd` と `rules/actions/move_action.gd`。
テスト: `tests/rules/test_map_objects.gd`、配置は `tests/rules/test_board_generator.gd`。

## 層

- 環境オブジェクトは、地形とも駒とも別の層。置いても地形は変わらない（森の上の泉は、入るのに森と同じだけ移動力を使う）。
- 1 マスに 1 つまで。入れる地形のマスにだけ置ける。
- 盤面（`Board`）が持つ。`Board.object_at(マス)` が種類（無し / 起爆樽 / 回復の泉 / ポータル）を返す。
  対戦の複製（`Battle.clone()`）では盤面ごと別になる。

| 種類 | 入れるか | 効果 |
| --- | --- | --- |
| 起爆樽 | 入れない（通り抜けも、駒を置くこともできない） | 攻撃されると爆発する |
| 回復の泉 | 入れる | フェーズの始めに、乗っている駒が回復する |
| ポータル | 入れる | 対になるポータルへ移れる |
| 砲台 | 入れる | 乗った後衛の射程が伸びる |
| 拠点（対戦モードの既定） | 入れる | 乗ったまま番を終えると確保が進み、決まった数で勝つ |

## 起爆樽

`Battle.apply(AttackBarrelAction.new(攻撃する駒の番号, 樽のマス))`。

- 攻撃できる条件は、駒への攻撃と同じ（`docs/combat.md`）: 行動できる駒が、いまの位置から、射程（マンハッタン距離）以内の樽を攻撃する。
  間に盾があれば届かない（`docs/field-effects.md`）。
  巡航で動いた駒は攻撃できない。攻撃すると行動を終える。
- 樽の耐久力は 1（`BARREL_HP`）で、攻撃 1 回で（攻撃力によらず）爆発する。爆発した樽は盤から消え、そのマスは通れるようになる。
- 爆発は、樽の周り 8 マス（チェビシェフ距離 1）の**駒すべて**に **15**（`BLAST_DAMAGE`）のダメージを与える。
  敵・味方・中立を問わず、攻撃した駒自身も巻き込む。
- ダメージは固定。攻撃力にも、森の軽減にもよらない。煙幕でも防げない（攻撃ではない）。盾には当たらない。
- 爆発は、ほかの樽を誘爆させない。
- **バリアは爆発も防ぐ**（その駒へのダメージが 0 になり、バリアは消える。`docs/unit-statuses.md`、`docs/combat.md` の「ダメージの解決」）。
  爆発のダメージも、駒の攻撃と同じ解決（`MapObject.blast_hit`）を通る。
- 爆発で将が倒れたら、勝ち負けに数える（`docs/win-conditions.md`）。自分の将を倒せば負け、両方の将が倒れれば引き分け。

返すイベントは順に、

1. `BarrelExplodedEvent`（攻撃した駒、樽のマス、爆発の届いたマス、巻き込まれた駒の番号 `victim_ids`）
2. 巻き込まれた駒ごとの `ExplosionDamagedEvent`（盤面の上の行から、左の列から。`victim_ids` と同じ並びで、同じ数。
   `barrel_cell` が樽のマス。攻撃した駒は持たない。`docs/battle.md`）
3. バリアで防いだ駒ごとの `StatusRemovedEvent`（同じ並び）
4. 攻撃した駒の、攻撃で消える状態（照準）の `StatusRemovedEvent`（`CONSUMED`）
5. 倒れた駒ごとの `UnitDefeatedEvent`（同じ並び。中ボスなら続けて `MidBossDefeatedEvent` と、聖遺物を受け取れば `RelicGainedEvent`。
   `docs/neutral-mid-boss.md`、`docs/relic-buff.md`）
6. `UnitActedEvent`（攻撃した駒が自分の爆発で倒れたときは出ない）

爆発は同時に当たるので、全員のダメージを先に並べ、撃破はそのあとにまとめる。
1 つの爆発に属するダメージは、`BarrelExplodedEvent` のすぐあとに `victim_ids` の数だけ続くもの（どれも `barrel_cell` が同じ）。
同時に見せたい画面は、爆発のイベントを見た時点で、何体ぶん先を読めばよいかが分かる。

状態を変えない計算（戦闘予測も同じものを使う）: `MapObject.can_attack_barrel`、`barrel_targets`（いまの位置から攻撃できる樽）、
`blast_cells`（爆発の届くマス）、`blast_victims`（巻き込まれる駒）、`blast_damage`（駒ごとのダメージ）。

## 回復の泉

- プレイヤーのフェーズが始まるとき、そのプレイヤーの駒のうち、回復の泉のマスにいるものが HP を **12**（`SPRING_HEAL`）回復する。
  最大 HP の実効値は超えない。
- 相手のフェーズと中立のフェーズでは回復しない。中立の駒は回復しない。
- 対戦の最初のフェーズ（ターン 1 のプレイヤー1）では起きない（誰の HP も減っていない）。
- `PhaseStartedEvent` のあとに、回復した駒ごとの `SpringHealedEvent`（上の行から、左の列から。`cell` が泉のマス。
  回復した駒は持たない。`docs/battle.md`）が続く。
  HP が満タンの駒には、イベントは出ない。
- 状態を変えない計算: `MapObject.spring_targets`（そのフェーズの始めに回復する駒）、`spring_heal`（実際に増える HP）。

## ポータル

ポータルは 2 つで対になり、互いが行き先になる。

`Battle.apply(WarpAction.new(駒の番号))`（`rules/actions/warp_action.gd`）。

- ポータルのマスにいる駒は、対になるポータルへ**移動力を使わずに**移れる（転移）。**移動（`MoveAction`）はポータルを越えない**ので、
  ポータルのマスまで動いて止まり、そこで転移を選ぶ。フェーズの始めからポータルの上にいる駒も、その場から転移できる（踏み直さなくてよい）。
- 転移したあとは、そこまでに歩いて使った移動力を引いた残りで、転移した先から**もう 1 回動ける**（ほかのマスへ。`docs/movement.md`）。
  巡航で動いていれば、続きも巡航。続けて動かずに、攻撃・待機・取り消しを選んでもよい。
- **行き先のポータルにほかの駒（敵・味方・中立を問わない）がいる間は、転移できない。**
  ポータルのマスそのものには、ふつうのマスと同じに入れて、止まれる。
- 転移してすぐ、もう一度転移することはできない（来たポータルへ戻るだけ。戻るなら取り消す）。
  続けて歩いて、別の（または同じ）ポータルに止まれば、また転移できる。行動を終えないスキル（シャドウステップ）を使ったあとは転移できない。
- 支配領域（ZOC。`docs/movement.md`）との関係は、歩くときと同じ。敵の支配領域にあるポータルへ歩いて入ったら、そこで止まり、転移できない
  （動き出したマスなら転移できる）。転移した先が敵の支配領域なら、そこで止まる（続けて動けない）。
- 転移はほかのマスへ移るので、動くと外れる状態（照準）が外れる。移動の取り消し（`UndoMoveAction`）は、転移の前の、動き出したマスへ戻す（外れた状態も戻る）。
- `Battle.portal_exit(マス)` が、いま転移できる先を返す（ポータルでないか、行き先がふさがっていれば `Board.NO_CELL`）。
  その駒がいま転移できるかは `Battle.options(駒の番号).warp_exit`。

イベントは、行動ごとに出る。

- ポータルまで歩き、転移し、その先を歩く: `MoveAction` の `UnitMovedEvent`、`WarpAction` の `UnitWarpedEvent`（入ったポータル、出たポータル）、
  続きの `MoveAction` の `UnitMovedEvent`
- 転移した先で止まる: `UnitMovedEvent`、`UnitWarpedEvent`
- ポータルの上から転移する: `UnitWarpedEvent` から始まる
- `UnitWarpedEvent` の巡航かどうか（`cruise`）は、それまでの移動のまま。
- 移動の取り消しは、転移の前のマスへ戻る（`MoveUndoneEvent` は 1 つ）。
- 中立の駒は行動を使わないので、移動の道の中でポータルを通る（転移も使った道。`UnitMovedEvent` の間に `UnitWarpedEvent` が入る）。
- ポータルが働くのは、移動と転移の行動だけ。スキルでポータルのマスに着いた駒（シャドウステップ。入れ替えられた駒も）は、転移しない
  （そのあとは、行動を終えないスキルを使ったあとなので、転移を選べない）。

## 砲台

コード: `rules/map_object.gd`（`battery_bonus`、`BATTERY_RANGE`）、`rules/board.gd`（`battery_spots`、`battery_cells`）、
`rules/board_generator.gd`（`battery_spots_for`、`arm_batteries`）、`rules/hand_map.gd`（`C` と、対戦モードだけの `V`）、`game/versus_fields.gd`（対戦モードの盤）、
`rules/unit.gd`（`site_range`）、`rules/battle.gd`（`refresh_sites`）。
テスト: `tests/rules/test_battery.gd`。

占拠していると有利なマス（Issue #47）。**回復の泉やポータルと同じ、マップの物**（人間の決定。Issue #47 の 11/23）。
盤の出どころが置く: 手で作ったマップはファイルの `C`（書けばいつもある。話のマップにも置ける）か `V`（対戦モードだけ。話では平地なので、話の盤と難しさを変えずに置ける）、生成のマップは置く盤の種類（`BoardGenerator.BATTERY_STAGES`）だけ。
対戦の始めに説明はしない（マスの説明と、乗ったときの射程の表示で分かる）。

- **後衛が砲台のマスに立っている間、射程が +4（`MapObject.BATTERY_RANGE`）。** 攻撃も、射程で測るものも（樽・盾への攻撃）伸びる。
  ほかの役割（将、前衛、奇襲、回復）と中立の駒には、何も起きない。
- 伸びるのは、立っている間だけ。動いて乗ればその行動から伸び、降りれば戻る（移動を取り消して戻れば、また伸びる）。
  駒の実効値の層（`docs/player-loadout.md`）とは別に、駒が `Unit.site_range` に持ち、対戦が、駒を置いたときと行動のたびに付け直す。
- 砲台は壊れず、だれのものでもない。入るのに使う移動力は地形のまま。ほかの駒が乗っていれば入れないのは、ふつうのマスと同じ。
- イベントは無い（射程は駒の状態から読める）。
- **場所**（`Board.battery_spots`）は盤が持つ。生成のマップは、砲台を置かない盤の種類でも場所を持つ（拠点がそのマスを避けるので、砲台の有無で拠点は動かない）。
  置く盤の種類は、盤を作るとき（`BoardGenerator.generate` の最後。ほかの物を置いたあと）に `BoardGenerator.arm_batteries` が砲台（`Board.battery_cells`）にする。
  場所が障害物なら平地にし、本陣から歩いて行けなければ道を削る。ほかの環境オブジェクトのあるマスには置かない。
- 場所は 2 つで、本陣どうしを入れ替える点対称。**どちらの本陣からも、ほぼ同じ遠さに置く**（自陣寄りに置くと守る側の物になり、先手が不利になった。比べた数字は、入れた PR の本文）。
  真ん中から外した置き方（左右の端・回り道）も比べたが、両方の本陣から同じ遠さで中ボスの届かないマスは盤の端にしか無く、そこからの射程ではぶつかり合う真ん中に届かないので、
  CPU はほとんど使わなかった（比べた数字は手直しの PR の本文）。いまは、真ん中の近くのまま。砲台からは、どちらの本陣にも届かない。
  中ボスの届く距離（縄張り + 射程）の外に置く（`tests/rules/test_battery.gd`、`tests/game/test_match_choice.gd` で固定）。

| 盤 | 場所（置くのは、下の「置くマップ」） |
| --- | --- |
| 中央平原、迷宮回廊 | 本陣の列の、真ん中の行の 1 つ手前と 1 つ先（30 x 30 なら `(14,13)` と `(14,16)`） |
| 双子結晶 | 左上と右下の角から 7（`BoardGenerator.BATTERY_CORNER`）ずつ内側（30 x 30 なら `(7,7)` と `(22,22)`） |
| 手で作ったマップ | マップのファイルの `C` のマス（どの対戦にも）と `V` のマス（対戦モードだけ。`docs/hand-map.md`）。書いたマップにだけある |

- CPU は砲台を知っている（`docs/cpu-ai.md` の「砲台」）。危険の見積もりと、駒の脅威範囲の表示（`docs/threat-range.md`）は、後衛が砲台に乗れるなら、そこからの射程も数える。
- **置くマップ**: 対戦モードのマップのうち、置いても CPU どうしの対戦で先手と MILITARY が 45〜55% に収まるものだけ（全部のマップには置かない）。
  数字は `docs/cpu-ai.md` の「いまの集計」。

| マップ | 砲台 |
| --- | --- |
| 中央平原、迷宮回廊 | 置く（`BoardGenerator.BATTERY_STAGES`） |
| 結晶の岩山 | 対戦モードだけ置く（`V`。`(8,8)` と `(11,11)`。両方の本陣から同じ道のりで、中ボスの届く距離の外） |
| 双子結晶 | 置かない（置くと MILITARY が下がる） |
| 尾根の小道 | 置かない（両方の本陣から同じ道のりのマスは、どれも中ボスの届く距離の内側。縄張りの外に置くと、先手に寄り、MILITARY が下がる） |
| 大岩の峠 | 置かない（左右の道の端に置くと、MILITARY が下がる） |

比べた数字は `docs/cpu-ai.md` の「いまの集計」。

## 拠点

コード: `rules/stronghold.gd`（`Stronghold`。置く場所、確保の数え方）、`rules/board.gd`（`stronghold_cell`）、
`rules/actions/end_phase_action.gd`、`rules/events/stronghold_progress_event.gd`。テスト: `tests/rules/test_stronghold.gd`。

待っている側が損をする物（Issue #47 の「先制攻撃が不利で、待ち有利」）。**対戦モードの既定で置かれる**（`OptionalRules.STRONGHOLD`。
対戦設定で「拠点: なし」にすれば置かない。`docs/match-setup.md` の「選べる決まり」。ストーリーの話には置かない）。拠点を確保し続けると勝つ（勝ち方の決まりは `docs/win-conditions.md` の「拠点を確保し続ける」）。

- 盤に 1 つ。入るのに使う移動力は地形のまま。ほかの駒が乗っていれば入れないのは、ふつうのマスと同じ。壊れず、だれのものでもない。
- **置く場所**（`Stronghold.choose_cell`）は、盤ごとに決める。どちらに寄せるかで先手・後手の勝ちやすさが大きく変わる（1 マス違うだけで、先手と後手のどちらにも大きく傾く盤がある）ので、
  CPU どうしの実測（部隊を変えて。数字は `docs/cpu-ai.md` の「いまの集計」）で、先手と後手が釣り合うマスを選んだ。
  - **手で作ったマップ**: マップのファイルの `H` のマス（`docs/hand-map.md`）。書いていなければ、生成のマップと同じ選び方（寄せ 0）。
  - **生成のマップ**: 両方の本陣からの道のり（移動のコスト。ポータルは転移も使う。`Stronghold.distances`）から選ぶ。
    「先手の本陣からの道のり - 後手の本陣からの道のり」が盤の種類ごとの寄せ（`BoardGenerator.STRONGHOLD_LEAN`。正 = 後手の本陣に近い側）にいちばん近いマスのうち、
    両方の本陣の真ん中にいちばん近いもの（`Stronghold.candidates`）。それが何マスかあれば、対戦の種から引いた乱数で選ぶ（同じ種なら同じマス）。
  - どちらも、置けるのは、どちらの本陣からも歩いて行ける、ほかの環境オブジェクトの無いマスで、本陣・結晶泉・砲台の場所でなく、中ボスの家から 4（`Stronghold.BOSS_CLEARANCE`。中ボスの縄張り）より遠いもの。
    砲台の場所を避けるので、砲台の入・切で拠点は動かない。
- 選んだマスが森なら、平地にする（拠点が木立に隠れないように。乗った駒が森の軽減で守られないように）。ほかのマスの地形は変えない。
- 置き場所（30 x 30 の生成のマップは、種で 1〜2 マス動く）:

| 盤 | 寄せ・場所 | 選んだわけ |
| --- | --- | --- |
| 中央平原 | 寄せ 0。盤の真ん中の辺り（`(13〜15, 13〜15)` が多い。真ん中に道のりのそろうマスが無い種では、左右の端） | 寄せ 0 で釣り合う。後手へ 2 寄せると後手に大きく傾く |
| 迷宮回廊 | 寄せ 1。盤の真ん中の辺り（`(13〜16, 13〜16)`） | 格子の壁で道のりのそろうマスが無い。先手に 1 歩近いと先手に、後手に 3 歩近いと後手に傾く |
| 双子結晶 | 寄せ 3。下の道の `(16〜17, 23〜25)` か、上の道の `(14〜16, 2〜4)` 辺り（種による） | 寄せ 0 では先手が勝ち越す。上の道・下の道のどちらに置いても、勝ちやすさはほとんど変わらない |
| 尾根の小道 | `H` の `(12, 9)`。右の中ボスの斜め上、真ん中の段から後手の側へ 1 段 | 真ん中の岩の脇（`(6〜10, 10〜11)`）は、どれも先手に大きく傾く |
| 結晶の岩山 | `H` の `(7, 7)`。岩山の上の道の、左寄り | 岩山の真ん中の上（`(9〜10, 8)`）は後手に、下は先手に大きく傾く。上の道の左寄りで釣り合う |
| 大岩の峠 | `H` の `(17, 11)`。右の道の、盤の右の端 | 左右の道には、どちらも片方の陣地の側に中ボスがいて、中ボスのそばを通る側が着くのに遅れる。右の道の、中ボスの縄張りから離れた端で釣り合う |

- イベントは、確保が変わったときの `StrongholdProgressEvent`（プレイヤーと、いまの数）。
- 画面（`game/board_view.gd`、`game/battle_hud.gd`）: 拠点のマスに旗竿と旗。旗は確保の多いほうの陣営の色になり、確保の数だけ竿を上る（勝つ数で上まで）。
  竿の上に、いつも手前に描く小さな数の札（「3 / 8」）。乗っている駒の確保が隣の敵で止まっている間は、文字を足さず札の色を落とす。
  上の帯のすぐ下の左に、決まった大きさの拠点の札（「拠点 青 3 / 8 赤 0 / 8」。陣営の色の数。あと 1 回で勝つ陣営がいれば札を急ぎの色にする。
  マウスを乗せると決まりの文）。マスの説明は、下の帯の 1 行には短い説明、クリックした枠には決まりを 1 行ずつ 3 文で。対戦の始めの「対戦ルール」に、勝利条件の札（拠点の確保）が出る。
- CPU は拠点を知っている（`docs/cpu-ai.md` の「拠点」）。入のときの CPU どうしの実測は `docs/cpu-ai.md` の「いまの集計」。

## マップごとの配置

盤面の生成（`BoardGenerator.generate`。`docs/game-board.md`）が、地形のあとに置く。同じマップ・同じシードなら、いつも同じ配置になる。
地形は、オブジェクトを置いても置かなくても同じ（別の乱数を使う）。

| マップ | 置くもの | 場所（30 x 30 のとき） |
| --- | --- | --- |
| 1 中央平原 | 起爆樽 4（`MIN_BARRELS`）〜6（`MAX_BARRELS`）個 | 中央の左右の帯（`x: 8〜10` と `x: 20〜22`、どちらも `y: 10〜20`）に、左右交互に、でたらめに |
| 2 迷宮回廊 | 回復の泉 2 か所 | 左 `(9,22)`（プレイヤー1 の側）と右 `(19,7)`（プレイヤー2 の側）。本陣どうしを入れ替える点対称（`BoardGenerator.spring_cells_for`）。どちらのプレイヤーにも、本陣に近い泉と遠い泉が 1 つずつ |
| 3 双子結晶 | ポータル 2 対 | 左の道に上下を結ぶ 1 対（`(5,4)` と `(5,25)`）、右の道にも 1 対（`(24,4)` と `(24,25)`） |

ほかの大きさでは、盤の中心と端からの位置で決まる。

どのマップでも次を守る。

- 置くのは**平地**だけ。本陣の周り（チェビシェフ距離 3（`PROTECT_RADIUS`）以内。軍の初期配置はこの中に収まる）、結晶泉、
  中ボスの場所の周り（チェビシェフ距離 1（`MID_BOSS_CLEARING`）以内）には置かない。
- ポータルは、本陣から歩いて行けるマスに置く。上の表のマスが使えなければ、近く（チェビシェフ距離 3（`OBJECT_SEARCH_RADIUS`）まで）の使えるマスへずらす。
- 回復の泉は、いつも上の表のマスに置く（壁や森なら平地にし、本陣から歩いて行けなければ道を削る）。左右を点対称に保つため。
  泉の回復は中ボスの攻撃力より多いので、泉は中ボスの家から、縄張り（`Neutral.TERRITORY_RADIUS`）にいちばん長い射程（スナイパー）を
  足した距離より遠くに置く（泉に立ったまま中ボスと殴り合えると、硬い駒 1 体で狩れてしまう。`tests/rules/test_board_generator.gd` で固定）。
- 起爆樽は、通れる場所を分けない（樽を置く前に歩いて行けたマスは、樽のマスを除いて、置いたあとも行ける）。
  そうなる置き方は選び直す。
