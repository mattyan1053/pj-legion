# セーブデータとオートセーブ

コード: `game/save_slots.gd`（スロット。ノードに依存しない）、`game/slot_screen.gd`（セーブデータ選択の場面）、
`game/save_mark.gd`（保存の小さな印）、`game/confirm_window.gd`（確かめの窓）、`game/save_store.gd`（ファイルの読み書き）。
テスト: `tests/game/test_save_slots.gd`、自動の対戦（`--autoplay` の `story`。セーブデータ選択からストーリーに入り、コピー・削除と、話を終えたあとのオートセーブを通す）。

人間の言葉（11/21。Issue #46）: 「昨今のゲームだと基本オートセーブがあるのが多いけど、オートセーブのタイミングとかがある程度決まってるんじゃないかな。
さすがに対戦中の状況をまるっと保存して次から再開できるまではいらない。セーブデータ数はいくつかある方が俺は好み。
× をしたときは、セーブした地点までしかセーブされてなくて、その瞬間のものをセーブするにはしてなくていい」

## セーブデータ（スロット）

- スロットは 3 つ（`save_slots.gd` の `COUNT`）。1 つのスロットに、**ストーリーの進み具合**（クリアした話、出撃準備で選んだ部隊、最後に選んだ物語。`docs/story.md`）と、
  **ストーリー用の部隊**（`docs/deck-screen.md`）をまとめる。
- **スロットに入れないもの**: オプションの設定と、対戦用の部隊。どのスロットで遊んでも同じ（対戦モードはスロットを選ばずに遊ぶ）。
- 起動したときは、最後に保存したスロットを開く。中身のあるスロットが無ければ、空きの最初のスロット（選ぶまでファイルは作らない）。
- 対戦の途中は保存しない（人間の言葉）。

## セーブデータ選択

タイトルの「ストーリー」→ セーブデータ選択 → 物語選択（`docs/scene-flow.md`）。

- スロットをカードで並べる。中身のあるカードは「つづきから」: 物語（最後に選んだ物語。無ければクリアのある最初の物語）、クリアした話の数、
  いちばん先のクリアした話、最後に保存した日時（この機械の時間帯）、プレイ時間。上の縁の帯と地紋は、その物語の国のもの（物語のカードと同じ）。
- 空きのカードは「はじめから」。押すと、そのスロットを新しく始めて、すぐ書く。
- カードの下に「コピー」「削除」。
  - コピー: 写す先のカードを選ぶ（見出しの下が「データ N のコピー先を選択」、下のボタンが「キャンセル」。右クリック・Esc でもやめる）。
    中身のあるスロットへは、上書きを確かめる。
  - 削除: 確かめてから消す。いまのスロットを消したら、いまの進み具合も空になる。
- 読み込めないデータ・新しい版のデータのカードは選べず、コピーの元にもならない（削除はできる）。消すまで、勝手に書き直さない。
- 「タイトルへ戻る」（右クリック・Esc でも）でタイトルへ。左右の矢印と Enter でも選べる。

## 保存する所（オートセーブ）

ファイルに書くのは、決まった区切りだけ。ウィンドウの × やメニューの「ゲーム終了」で閉じた瞬間のものは書かない（最後に保存した所までが残る）。

| 区切り | 書くもの |
| --- | --- |
| セーブデータ選択で「はじめから」を選んだとき | 空のスロット（以後「つづきから」になる） |
| 話の流れ（出撃準備・会話・対戦・寄り道の部隊編成）を抜けて、話の一覧・物語選択・タイトルへ出たとき | そこまでの進み具合と遊んだ時間。話をクリアしたなら、あとの会話と解放の知らせが済んだ所 |
| あとの会話の「次の話へ」で、次の話の出撃準備へ進んだとき | 同上 |
| 部隊編成で部隊を取っておいたとき（「編成完了」、名前の変更、コピー、削除） | ストーリー用の部隊はスロット、対戦用の部隊は `user://decks.json` |
| オプションの画面を閉じたとき | 設定（`user://settings.json`。`docs/system-menu.md`） |

- 対戦で勝ってクリアを記録しても、話の流れを抜けるまでは書かない（覚えておくだけ）。決着の画面やあとの会話の途中で閉じると、そのクリアは残らない。
  決着の画面の「部隊変更」で寄り道した部隊編成で「編成完了」を押したときは、その時点の進み具合もいっしょに書く。
- 書いたときは、画面の右下に「保存しました」を少しの間だけ出す（`save_mark.gd`。クリックは通す）。オプションは、何か変えたときだけ出す。
- 最後に保存した日時は、話の一覧の右下と、ストーリーの間に開いたシステムメニューの見出しの下に出す（「最後に保存: 年/月/日 時:分」。まだ書いていなければ「未保存」）。
- 遊んだ時間は、物語選択に入ってから、タイトル・セーブデータ選択・マップ選択へ出るまで数える（メニューで止めている間も数える）。書くのは上の区切りだけ。

## ファイル

`save_store.gd` の仕組みで、スロットごとに 1 つのファイル `user://slot_<番号>.json`（名前 `slot_1` など、版 1 = `SaveSlots.FORMAT_VERSION`）。中身:

```json
{
  "saved_at": 1795000000,
  "played_seconds": 9000,
  "sections": {
    "story": {"version": 2, "data": {"campaign": "military", "campaigns": {"military": {"cleared": ["..."], "squad": "3"}}}},
    "decks": {"version": 1, "data": {"next_id": 5, "decks": ["..."]}}
  }
}
```

- `sections` の中は、前の置き方の `story.json` と `decks.json` の中身と同じ形（それぞれの版と読み替えのまま。`docs/story.md`、`docs/deck-screen.md`）。
- 部隊の id は、対戦用とストーリー用で 1 つの番号の並びから付け、次の番号（`next_id`）を両方のファイルに書く（スロットを替えても、id が重ならない）。

### 読めないとき

起動は止めない。

| 中身 | 扱い |
| --- | --- |
| ファイルが無い | 空き |
| JSON でない・形が違う（`data` が辞書でない、`sections` が辞書でない） | 読み込めないデータ（選べない。削除できる。消すまで書かない） |
| 新しい版（`FORMAT_VERSION` より大きい） | 新しい版のデータ（同上） |
| `saved_at`・`played_seconds` が数でない、負 | 0 |
| まとまり（`story`・`decks`）が読めない | 無いものとして読む（進み具合なし、部隊なし） |

### 前の置き方からの移し替え

スロットの前は、ストーリーの進み具合が `user://story.json`、ストーリー用の部隊が `user://decks.json` の中（対戦用と同じファイル）にあった。

- 起動したとき、スロットのファイルが 1 つも無く、前の `story.json`（読めるもの）かストーリー用の部隊があれば、それを 1 番のスロットへ移す（最後に保存した日時は `story.json` を書いた時刻。プレイ時間は 0）。
- 前のファイルは消さない: `story.json` は `story-before-slots.json` へ名前を変え、`decks.json` は `decks-before-slots.json` へ写してから、対戦用の部隊だけを残して書き直す。
- 2 度目の起動では移さない（スロットのファイルがある。`story.json` も無い）。1 番を消しても、前のファイルからは戻らない。
- 壊れた `story.json` は移さず、そのまま残す。
- `decks.json` にストーリー用の部隊が残っていたら（前の版の exe で書いた、など）、読んだときにいまのスロットへ移し、`decks.json` から外す。

### 検査

自動の対戦とスクリーンショットは、ファイルを読み書きしない（`slots.store` が無い）。スロットの中身は覚えておくだけで、同じように選ぶ・コピー・削除できる。
スクリーンショットの場面は、場面ごとにスロットを空にしてから作る（`story_slots` は 1 番と 2 番に進み具合を入れて撮る）。
