# 対戦の画面（見た目の試作）

コード: `prototype/`。テスト: `tests/prototype/`（ノードに依存しない部分）と、`tools/check.sh` の自動の対戦。

1 人で CPU を相手に、または 2 人が 1 台で交代しながら、対戦を最後まで遊べる。操作の一覧はルートの `README.md`。

## ルールとのつなぎ方

- 画面はルールを持たない。操作を行動（`BattleAction`）にして `Battle.apply()` に渡し、
  返ってきた `ActionResult.events` を順に再生する（`board_prototype.gd` の `_do` と `_play`）。
- 再生している間は、操作を受け付けない。再生が終わったら、対戦の状態と選んでいる駒から、
  塗るマス・ボタン・文字を作り直す（`_refresh`）。
- 選べること（動けるマス、攻撃できる相手、攻撃できる樽、回復できる味方、スキルの対象のマス）は、ルールの問い合わせ `Battle.options()`（`docs/battle.md`）に聞き、
  `battle_queries.gd` が画面の使いやすい形にする。どれも `Battle.can_apply()` が受け付けるものと一致する（テストで固定している）。
- 攻撃の見込み（ダメージと残り HP）は、実際の攻撃と同じ `Combat.damage()` で出す。
  樽の爆発の見込み（届くマス、巻き込む駒）は `MapObject.blast_cells` / `blast_victims` / `blast_damage` で出す。
  回復の見込み（回復量とあとの HP）は `Healing.amount()` で出す。
- スキルの見込みは、`Skills.preview()`（実際に使うのと同じ処理を複製の上で走らせたイベントの列）から出す。
  どのスキルにも同じ読み方を使う（置かれる効果、ダメージ、回復、入る経験値。何も起きなければ「何も起きない」）。
- イベントの種類と再生するメソッドの対応は `board_prototype.gd` の `event_players()` に並べる。
  `rules/events/` にあるのに載っていない種類があると、テスト（`tests/prototype/test_event_playback.gd`）が落ちる。

| イベント | 再生 |
| --- | --- |
| `UnitMovedEvent` | 道順を 1 マスずつ補間して走らせる（`cruise` が真なら速く） |
| `UnitWarpedEvent` | 入ったポータルで縮んで消え、出たポータルに現れる。カメラを出た先へ寄せる |
| `MoveUndoneEvent` | 動く前のマスへ戻す |
| `AttackDamagedEvent` | 攻撃の動き → 被弾の動き、ダメージの数、HP のバーの更新 |
| `ExplosionDamagedEvent` | 被弾の動き、ダメージの数、HP のバーの更新だけを、駒ごとに続けて見せる |
| `SkillDamagedEvent` | 爆発と同じ（使った駒の動きは `SkillUsedEvent` が見せる）。数の色だけ違う |
| `HealerHealedEvent` | 回復役が相手のほうを向いて手を振る → 回復の数、HP のバーの更新、光 |
| `SpringHealedEvent` | 回復の数、HP のバーの更新、光 |
| `RegenerationHealedEvent` | 泉と同じ（回復の数、HP のバーの更新、光） |
| `ExperienceGainedEvent` | 「経験 +N」の小さい文字 |
| `LevelUpEvent` | 札にレベル（Lv2 など）を足し、HP のバーを新しい最大 HP で描き直す。金の光と「レベル N！」 |
| `EvolutionOfferedEvent` | 紫の光と「進化できる！」。選択肢は、再生が終わってから出す |
| `UnitEvolvedEvent` | 札に ★ を足し、HP のバーを新しい最大 HP で描き直す。紫の光と、進化先の名前 |
| `BarrelExplodedEvent` | 攻撃の動き → 樽を消し、爆発の届いたマスを橙に塗る（続くダメージの再生の間も塗ったまま） |
| `UnitDefeatedEvent` | 倒れる動きのあと、駒を取り除く |
| `UnitSpawnedEvent` | 駒（中立のエナジー・コアは宙に浮く結晶）を置き、光とともに大きくする。カメラをそこへ寄せる |
| `SkillUsedEvent` | 使った駒が対象のほうを向いて手を振り、スキルの名前を出す。効果は、続くイベントが見せる |
| `SkillReadyEvent` | 何も出さない（残りは、左下の駒の情報とスキルのボタンに出る） |
| `UnitActedEvent` | 駒を暗くする（行動済み） |
| `PhaseStartedEvent` | その陣営の駒を明るく戻し、番の知らせを出し、カメラをその陣営の将へ寄せる。中立の番は知らせだけ（カメラは、動く・攻撃する中立の駒を順に追う） |
| `CaptureProgressEvent` | 本陣の上に占拠の数を出す |
| `GameWonEvent` | 勝者と理由、やり直しのボタンを出す |
| `GameDrawnEvent` | 「引き分け」と理由、やり直しのボタンを出す |

## 画面に出るもの

- 上の帯: ターン、どちらの番か、陣営ごとの駒の数と本陣の占拠の数（●○○）。
- 駒の頭の上: HP のバーと、役割の 1 文字（将・前・後・奇・回）+ HP の数。レベル 2 からは「Lv2」が付き、進化した駒は「Lv3★」になる。行動済みの駒は暗い。
- マスの色: 青 = 移動、黄 = 巡航でだけ届く、赤 = 攻撃できる相手と樽、緑 = 回復できる味方、白 = 動かせない駒の移動範囲（眺めるだけ）、
  明るい白 = マウスの下のマスまでの道、橙 = マウスの下の樽の爆発が届くマス、
  紫 = スキルの対象に選べるマス（対象を選んでいる間だけ）、明るい紫 = マウスの下のマスに使ったときに効果が及ぶマス。
- 左下: マウスの下の駒（いなければ選んでいる駒）の名前（進化した駒は進化先の名前）、能力値、レベルと経験値（育つ駒だけ）、
  スキルの名前と使えるか（あと何ターンか）、
  進化先の特性、状態、攻撃の見込み
  （入る経験値と、レベルが上がるか。`Growth.preview` で出す）。狙える樽にマウスを乗せると、爆発の見込み。
  回復役を選んで、回復できる味方にマウスを乗せると、回復の見込み。
- 右上: 相手（プレイヤー2）が CPU か人かを書いたボタン。押すと切り替わる。
- 下の帯: いまできることの説明、マウスの下のマスの地形と環境オブジェクト（ポータルは行き先も）、待機・スキル・取り消し・ターン終了のボタン。
- 本陣のマスには陣営の色の旗が立つ。
- 環境オブジェクト（`docs/map-objects.md`）。どれもコードで作った形で、素材は足していない。
  - 起爆樽: ふたと帯の赤い樽。
  - 回復の泉: 石の縁の青い水面。駒が乗っても分かるよう、マスの隅に緑の十字の札が立つ。
  - ポータル: 色の輪と、両脇の柱。色は対ごとに違い、同じ色の 2 つがつながっている。

## 環境オブジェクトの操作

- 樽の攻撃: 駒を選ぶと、いまの位置から攻撃できる樽のマスが赤くなる。クリックで攻撃（`AttackBarrelAction`）。
  動く前でも、動いたあとでもよい。
- ポータル: 専用の操作は無い。行き先のマスを選ぶと、ルールが移動力のいちばん少ない道を選び、
  転移したほうが近ければ転移する（道の表示は、通るポータルの両方のマスを含む）。
- 回復の泉: 操作は無い。乗ったまま自分の番を迎えると回復する。

## 相手を CPU にする

- 相手（プレイヤー2）は、CPU か人かを選べる（右上のボタンか F4。始めは CPU）。人にすると、2 人が 1 台で交代する形になる。
  対戦の途中でも切り替えられる。プレイヤー2 の番の途中で CPU にすれば、続きを CPU が引き取る。
  人に戻せば、CPU はいまの行動を最後に手を止める。
- CPU の番は、`CpuPlayer.next_action()`（`docs/cpu-ai.md`）が返す行動を、人の操作と同じ入口（`_do`）に 1 つずつ流す（`_run_cpu`）。
  画面はルールにも CPU の考えにも立ち入らない。再生も、人の行動と同じイベントの再生をそのまま使う。
- 何をしたか追えるように、駒が動き出す前にカメラをその駒へ寄せ（0.35 秒）、1 体の行動が終わるたびに間を置く（0.45 秒）。
  動かずに待機するだけの駒は、見せるものが無いので間を置かない。
- CPU の番の間は、盤面の操作・待機・取り消し・ターン終了・やり直しを受け付けない（`is_busy()`）。
  選べるマスは塗らず、CPU の駒の進化先の選択肢も出さない（CPU が自分で選ぶ）。下の帯に「CPU が考えている…」と出す。
- CPU の軍は、試作の決め打ち（プレイヤー2 = FANTASY）。
- 飾らない最小の作り。CPU の番を早送りする・飛ばす操作は無い。

## 回復の操作

- 回復役（衛生兵・プリースト）を選ぶと、いまの位置から回復できる味方（HP が減っていて、射程の中）のマスが緑になる。
  クリックで回復する（`HealAction`）。動く前でも、動いたあとでもよい。巡航のあとは回復できない。
- 回復役は攻撃できないので、赤いマスは出ない。

## スキルの操作

どのスキルも同じ操作に乗る（`docs/active-skills.md`。スキルの対象は、いつもマスで指す）。

- スキルのボタン（下の帯。F のキー）には、選んでいる駒のスキルの名前が出る。クールダウンの間は「あと N ターン」、
  対象に選べるマスが無いときは「いまは使えない」、スキルの無い駒では「スキル（なし）」と出て、押せない。
- 押すと、**対象を選ぶ途中**になる。対象に選べるマス（`Battle.options()` の `skill_cells`）だけが紫になり、
  移動や攻撃のマスは塗らない。マウスを乗せると、効果が及ぶマス（`Skill.affected_cells`）が明るい紫になり、
  左下にスキルの説明と見込みが出る。
- 紫のマスをクリックすると使う（`UseSkillAction`）。使うと行動を終える。動く前でも、動いたあとでもよい。
- やめるには、ほかのマスをクリックするか、もう一度ボタン（F）を押すか、Esc・右クリック。
  駒の選択と、動いたあとの状態はそのまま残る（もう一度戻す操作をすると、移動の取り消し・選択をやめる）。
- 自分に使うスキルも、同じに自分のマスをクリックして使う。
- 飾らない最小の作り。スキルごとの演出は無く、置かれた効果の描き方は `docs/field-effects.md` のまま。

## 進化先を選ぶ操作

- 駒が上限のレベルに届くと、画面の上寄りに 2 つのボタンが出る。ボタンには、進化先の名前、能力値の増減、特性が書いてある
  （`BattleHud.evolution_text`。`docs/branch-evolution.md` の表から作る）。
- ボタンを押すか、1・2 のキーで選ぶ（`EvolveAction`）。選ぶまで、ターン終了のボタンは押せず、ほかの操作は何も起こさない。
- 飾らない最小の作り。進化した駒の見た目は、札の ★ と名前だけで、形は変えていない。

## 仮のもの

- **編成と配置**（`trial_setup.gd`）: 将 + 前衛 2 + 後衛 2 + 奇襲 1 + 回復 1 を本陣の周りに点対称に置く。
  プレイヤー1 は MILITARY、プレイヤー2 は FANTASY。装備は持たせていない。予算も見ていない（両軍を同じ数にそろえている）。
  編成のルール（`docs/player-loadout.md` の `Deck` と `Deployment`）と CPU の編成（`CpuDeck`）には、まだつないでいない。
- **中立の駒**の見た目は、宙に浮く結晶のコア（`unit_view.gd`）。縄張りの表示はまだ無い。
- **駒の形**: 素材のキャラクターは 4 体なので、種類は持ち物で分けている
  （将 = 大きい騎士 + 金の輪、前衛 = 騎士 + 盾、後衛 = 弩 / 杖、奇襲 = 短剣 / 斧、回復 = 本）。
- 文字は OS のフォントで出している（フォントは同梱していない）。

## 検査

`godot --headless --fixed-fps 60 -- --autoplay` で、自動の対戦（`autoplay.gd`）が人と同じ入口
（マスを選ぶ・待機・戻す・ターン終了・進化先を選ぶ）だけを使って対戦を最後まで進め、小さな盤面で決まった手順の場面
（ポータルを通る移動とその取り消し、回復の泉、本陣の占拠、樽の爆発による引き分け、エナジー・コアが湧いて襲う、
撃破でレベルが上がる、上限のレベルに届いて進化先を選び、次の番に再生で回復する、回復役が動いて味方を回復する、スキルのボタンから盾と聖域を置き、クールダウンが明けるまで進める、
相手を CPU にしてターンを終えると CPU が自分の番を進めて戻ってくる）を通し、
盤面を作り直して残りのステージも少し動かす（そのうち 1 戦は相手を CPU にして、プレイヤー1 だけを操作する）。
途中で画面と対戦の状態（駒の数・位置・HP、樽のマス）が食い違えば失敗。
どの種類のイベントも 1 回は再生したことを確かめて、最後に `autoplay: OK` を出す。`tools/check.sh` がこれを回す。
