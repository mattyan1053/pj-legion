# 対戦の画面

コード: `game/`。テスト: `tests/game/`（ノードに依存しない部分）と、`tools/check.sh` の自動の対戦。

1 人で CPU を相手に、または 2 人が 1 台で交代しながら、対戦を最後まで遊べる。操作の一覧はルートの `README.md`。

## 操作の考え方

**操作の説明を読まなくても遊べること**を基準にする。マウスのクリックだけで 1 局を最後まで遊べて、どこを押せばよいかを探さずに済むようにする。

- **駒に属する操作は、駒のそばのメニューから選ぶ**（攻撃、回復、スキル、待機、移動を取り消す、ポータルの上なら転移）。出すのは、いま選べるものだけ。
  スキルだけは、持っている駒なら使えない間も理由を添えて出す（押せない。「スキル（あと 2 ターン）」）。
- **駒に属さない操作は、画面の決まった場所に置く**。右下にターン終了（色付き。動かせる駒が残っていなければ明るくなる）、おまかせ、必殺技（相手の番の間は、かわりに早送りとスキップ）、
  敵の攻撃範囲の切り替え（スイッチ）、
  上の帯の右に相手の切り替え、ログ、システムメニュー（`docs/system-menu.md`）のボタン。
- **マスを直接クリックしても進む**。青・黄のマスで移動、赤いマスの相手で攻撃、緑のマスの味方で回復。メニューの「攻撃」「回復」は、
  相手だけを塗って見せる近道で、押さなくても攻撃できる。
- **右クリックは、いつでも 1 つ戻す**（必殺技の確かめ → 駒を見ている → 対象を選ぶ途中 → 移動 → 選択 の順にやめる。対戦設定のパネルも閉じる）。
  「戻す」の主役は右クリック。Esc も、戻すものがある間は同じに働き、**戻すものが何も無いときはシステムメニューを開く**（`docs/system-menu.md`）。
- キーボードのショートカット（Space、F、G、T、Enter、Esc、1・2、視点の Q・E・R、F1〜F4）は残してあるが、画面には書かない。
- **説明が要らないのは操作だけ。中身の説明（スキル、必殺技、進化先、聖遺物、地形、環境オブジェクト）は、読める場所に出す。**
  - スキル: 選んだ駒・マウスを乗せた駒の左下の枠に、スキルの名前・使えるか・説明がいつも出る。メニューのスキルの項目に
    マウスを乗せると、説明・使ったあと行動が終わるか・クールダウンが出る。対象を選んでいる間は、説明が左下に、見込みが予測のパネルに出る。
  - メニューのほかの項目（転移・攻撃・回復・待機・移動を取り消す・キャンセル）も、マウスを乗せると、押すと何が起きるかが左下の枠に出る。
  - 必殺技: ボタンにマウスを乗せている間と、使うかを確かめている間、説明がボタンの上に出る。
  - 進化先: 選ぶボタンに、名前・能力値の増減・特性が書いてある。進化した駒の特性は、左下の枠に出る。
  - 聖遺物: 手に入れたときに、名前と効果を画面の中央に出す。上の帯の陣営の欄にマウスを乗せると、持っている聖遺物の効果が出る。
  - 地形・環境オブジェクト・盤の上の効果: マスをクリックすると左下の枠に、マウスを乗せると下の帯に 1 行で出る。

### 選ぶ・動かす・攻撃する

- **駒を選ぶと、移動と巡航の範囲を同時に塗る**（青と黄）。押す前に届く範囲が見える。
- **攻撃は、赤いマスの相手を 1 回クリック**。メニューの「攻撃」から相手を選ぶ 2 手でもよい（「赤 = 攻撃できる」を知らなくても辿れる）。
- **範囲の外の、駒のいないマスをクリックすると、選択をやめて**、そのマスの情報を出す。行動できる自分の駒なら、その駒を選び直す。
  ほかの駒なら、選択はそのままで、その駒を見る（下の「駒を見る」）。
  **動いたあと**（攻撃・回復・待機・取り消しを選ぶところ）は、対象のマス（赤・緑）とほかの駒のほかをクリックしても何も起きない（選択も外れない）。
- **巡航のあとも「移動を取り消す」が出る**（ルールの `UndoMoveAction` が受け付ける）。黄のマスの押し間違いを戻せる。
- **ターン終了は、未行動の駒が残っていれば 2 回押す**。1 回目でボタンが「もう一度押して終了」になり、もう一度押すと終わる
  （残っていなければ 1 回で終わる。間にほかの操作をすると、確かめはやめる。右クリック・Esc でもやめる）。取り消せない操作の押し間違いを防ぐ。
  - **ボタンには短い言葉だけを書く。** 理由は、まだ行動していない駒の足元を光らせ、下の帯の説明に数を出して見せる。
  - **確かめに変わった直後の短い間（`battle_ui_state.gd` の `CONFIRM_GUARD_MSEC`。いまは 0.4 秒）は、2 回目を受けない。** ダブルクリックや Enter の連打で、確かめを飛ばさないため。必殺技の確かめも同じ。

### 駒を見る（閲覧）

**見ること（情報を出す、範囲を塗る）は、選ぶこと（行動させる駒を決める）と別の状態**（`battle_ui_state.gd` の `inspected_id` と `selected_id`）。
自分の駒を動かしている途中でも、相手の脅威範囲を確かめてから、続きを選べる。

- **行動させられない駒**（相手の駒、中立の駒、行動を終えた自分の駒、動いたあとの自分のほかの駒）を**クリックすると、その駒を見る**。
  いつでもよい: 何も選んでいないとき、選んだあと、動いたあと、メニューの「攻撃」「回復」・スキルの対象を選ぶ途中。
  ただし、攻撃・回復・スキルの対象（赤・緑・紫のマス）の駒は、クリックすると行動になる（下の「敵の攻撃範囲」で範囲を見る）。
- 見ている間: その駒の動ける範囲を白で、相手の駒（中立も）なら脅威範囲（`docs/threat-range.md`。`Threat.of()`）を薄い赤で塗る。
  選んでいる駒の届くマスは塗らない（見終わると戻る）。見ている駒の足元に白い輪、選んでいる駒には黄の輪が付いたまま。
  左下の枠に、見ている駒の情報が出る。下の帯は「〜 を表示中」と、塗った色の意味と、戻り方。駒のそばのメニューは出たまま。
- 見ている間のクリックは**見るだけ**（移動や攻撃はしない）: ほかの駒なら見る駒を替える。駒のいないマス・見ている駒・選んでいる駒なら、
  見るのをやめる。右クリックでもやめる。メニューの項目を押すと、見るのをやめて、その項目を行う。
  **やめると、元の行動の途中へそのまま戻る**（選んだ駒、動いたあとの状態、対象を選ぶ途中は残る）。何も選んでいなければ、何も選ばない状態に戻る。
- 行動すると、見るのをやめる（盤が変わるので）。
- マウスを乗せれば、いつでも（行動の途中も、CPU の番も）その駒の情報が左下に出る（範囲は塗らない。盤の上を動かすたびに大きな範囲が
  出入りしないように）。
- CPU の番の間は、クリックで見られない（操作を受け付けない）。

### 敵の攻撃範囲（全員の脅威範囲）

- 下の帯のスイッチ「敵の攻撃範囲」（キーボードでは T）で、盤を見ている人のプレイヤーの敵（相手のプレイヤーと中立の駒）の全員の脅威範囲
  （`Threat.against()`）を、**赤い斜線と、範囲の縁の赤い線**で重ねて出す・消す。盤を見ている人は、CPU と対戦するときはいつも人のプレイヤー、
  人どうしではいまの番のプレイヤー（必殺技のボタンと同じ）。
- 出したままにできる。塗りではなく斜線なので、下の移動（青）・巡航（黄）・攻撃（赤）の塗りがそのまま見え、
  「動けるが、次の番に攻撃が届く」マスが一目で分かる。行動のたびに作り直す（再生の間は消す）。
- 斜線と縁の線、見ている相手の駒の赤い塗りは、どれも薄めにしてある（下の地面・駒・ほかの塗りが読めるように。
  `board_view.gd` の `COLOR_DANGER_*`、`battle_screen.gd` の `COLOR_THREAT`）。草原・石畳・結晶の森のどれでも読めることを、
  スクリーンショットの場面 `threat_mix_*` で見る。
- 選択・見ること・対象を選ぶ途中には関わらない（切り替えても、行動の途中はそのまま）。
- **相手の駒 1 体ずつの範囲を、表示したままにできる（ピン留め）。** 相手の駒（中立も）をクリックして見ると、左下の情報の枠の
  いちばん下にスイッチ「範囲を表示したまま」が出る。入れると、その駒の脅威範囲（`Threat.of()`）を、薄い橙の塗りと橙の縁の線で出し続ける
  （見るのをやめても、行動や番が変わっても残る）。何体でも留められる（重なったところは塗りが濃くなる）。
  - 外すのは、その駒をもう一度見てスイッチを切るか、右クリック（Esc）。右クリックは、ほかに戻すもの（確かめ・閲覧・対象を選ぶ途中・
    移動の取り消し・選択）が無いときに、留めた範囲を全部外す。
  - 留めた駒が動けば、範囲も付いていく（行動のたびに作り直す。再生の間は消す）。倒れたら外れる。新しい対戦には持ち越さない。
  - 全体のスイッチ「敵の攻撃範囲」（赤い斜線）とは別の層・別の色なので、両方を出してもよい。盤を見ている人のプレイヤーの駒には出さない。
  - 留めた範囲があれば、何も選んでいないときの下の帯に「橙の枠: 表示したままの相手の範囲（右クリック: 全部消す）」を添える。
- マスの説明は、クリックで左下の枠に、マウスを乗せると下の帯に 1 行で出る（選んでいる駒がいても地形が読める）。
  ポータルのマスは、行き先の座標と、止まるとメニューの「転移」で対のポータルへ移れること（移動力は使わない）を書く。
  行き先に駒がいれば、いまは使えないことも書く。
- 駒は、形（手に持つ物。下の「仮のもの」）と陣営の色（足元の円盤と服の差し色）で見分ける。頭の上には何も出さない。
- スキルは、メニューに名前をそのまま出す（1 手少なく、何のスキルかが分かる。説明は、マウスを乗せると出る）。

### クリックとドラッグ

- 左ボタンは、**離したとき**に働く。押してから離すまでにマウスが少し（`battle_ui_state.gd` の `DRAG_THRESHOLD`）より動かなければクリック、動けばドラッグ。
- **駒のいないところで押してドラッグすると、視点が動く**。横の動きで向きが回り（左右に好きなだけ）、縦の動きで見下ろす角度が変わる。
  斜めに動かせば両方が同時に変わる。ドラッグのあとは、クリックにならない。
  - 向きは、盤を掴んで動かす感じに合わせる。右へ動かすと盤が右へ回り、**下へ動かすと真上からの見下ろしに近づき、上へ動かすと浅くなる**
    （盤の奥を手前へ引き倒す感じ。「上へ動かすと上を見る」感覚とも同じ向きになる）。
  - 見下ろす角度は、盤の外が見えすぎない浅さから、ほぼ真上までに収める（`orbit_camera.gd` の `MIN_PITCH` と `MAX_PITCH`）。
  - 感度（1 px あたりの回る量）は横と縦で同じ値で、`orbit_camera.gd` の `drag_sensitivity` の 1 か所にある（オプションの「マウスの感度」（`docs/system-menu.md`）を、ここに掛ける）。
  - R のキーは、いまの角度より深い次の段（`orbit_camera.gd` の `PITCH_PRESETS`）へ滑らかに移す。ドラッグで段の間にしていても、そこから次へ進む。
  - ドラッグは視点の向きと角度だけを変え、カメラの追従（相手の番や再生の途中）は止めない。どちらも行き先へ滑らかに寄るので、重なっても跳ねない。
- 駒のいるマスで押したときは、動かしてもクリックとして扱う（駒を選ぼうとして手がぶれても、選べる）。
- ドラッグの途中で、帯やメニューの上でボタンを離したら、そこで視点を動かすのをやめる（ボタンを押していない動きでは回さない）。
- **駒のいないマスのクリック**は、選択をやめて、そのマスの情報（地形、本陣、盤の上の効果、環境オブジェクト）を左下の枠に出す。
  マスには白い枠が付く。選んでいる駒の届くマス（青・黄）は移動になるので、情報を見るなら先に選択をやめる。
- 視点の平行移動はマウスに割り当てていない（WASD と矢印）。ホイールは拡大・縮小。右上に 1 行だけ、視点の動かし方を出している。
  - 引ける上限は盤の大きさに合わせる（`orbit_camera.gd` の `max_distance_for`。値は `MAX_DISTANCE`、`REFERENCE_SIDE`、`MIN_MAX_DISTANCE`）。
    長い辺が 30 マスの盤でいちばん引け、小さい盤ほど長い辺に比べて縮める（17 × 22 の盤では 3 / 4 ほど）。ただし小さな盤でも、始めの距離より少し引けるところまでは残す。
    大きい盤でも、30 マスの盤より引けはしない。

### 駒のそばのメニュー

- 自分の番に、行動できる自分の駒を選ぶと出る。動いたあと（攻撃・待機・取り消しを選ぶところ）も出たままになる。
  相手の駒、行動済みの駒、CPU の番、進化先を選ぶ途中、再生の途中には出ない。
- 並び: 転移（ポータルの上で、転移できるとき。下の「環境オブジェクトの操作」）、攻撃（攻撃できる相手・樽・盾があるとき）、回復（回復できる味方がいるとき）、スキル（スキルの名前。持っている駒だけ）、
  待機、移動を取り消す（動いたあとで、取り消せるとき）。対象を選んでいる途中は「キャンセル」だけになる。
- **置き場所**（`menu_placement.gd`。画面の座標だけの計算で、テストがある）: 駒が画面に占める四角を投影で出し、その周りの候補
  （右・左・下・上と、辺に沿ってずらしたもの、斜め。それぞれ近くと 1 つ離れたところ）を、画面の中（上の帯と下の帯を除いたところ）へ
  収めてから比べる。隠してしまうものの重みの合計がいちばん小さい候補を選ぶ。重みは重い順に、攻撃・回復・スキルの相手のマス、情報の枠、
  ほかの駒、届くマス、巡航でだけ届くマス（`panel_layout.gd` の `MENU_WEIGHT_*`）。駒そのものには重ねない。同点なら右、左、下、上の順。
- **動く前は、届くマスをなるべく隠さない。** 周りが届くマスで埋まるので、向きごとに駒から 1 つずつ離した候補（`menu_placement.gd` の `REGION_MAX_STEPS` まで）も比べ、
  届くマスを隠すより得なら、範囲の外まで離す（離れるほど重い。`REGION_STEP_COST`）。駒から離れたときは、駒まで細い線を引く（駒が下の帯の後ろにいれば、線は帯の上の縁で止める）。
  動いたあとは届くマスが無いので、駒の隣に出る。
- それでも届くマス（青・黄）に掛かるとき（範囲が画面いっぱい、など）は、マウスが乗っていない間、メニューを薄く描く（下のマスが読める）。
  マウスを乗せると、ふつうの濃さに戻る。
- カメラが動いたら置き直すので、回しても動かしても付いてくる。ちらつかないよう、前に選んだ側を少しひいきする。
  駒が画面の外へ出ても、メニューは画面の端に残る。

## ルールとのつなぎ方

- 画面はルールを持たない。操作を行動（`BattleAction`）にして `Battle.apply()` に渡し、
  返ってきた `ActionResult.events` を順に再生する（`battle_screen.gd` の `_do` と、`battle_playback.gd` の `play_all`）。
- 再生している間は、操作を受け付けない。再生が終わったら、対戦の状態と選んでいる駒から、
  塗るマス・ボタン・文字を作り直す（`_refresh`）。帯・メニュー・マスの説明などの文は、ノードに依存しない `battle_texts.gd` が作る（テストは `tests/game/test_battle_texts.gd`）。
- 選べること（動けるマス、攻撃できる相手、攻撃できる樽、回復できる味方、スキルの対象のマス）は、ルールの問い合わせ `Battle.options()`（`docs/battle.md`）に聞き、
  `battle_queries.gd` が画面の使いやすい形にする。どれも `Battle.can_apply()` が受け付けるものと一致する（テストで固定している）。
- 見込み（攻撃、樽・盾への攻撃、回復、スキル）は、どれも戦闘予測 `Forecast.of()`（`docs/battle-forecast.md`。実際と同じ処理を
  複製の上で走らせる）から出し、`forecast_text.gd` が同じ読み方で、駒ごとの行と駒に属さない行にまとめる（`summarize`）。
  画面は計算を持たず、それを予測のパネル（下の「戦闘予測のパネル」）に並べるだけ。樽の爆発が届くマスは `MapObject.blast_cells` で塗る。
- 相手の駒（中立の駒も）を見ると、脅威範囲（`docs/threat-range.md`。`Threat.of()`）を薄い赤で塗る。
  敵の全員の脅威範囲（`Threat.against()`）は、スイッチで斜線を重ねる（上の「敵の攻撃範囲」）。
- イベントの種類と再生するメソッドの対応は `battle_playback.gd` の `event_players()` に並べる。
  `rules/events/` にあるのに載っていない種類があると、テスト（`tests/game/test_event_playback.gd`）が落ちる。

| イベント | 再生 |
| --- | --- |
| `UnitMovedEvent` | 道順を 1 マスずつ補間して走らせる（`cruise` が真なら速く、中立の駒はゆっくり）。CPU の駒と中立の駒は、歩いている間カメラが追いかける |
| `UnitWarpedEvent` | 入ったポータルで縮んで消え、出たポータルに現れる。カメラを出た先へ寄せる |
| `UnitTeleportedEvent` | その場で縮んで消え、着いたマスに現れる（紫の光。シャドウステップ）。カメラを着いた先へ寄せる |
| `UnitsSwappedEvent` | 2 体が同時に縮んで消え、互いのマスに現れる（シャドウステップで敵と入れ替わった）。カメラを使った駒の着いた先へ寄せる |
| `MoveUndoneEvent` | 動く前のマスへ戻す |
| `AttackDamagedEvent` | 攻撃の動きと、攻撃した駒の種類ごとの当たり方（下の「攻撃の当たり方」）→ 被弾の動き、ダメージの数、HP の更新。確定クリティカルは「クリティカル -N」、バリアに防がれたら「バリア が防いだ」（爆発とスキルのダメージでも同じ） |
| `ExplosionDamagedEvent` | 被弾の動き、ダメージの数、HP の更新だけを、駒ごとに続けて見せる |

| `HealerHealedEvent` | 回復役が相手のほうを向いて手を振る → 回復の数、HP の更新、光 |

| `RegenerationHealedEvent` | 泉と同じ（回復の数、HP の更新、光） |
| `ExperienceGainedEvent` | 「経験 +N」の小さい文字 |
| `LevelUpEvent` | 最大 HP を新しくする。金の光と「レベル N！」（レベルは左下の駒の情報に出る） |
| `EvolutionOfferedEvent` | 紫の光と「進化できる！」。選択肢は、再生が終わってから出す |
| `UnitEvolvedEvent` | 最大 HP を新しくし、足元に金の輪を付ける。紫の光と、進化先の名前（進化先は左下の駒の情報に出る） |
| `BarrelExplodedEvent` | 攻撃の動きと当たり方 → 樽を消し、爆発の届いたマスを橙に塗る（続くダメージの再生の間も塗ったまま） |
| `BarricadePlacedEvent`、`AreaEffectPlacedEvent` | 盤の上の効果を描き（下の「画面に出るもの」）、中心に持ち主の色の光と効果の名前を出す（スキルで置いたときは、名前は出さない。スキルの名前と形が見せている） |
| `FieldEffectTickedEvent` | 何も出さない（残りはマスの説明に出る） |

| `SanctuaryHealedEvent` | 泉と同じ（回復の数、HP の更新、光） |
| `UnitDefeatedEvent` | 倒れる動きのあと、駒を取り除く |
| `MidBossDefeatedEvent` | 倒した陣営の色の光と「〜が左（右）の中ボスを倒した」（双子結晶では上・下）。倒した陣営が無ければ「左（右）の中ボスが倒れた」だけ |

| `UnitSpawnedEvent` | 駒（中立のエナジー・コアは宙に浮く結晶。中ボスは、大きく、輪が 2 本で、欠片が周りを回る結晶）を置き、光とともに大きくする。カメラをそこへ寄せる（中立のフェーズの静かな場面では寄せない） |

| `SkillReadyEvent` | 魔力解放のときだけ、駒の上に「スキル使用可」。クールダウンが明けただけのときは何も出さない（残りは、左下の駒の情報とメニューのスキルの項目に出る） |
| `UltUsedEvent` | 上の帯のゲージを空にし、画面の全体を必殺技の色で一瞬光らせ、中央に「必殺技: 名前!!」を大きく出す（軍ごとの色）。続く効果（状態が付いた・スキルが使えるようになった）は、**駒ごとに順にではなく全員に同時に**見せる: 効果の掛かった駒に陣営の色の光の柱が立ち、それぞれの知らせが一度に出る（待つのは駒の数に依らず 1 回） |

| `StatusRemovedEvent` | 期限なら「〜が消えた」、動いたなら「〜が解けた」。使い切ったときは何も出さない（ダメージや攻撃の再生が見せている） |

### 攻撃の当たり方

攻撃が当たる形は、攻撃した駒の種類で変える（`battle_effects.gd` の `hit_style`）。何で殴られたかが、数を読まなくても分かるように。
どれも素材は使わず、光に左右されない色の形と動きだけで描く（後処理のグローや画面のシェーダーには頼らない）。

| 当たり方 | 駒 | 形 |
| --- | --- | --- |
| 叩く | 前衛（シールドトルーパー、パラディン）、将 | 相手の足元から、橙と白の衝撃の輪が地面を這って広がる |
| 斬る | 奇襲（コマンドー、スペルブレード） | 相手の体に、白い斜めの弧（青い縁）が走る。攻撃した駒が画面の右にいれば、向きを反転する |
| 撃つ | スナイパー | 撃った駒から相手へ、細い黄色の光の弾がまっすぐ速く飛んで当たり、火花が散る |
| 魔法 | ソーサラー、プリースト、中ボス | 光る紫の球が飛んで当たり、紫の光と輪が弾ける |
| そのほか | 衛生兵、エナジー・コア | 当たったところに、小さい光が弾ける |

- 当たる瞬間は、攻撃の動きが当たる瞬間と同じ（弾はそれに間に合うように撃ち出す）。**再生の待ち時間は変えない**（形は出したら待たずに消える）。
- 演出の起点は、種類ごとに `battle_effects.gd` の 1 つのメソッドにまとめてある（`strike`、`wait_sign`、`skill_flash`、`ult_burst`。
  画面のフラッシュは `battle_hud.gd` の `flash_screen`）。効果音もそこで鳴らす（`docs/sound.md`）。

### スキルの形

スキルを使うと、通常の攻撃と見分けられるよう、使った駒の足元にスキルの色の輪が広がり、スキルの名前がその色で出る。
対象には、スキルごとの形が出る（`battle_effects.gd` の `skill_flash`）。形は手振りの終わり（0.4 秒）に対象へ届き、再生の待ち時間は変えない。

| スキル | 色 | 形 |
| --- | --- | --- |
| ファイアボール | 赤橙 | 炎の球が弧を描いて飛び、着いたところで大きく弾ける |
| 戦術バリケード | 砂色 | 置いたマスに、短い光の柱が立つ |
| スモークグレネード | 灰 | 黒い弾が弧を描いて飛び、着いたところに煙の塊が膨らむ |
| セイントプレイス | 金 | 置いたところに、太い光の柱と広がる輪 |
| ディバインシールド | 水色 | 対象の駒を包む泡が膨らんで消える |
| 精密照準 | 赤 | 対象の駒に、照準の輪と十字が縮みながら合う |
| シャドウステップ | 紫 | 使った駒の周りに紫の煙（続く転移の再生で、縮んで消える） |
| アドレナリン注射 | 黄緑 | 対象の足元から、光の粒が立ち昇る |


### フェーズの始めのカメラ

コード: `game/phase_focus.gd`。テスト: `tests/game/test_phase_focus.gd`。

- 寄るのは、その陣営が**前回のフェーズで最後に行動を確定した駒**（待機・攻撃・回復・スキル・動いたままのターン終了。`UnitActedEvent`）。
  前の自分の番の続きから見られる。
- その駒が倒れていたら、または対戦の始めでまだ誰も動いていなければ、その陣営の生きている駒のうち、味方の真ん中（位置の平均）にいちばん近い駒。
  **将かどうかには依らない**（将は本陣の近くにいて、前線が映らないことが多いため）。
- 対戦の画面は、行動のたびに起きたことを食わせ（`_do`）、新しい対戦で忘れる。CPU の番も同じ入口を通る。
## 画面に出るもの

- 上の帯: ターン、どちらの番か、
  勝ち方がいつもと違う戦い（ストーリーの守り切る・全滅させる）では、上の帯のすぐ下の左に**勝ち方の札**（枠で囲んだ金色の文字。`win_text.gd` の `goal_tag`。
  帯の中は陣営の欄で埋まっていて、入れると駒の数が省かれるため、帯の外に出す）。
  守り切るは「あと 8 ターン守り切れば勝ち」（攻める側なら「あと 8 ターンで決着しなければ負け」。いまのターンを含めて数える）で、
  最後のターンは「最後のターン: 守り切れば勝ち」にして札を赤く塗る。全滅させるは「勝ち: 敵の全滅（将を倒しても終わらない）」。
  札にマウスを乗せると、出撃準備と同じ勝ち方と負け方の文が出る。対戦モード（いつもの勝ち方）では札を出さない。
  そのあとに陣営ごとの駒の数と本陣の占拠の数（●○○。本陣の占拠が勝ちの条件に無い陣営は出さない）、必殺技のゲージ（棒に重ねた %。いっぱいなら「READY」で、ゆっくり金色に明滅する。両方の陣営のぶんを、同じ大きさで出す）、
  相手が CPU か人かを書いたボタン（押すと切り替わる）、ログのボタン（`docs/battle-log.md`）、右端にシステムメニューのボタン（「メニュー」）。陣営の欄の右に、聖遺物のアイコンが 2 つ並ぶ（英知 = 菱形の宝石、勇気 = 剣。`relic_icon.gd`）。持っていない聖遺物は暗い輪郭だけで、
  手に入れると聖遺物の色で点く（点いた瞬間に少し弾む）。名前と効果は、アイコンか陣営の欄にマウスを乗せると出る。
  陣営の欄は残った幅を分け合い、足りなければ「…」で省く（帯が画面の幅を超えない。全文はツールチップに出る）。
- **駒の頭の上には、何も出さない。** 盤の上で分かることは、足元にまとめる: 行動済みの駒は暗い。HP が減っている駒は、足元に小さい棒が出る
  （満タンなら出ない）。進化した駒は、足元の円盤を金の輪が囲む。状態（バリア、照準、突撃など）が付いている駒は、その外に水色の細い輪が出る。
  名前・役割・HP の数・レベル・進化先・状態の中身は、左下の枠で確かめる。ダメージの数などの、浮かんで消える文字は出る（まだ浮かんでいる文字と画面の上で重なるときは、その下から出す）。
- マスの色: 青 = 移動、黄 = 巡航でだけ届く、赤 = 攻撃できる相手・樽・盾、緑 = 回復できる味方、白 = 見ている駒の移動範囲、
  薄い赤 = 見ている相手の駒が次の番に攻撃・スキルを届かせうるマス（脅威範囲。その上に白の移動範囲を重ねる）、
  赤い斜線と縁の線 = 敵の全員の脅威範囲（スイッチで出しているときだけ。塗りの上に重ねる）、
  明るい白 = マウスの下のマスまでの道、橙 = マウスの下の樽の爆発が届くマス、
  紫 = スキルの対象に選べるマス（対象を選んでいる間だけ）、明るい紫 = マウスの下のマスに使ったときに効果が及ぶマス。
  駒のいるマスの赤・緑・紫は、駒の足元の円盤より上に塗る（円盤に隠れて見えなくならないように）。
- 左下の枠（駒の情報）: マウスの下の駒（いなければ見ている駒、選んでいる駒）。上から大事な順に、色と大きさで強弱を付けて並べる。
  1. 名前と役割（陣営の色。進化した駒は「進化先（元の種類 から進化・役割）」）。
  2. 所属: 盤を見ている人から見た `[自軍]` `[敵軍]` `[中立]`、陣営、軍（MILITARY / FANTASY。雇う駒だけ）。陣営の色。
     軍は陣営の軍。ストーリーで解放したほかの軍の駒は「MILITARY（FANTASY の駒）」と並べる（味方の駒に、敵と同じ軍の名前だけが出ないように）。
  3. HP の棒と数、能力値（持ち物・状態の補正が入った値）、レベルと経験値（育つ駒だけ）。
  4. 状態（水色）: 名前、残りのターン数、効果（「突撃（あと 1 ターン）: 移動 +2・攻撃 +5」）。付いているときだけ。
  5. 持ち物: 持っている持ち物の一覧（同じものは「×2」にまとめる。持っていなければ「なし」）。持ち物を持てない駒（将・中立）では出さない。
  6. スキル: 名前と使えるか（あと何ターンか、残りの回数）、その下に説明（薄い色）。使えるかは、メニューのスキルの項目と同じに見る
     （動いたあとの精密照準・巡航したあとは「使用不可」。その駒の陣営の番の間だけ。`Skills.can_use`）。
  7. 進化の特性（金。「★ …」）。
  8. 行動の状態（いまの番の陣営の駒だけ: 未行動・行動済み・行動の途中）と、いるマスの地形（平地でなければ）。
  9. メニューの項目にマウスを乗せている間は、押すと何が起きるか（黄）。
  見込みは、この枠には出さない（予測のパネル）。駒が無ければ、クリックしたマスの情報。文は `text_wrap.gd` で折り返す（枠を横に広げない）。
- 右上: 視点の動かし方の案内（1 行）と、その下にミニマップ（盤の縮図・駒の点・カメラが見ている範囲。押すとそこへ視点が移る。設定で隠せる。`docs/minimap.md`）。
- 下の帯: いまできることの説明（2 行まで）、マウスの下のマスの短い説明、敵の攻撃範囲のスイッチ、必殺技のボタン、おまかせのボタン、ターン終了のボタン。
  相手の番の間は、必殺技とおまかせのかわりに、早送りとスキップ（下の「相手を CPU にする」）。
- 文字とボタンの見た目は、UI のテーマ（`ui_theme.gd`。色は `ui_palette.gd`）でそろえる。フォントは同梱したもの（`assets/fonts/`）。
- 文の折り返しは `text_wrap.gd`（テストがある）。Label の自動の折り返しは日本語の禁則を見ないので、出す前に改行を入れる:
  行の頭に句読点・閉じ括弧・長音を置かない、半角の空白の前後では切らない（「スキル 7 回」を 1 つに保つ）、
  カタカナどうしの間では切らない（「ダメー」と「ジ」に分けない）、
  漢字どうしの間と、漢字・カタカナの後のひらがなの前は、ほかに切れる所が無いときだけ切る（「表 / 示」「範囲 / を」にしない）、
  切るなら全角の空白・句読点の後と開き括弧の前を優先する。
- **地面は、盤の外まで続く 1 枚の地形**（`board_view.gd`、`ground.gdshader`）。マスごとの板は並べない。地形の色（平地、森、岩場、結晶泉、本陣の陣営の色）は、
  ルールの盤面（`Board`）を読んで作った色の地図から取り、境目をノイズで揺らして、マスの形に切れないようにする。
- **マス目は、地面の上に重ねる線**（`grid.gdshader`）。地面の溝や板の縁ではない。ふだんはごく薄い。
  駒を選んでいる間と、マスを塗っている間（移動・攻撃・スキルの範囲、脅威範囲）は、盤の全体で濃くなる。マウスの下のマスの周り（4 マスほど）は、いつも濃い。
  塗ったマスどうしには細い隙間があり、線がそこに見える。
- **戦う範囲の境目**は、盤の縁の少し濃い線（いつも出ている）と、外の地面が少し暗いことで分かる。マス目の線は、盤の外には引かない。
- **ステージの見た目**（`stage_look.gd`）: 見た目ごとに 1 つの定義（テーマ。鍵は見た目の名前）で、地面（色・石畳などの模様）、障害物と森のマスに置くもの、
  盤の外の景色、空と霞と光、泉の石と結晶泉の結晶の色を決める。ステージ選択のカードとミニマップの色も、ここから取る。
  ステージを足す・素材を替えるときは、定義を 1 つ書くだけでよい（どの定義も全部の項目を持つことと、素材の高さの書き間違いは、テストが確かめる）。
  見た目はステージの番号ではなく名前で引く。どの見た目で描くかは、対戦の画面に渡すものが決める（`docs/battle-source.md`）。
  見た目の名前（`GRASSLAND` 草原、`STONE_WALLS` 石の壁、`CRYSTAL_FOREST` 結晶の森）は、対戦モードのステージの名前とは別に付ける。
  対戦モードの生成のステージは、`OF_STAGE` で見た目の名前に直す。ストーリーの話は、話の `LOOK` に見た目の名前を書く（同じ見た目を使い回せる）。
  以下は、いま対戦モードのステージに当てている見た目。
  - 中央平原: 若草色の草原。障害物は灰色の岩山（下の「岩山」）、森は木立。盤の外は森と岩山。昼の白い光。
  - 迷宮回廊: 遺跡。乾いた石畳の地面に、障害物は石の柱と、続いた障害物をつなぐ石の壁（ときどき崩れている）。
    盤の外は崩れた石組み・柱・瓦礫と砂色の岩山。低めの金色の光と、砂ぼこりの霞。
  - 双子結晶: 結晶の森。苔むした暗い青緑の地面に、障害物は青い結晶がところどころに生えた暗い紫の岩山（下の「岩山」）、森は暗い針葉樹。
    盤の上の結晶は青（`StageLook.CRAG_CRYSTAL`）にして、ポータルの紫・中ボスの紫・結晶泉の水色と見分ける。
    盤の外には紫と水色の結晶が光る。夜明けの薄紫の霞と、低い桃色の光。
  - どのステージでも、障害物は背の高い硬いもの（岩山・石の壁）、森は木、平地は何も置かない。地面の色も 3 つではっきり変える（テストが確かめる）。
    本陣の陣営の色、マスの塗り分け、駒、HP の棒、起爆樽とポータルの色は、どのステージでも変えない（読み方を変えないため）。
- **障害物の置き方**は 3 つ（`stage_look.gd` の `SINGLE`・`WALL`・`CRAG`）。迷宮回廊の石の壁（`WALL`）と岩山（`CRAG`）は、どちらも隣の障害物とつながる。
  - **岩山**（`CRAG`。`crag_mesh.gd` がコードで形を作る。素材は使わない）: 辺で接する障害物のかたまりを、1 つの岩山にする。
    かたまりの内側ほど高く（大きなかたまりの真ん中は峰になる）、縁は低い崖で終わる。1 マスだけの障害物は、小さく尖った岩。
    崖の裾は、通れるマスとの境目に沿い、境目からはみ出さない（テストが確かめる）。通れないマスと通れるマスの境目は、どの向きから見ても崖の裾で分かる。
    斜めにだけ接するマスどうしはつなげない（その間の通れるマスをふさいで見せない）。縁は低く、峰は大きなかたまりの内側にしか立たないので、
    岩山の手前のマスと駒は、高い峰に隠れにくい（それでも隠れるときは、下の「透ける」が効く）。
    面ごとに平らな影と色のローポリの岩。結晶はかたまりの内側のところどころと峰の上に生やす（結晶の森だけ）。
    形はマスごとに分けて作り（マスごとに透かすため）、1 マスの形の中に岩と結晶をまとめて、1 マス 1 回で描く。
- **盤の外の景色**（`scenery.gd`）: ステージの見た目が挙げる、大きいもの（岩山など）・小さいもの（木など）・散らばるもの（石など）を、種から決まる並びで置く。
  盤の上のものより目立たないよう、色を少し沈ませている（光る結晶は除く）。同じ素材はまとめて描く（MultiMesh）。置き方の決まりは次のとおり（テストが確かめる）。
  - 盤の端から 2 マスまでは、何も置かない（`scenery.gd` の `CLEAR`）。
  - 高さは、盤の端からの距離の半分まで（`HEIGHT_PER_DISTANCE`）。カメラはいちばん浅くても 30 度で見下ろすので、
    どの向き・どの距離から見ても、外のものが盤の中を隠さない。近くは低いものだけで、遠くほど大きいものになる。
  - 盤の端から 66 マスより先には置かない（`REACH`）。その先は霞んで見えない。
- **遠くは、空の色の霞に溶ける**（`stage_look.gd` の `FOG_BEGIN`、`FOG_END`）。背景も同じ色。地面の板は霞の先まで広げてあるので、端は見えない。
  霞は、いちばん引いて盤の端から端を見ても、盤の中にはほとんど掛からない距離から始まる。
- 本陣のマスには陣営の色の旗が立つ。
- 環境オブジェクト（`docs/map-objects.md`）。どれもコードで作った形で、素材は足していない（泉の石の色はステージの見た目が決める）。
  - 起爆樽: ふたと帯の赤い樽。
  - 回復の泉: 石の縁の青い水面。駒が乗っても分かるよう、マスの隅に緑の十字の札が立つ。水面に、白い波紋がゆっくり広がり続ける。
  - ポータル: 色の輪と、両脇の柱。色は対ごとに違い、同じ色の 2 つがつながっている。光の粒が渦を巻いて昇り、面がゆっくり脈打つ。
  - 泉とポータルの動きは、止まった絵でなく動きでそれと分かるためのもの。駒や塗ったマスより目立たないよう、ゆっくり・小さくしてある
    （`board_view.gd` の `_animate`）。
- 盤の上の効果（`docs/field-effects.md`。`board_view.gd` の `add_field_effect`）。煙幕と聖域の床は、駒の足元より低く描く。
  - 盾: 持ち主の色の堅い板（上に明るい縁）。
  - 煙幕: 灰色の薄い床と、駒を包む高さの淡い靄。
  - 聖域: 持ち主の色の、淡く光る床。
- 障害物（岩山・石の壁）と木立は、駒やマウスの下のマスの手前（カメラの側）にあると透ける（見下ろす角度が浅いほど、遠くまで透かす）。

## 戦闘予測のパネル

行動の対象にマウスを乗せている間、**何が起きるかを一目で分かる形で、対象のそばに出す**（`forecast_panel.gd`。中身は
`ForecastText.summarize`。`docs/battle-forecast.md` の `Forecast` をそのまま読む）。

- 出るとき: 選んでいる駒で、攻撃できる相手（赤）、狙える樽・盾、回復できる味方（緑）、スキルの対象のマス（紫）にマウスを乗せている間。
  自分に使うスキルは、対象を選び始めたら、マウスを乗せなくても出す。見ている間（閲覧）、CPU の番、再生の途中、メニューの上では出さない。
- 中身（上から）: 見出し（何をするか。「攻撃」「回復」「樽を撃つ（爆発 N ダメージ）」「盾を攻撃」、スキルの名前）→
  目立つ知らせ（**「倒せる！」「N 体を倒せる！」**（赤）、**「自分も巻き込まれる！」**（橙））→ 何かが起きる駒ごとに、
  名前（陣営の色。行動する駒は「自分（〜）」）、HP の棒（減るぶんを赤、増えるぶんを緑で、前と後を 1 本に描く）、
  「N ダメージ → 残り HP X」「N ダメージ → 倒れる」「0 ダメージ」「+N → HP X / Y」、内訳（クリティカル・森で軽減・爆発、バリアが防ぐ・煙幕に阻まれる）、
  ほかに起きること（状態が付く・解ける、移る先、もう一度行動できる、経験とレベルアップ・進化を選べる（進化先の名前））→
  駒に属さないこと（置かれる効果、盾の耐久、聖遺物と効果、必殺技のゲージの変わり方、決着）。
- 置き場所: 対象のマスのそば。駒のそばのメニューと同じ置き方（`menu_placement.gd`）で、行動する駒、何かが起きる駒と効果の及ぶマス、
  左下の枠を隠さない側を選び、画面（上下の帯の内側）に収める。**駒のそばのメニューには、決して重ねない**（メニューの出方はそのままで、
  パネルの側が逃げる）。対象の周りがどれもメニューに掛かるときは、メニューの上下左右に接するところへ置く。
  カメラが動いたとき、メニューが動いたとき（中身が変わった）に置き直す。マウスはパネルを素通しにする（下のマスを選べる）。
  カメラの向き・盤の位置・駒の位置を総当たりして、重ならず・はみ出さず・対象の駒を隠さないことをテストで固定している（`tests/game/test_forecast_placement.gd`）。
- 幅は決まっていて（`forecast_panel.gd` の `WIDTH`）、文は `text_wrap.gd` で折り返す。
  何かが起きる駒が多いとき（`COMPACT_FROM` 体から。樽の爆発は 8 体まで巻き込む）は、駒ごとに「名前: N ダメージ → 倒れる（爆発）」の
  1 行に詰め（HP の棒は描かない。倒れる駒は赤、自分は橙）、パネルが画面の高さを超えないようにする。

## 環境オブジェクトの操作

- 樽の攻撃: 駒を選ぶと、いまの位置から攻撃できる樽のマスが赤くなる。クリックで攻撃（`AttackBarrelAction`）。メニューの「攻撃」からでもよい。
  動く前でも、動いたあとでもよい。
- ポータル:
  - 動ける範囲の中で、転移して行けるポータルの対（入るポータルと出るポータル）を、ポータルと同じ色で塗る。
    ポータルの面に隠れないよう、面の上に塗る。行き先へこのポータルを通らずに歩いて行くとき（敵の支配領域で止まる、など）は塗らない。
  - **ポータルのマスをクリックすると、そこに止まる。** 転移できるなら、駒のそばのメニューのいちばん上に「転移」が出て、
    出るポータルを同じ色で塗る（下の帯は「ポータルの上。メニューの「転移」で、同じ色のマスへ移れる」）。
    「転移」を押すと、出るポータルへ移る（入ったポータルで縮んで消え、出たポータルに現れる）。転移のあとも、攻撃・待機・取り消しを選べる。
    取り消すと、動く前のマスへ戻る。フェーズの始めからポータルの上にいる駒も、選ぶと「転移」が出る。
  - 「転移」が出ないのは、出るポータルに駒がいるとき、ポータルが敵の支配領域にあって止まったとき、スキルを使って移動を取り消せないとき。
  - ルールに「転移する」行動は無い（`docs/map-objects.md`）。動いたあとの「転移」は、移動の取り消しと、動く前のマスから出るポータルへの移動の
    2 つとしてルールに渡す（`battle_queries.gd` の `warp`・`warp_actions`）。取り消して歩き直すところは見せず、転移だけを見せる。ログは「ポータル経由」の移動 1 行。
  - ポータルの先のマスを直接クリックしても、転移する道で動く（ルールが移動力のいちばん少ない道を選ぶ。道の表示は、通るポータルの両方のマスを含む）。
- 回復の泉: 操作は無い。乗ったまま自分の番を迎えると回復する。

## 決着の画面

- 決着すると、決着の画面を盤面の上に重ねて、段階的に出す（`docs/result-screen.md`）。
  後ろの盤の駒やマスの情報（左下の枠、下の帯のマスの説明、予測のパネル）は、決着したら出さない（決着の画面のボタンに重なるため）。
- 画面は、行動のたびに起きたことを `BattleStats` に食わせる（`_do`）。CPU の行動も同じ入口を通る。

## 対戦設定

- 対戦の前の設定は、対戦設定の場面（`setup_screen.gd`。ステージ選択のあと。`docs/scene-flow.md`）で選ぶ。対戦の途中でも、同じ画面（`match_setup_panel.gd`）を盤面の上に開ける（下）。
  選ぶもの: 相手（CPU / 人）、CPU と対戦するときの自分の手番（先手 / 後手 / ランダム。人どうしでは選ばない）、両方の軍（MILITARY / FANTASY）、
  人が動かすプレイヤーの部隊（人どうしなら両方）。
  既定は 相手 CPU、自分が先手、先手 MILITARY・後手 FANTASY。
- **ステージは選ばない**（ステージ選択の場面で選ぶ。`docs/stage-select.md`）。パネルには選んだステージの名前を出すだけで、
  対戦設定の場面では「ステージ選択へ戻る」（右クリック・Esc でも）でステージ選択の場面へ戻る（ほかの選択は残る）。
  対戦の途中で開いたパネルでは、閉じるボタンが「対戦へ戻る」なので、「ステージ変更」でステージ選択の場面へ戻る（押すといまの対戦は終わる）。
  ステージ選択へ行くボタンは、どちらでも 1 つだけ。
- 手番の「ランダム」は、対戦を作るたびに、種から先手か後手かを引く（`match_choice.gd` の `draw_side`。対戦の乱数とは別に引くので、盤や対戦の進みは変えない）。
  同じ種なら同じ手番なので、「同じ盤面で再戦」は同じ手番で始め直す。
  ランダムの間は、2 つの軍の行の見出しを「あなた」「CPU」にする（どちらが先手か決まっていないので、陣営の色を付けない）。
  ほかのときは「あなた・先手（青）」「CPU・後手（赤）」のように、誰が動かすかと手番を書く。人どうしなら「先手（青）」「後手（赤）」。
- 部隊は、軍を選んだあと、その軍の取っておいた部隊か既定の編成（コスト上限どおり。`docs/match-setup.md`）から選ぶ（`docs/deck-screen.md` の「対戦設定で選ぶ」）。
  CPU の編成は軍ごとの CPU の編成。
- **部隊の中身はパネルに文で並べない。** 行ごとの「編成確認」で、駒ごとの札（名前、役割、コスト、能力値、持ち物）を並べた画面を開く（`game/deck_preview.gd`）。
  自分の部隊も CPU の部隊も同じ見え方。「閉じる」・右クリック・Esc で閉じる。
- パネルの大きさは、選んだもの（軍、部隊、相手）に依らず同じ（`PANEL_WIDTH`。部隊の名前は欄の幅で切る）。
- 人が動かす行には「部隊編成」がある（対戦設定の場面だけ。対戦の途中で開いたパネルには出さない）。
  部隊編成（対戦用）へ寄り道し、「対戦設定へ戻る」で戻る。寄り道で取っておいた部隊が、その行の部隊に選ばれて戻る（`docs/deck-screen.md`）。
- 「対戦開始」で、選んだもの（`match_choice.gd`）の写しを対戦の場面に渡し（`docs/battle-source.md`）、それが作る `MatchSetup` で、新しい盤面で始める。自分が後手なら、CPU の番から始まる。
- 対戦の途中は、システムメニューの「対戦設定へ」で、盤面の上に開ける（再生の途中と CPU の番の間に選んだら、それが終わってから開く）。
  開いている間は、盤面の操作を受け付けない。
- **開いただけでは、いまの対戦は変わらない。** 「対戦へ戻る」（右クリック・Esc でも）で、何も変えずに閉じて、元の対戦へそのまま戻る。
  新しい対戦になるのは「新しい対戦」を押したときだけ。決着していない対戦の途中なら、押すといまの対戦が終わることを画面に書く。
  - **決着していない対戦の途中では、押すといまの対戦が終わるボタン（「ステージ変更」「新しい対戦」）を 2 回押させる**
    （ターン終了・必殺技の確かめと同じ形）。1 回目でボタンが「もう一度押して変更」「もう一度押して開始」（危ない操作の色）になり、理由（何が起きるか）は
    ボタンの下の文に出す。確かめに変わった直後の 0.4 秒（`battle_ui_state.gd` の `CONFIRM_GUARD_MSEC`）の 2 回目は受けない。
    ほかの選択を変える、もう一方のボタンを押す（そちらの確かめに変わる）、右クリック・Esc（パネルは閉じない）で、確かめはやめる。
    決着のあとと、対戦設定の場面では、1 回で進む。
  対戦設定の場面では、閉じるボタンは「ステージ選択へ戻る」（右クリック・Esc でも）。
- F1〜F3 と決着の画面のやり直しは、いまの設定のまま、ステージと盤面だけを変える。F1〜F3 と「新しい盤面」は生成のステージ（中央平原・迷宮回廊・双子結晶）だけ（`docs/stage-select.md`）。
- 対戦設定のパネル、F1〜F3、決着の画面の「新しい盤面」「対戦設定へ」、相手の切り替えは、対戦の画面に渡したもの（`docs/battle-source.md`）が許すときだけ出す。
  対戦モード（`match_choice.gd`）は、どれも許す。

## 相手を CPU にする

- 相手（自分でないほうのプレイヤー。始めはプレイヤー2）は、CPU か人かを選べる（対戦設定、上の帯のボタンか F4）。
  人にすると、2 人が 1 台で交代する形になる。
  対戦の途中でも切り替えられる。相手の番の途中で CPU にすれば、続きを CPU が引き取る。
  人に戻せば、CPU はいまの行動を最後に手を止める。
- CPU の番は、`CpuPlayer.next_action()`（`docs/cpu-ai.md`）が返す行動を、人の操作と同じ入口（`_do`）に 1 つずつ流す（`_run_cpu`）。
  画面はルールにも CPU の考えにも立ち入らない。再生も、人の行動と同じイベントの再生をそのまま使う。
- 何をしたか追えるように、駒が動き出す前にカメラをその駒へ寄せ（`CPU_FOCUS_TIME`）、1 体の行動が終わるたびに間を置く（`CPU_PAUSE`）。
  動かずに待機するだけの駒は、見せるものが無いので、カメラを寄せず、間も置かない。
- **歩いている間、カメラがその駒を追いかける**（`OrbitCamera.follow`）。長い距離を動いても、画面の外へ出ていかない。
  攻撃のときは、攻撃する駒と相手の間へカメラを寄せる（離れた相手を撃っても、どちらも見える）。
  自分で動かした駒は追わない（行き先を自分で選んでいるので）。WASD で視点を動かすと、追うのをやめる。
- CPU の番の間は、盤面の操作・待機・取り消し・ターン終了・やり直しを受け付けない（`is_busy()`）。
  選べるマスは塗らず、メニューも、CPU の駒の進化先の選択肢も出さない（CPU が自分で選ぶ）。下の帯に「相手（CPU）の番」と出す。
  視点は、CPU の番の間も動かせる。
- CPU の軍と手番は、対戦設定で選ぶ。
- CPU の番の速さの既定は、オプションの「CPU の番の速さ」（`docs/system-menu.md`）。
- **相手の番の早送りとスキップ。** 相手が CPU のとき（ストーリーも）、自分の番を終えてから次の自分の番が来るまで（中立のフェーズと CPU の番）、
  下の帯の必殺技のボタンの場所に「早送り」「スキップ」が出る。
  - 早送り: 切り替え。入れると、オプションの速さにさらに 4 倍（`battle_screen.gd` の `FAST_FORWARD_SCALE`）を掛ける。入れたままなら、次の相手の番も早送り。
    自分の番には効かない。
  - スキップ: 押すと、自分の番が来るまでの残りを見せずに進める（CPU は同じように考えて動く。カメラを寄せる間も置かない）。
    起きたことはログに残る（`battle_log`）。対戦の途中の台詞（`docs/story.md`）も、スキップの途中に出たものはログにだけ残す。
    終わったら、駒・樽・盤の上の効果の見た目を、いまの盤から作り直し、番の知らせを出して、カメラを番の始めの位置へ寄せる。
    途中で決着したら、見た目を作り直してから、決着をふつうに見せる。
  - 見せずに済ませるのは `BattlePlayback.skipping`。再生の途中（中立のフェーズの場面の間、CPU の 1 体の行動の間）でも、次の区切りから効く。
- **自分の番のおまかせ。** 下の帯のターン終了の左に「おまかせ」。押すと「もう一度押して実行」に変わり（下の帯に、取り消せないこと）、
  もう一度押すと、このターンの残りの駒を CPU（相手の CPU と同じ考え。`CpuPlayer`）が動かして、ターンを終える。
  確かめに変わった直後の 2 回目は受けない（ターン終了と同じ）。右クリックか盤のクリックで、確かめをやめる。
  駒が行動の途中（動いたあと）・進化先を選ぶ途中は押せない。任せている間は、相手の番と同じに見るだけ（早送り・スキップも効く）。
  人どうしの対戦でも使える（任せた番が終われば、次の人の番で止まる）。

## 中立のフェーズの再生

中立の駒は、ルールの上では 1 体ずつ「動く → 攻撃する」。そのまま順に 1 体ずつカメラで追うと、何も起きなかった駒のために
カメラが盤の端から端へ飛び続けて、目で追えない。そこで、起きたことを駒ごとの**場面**に分けて見せる
（`neutral_playback.gd`。イベントを読むだけで、ルールは持たない。テストがある）。

- **静かな場面**: 動いただけ、湧いただけ（`UnitMovedEvent`、`UnitWarpedEvent`、`UnitSpawnedEvent` だけ）。
  カメラを動かさず、続いている静かな場面を**まとめて同時に**流す（待ち時間は、いちばん長く歩く 1 体のぶんだけ）。
- **見せる場面**: 攻撃した、煙幕に阻まれた、倒した、など。**必ずカメラを寄せて、1 体ずつ**見せる:
  攻撃する駒へ寄せる（`NEUTRAL_FOCUS_TIME`）→ 歩く間は追いかける → 攻撃のときは相手との間へ寄せる → 間を置く（`NEUTRAL_PAUSE`）。
- 中立の駒は、プレイヤーの駒よりゆっくり歩く（1 マスの時間は `NEUTRAL_STEP_TIME`。プレイヤーの駒は `STEP_TIME`、巡航は `CRUISE_STEP_TIME`。どれも `battle_playback.gd`）。
- 起きた順は変えない（静かな場面をまとめるのは、間に見せる場面をはさまずに続いているものだけ）。

## 回復の操作

- 回復役（衛生兵・プリースト）を選ぶと、いまの位置から回復できる味方（HP が減っていて、射程の中）のマスが緑になる。
  クリックで回復する（`HealAction`）。メニューの「回復」を押すと、回復できる味方だけが塗られる（押さなくても回復できる）。
  動く前でも、動いたあとでもよい。巡航のあとは回復できない。
- 回復役は攻撃できないので、赤いマスは出ない。

## スキルの操作

どのスキルも同じ操作に乗る（`docs/active-skills.md`。スキルの対象は、いつもマスで指す）。

- 駒のそばのメニューに、選んでいる駒のスキルの名前の項目が出る。クールダウンの間は「スキル（あと N ターン）」、
  対象に選べるマスが無いときは「スキル（使用不可）」と出て、押せない。スキルの無い駒では、項目そのものが出ない。
- 押すと、**対象を選ぶ途中**になる。対象に選べるマス（`Battle.options()` の `skill_cells`）だけが紫になり、
  移動や攻撃のマスは塗らない。マウスを乗せると、効果が及ぶマス（`Skill.affected_cells`）が明るい紫になり、
  そのそばに予測のパネルが出る（左下には、使う駒とスキルの説明）。
- 紫のマスをクリックすると使う（`UseSkillAction`）。使うと行動を終える。動く前でも、動いたあとでもよい。
- **行動を終えないスキル**（シャドウステップ）は、使ったあとも同じ駒を選んだままになり、動いたあとと同じに、攻撃できる相手が赤くなる。
  続けて攻撃するか、待機する。メニューに「移動を取り消す」は出ず、戻す操作（右クリック）も何もしない。
  下の帯の説明は、対象を選ぶ間は「使ったあと、続けて攻撃できる」、使ったあとは「スキル使用済み。…」になる。
- **回数に上限のあるスキル**（アドレナリン注射）は、項目に「あと N 回」、使い切ると「スキル（使用済み）」と出る（左下の駒の情報にも残りの回数）。
- やめるには、メニューの「キャンセル」を押すか、ほかのマスをクリックするか、右クリック。
  駒の選択と、動いたあとの状態はそのまま残る（もう一度戻す操作をすると、移動の取り消し・選択をやめる）。
- 自分に使うスキル（対象が自分のマスだけ）も、同じ操作。項目を押すと自分のマスが紫になり、
  マウスを乗せなくても、その駒のそばに予測のパネル（付く状態と期限）が出る。下の帯の説明は「この駒をクリックで使う」になる。
  その駒（紫のマス）をクリックすると使う。項目を押しただけでは使わない（押し間違いで行動を終えないように）。
- 使ったときの形は、上の「スキルの形」。置かれた効果は、上の「画面に出るもの」の形で描く。

## 必殺技の操作

必殺技（`docs/tactical-ult.md`）は駒の行動ではないので、駒を選んでいなくても使える。対象は選ばない。

- 必殺技のボタン（下の帯の右、おまかせの左）には、必殺技の名前とゲージ（%。いっぱいなら「使用可」）が出る。いっぱいになるまで押せない。
  CPU と対戦するときは、いつも人のプレイヤーのもの（CPU の番と中立の番の間も、人のゲージを出して、押せない）。
  人どうしでは、いまの番のプレイヤーのもの（中立の番の間は、プレイヤー1 のもの）。
- スキルは「ボタン → マスを選ぶ」の 2 手で使う。必殺技は選ぶマスが無いので、**「ボタン → もう一度ボタン」の 2 手**にしてある
  （押し間違いで使わないように。使ったら取り消せない）。1 回目でボタンが「もう一度押して発動」になる（直後の短い間の 2 回目は受けない。ターン終了と同じ）。
  必殺技の説明は、ボタンにマウスを乗せている間と、使うかを確かめている間、ボタンの上に出る。
- やめるには、右クリックか、盤面のどこかをクリックする。どちらも、やめるだけ（クリックしたマスへの移動や攻撃はしない）。駒の選択と、動いたあとの状態はそのまま残る。
- 使っても、選んでいた駒はそのまま（総員突撃なら、伸びた移動力のマスがすぐに塗り直される）。駒が行動の途中でも使える。
- 発動すると、画面が必殺技の色に一瞬光り、中央に必殺技の名前が出る。効果の掛かった駒には、全員に同時に陣営の色の光の柱が立ち、
  「突撃」「スキル使用可」が一度に出る（駒ごとに順に出さない。7 体でも再生の長さは変わらない）。
- ゲージが READY の間、上の帯のゲージと、押せる必殺技のボタンが、ゆっくり金色に明滅する（実時間で測る。CPU の番の速さに依らない）。

## 進化先を選ぶ操作

- 駒が上限のレベルに届くと、画面の上寄りに 2 つのボタンが出る。ボタンには、進化先の名前、能力値の増減、特性が書いてある
  （`BattleHud.evolution_text`。`docs/branch-evolution.md` の表から作る）。
- ボタンを押して選ぶ（`EvolveAction`）。選ぶまで、ターン終了のボタンは押せず、メニューは出ず、ほかの操作は何も起こさない。
- 進化した駒は、足元に金の輪が付く（形は変えていない。進化先は、左下の駒の情報の名前に出る）。

## 仮のもの

- **カメラの向き**: 後手を選んでも、カメラはプレイヤー1 の側から見る向きで始まる（ドラッグで回せる）。
- **中立の駒**の見た目は、宙に浮く結晶のコア（`unit_view.gd`）。小さい駒は黄、中ボスは紫で大きく、足元から結晶が突き出している。縄張りは描かない。
- **駒の形**: 素材のキャラクターは 4 体なので、種類は持ち物で分けている
  （将 = 大きい騎士 + 金の輪、前衛 = 騎士 + 盾、後衛 = 弩 / 杖、奇襲 = 短剣 / 斧、回復 = 本）。

## 検査

`godot --headless --fixed-fps 60 -- --autoplay` で、自動の対戦（`autoplay.gd`）が人と同じ入口
（マスを選ぶ・駒のそばのメニューの項目を押す・戻す・ターン終了・進化先を選ぶ）だけを使って対戦を最後まで進め、
続けて小さな盤面で決まった手順の場面を通す。

場面の一覧は `game/autoplay.gd` の `SCENES`（名前と説明）が正で、**この文書には場面ごとの箇条書きを書かない**
（場面を足す PR が毎回同じところに書き足して、衝突するため）。場面は次のようなまとまりで並ぶ。

- 盤と環境: 環境オブジェクト、盤の上の効果、中立の駒、成長と進化。
- 画面の表示: 予測のパネル、駒と脅威範囲の見方、ミニマップ。
- 操作: メニューの項目、スキル、必殺技、システムメニューとログ、設定と CPU の番。

長い検査（`-- --autoplay --full`）では、そのあと盤面を作り直して残りのステージも少し動かす（そのうち 1 戦は相手を CPU にして、プレイヤー1 だけを操作する）。
途中で画面と対戦の状態（駒の数・位置・HP、樽のマス、盤の上の効果）が食い違えば失敗。メニューが画面（上下の帯の内側）からはみ出しても失敗。
最後に `autoplay: OK` を出す。

- 場面は `autoplay.gd` の `SCENES` に名前で並んでいる。`-- --autoplay --only <名前,…>` で、選んだ場面だけを回せる（`GROUPS` のまとまりの名前も使える）。
  場面はどれも、自分で盤面を作って始める（前の場面の状態に頼らない）。足すときは、`SCENES` に名前と説明を足し、`_queue_<名前>_scene()` に手順を積む。
- 場面の中で確かめたことが外れたら、その場面の残りを飛ばして次へ進み、最後に外れたことをまとめて出して失敗で終わる。
- イベントを再生する場面（まとまり `events`）を全部回したときは、どの種類のイベントも 1 回は再生したことを確かめる。
- `tools/check.sh` は、`events` と、操作の決まりの場面（まとまり `ui`）を別のプロセスで並べて回す（`--full` を付けると、`events` のほうが長い検査になる）。
