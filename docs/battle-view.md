# 対戦の画面（見た目の試作）

コード: `prototype/`。テスト: `tests/prototype/`（ノードに依存しない部分）と、`tools/check.sh` の自動の対戦。

2 人が 1 台で交代しながら、対戦を最後まで遊べる。操作の一覧はルートの `README.md`。

## ルールとのつなぎ方

- 画面はルールを持たない。操作を行動（`BattleAction`）にして `Battle.apply()` に渡し、
  返ってきた `ActionResult.events` を順に再生する（`board_prototype.gd` の `_do` と `_play`）。
- 再生している間は、操作を受け付けない。再生が終わったら、対戦の状態と選んでいる駒から、
  塗るマス・ボタン・文字を作り直す（`_refresh`）。
- 選べること（動けるマス、攻撃できる相手、攻撃できる樽）は、ルールの問い合わせ `Battle.options()`（`docs/battle.md`）に聞き、
  `battle_queries.gd` が画面の使いやすい形にする。どれも `Battle.can_apply()` が受け付けるものと一致する（テストで固定している）。
- 攻撃の見込み（ダメージと残り HP）は、実際の攻撃と同じ `Combat.damage()` で出す。
  樽の爆発の見込み（届くマス、巻き込む駒）は `MapObject.blast_cells` / `blast_victims` / `blast_damage` で出す。
- イベントの種類と再生するメソッドの対応は `board_prototype.gd` の `event_players()` に並べる。
  `rules/events/` にあるのに載っていない種類があると、テスト（`tests/prototype/test_event_playback.gd`）が落ちる。

| イベント | 再生 |
| --- | --- |
| `UnitMovedEvent` | 道順を 1 マスずつ補間して走らせる（`cruise` が真なら速く） |
| `UnitWarpedEvent` | 入ったポータルで縮んで消え、出たポータルに現れる。カメラを出た先へ寄せる |
| `MoveUndoneEvent` | 動く前のマスへ戻す |
| `AttackDamagedEvent` | 攻撃の動き → 被弾の動き、ダメージの数、HP のバーの更新 |
| `ExplosionDamagedEvent` | 被弾の動き、ダメージの数、HP のバーの更新だけを、駒ごとに続けて見せる |
| `HealerHealedEvent` | 回復の数、HP のバーの更新（操作がまだ無いので、自動の対戦では再生されない） |
| `SpringHealedEvent` | 回復の数、HP のバーの更新、光 |
| `BarrelExplodedEvent` | 攻撃の動き → 樽を消し、爆発の届いたマスを橙に塗る（続くダメージの再生の間も塗ったまま） |
| `UnitDefeatedEvent` | 倒れる動きのあと、駒を取り除く |
| `UnitActedEvent` | 駒を暗くする（行動済み） |
| `PhaseStartedEvent` | その陣営の駒を明るく戻し、番の知らせを出し、カメラをその陣営の将へ寄せる。中立の番は何も見せない |
| `CaptureProgressEvent` | 本陣の上に占拠の数を出す |
| `GameWonEvent` | 勝者と理由、やり直しのボタンを出す |
| `GameDrawnEvent` | 「引き分け」と理由、やり直しのボタンを出す |

## 画面に出るもの

- 上の帯: ターン、どちらの番か、陣営ごとの駒の数と本陣の占拠の数（●○○）。
- 駒の頭の上: HP のバーと、役割の 1 文字（将・前・後・奇・回）+ HP の数。行動済みの駒は暗い。
- マスの色: 青 = 移動、黄 = 巡航でだけ届く、赤 = 攻撃できる相手と樽、白 = 動かせない駒の移動範囲（眺めるだけ）、
  明るい白 = マウスの下のマスまでの道、橙 = マウスの下の樽の爆発が届くマス。
- 左下: マウスの下の駒（いなければ選んでいる駒）の能力値と状態、攻撃の見込み
  （狙える樽にマウスを乗せると、爆発の見込み）。
- 下の帯: いまできることの説明、マウスの下のマスの地形と環境オブジェクト（ポータルは行き先も）、待機・取り消し・ターン終了のボタン。
- 本陣のマスには陣営の色の旗が立つ。
- 環境オブジェクト（`docs/map-objects.md`）。どれもコードで作った形で、素材は足していない。
  - 起爆樽: ふたと帯の赤い樽。
  - 回復の泉: 石の縁の青い水面。駒が乗っても分かるよう、マスの隅に緑の十字の札が立つ。
  - ポータル: 色の輪と、両脇の柱。色は対ごとに違い、同じ色の 2 つがつながっている。

## 環境オブジェクトの操作

- 樽の攻撃: 駒を選ぶと、いまの位置から攻撃できる樽のマスが赤くなる。クリックで攻撃（`AttackBarrelAction`）。
  動く前でも、動いたあとでもよい。
- ポータル: 専用の操作は無い。行き先のマスを選ぶと、ルールが移動力のいちばん少ない道を選び、
  転移したほうが近ければ転移する（道の表示は、通るポータルの両方のマスを含む）。
- 回復の泉: 操作は無い。乗ったまま自分の番を迎えると回復する。

## 仮のもの

- **編成と配置**（`trial_setup.gd`）: 将 + 前衛 2 + 後衛 2 + 奇襲 2 を本陣の周りに点対称に置く。
  プレイヤー1 は MILITARY、プレイヤー2 は FANTASY。装備は持たせていない。
  編成のルール（`docs/player-loadout.md` の `Deck` と `Deployment`）には、まだつないでいない。
- **回復役の回復**の操作は、まだ画面に無い（回復役も置いていない）。
- **中立の駒**は置かない（中立のルールがまだ無い）。見た目（宙に浮く結晶のコア）は `unit_view.gd` に残してある。
- **駒の形**: 素材のキャラクターは 4 体なので、種類は持ち物で分けている
  （将 = 大きい騎士 + 金の輪、前衛 = 騎士 + 盾、後衛 = 弩 / 杖、奇襲 = 短剣 / 斧、回復 = 本）。
- 文字は OS のフォントで出している（フォントは同梱していない）。

## 検査

`godot --headless --fixed-fps 60 -- --autoplay` で、自動の対戦（`autoplay.gd`）が人と同じ入口
（マスを選ぶ・待機・戻す・ターン終了）だけを使って対戦を最後まで進め、小さな盤面で決まった手順の場面
（ポータルを通る移動とその取り消し、回復の泉、本陣の占拠、樽の爆発による引き分け）を通し、
盤面を作り直して残りのステージも少し動かす。
途中で画面と対戦の状態（駒の数・位置・HP、樽のマス）が食い違えば失敗。
どの種類のイベントも（操作がまだ無い `HealerHealedEvent` を除いて）1 回は再生したことを確かめて、最後に `autoplay: OK` を出す。`tools/check.sh` がこれを回す。
