# 対戦の画面

コード: `game/`。テスト: `tests/game/`（ノードに依存しない部分）と、`tools/check.sh` の自動の対戦。

1 人で CPU を相手に、または 2 人が 1 台で交代しながら、対戦を最後まで遊べる。操作の一覧はルートの `README.md`。

## 操作の考え方

**操作の説明を読まなくても遊べること**を基準にする。マウスのクリックだけで 1 局を最後まで遊べて、どこを押せばよいかを探さずに済むようにする。

- **駒に属する操作は、駒のそばのメニューから選ぶ**（攻撃、回復、スキル、待機、移動を取り消す、ポータルの上なら転移）。出すのは、いま選べるものだけ。
  スキルだけは、持っている駒なら使えない間も理由を添えて出す（押せない。「スキル（あと 2 ターン）」）。
- **駒に属さない操作は、画面の決まった場所に置く**。右下にターン終了（色付き。動かせる駒が残っていなければ明るくなる）、おまかせ、必殺技（相手の番の間は、かわりに早送りとスキップ）、
  敵の攻撃範囲の切り替え（スイッチ）、
  上の帯の右に相手の切り替え、ログ、システムメニュー（`docs/system-menu.md`）のボタン。
- **マスを直接クリックしても進む**。青・黄のマスで移動、赤いマスの相手で攻撃、緑のマスの味方で回復。メニューの「攻撃」「回復」は、
  相手だけを塗って見せる近道で、押さなくても攻撃できる。
- **右クリックは、いつでも 1 つ戻す**（必殺技の確かめ → 駒を見ている → 対象を選ぶ途中 → 移動 → 選択 の順にやめる。対戦設定のパネルも閉じる）。
  「戻す」の主役は右クリック。Esc も、戻すものがある間は同じに働き、**戻すものが何も無いときはシステムメニューを開く**（`docs/system-menu.md`）。
- キーボードのショートカット（Space、F、G、T、Enter、Esc、1・2、視点の Q・E・R、F1〜F4）は残してあるが、画面には書かない。
- **説明が要らないのは操作だけ。中身の説明（スキル、必殺技、進化先、聖遺物、地形、環境オブジェクト）は、読める場所に出す。**
  - スキル: 選んだ駒・マウスを乗せた駒の左下の枠に、スキルの名前・使えるか・説明がいつも出る。メニューのスキルの項目に
    マウスを乗せると、説明・使ったあと行動が終わるか・クールダウンが出る。対象を選んでいる間は、説明が左下に、見込みが予測のパネルに出る。
  - メニューのほかの項目（転移・攻撃・回復・待機・移動を取り消す・キャンセル）も、マウスを乗せると、押すと何が起きるかが左下の枠に出る。
  - 必殺技: ボタンにマウスを乗せている間と、使うかを確かめている間、説明がボタンの上に出る。
  - 進化先: 選ぶボタンに、名前・能力値の増減・特性が書いてある。進化した駒と、特性を与える持ち物を持つ駒の特性は、左下の枠に出る。
  - 聖遺物: 手に入れたときに、名前と効果を画面の中央に出す。上の帯の陣営の欄にマウスを乗せると、持っている聖遺物の効果が出る。
  - 地形・環境オブジェクト・盤の上の効果: マスをクリックすると左下の枠に、マウスを乗せると下の帯に 1 行で出る。

### 選ぶ・動かす・攻撃する

- **駒を選ぶと、移動と巡航の範囲を同時に塗る**（青と黄）。押す前に届く範囲が見える。
- **攻撃は、赤いマスの相手を 1 回クリック**。メニューの「攻撃」から相手を選ぶ 2 手でもよい（「赤 = 攻撃できる」を知らなくても辿れる）。
- **範囲の外の、駒のいないマスをクリックすると、選択をやめて**、そのマスの情報を出す。行動できる自分の駒なら、その駒を選び直す。
  ほかの駒なら、選択はそのままで、その駒を見る（下の「駒を見る」）。
  **動いたあと**（攻撃・回復・待機・取り消しを選ぶところ）は、対象のマス（赤・緑）とほかの駒のほかをクリックしても何も起きない（選択も外れない）。
- **巡航のあとも「移動を取り消す」が出る**（ルールの `UndoMoveAction` が受け付ける）。黄のマスの押し間違いを戻せる。
- **ターン終了は、未行動の駒が残っていれば 2 回押す**。1 回目でボタンが「もう一度押して終了」になり、もう一度押すと終わる
  （残っていなければ 1 回で終わる。間にほかの操作をすると、確かめはやめる。右クリック・Esc でもやめる）。取り消せない操作の押し間違いを防ぐ。
  - **ボタンには短い言葉だけを書く。** 理由は、まだ行動していない駒の足元を光らせ、下の帯の案内に数を出して見せる（「未行動 3 体」）。
  - **確かめに変わった直後の短い間（`battle_ui_state.gd` の `CONFIRM_GUARD_MSEC`。いまは 0.4 秒）は、2 回目を受けない。** ダブルクリックや Enter の連打で、確かめを飛ばさないため。必殺技の確かめも同じ。

### 駒を見る（閲覧）

**見ること（情報を出す、範囲を塗る）は、選ぶこと（行動させる駒を決める）と別の状態**（`battle_ui_state.gd` の `inspected_id` と `selected_id`）。
自分の駒を動かしている途中でも、相手の脅威範囲を確かめてから、続きを選べる。

- **行動させられない駒**（相手の駒、中立の駒、行動を終えた自分の駒、動いたあとの自分のほかの駒）を**クリックすると、その駒を見る**。
  いつでもよい: 何も選んでいないとき、選んだあと、動いたあと、メニューの「攻撃」「回復」・スキルの対象を選ぶ途中。
  ただし、攻撃・回復・スキルの対象（赤・緑・紫のマス）の駒は、クリックすると行動になる（下の「敵の攻撃範囲」で範囲を見る）。
- 見ている間: その駒の動ける範囲を白で、相手の駒（中立も）なら脅威範囲（`docs/threat-range.md`。`Threat.of()`）を薄い赤で塗る。
  選んでいる駒の届くマスは塗らない（見終わると戻る）。見ている駒の足元に白い輪、選んでいる駒には黄の輪が付いたまま。
  左下の枠に、見ている駒の情報が出る。下の帯の案内は、塗った色の印（移動・攻撃）と「右クリック 戻る」。駒のそばのメニューは出たまま。
- 見ている間のクリックは**見るだけ**（移動や攻撃はしない）: ほかの駒なら見る駒を替える。駒のいないマス・見ている駒・選んでいる駒なら、
  見るのをやめる。右クリックでもやめる。メニューの項目を押すと、見るのをやめて、その項目を行う。
  **やめると、元の行動の途中へそのまま戻る**（選んだ駒、動いたあとの状態、対象を選ぶ途中は残る）。何も選んでいなければ、何も選ばない状態に戻る。
- 行動すると、見るのをやめる（盤が変わるので）。
- マウスを乗せれば、いつでも（行動の途中も、CPU の番も）その駒の情報が左下に出る（範囲は塗らない。盤の上を動かすたびに大きな範囲が
  出入りしないように）。
- CPU の番の間は、クリックで見られない（操作を受け付けない）。

### 敵の攻撃範囲（全員の脅威範囲）

- 下の帯のスイッチ「敵の攻撃範囲」（キーボードでは T）で、盤を見ている人のプレイヤーの敵（相手のプレイヤーと中立の駒）の全員の脅威範囲
  （`Threat.against()`）を、**赤い斜線と、範囲の縁の赤い線**で重ねて出す・消す。盤を見ている人は、CPU と対戦するときはいつも人のプレイヤー、
  人どうしではいまの番のプレイヤー（必殺技のボタンと同じ）。
- 出したままにできる。塗りではなく斜線なので、下の移動（青）・巡航（黄）・攻撃（赤）の塗りがそのまま見え、
  「動けるが、次の番に攻撃が届く」マスが一目で分かる。行動のたびに作り直す（再生の間は消す）。
- 斜線と縁の線、見ている相手の駒の赤い塗りは、どれも薄めにしてある（下の地面・駒・ほかの塗りが読めるように。
  `board_view/board_base.gd` の `COLOR_DANGER_*`、`battle_screen/screen_base.gd` の `COLOR_THREAT`）。草原・石畳・結晶の森のどれでも読めることを、
  スクリーンショットの場面 `threat_mix_*` で見る。
- 選択・見ること・対象を選ぶ途中には関わらない（切り替えても、行動の途中はそのまま）。
- **情報の枠の「詳細」で、駒のステータスの窓を開ける**（`docs/deck-screen.md` の「駒の詳細」。いまの HP・経験値・状態・スキルの残り）。クリックして見ている駒か、選んでいる駒がいるときだけ出る。開いている間は時間を止める。
- **相手の駒 1 体ずつの範囲を、表示したままにできる（ピン留め）。** 相手の駒（中立も）をクリックして見ると、左下の情報の枠の
  いちばん下にスイッチ「範囲を表示したまま」が出る。入れると、その駒の脅威範囲（`Threat.of()`）を、薄い橙の塗りと橙の縁の線で出し続ける
  （見るのをやめても、行動や番が変わっても残る）。何体でも留められる（重なったところは塗りが濃くなる）。
  - **相手の駒（将・中立も）をダブルクリックしても留める**（スイッチと同じ。見たまま）。もう一度ダブルクリックで外す（`screen_input.gd` の `double_click_cell`）。
    兵を選んでいる・対象を選んでいる・確かめている途中は効かず、ふつうのクリック 2 回として扱う（攻撃や移動の対象を取り違えない）。自分の兵では留めない。
  - 外すのは、その駒をもう一度見てスイッチを切るか、ダブルクリックか、右クリック（Esc）。右クリックは、ほかに戻すもの（確かめ・閲覧・対象を選ぶ途中・
    移動の取り消し・選択）が無いときに、留めた範囲を全部外す。
  - 留めた駒が動けば、範囲も付いていく（行動のたびに作り直す。再生の間は消す）。倒れたら外れる。新しい対戦には持ち越さない。
  - 全体のスイッチ「敵の攻撃範囲」（赤い斜線）とは別の層・別の色なので、両方を出してもよい。盤を見ている人のプレイヤーの駒には出さない。
  - 留めた範囲があれば、何も選んでいないときの下の帯の案内に、橙の枠の印「表示中」と「右クリック 解除」を出す。
- マスの説明は、クリックで左下の枠に、マウスを乗せると下の帯に出る（選んでいる駒がいても地形が読める。長い説明は 2 行に折り返す。下の「大きさを変えない枠」）。
  ポータルのマスは、行き先の座標と、止まるとメニューの「転移」で対のポータルへ移れること（移動力は使わず、残りで続けて動ける）を書く。
  行き先に駒がいれば、いまは使えないことも書く。
- 駒は、形（手に持つ物。下の「仮のもの」）と陣営の色（足元の円盤と服の差し色）で見分ける。頭の上には、軍略の札のほかは何も出さない。
- スキルは、メニューに名前をそのまま出す（1 手少なく、何のスキルかが分かる。説明は、マウスを乗せると出る）。

### クリックとドラッグ

- 左ボタンは、**離したとき**に働く。押してから離すまでにマウスが少し（`battle_ui_state.gd` の `DRAG_THRESHOLD`）より動かなければクリック、動けばドラッグ。
- **駒のいないところで押してドラッグすると、視点が動く**。横の動きで向きが回り（左右に好きなだけ）、縦の動きで見下ろす角度が変わる。
  斜めに動かせば両方が同時に変わる。ドラッグのあとは、クリックにならない。
  - 向きは、盤を掴んで動かす感じに合わせる。右へ動かすと盤が右へ回り、**下へ動かすと真上からの見下ろしに近づき、上へ動かすと浅くなる**
    （盤の奥を手前へ引き倒す感じ。「上へ動かすと上を見る」感覚とも同じ向きになる）。
  - 見下ろす角度は、盤の外が見えすぎない浅さから、ほぼ真上までに収める（`orbit_camera.gd` の `MIN_PITCH` と `MAX_PITCH`）。
  - 感度（1 px あたりの回る量）は横と縦で同じ値で、`orbit_camera.gd` の `drag_sensitivity` の 1 か所にある（オプションの「マウスの感度」（`docs/system-menu.md`）を、ここに掛ける）。
  - R のキーは、いまの角度より深い次の段（`orbit_camera.gd` の `PITCH_PRESETS`）へ滑らかに移す。ドラッグで段の間にしていても、そこから次へ進む。
  - ドラッグは視点の向きと角度だけを変え、カメラの追従（相手の番や再生の途中）は止めない。どちらも行き先へ滑らかに寄るので、重なっても跳ねない。
- 駒のいるマスで押したときは、動かしてもクリックとして扱う（駒を選ぼうとして手がぶれても、選べる）。
- ドラッグの途中で、帯やメニューの上でボタンを離したら、そこで視点を動かすのをやめる（ボタンを押していない動きでは回さない）。
- **駒のいないマスのクリック**は、選択をやめて、そのマスの情報（地形、本陣、盤の上の効果、環境オブジェクト）を左下の枠に出す。
  マスには白い枠が付く。選んでいる駒の届くマス（青・黄）は移動になるので、情報を見るなら先に選択をやめる。
- 視点の平行移動はマウスに割り当てていない（WASD と矢印）。ホイールは拡大・縮小。右上に 1 行だけ、視点の動かし方をキーの印と一語で出している。
  - 引ける上限は盤の大きさに合わせる（`orbit_camera.gd` の `max_distance_for`。値は `MAX_DISTANCE`、`REFERENCE_SIDE`、`MIN_MAX_DISTANCE`）。
    長い辺が 30 マスの盤でいちばん引け、小さい盤ほど長い辺に比べて縮める（17 × 22 の盤では 3 / 4 ほど）。ただし小さな盤でも、始めの距離より少し引けるところまでは残す。
    大きい盤でも、30 マスの盤より引けはしない。

### 駒のそばのメニュー

- 自分の番に、行動できる自分の駒を選ぶと出る。動いたあと（攻撃・待機・取り消しを選ぶところ）も出たままになる。
  相手の駒、行動済みの駒、CPU の番、進化先を選ぶ途中、再生の途中には出ない。
- 並び: 転移（ポータルの上で、転移できるとき。下の「環境オブジェクトの操作」）、攻撃（攻撃できる相手・樽・盾があるとき）、回復（回復できる味方がいるとき）、スキル（スキルの名前。持っている駒だけ）、
  待機、移動を取り消す（動いたあとで、取り消せるとき）。対象を選んでいる途中は「キャンセル」だけになる。
- **置き場所**（`menu_placement.gd`。画面の座標だけの計算で、テストがある）: 駒が画面に占める四角を投影で出し、その周りの候補
  （右・左・下・上と、辺に沿ってずらしたもの、斜め。それぞれ近くと 1 つ離れたところ）を、画面の中（上の帯と下の帯を除いたところ）へ
  収めてから比べる。隠してしまうものの重みの合計がいちばん小さい候補を選ぶ。重みは重い順に、攻撃・回復・スキルの相手のマス、情報の枠、
  ほかの駒、届くマス、巡航でだけ届くマス（`panel_layout.gd` の `MENU_WEIGHT_*`）。駒そのものには重ねない。同点なら右、左、下、上の順。
- **動く前は、届くマスをなるべく隠さない。** 周りが届くマスで埋まるので、向きごとに駒から 1 つずつ離した候補（`menu_placement.gd` の `REGION_MAX_STEPS` まで）も比べ、
  届くマスを隠すより得なら、範囲の外まで離す（離れるほど重い。`REGION_STEP_COST`）。駒から離れたときは、駒まで細い線を引く（駒が下の帯の後ろにいれば、線は帯の上の縁で止める）。
  動いたあとは届くマスが無いので、駒の隣に出る（転移して続けて動けるときは、動く前と同じに比べる）。
- それでも届くマス（青・黄）に掛かるとき（範囲が画面いっぱい、など）は、マウスが乗っていない間、メニューを薄く描く（下のマスが読める）。
  マウスを乗せると、ふつうの濃さに戻る。
- カメラが動いたら置き直すので、回しても動かしても付いてくる。ちらつかないよう、前に選んだ側を少しひいきする。
  駒が画面の外へ出ても、メニューは画面の端に残る。

## ルールとのつなぎ方

- 画面はルールを持たない。操作を行動（`BattleAction`）にして `Battle.apply()` に渡し、
  返ってきた `ActionResult.events` を順に再生する（`battle_screen/screen_sides.gd` の `_do` → `_do_all` と、`battle_playback.gd` の `play_all`）。
- 再生している間は、操作を受け付けない。再生が終わったら、対戦の状態と選んでいる駒から、
  塗るマス・ボタン・文字を作り直す（`_refresh`）。帯・メニュー・マスの説明などの文は、ノードに依存しない `battle_texts.gd` が作る（テストは `tests/game/test_battle_texts.gd`）。
- 選べること（動けるマス、攻撃できる相手、攻撃できる樽、回復できる味方、スキルの対象のマス）は、ルールの問い合わせ `Battle.options()`（`docs/battle.md`）に聞き、
  `battle_queries.gd` が画面の使いやすい形にする。どれも `Battle.can_apply()` が受け付けるものと一致する（テストで固定している）。
- 見込み（攻撃、樽・盾への攻撃、回復、スキル）は、どれも戦闘予測 `Forecast.of()`（`docs/battle-forecast.md`。実際と同じ処理を
  複製の上で走らせる）から出し、`forecast_text.gd` が同じ読み方で、駒ごとの行と駒に属さない行にまとめる（`summarize`）。
  画面は計算を持たず、それを予測のパネル（下の「戦闘予測のパネル」）に並べるだけ。樽の爆発が届くマスは `MapObject.blast_cells` で塗る。
- 相手の駒（中立の駒も）を見ると、脅威範囲（`docs/threat-range.md`。`Threat.of()`）を薄い赤で塗る。
  敵の全員の脅威範囲（`Threat.against()`）は、スイッチで斜線を重ねる（上の「敵の攻撃範囲」）。
- イベントの種類と再生するメソッドの対応は `battle_playback/playback_base.gd` の `event_players()` に並べる。
  `rules/events/` にあるのに載っていない種類があると、テスト（`tests/game/test_event_playback.gd`）が落ちる。

| イベント | 再生 |

### 再生の盤（出来事だけで再生する）

再生（`battle_playback.gd`）は対戦（`Battle`）を読まない。読むのは、**始めの盤の写しと出来事の列**だけ。
写しは**再生の盤**（`game/replay_board.gd`）で、出来事を 1 つ再生するたびに（見せる前に）食わせて、再生が見せている盤のいまを持つ。

- 持つもの: 駒（陣営・種類・マス・HP・最大 HP・レベル・進化・行動済み・付いている状態の種類）、樽、盤の上の効果、本陣の占拠と拠点の確保の数、聖遺物、ターンと番、決着。
  盤の形（本陣・拠点・ポータル・中ボスの場所）は写しの盤から読む。目に見えない数（経験値、クールダウン、状態と効果の残りのターン数、必殺技のゲージ）は持たない。
- 再生がここから読むもの: 駒の陣営（中立の駒の歩く速さ、カメラが追うか）、種類（倒れた駒の当たり方）、中立の番に駒がいるか、
  番の始めに明るく戻す駒、ポータルの色、中ボスの場所、本陣と拠点のマス、もう一方の陣営の確保の数、上の帯に渡すターンと番、
  再生の終わりの状態の輪（足元の水色の輪）。
- 対戦の場面は、行動をルールに渡す前に、対戦から写し直す（`BattlePlayback.take`。`screen_sides.gd` の `_do_all`）。
  検査が盤を直に書き換えても、ずれを次の行動へ持ち越さない。リプレイとカットシーンは、始めに 1 度だけ写し、あとは出来事だけで進める。
- 出来事を種類ごとに読むので、出来事を足したら、読むか読まないかを決める（`docs/battle.md` の「出来事を 1 つ足すとき」。`tests/game/test_event_readers.gd` が見張る）。
- テスト（`tests/game/test_replay_board.gd`）: 控えた CPU どうしの 1 局で、(1) 再生の盤が、どの行動のあとも実際の対局と同じ見え方になる、
  (2) 長い検査で、再生の場面に対戦を渡さず、始めの写しと全部の出来事だけを流すと、終わりの駒の見た目（位置・HP・最大 HP・行動済み・状態の輪）と決着が実際の対局と同じになる。

場面の側（再生の外）は、いまも対戦を読む: 上の帯の中身（駒の数・占拠・確保・聖遺物・必殺技のゲージ。`_refresh_status`）、
番の始めにカメラが寄る地点（`camera_point`。`phase_focus.gd`）、スキップしたあとの作り直し（`sync_views`）、再生のあとの作り直し（`_refresh`）。
どれも場面が渡す `Callable` なので、リプレイやカットシーンは、自分の物を渡せば対戦なしで回る（テストは、何もしない物を渡している）。

### リプレイとカットシーン（見立て）

どちらも、まだ作っていない。上の土台（再生の盤 + 出来事の列 → `play_all`）の上に、次のように作れる。

- **リプレイ**: 対戦の設定（マップと種・両方の部隊・選べる決まり）と、受け付けられた行動の列を残す。ルールは種で決まるので、
  見るときに見えない対戦へ行動を当て直して出来事を作り、始めの写しと一緒に再生へ流す（`tests/support/cpu_game.gd` と同じ形）。
  出来事そのものを残すなら、出来事を書き出し・読み戻す形が要る（いまは無い）。行動を残すほうが小さく、ルールが変わると再現できない（版を合わせる）。
- **盤の上で駒を台本どおりに動かすカットシーン**: 話のファイルに、マップ・置く駒・台本の行を書き、読む側が台本の行を出来事に直して流す。
  台本の行の例（書き方は仮）: `move 名前 3,4 5,4`（道順。間のマスは盤の問い合わせで埋める）→ `UnitMovedEvent`、
  `attack 名前 相手 12` → `AttackDamagedEvent`（残りの HP は読む側が数える）、`appear 種類 5,2` → `UnitSpawnedEvent`、`fall 名前` → `UnitDefeatedEvent`、
  `status 名前 バリア` → `StatusAppliedEvent`。台詞の行は出来事にせず、読む側が列を台詞のところで切って、再生 → 台詞 → 再生と交互に回す。
  置く駒から始めの盤を作るには、対戦を作らずに再生の盤を組む入口（駒の列から作る）を足す。
- **足りないもの**（カットシーンのため）: 盤の外へ歩いて去る（倒れずに消える。いまは倒れる動きしかない）、向きを変える・身振り（駒の見た目には `play_gesture` がある）、
  カメラの指示（いまは CPU と中立の駒だけを追う）、歩く速さの指定（巡航・中立のほかは決まった速さ）、湧くときの光を出さずに置く。
  どれも出来事の種類を足すことになるが、ルールが返す出来事ではないので、`rules/events/` でなく、再生の側の「台本の出来事」として足すのがよい
  （`event_players()` の表と、読む側の見張りの扱いを決める必要がある）。

### 攻撃の当たり方

攻撃が当たる形は、攻撃した駒の種類で変える（`battle_effects.gd` の `hit_style`）。何で殴られたかが、数を読まなくても分かるように。
どれも素材は使わず、光に左右されない色の形と動きだけで描く（後処理のグローや画面のシェーダーには頼らない）。

| 当たり方 | 駒 | 形 |
| --- | --- | --- |
| 叩く | 前衛（シールドトルーパー、パラディン）、将 | 相手の足元から、橙と白の衝撃の輪が地面を這って広がる |
| 斬る | 奇襲（コマンドー、スペルブレード） | 相手の体に、白い斜めの弧（青い縁）が走る。攻撃した駒が画面の右にいれば、向きを反転する |
| 撃つ | スナイパー | 撃った駒から相手へ、細い黄色の光の弾がまっすぐ速く飛んで当たり、火花が散る |
| 魔法 | ソーサラー、プリースト、中ボス | 光る紫の球が飛んで当たり、紫の光と輪が弾ける |
| そのほか | 衛生兵、エナジー・コア | 当たったところに、小さい光が弾ける |

- 当たる瞬間は、攻撃の動きが当たる瞬間と同じ（弾はそれに間に合うように撃ち出す）。**再生の待ち時間は変えない**（形は出したら待たずに消える）。
- 演出の起点は、種類ごとに `battle_effects.gd` の 1 つのメソッドにまとめてある（`strike`、`wait_sign`、`skill_flash`、`ult_burst`。
  画面のフラッシュは `battle_hud/hud_overlays.gd` の `flash_screen`）。効果音もそこで鳴らす（`docs/sound.md`）。

### スキルの形

スキルを使うと、通常の攻撃と見分けられるよう、使った駒の足元にスキルの色の輪が広がり、スキルの名前がその色で出る。
対象には、スキルごとの形が出る（`battle_effects.gd` の `skill_flash`）。形は手振りの終わり（0.4 秒）に対象へ届き、再生の待ち時間は変えない。

| スキル | 色 | 形 |
| --- | --- | --- |
| ファイアボール | 赤橙 | 炎の球が弧を描いて飛び、着いたところで大きく弾ける |
| 戦術バリケード | 砂色 | 置いたマスに、短い光の柱が立つ |
| スモークグレネード | 灰 | 黒い弾が弧を描いて飛び、着いたところに煙の塊が膨らむ |
| セイントプレイス | 金 | 置いたところに、太い光の柱と広がる輪 |

| シャドウステップ | 紫 | 使った駒の周りに紫の煙（続く転移の再生で、縮んで消える） |
| アドレナリン注射 | 黄緑 | 対象の足元から、光の粒が立ち昇る |

### フェーズの始めのカメラ

コード: `game/phase_focus.gd`。テスト: `tests/game/test_phase_focus.gd`。

- 寄るのは、その陣営が**前回のフェーズで最後に行動を確定した駒**（待機・攻撃・回復・スキル・動いたままのターン終了。`UnitActedEvent`）。
  前の自分の番の続きから見られる。
- その駒が倒れていたら、または対戦の始めでまだ誰も動いていなければ、その陣営の生きている駒のうち、味方の真ん中（位置の平均）にいちばん近い駒。
  **将かどうかには依らない**（将は本陣の近くにいて、前線が映らないことが多いため）。
- 対戦の画面は、行動のたびに起きたことを食わせ（`_do`）、新しい対戦で忘れる。CPU の番も同じ入口を通る。
## 画面に出るもの

- 上の帯: ターン、どちらの番か、
  勝ち方がいつもと違う戦い（ストーリーの守り切る・全滅させる）では、上の帯のすぐ下の左に**勝利条件の札**（勝ち方の印（`goal_mark.gd`。`WinText.goal_tag_marks`）と、枠で囲んだ金色の文字。`win_text.gd` の `goal_tag`。
  帯の中は陣営の欄で埋まっていて、入れると駒の数が省かれるため、帯の外に出す）。
  守り切るは「あと 8 ターン守り切れば勝ち」（攻める側なら「あと 8 ターンで決着しなければ負け」。いまのターンを含めて数える）で、
  最後のターンは「最後のターン: 守り切れば勝ち」にして札を赤く塗る。全滅させるは「勝利条件: 敵の全滅のみ」（「のみ」は将を倒しても終わらないこと。敵に将がいないか、将の撃破も勝ち方にあれば付けない）。中ボスの撃破も同じ形（「勝利条件: 峠の番人の撃破のみ」）。
  札にマウスを乗せると、勝ち方と負け方の文が出る。対戦モード（いつもの勝ち方）では札を出さない。
  拠点のある対戦（対戦モードの既定）では、勝ち方の札とは別に、同じ所（勝ち方の札が出ていれば、その下）に決まった大きさの拠点の札
  （拠点の確保の印と）「拠点　⚑　青 3 / 8　赤 0 / 8」を出す。数は陣営ごとの確保の数（陣営の色の数だけで。確保の数だけ印を並べることはしない）。
  「拠点」の右は、**拠点ごとの持ち主の旗**（`game/stronghold_flags.gd`。拠点 1 つにつき小さな旗 1 本。確保を進めている陣営の色、だれも進めていなければ白い縁だけ。`WinText.stronghold_owners`）。
  旗の欄は決まった幅（3 本ぶん。それより多ければ間を詰める）なので、拠点が 1 つでも 2〜3 つでも札は同じ大きさ。いまの決まりでは拠点は盤に 1 つなので、旗は 1 本
  （3 つのときの形は、スクリーンショットの場面 `stronghold_three` が手で作って見せる）。
  役割の分け方: 札は「陣営ごとに、あと何回で勝つか」と「どの拠点がだれのものか」、盤の上の竿（旗の色と高さ、竿の上の「N / 8」）は「その拠点で、いま何が起きているか」。どちらかがあと 1 回で勝つなら札を急ぎの色に塗り、数の字を白に寄せる（陣営の色のままだと赤い地に沈む。`STRONGHOLD_URGENT_LIGHTEN`）。
  マウスを乗せると決まりの文（`docs/map-objects.md` の「拠点」、`docs/win-conditions.md` の「拠点を確保し続ける」）。
  そのあとに陣営ごとの駒の数と本陣の占拠の数（●○○。本陣の占拠が勝ちの条件に無い陣営は出さない）、必殺技のゲージ（棒に重ねた %。いっぱいなら「READY」で、ゆっくり金色に明滅する。両方の陣営のぶんを、同じ大きさで出す）、
  相手が CPU か人かを書いたボタン（押すと切り替わる）、ログのボタン（`docs/battle-log.md`）、右端にシステムメニューのボタン（「メニュー」）。陣営の欄の右に、聖遺物のアイコンが 2 つ並ぶ（英知 = 菱形の宝石、勇気 = 剣。`relic_icon.gd`）。持っていない聖遺物は暗い輪郭だけで、
  手に入れると聖遺物の色で点く（点いた瞬間に少し弾む）。名前と効果は、アイコンか陣営の欄にマウスを乗せると出る。
  陣営の欄は残った幅を分け合い、足りなければ「…」で省く（帯が画面の幅を超えない。全文はツールチップに出る）。
  軍略のある対戦では、陣営の欄を 2 段にする: 上に兵の数と占拠、下に軍略の印と名前（`game/trait_tag.gd`。幅はいちばん長い名前で決まる。帯の高さは変えない）。札をクリックすると軍略の窓（`game/trait_card.gd`。`docs/troop-traits.md` の「対戦の画面」）。
- **駒の頭の上には、軍略が効く兵の札（増える数。`docs/troop-traits.md` の「対戦の画面」）のほかは、何も出さない。** 盤の上で分かることは、足元にまとめる: 行動済みの駒は暗い。HP が減っている駒は、足元に小さい棒が出る
  （満タンなら出ない）。足元の円盤には、内側に陣営の色の明るい縁、外側に暗い縁が付く（範囲の色の上でも暗い地面の上でも、円盤の形が切れて見える。どの組でも同じ）。
  進化した駒は、足元の円盤を金の輪が囲む。状態（バリア、照準、突撃など）が付いている駒は、その外に水色の細い輪が出る。
  名前・役割・HP の数・レベル・進化先・状態の中身は、左下の枠で確かめる。ダメージの数などの、浮かんで消える文字は出る（まだ浮かんでいる文字と画面の上で重なるときは、その下から出す。画面の中央の知らせの帯（必殺技など）が出ている間は、昇りきるまで帯にかからないよう、帯の上か下へ逃がす）。
- マスの色: 青 = 移動、黄 = 巡航でだけ届く、赤 = 攻撃できる相手・樽・盾、緑 = 回復できる味方、白 = 見ている駒の移動範囲、
  薄い赤 = 見ている相手の駒が次の番に攻撃・スキルを届かせうるマス（脅威範囲。その上に白の移動範囲を重ねる）、
  赤い斜線と縁の線 = 敵の全員の脅威範囲（スイッチで出しているときだけ。塗りの上に重ねる）、
  明るい白 = マウスの下のマスまでの道、橙 = マウスの下の樽の爆発が届くマス、
  紫 = スキルの対象に選べるマス（対象を選んでいる間だけ）、明るい紫 = マウスの下のマスに使ったときに効果が及ぶマス。
  駒のいるマスの赤・緑・紫は、駒の足元の円盤より上に塗る（円盤に隠れて見えなくならないように）。
- 左下の枠（駒の情報）: マウスの下の駒（いなければ見ている駒、選んでいる駒）の**ステータスの札**（`game/info_card.gd`）。
  部隊編成の右の札（`unit_summary.gd`）・「詳細」で開くステータスの窓（`unit_detail.gd`）と同じ部品で組む。**文の段落では並べない**（人間の「相変わらず文章すぎる」から）。
  1. 頭: 額（縁は陣営の色、役割の印）、役割の印と名前（陣営の色。進化した駒は「進化先（元の種類）」）、名前の右に行動の状態の札（「未行動」「行動済み」）。回復役は、その前に回復役の攻撃の強さの札（「攻撃 4」。`docs/healer-role.md`）。
     その下に札: 所属（対戦モードは盤を見ている人から見た「自軍」「敵軍」「中立」、ストーリーは「味方」「敵」）、役割、軍（魔物は「魔物」。
     ストーリーで解放したほかの軍の駒は「FANTASY 出身」を添える）、レベル（育つ駒だけ。「Lv 2」と、次のレベルまでの経験値の小さな棒。最大は「Lv 3 最大」）。
  2. 能力値の行（`stat_meter.gd` の詰めた行）: HP（いまの HP / 最大。棒）、攻撃か回復（棒）、移動・射程（粒）。持ち物・状態での増減は「▲ +2」と色で。
  3. **乗っている効果の札**（`game/effect_chips.gd`。決まった高さの 1 行。下の「兵に乗っている効果」）。入りきらなければ最後を「ほか N」にし、全部は「詳細」の窓で見る。
  4. スキルの札: 名前、使えるか（「使用可」「あと 2 ターン」「使用不可」。メニューのスキルの項目と同じに見る。`Skills.can_use`）、説明。持たない駒は、沈めた「スキルなし」。
  5. 持ち物の枠: 持っているものは印と名前（同じものは「×2」）、空きは小さな沈めた枠。持てない駒（将・中立）では出さない。
  6. いるマスの地形（平地でなければ。小さな 1 行）。
  7. メニューの項目にマウスを乗せている間・スキルの対象を選ぶ間は、いま要る説明（金の縁の札）。
  見込みは、この枠には出さない（予測のパネル）。駒が無ければ、クリックしたマスの札: 見出し（位置と地形）と、項目ごとの札（名前と、説明の行）。
- **兵に乗っている効果**（`game/unit_effects.gd`。Issue #46 の 11/26「バフ効果が兵の詳細情報に反映されてるのかわからない」から）:
  兵の情報の札と「詳細」の窓に、その兵にいま乗っている効果を「名前　数」の短い札で並べる（「集中砲火　被ダメージ +2」「隊列　被ダメージ -4」「胞子　ダメージ -4」「森　被ダメージ -20%」）。
  兵に良いものは緑、悪いものは赤、駒の特性（進化先と持ち物が与えたもの。名前だけ）は金。状態は残りのターン（「あと 2」）を添える。並びは、状態 → 軍略 → 縫い目 → 魔物 → 地形 → 聖遺物 → 特性。
  - 出どころ: 状態（バリア・照準・反動・突撃・奮起・絡み）、軍略（相手の集中砲火・仇討ち・誓いの印、自分の隊列・補給線・守護、誓いの相手）、
    縫い目の様子（天裂の名残り・天裂の光。深い茂みは森の札の名前と数になる）、胞子、森・回復の泉・拠点・砲台・煙幕・聖域、聖遺物。
  - 数はルールの問い合わせ（`Traits`、`Monsters.spore_penalty`、`Seam`、`MapObject`、`FieldEffects`）から読む。予測のパネルの内訳と同じ数になる（`tests/game/test_unit_effects.gd`）。
  - 能力値の行の数（と増減の矢印）に入っているのは、持ち物・状態・縫い目・砲台・聖遺物。ダメージの増減（軍略・森・胞子・バリア・煙幕）と、番の始めの回復（補給線・泉・聖域）は能力値に入らないので、札だけが知らせる。
  - 欄の大きさは中身で変えない（情報の札は 1 行、「詳細」の窓は 2 行。効果が無ければ空のまま）。持ち物そのものは持ち物の枠に出すので、効果の札には入れない。スキルのクールダウンはスキルの札に出す。
- 右上: 視点の動かし方（キーの印と一語の並び。「ドラッグ 回転　ホイール 拡大　WASD 移動」）と、その下にミニマップ（盤の縮図・駒の点・カメラが見ている範囲。押すとそこへ視点が移る。設定で隠せる。`docs/minimap.md`）。
- 下の帯: 案内（下の「下の帯の案内」）、マウスの下のマスの短い説明、敵の攻撃範囲のスイッチ、必殺技のボタン、おまかせのボタン、ターン終了のボタン。
  - **下の帯の案内**（`BattleTexts.guide`、`game/key_marks.gd`）は、文で操作を教えない（`docs/wording.md` の決まり 1）。出すのは、短い句と、キーの印・色の印に一語を添えた小さな並びだけ。
    - 何も出さない: 駒を選ぶ前、相手の番、決着、台詞の途中、進化先を選ぶ間、スキルを使ったあと、おまかせの間。
    - 駒を選んだ: 塗った色の印（移動・巡航・攻撃。回復役は回復も）。動いたあとは「右クリック 取り消し」。
    - 対象を選ぶ間（攻撃・回復・スキル）: 「対象を選択」と「右クリック キャンセル」。
    - 確かめ（必殺技・おまかせ）: 「右クリック キャンセル」。ターン終了の確かめは「未行動 N 体」を添える。
    - 駒を見ている: 色の印（移動。相手の駒なら攻撃も。留めた範囲があれば橙の枠の「表示中」）と「右クリック 戻る」。
    - 案内は、右のボタンが広がっても使える幅に収まる（`guide_overflows`。自動の対戦と `test_steady_frames.gd` が確かめる）。
  - メニューの項目にマウスを乗せたときの説明は、名前だけでは分からない項目（攻撃・回復・スキル・転移）にだけ出す。待機・移動を取り消す・キャンセルには出さない。
- **大きさを変えない枠**（`docs/ui-theme.md` の「枠の大きさ」。`tests/game/test_steady_frames.gd`）:
  - 下の帯の高さは `BattleHud.BOTTOM_BAR_HEIGHT` のまま。左の欄は、案内の行（出すものが無い場面も同じ高さ。`BattleHud.GUIDE_HEIGHT`）と、マスの説明（2 行まで）。
    マスの説明は、入らなければ字を小さくし（14 → 12 px）、それでも入らなければ「…」（マスを押すと、左下の枠で全部読める）。
  - 左下の枠は、駒でもマスでも同じ大きさ（幅 340、高さ `BattleHud.INFO_HEIGHT`）。「詳細」とピン留めのスイッチは、枠の下の端の 1 行（左にスイッチ、右に「詳細」）。
    札が入りきらなければ、後で読めるものから省く（いるマスの行 → スキルの説明 → 持ち物 → 状態・特性の札。`InfoCard.fit`。字は小さくしない）。
    スキルの名前と、いま要る説明は省かない。持ち物と状態 1 つを持った駒は、どの兵種も何も省かずに入る。何も見ていないときは、枠を出さない（盤を隠さない）。
  - 駒のそばのメニューは、幅を変えない（項目の幅 `BattleHud.MENU_ITEM_WIDTH`）。高さは項目の数。長い項目（スキルの名前と残りの回数）は、字を小さくして入れる（17 → 13 px まで）。
  相手の番の間は、必殺技とおまかせのかわりに、早送りとスキップ（下の「相手を CPU にする」）。
- 文字とボタンの見た目は、UI のテーマ（`ui_theme.gd`。色は `ui_palette.gd`）でそろえる。フォントは同梱したもの（`assets/fonts/`）。
- 文の折り返しは `text_wrap.gd`（テストがある）。Label の自動の折り返しは日本語の禁則も語の切れ目も見ないので、出す前に改行を入れる。
  会話の枠と会話のログも同じ（自動の折り返しは使わない）。辞書は使わず、字の種類の並びを手がかりにする:
  行の頭に句読点・閉じ括弧・長音・小さい仮名を置かない、行の末に開き括弧を置かない、半角の空白の前後では切らない（「スキル 7 回」を 1 つに保つ。ただし、ひらがなの後の空白で次が数でも英字でもない所と「→」の前は切れる。名前やマスを差し込むログの文「パラディンが (1, 2) → (5, 6) へ移動」のため）、
  カタカナどうしの間では切らない（「ダメー」と「ジ」に分けない）、
  語の途中（漢字どうし、漢字・カタカナの後のひらがな、ひらがなどうし）は、ほかに切れる所が無いときだけ切る（「表 / 示」「範囲 / を」「まずかっ / た」にしない。
  ひらがなどうしでも「を」の後と、助詞らしい字の後はまだ良い）、次の行がひらがな 1〜2 字と句読点だけで始まる所（「た。」）はいちばん後回し、
  切るなら全角の空白・句読点の後と開き括弧の前を優先し、次に語の切れ目（ひらがなの後に漢字・カタカナが来る所など）。
  段落の最後の行が短すぎる（幅の 2 割より短い）ときは、行の数を増やさずに行の長さをそろえる。
  送り仮名をはさむ、よく出る言葉（「縫い目」「縫い代」。`TextWrap.KEEP_WORDS`）は中で切らない（ひらがなの後の漢字を語の切れ目と見誤るため）。
  全部の話の台詞が、出る所の幅で語の途中を切らず、枠の行の数を超えないことは、`tests/game/test_wrap_audit.gd` が確かめる。
  札の文（物語の選択のカードの紹介、出撃準備の手ほどき、対戦ルールの札、縫い目の様子の札、兵の情報の札と詳しい窓のスキル・必殺技・状態）も、
  同じテストが、それぞれの札の幅・字の大きさ・行の数の上限で確かめる（`tools/wrap_audit_lib.gd` の `card_sites`。札を足したら、ここにも足す）。
  対戦ルールの札は欄が狭いので、説明が 2 行に収まらないか語の途中で切れるときは、字を小さくする（13 → 11 px まで。`RuleCard.fold_line`）。
  画面の文の表（`game/text/*.csv`）の長い文も、同じテストが決めた幅で確かめる。場所を見るときは、`godot --headless --path . -s res://tools/wrap_audit.gd`。
- **地面は、盤の外まで続く 1 枚の地形**（`board_view.gd`、`ground.gdshader`）。マスごとの板は並べない。地形の色（平地、森、岩場、結晶泉、本陣の陣営の色）は、
  ルールの盤面（`Board`）を読んで作った色の地図から取り、境目をノイズで揺らして、マスの形に切れないようにする。
- **マス目は、地面の上に重ねる線**（`grid.gdshader`）。地面の溝や板の縁ではない。ふだんはごく薄い。
  駒を選んでいる間と、マスを塗っている間（移動・攻撃・スキルの範囲、脅威範囲）は、盤の全体で濃くなる。マウスの下のマスの周り（4 マスほど）は、いつも濃い。
  塗ったマスどうしには細い隙間があり、線がそこに見える。
- **戦う範囲の境目**は、盤の縁の少し濃い線（いつも出ている）と、外の地面が少し暗いことで分かる。マス目の線は、盤の外には引かない。
- **マップの見た目**（`stage_look.gd`）: 見た目ごとに 1 つの定義（テーマ。鍵は見た目の名前）で、地面（色・石畳などの模様）、障害物と森のマスに置くもの、
  盤の外の景色、空と霞と光、泉の石と結晶泉の結晶の色を決める。マップ選択のカードとミニマップの色も、ここから取る。
  マップを足す・素材を替えるときは、定義を 1 つ書くだけでよい（どの定義も全部の項目を持つことと、素材の高さの書き間違いは、テストが確かめる）。
  見た目はマップの番号ではなく名前で引く。どの見た目で描くかは、対戦の画面に渡すものが決める（`docs/battle-source.md`）。
  見た目の名前（`GRASSLAND` 草原、`STONE_WALLS` 石の壁、`CRYSTAL_FOREST` 結晶の森）は、対戦モードのマップの名前とは別に付ける。
  対戦モードの生成のマップは、`OF_STAGE` で見た目の名前に直す。手で作ったマップは、マップのファイルの `look` に見た目の名前を書く（`docs/hand-map.md`。対戦モードでもストーリーでも、その景色になる）。
  ストーリーの話は、話の `look` で、その話だけ別の見た目にできる。
  以下は、いまある見た目（対戦モードの生成のマップに当てているものと、手で作ったマップのためのもの）。
  - 中央平原: 若草色の草原。障害物は灰色の岩山（下の「岩山」）、森は木立。盤の外は森と岩山。昼の白い光。
  - 迷宮回廊: 遺跡。乾いた石畳の地面に、障害物は石の柱と、続いた障害物をつなぐ石の壁（ときどき崩れている）。
    盤の外は崩れた石組み・柱・瓦礫と砂色の岩山。低めの金色の光と、砂ぼこりの霞。
  - 双子結晶: 結晶の森。苔むした暗い青緑の地面に、障害物は青い結晶がところどころに生えた暗い紫の岩山（下の「岩山」）、森は暗い針葉樹。
    盤の上の結晶は青（`StageLook.CRAG_CRYSTAL`）にして、ポータルの紫・中ボスの紫・結晶泉の水色と見分ける。
    盤の外には紫と水色の結晶が光る。夜明けの薄紫の霞と、低い桃色の光。
  - 結晶の採掘場（`QUARRY`）: 露天掘り。掘り返した茶色の土が段々に下がり（地面の模様 `STRATA`。等高線のような段の縁）、障害物は切り出した土色の岩山に、掘り残した青い結晶がのぞく。
    盤の外は、坑口・足場・木箱・石の山・手押し車・切り株を、まばらに（`SMALL_SHARE`）。高い日の白い光と、土ぼこりの霞。
    地面は、起爆樽の橙と脅威範囲の赤が沈まないよう、赤みを抑えた暗めの茶色にしてある。
  - 縫い目の谷（`SEAM`）: 糸を抜かれて、いちばん傷んだ所。少し暖かい灰色のひび割れた地面（地面の模様 `CRACKS`。宵の菫の光で、移動範囲の青と同じ色に沈まないように）に、障害物は結晶の抜けた暗い岩山、森は枯れかけた木立。
    盤の外は、両側から迫る暗い山並み（`BIG_SPREAD`。大きいものの尾根を太らせる）と、割れ残った結晶。宵の暗い菫の霞と冷たい光。
    プレイヤー2 の本陣の先の地面を、光る裂け目（縫い目。`SEAM_GLOW`。色はタイトルの裂けた空の裂け目と同じ）が横切る。盤の中には掛からない。
    地面を灰色にしたのは、ポータル（紫・橙・桃）と範囲の色を沈ませないため。空は、対戦のどの視点でも映らないので、裂け目は地面に描いた。
  - 古戦場（`BARROW`）: 両方の国の兵が、同じ土の下に眠る野。枯れ草まじりのくすんだ草地に、障害物は苔むした石の壁（迷宮回廊と同じ `WALL`。崩れた壁のほうが多い）。
    盤の外は、墓標の群れ（`grave_mesh.gd` がコードで作る。素材は使わない）、土に刺さった折れた剣と盾、崩れた家と石組み、木。
    曇り空の平たい光（日は弱く、まわりの光が強い）と、近くから掛かる灰緑の霞（`MIST`。盤の外は近くから霞むが、盤の中はほとんど霞まない）。
  - 大岩の峠（`PASS`）: 雪の残る高い峠。灰緑の高山の草地に残雪（地面の模様 `SNOW`。盤の外は濃く、盤の中は薄く。白い移動範囲とマスの色分けを沈ませないため）。
    障害物は雪をかぶった灰色の岩山（岩山の上を向いた面を白に）、森は暗い針葉樹。盤の外は、四方を囲む雪の峰（`BIG_SPREAD`）と、まばらな針葉樹、岩。
    澄んだ冷たい朝の低い光（長い影）と、淡い青の霞。
  - 尾根の小道（`RIDGE`）: 両軍が陣を張る、風の通る尾根。暗めの枯れ草色の草地に、障害物は灰色の石の壁（`WALL`）、森は濃い木立。
    盤の外は、天幕、木の柵、武器の架、的、木箱、まばらな木と岩、遠くの山。夕焼けの低い橙の光（長い影）と、桃色がかった霞。
    地面を暗めにしたのは、橙の光の下でも、巡航の黄と攻撃範囲の赤を沈ませないため。
  - リュエルの森（`DEEP_FOREST`）: 騎士領の、古い深い森。苔むした濃い緑の地面に、森のマスは枝を広げた大きな木立、障害物は苔の付いた岩（`CRAG`）。
    盤の外は、すぐそばから盤を囲む高い森（`SMALL_SPREAD`。小さいもののかたまりを太らせる）と、木の茂る山。
    木もれ日のまだら（地面を流れる影を濃くする。`CLOUD_SHADE`）、淡い金の光、緑がかった朝もや（`MIST`）。
    草原（中央平原）とは、地面の暗さ、木の大きさと密度、まだらの影で見分ける。
  - 練兵場（`DRILL_YARD`）: 連邦の演習場。踏み固めた土の地面に、障害物は積んだ木箱（演習の遮蔽物。マスごとに 1 つ置く `SINGLE`）、森は木立。
    盤の外は、兵舎、天幕、木の柵、的、武器の架、木箱。晴れた午前の明るい光と、淡い空色の霞。
    FANTASY の演習は、同じ盤を修練場の見た目で使う（話のファイルの `look`。導師の修練場で、連邦の演習場ではないため）。
  - 修練場（`TRIAL_COURT`）: リュエル騎士領の、導師の修練場。森に囲まれた、白い石の庭。灰緑の石畳に、障害物は白い石の壁、森は枝を広げた大きな木立。
    隣に障害物の無い 1 マスの障害物は、柱ではなく短い壁（両端に細い柱。置き方の `lone_wall`。話の台詞が「壁」と呼ぶため）。
    盤の外は、すぐそばまで迫る騎士領の高い森と木の茂る山、石の柱、的と武器の架、墓所の墓標（「修練場の裏の縫い代から、亡者が上がってきおった」）。
    晴れた午後の白い光と、淡い藤色の霞。練兵場とは、石畳と石の壁、まわりの森、霞の色で見分ける。
  - 結晶の祠（`SHRINE`）: 縫い目の土地の、古い祠の窪地。苔むした翡翠色の石畳に、障害物は青い結晶を抱いた石の柱（祠の柱）、森は暗い針葉樹。
    盤の外は、柱の列と崩れた石組み、光る水色と紫の結晶、針葉樹、遠くの峰。高い日の白い光が、近くから掛かる淡い翡翠の霞（`MIST`）に差す。
    結晶の森（双子結晶）とは、石畳と柱、霞の色（紫でなく翡翠）、昼の光で見分ける。
  - 結晶の岩山（`CRYSTAL_NIGHT`）: 月夜。結晶の森（双子結晶）と同じ土地の、夜の姿。暗い青緑の地面に、障害物は青い結晶の光る暗い菫の岩山、森は暗い針葉樹。
    盤の外は、黒い峰と、光る紫と水色の結晶（双子結晶より多い）。高い月の青白い光と、濃い藍の霞。結晶の光がにじむ（画面の効果）。
  - どのマップでも、障害物は背の高い硬いもの（岩山・石の壁）、森は木、平地は何も置かない。地面の色も 3 つではっきり変える（テストが確かめる）。
    本陣の陣営の色、マスの塗り分け、駒、HP の棒、起爆樽とポータルの色は、どのマップでも変えない（読み方を変えないため）。
- **障害物の置き方**は 3 つ（`stage_look.gd` の `SINGLE`・`WALL`・`CRAG`）。迷宮回廊の石の壁（`WALL`）と岩山（`CRAG`）は、どちらも隣の障害物とつながる。
  - **岩山**（`CRAG`。`crag_mesh.gd` がコードで形を作る。素材は使わない）: 辺で接する障害物のかたまりを、1 つの岩山にする。
    かたまりの内側ほど高く（大きなかたまりの真ん中は峰になる）、縁は低い崖で終わる。1 マスだけの障害物は、小さく尖った岩。
    崖の裾は、通れるマスとの境目に沿い、境目からはみ出さない（テストが確かめる）。通れないマスと通れるマスの境目は、どの向きから見ても崖の裾で分かる。
    斜めにだけ接するマスどうしはつなげない（その間の通れるマスをふさいで見せない）。縁は低く、峰は大きなかたまりの内側にしか立たないので、
    岩山の手前のマスと駒は、高い峰に隠れにくい（それでも隠れるときは、下の「透ける」が効く）。
    面ごとに平らな影と色のローポリの岩。結晶はかたまりの内側のところどころと峰の上に生やす（結晶の森だけ）。
    形はマスごとに分けて作り（マスごとに透かすため）、1 マスの形の中に岩と結晶をまとめて、1 マス 1 回で描く。
- **盤の外の景色**（`scenery.gd`）: マップの見た目が挙げる、大きいもの（岩山など）・小さいもの（木など）・散らばるもの（石など）を、種から決まる並びで置く。
  盤の上のものより目立たないよう、色を少し沈ませている（光る結晶は除く）。同じ素材はまとめて描く（MultiMesh）。置き方の決まりは次のとおり（テストが確かめる）。
  - 盤の端から 2 マスまでは、何も置かない（`scenery.gd` の `CLEAR`）。
  - 高さは、盤の端からの距離の半分まで（`HEIGHT_PER_DISTANCE`）。カメラはいちばん浅くても 30 度で見下ろすので、
    どの向き・どの距離から見ても、外のものが盤の中を隠さない。近くは低いものだけで、遠くほど大きいものになる。
  - 盤の端から 66 マスより先には置かない（`REACH`）。その先は霞んで見えない。
- **遠くは、空の色の霞に溶ける**（`stage_look.gd` の `FOG_BEGIN`、`FOG_END`）。背景も同じ色。地面の板は霞の先まで広げてあるので、端は見えない。
  霞は、いちばん引いて盤の端から端を見ても、盤の中にはほとんど掛からない距離から始まる。
- **空気**（`stage_look.gd` の `build_environment`・`apply`、`game/board_sky.gdshader`、`game/ground.gdshader`）:
  - **空**: カメラを囲む球の内側に、シェーダーで描く（絵は使わない）。地平は霞の色（見た目の `HAZE`）、高いほど空の色（`SKY`）。日のある側の地平が明るく、低い空に雲がたなびく。
    低く構えて引いたとき、地平の上に見える。
  - **地面**: 大きなむら、日なたの黄みと日かげの青みへの色の寄り、細かい斑、ゆっくり流れる雲の影（ごく薄い）。
    盤の外は少し暗く、色を抜き、境目のすぐ外に細い影を落とす（戦う範囲が、光の当たった舞台に見える）。マスの色分けと駒の色は変えない。
  - **画面の効果**（オプションの「画面の効果」。既定はオン。`StageLook.set_effects`）: 光るもの（結晶など、`GLOW_THRESHOLD` より明るいところ）だけの光のにじみ、
    物の合わせ目の陰（SSAO）、色の調子（コントラストと彩度を、ほんの少し）。切ると、どれも掛けない。地面や駒はにじませない。
  - 対戦の画面は、盤の四隅をごく薄く沈める（`UiTheme.vignette`。帯や枠の下）。
- **描画方式**（`game/render_tone.gd`。テストは `tests/game/test_render_tone.gd`）: Windows の exe は Forward+ で動く。見た目の基準は Forward+ で撮った絵（`docs/screenshots.md`）。
  光・色の調子・地面の模様・範囲の色の濃さの値は、互換の描画（OpenGL）で見て決めたので、Forward+ の側をその見え方に寄せる。互換の描画では何も変えない。
  - Forward+ は、同じ光でも地面が暗く、むらと石畳の目が薄く、暗い景色（結晶の森）ほど沈む → トーンマッピングを ACES にして露出を上げ（`FORWARD_EXPOSURE`）、
    環境光を強め（`FORWARD_AMBIENT`）、地面の模様を濃くする（`FORWARD_PATTERN_GAIN`。`ground.gdshader` の `pattern_gain`）。
  - 半透明の重ね塗り（範囲の色、マス目の線、脅威範囲の斜線）は、互換の描画が sRGB の値のまま混ぜ、Forward+ が光の量（線形）で混ぜるので、
    同じ不透明度でも Forward+ では白い塗りが濃く、暗い色の塗りが薄く出る → 地面の明るさ（マップの見た目の平地の色）と塗る色の明るさから、
    互換で混ぜたときと同じ明るさになる不透明度に直す（`overlay_alpha`。白はさらに `FORWARD_WHITE_SCALE` を、マス 1 枚ぶんの範囲の塗りはさらに `FORWARD_FILL_SCALE` を掛ける）。
  - タイトルの裂けた空（光を受けない空）は、露出を上げたぶん白く出るので、Forward+ では暗くする（`FORWARD_TITLE_SKY`）。
  - 残る差: Forward+ では、草原の緑と石畳の黄みが互換より少し淡く、結晶の光のにじみが少し強い。
- 本陣のマスには陣営の色の旗が立つ。
- 環境オブジェクト（`docs/map-objects.md`）。どれもコードで作った形で、素材は足していない（泉の石の色はマップの見た目が決める）。
  - 起爆樽: ふたと帯の赤い樽。
  - 回復の泉: 石の縁の青い水面。駒が乗っても分かるよう、マスの隅に緑の十字の札が立つ。水面に、白い波紋がゆっくり広がり続ける。
  - 砲台: 灰色の石の台に橙の縁。駒が乗っても分かるよう、マスの隅に砲身と橙の札が立つ（`_add_battery`）。
  - 拠点: 黒の縁取りに明るい黄の輪、三隅の短い杭と、奥の隅の高い旗竿（`_add_stronghold`）。どの景色の地面でも沈まないよう、光に左右されない色で描く。
    旗は白で、確保の多いほうの陣営の色に変わり、確保の数だけ竿を上る。竿の上に、いつも手前に描く小さな数の札（「3 / 8」。字の大きさ `STRONGHOLD_LABEL_FONT`）。隣の敵で止まっている間は、文字を足さず札の色を落とす（`STRONGHOLD_BLOCKED_ALPHA`。色と数で十分。人間の感想。Issue #46 の 11/23。`set_stronghold_progress`）。
  - ポータル: 色の輪と、両脇の柱。色は対ごとに違い、同じ色の 2 つがつながっている。光の粒が渦を巻いて昇り、面がゆっくり脈打つ。
  - 泉とポータルの動きは、止まった絵でなく動きでそれと分かるためのもの。駒や塗ったマスより目立たないよう、ゆっくり・小さくしてある
    （`board_view.gd` の `_animate`）。
- 盤の上の効果（`docs/field-effects.md`。`board_view/board_objects.gd` の `add_field_effect`）。煙幕と聖域の床は、駒の足元より低く描く。
  - 盾: 持ち主の色の堅い板（上に明るい縁）。上に、**残りの耐久の棒**をいつも出す（駒の HP の棒と同じ形を少し大きく。持ち主の色。`game/gauge_sprite.gd`、
    `BoardView.set_barricade_durability`）。削られたら、その場で棒が縮む。数は、盾のマスを押すと情報の枠に、マウスを乗せると下の帯に出る（「耐久 7」）。
    耐久のある物は、いまは盾だけ（起爆樽は 1 回の攻撃で爆発する）。
  - 煙幕: 灰色の薄い床と、駒を包む高さの淡い靄。
  - 聖域: 持ち主の色の、淡く光る床。
- 障害物（岩山・石の壁）と木立は、駒やマウスの下のマスの手前（カメラの側）にあると透ける（見下ろす角度が浅いほど、遠くまで透かす）。

## 戦闘予測のパネル

行動の対象にマウスを乗せている間、**何が起きるかを一目で分かる形で、対象のそばに出す**（`forecast_panel.gd`。中身は
`ForecastText.summarize`。`docs/battle-forecast.md` の `Forecast` をそのまま読む）。

- 出るとき: 選んでいる駒で、攻撃できる相手（赤）、狙える樽・盾、回復できる味方（緑）、スキルの対象のマス（紫）にマウスを乗せている間。
  自分に使うスキルは、対象を選び始めたら、マウスを乗せなくても出す。見ている間（閲覧）、CPU の番、再生の途中、メニューの上では出さない。
- 中身（上から）: 見出し（何をするか。「攻撃」「回復」「樽を撃つ（爆発 N ダメージ）」「盾を攻撃」、スキルの名前）→
  目立つ知らせ（**「倒せる！」「N 体を倒せる！」**（赤）、**「自分も巻き込まれる！」**（橙））→ 何かが起きる駒ごとに、
  名前（陣営の色。行動する駒は「自分（〜）」）、HP の行（情報の枠の HP の行と同じ部品 `stat_meter.gd`。あとの HP の数、増減「▼ -N」「▲ +N」「±0」、
  枠の長さが最大 HP の棒に、減るぶんを赤・増えるぶんを緑で重ねる。倒れるなら数を赤で 0。文の段落にはしない）、内訳（クリティカル・森で軽減・爆発、バリアが防ぐ・煙幕に阻まれる）、
  （内訳・ほかに起きること・駒に属さないことは、情報の枠と同じ小さな札にして並べる。幅に入らない長い文だけ、折り返した行）
  ほかに起きること（状態が付く・解ける、移る先、もう一度行動できる、経験とレベルアップ・進化を選べる（進化先の名前））→
  駒に属さないこと（置かれる効果、盾の耐久、聖遺物と効果、必殺技のゲージの変わり方、決着）。
- 置き場所: 対象のマスのそば。駒のそばのメニューと同じ置き方（`menu_placement.gd`）で、行動する駒、何かが起きる駒と効果の及ぶマス、
  左下の枠を隠さない側を選び、画面（上下の帯の内側）に収める。**駒のそばのメニューには、決して重ねない**（メニューの出方はそのままで、
  パネルの側が逃げる）。対象の周りがどれもメニューに掛かるときは、メニューの上下左右に接するところへ置く。
  カメラが動いたとき、メニューが動いたとき（中身が変わった）に置き直す。マウスはパネルを素通しにする（下のマスを選べる）。
  カメラの向き・盤の位置・駒の位置を総当たりして、重ならず・はみ出さず・対象の駒を隠さないことをテストで固定している（`tests/game/test_forecast_placement.gd`）。
- 幅は決まっていて（`forecast_panel.gd` の `WIDTH`。中身が「何も起きない」だけでも同じ幅）、文は `text_wrap.gd` で折り返す。
  何かが起きる駒が多いとき（`COMPACT_FROM` 体から。樽の爆発は 8 体まで巻き込む）は、駒ごとに「名前: N ダメージ → 倒れる（爆発）」の
  1 行に詰め（HP の棒は描かない。倒れる駒は赤、自分は橙）、パネルが画面の高さを超えないようにする。

## 環境オブジェクトの操作

- 樽の攻撃: 駒を選ぶと、いまの位置から攻撃できる樽のマスが赤くなる。クリックで攻撃（`AttackBarrelAction`）。メニューの「攻撃」からでもよい。
  動く前でも、動いたあとでもよい。
- ポータル:
  - **動ける範囲（青・黄）は、転移の先まで広げない。** 範囲の中の、止まれば転移できるポータル（印）と、その対の出るポータルを、
    ポータルと同じ色で塗る（`battle_queries.gd` の `reachable_portals`）。出るポータルが範囲の外でも塗るので、どこへ出るかが分かる。
    ポータルの面に隠れないよう、面の上に塗る。止まっても転移できないポータル（行き先がふさがっている、敵の支配領域）は塗らない。
  - **ポータルのマスをクリックすると、そこに止まる。** 転移できるなら、駒のそばのメニューのいちばん上に「転移」が出て、
    出るポータルを同じ色で塗る（メニューのいちばん上に「転移」が出る）。
    「転移」を押すと、出るポータルへ移る（`WarpAction`。入ったポータルで縮んで消え、出たポータルに現れる）。
  - **転移のあと、移動力が残っていれば、そこから届くマスを青・黄で塗り直す。** クリックで続けて動く（下の帯の案内は、色の印「移動」「巡航」と「右クリック 取り消し」）。
    続けて動かずに、メニューから攻撃・待機・取り消しを選んでもよい。取り消すと、動く前のマスへ戻る。
    フェーズの始めからポータルの上にいる駒も、選ぶと「転移」が出る。
  - 「転移」が出ないのは、出るポータルに駒がいるとき、ポータルが敵の支配領域にあって止まったとき、転移したばかりのとき、スキルを使ったあと。
  - ログは「ポータル経由」の移動 1 行（歩く・転移・続きを歩くを、まとめて書く）。
- 回復の泉: 操作は無い。乗ったまま自分の番を迎えると回復する。
- 砲台: 操作は無い。後衛を乗せると、その駒の射程が伸びる（駒の情報の射程と、攻撃できる相手に出る）。マスの説明に「砲台」と効果が出る。
- 拠点: 操作は無い。将でない駒を乗せたまま番を終えると、確保が進む（隣に敵がいる間は止まる）。マスの説明に「拠点」と決まりが出る（下の帯の 1 行は短い説明）。

## 決着の画面

- 決着すると、決着の画面を盤面の上に重ねて、段階的に出す（`docs/result-screen.md`）。
  後ろの盤の駒やマスの情報（左下の枠、下の帯のマスの説明、予測のパネル）は、決着したら出さない（決着の画面のボタンに重なるため）。
- 画面は、行動のたびに起きたことを `BattleStats` に食わせる（`_do`）。CPU の行動も同じ入口を通る。

## 対戦設定

- 対戦の前の設定は、対戦設定の場面（`setup_screen.gd`。マップ選択のあと。`docs/scene-flow.md`）で選ぶ。対戦の途中でも、同じ画面（`match_setup_panel.gd`）を盤面の上に開ける（下）。
  選ぶもの: 相手（CPU / 人）、CPU と対戦するときの自分の手番（先手 / 後手 / ランダム。人どうしでは選ばない）、両方の軍（MILITARY / FANTASY）、
  両方のプレイヤーの部隊。
  既定は 相手 CPU、自分が先手、先手 MILITARY・後手 FANTASY。
- パネルの頭に、**対戦の組み合わせの帯**（`game/versus_banner.gd`）: 左に 1 人目、右に 2 人目の、国の紋・だれか（「あなた・先手（青）」など）・軍の名前。真ん中にマップの縮図（マップ選択のカードと同じ代表の形）。
  下の行で選び直すと、すぐ帯に出る。地は左右の端から真ん中へ消える陣営の色（手番がランダムの間は、色を付けない）。帯の大きさは選んだもので変わらない。
- 軍と部隊の 2 行は、プレイヤーごとに 1 つの板にまとめる（左の縁に陣営の色の線）。
- **マップは選ばない**（マップ選択の場面で選ぶ。`docs/map-select.md`）。パネルには選んだマップの名前を出すだけで、
  対戦設定の場面では「マップ選択へ戻る」（右クリック・Esc でも）でマップ選択の場面へ戻る（ほかの選択は残る）。
  対戦の途中で開いたパネルでは、閉じるボタンが「対戦へ戻る」なので、「マップ変更」でマップ選択の場面へ戻る（押すといまの対戦は終わる）。
  マップ選択へ行くボタンは、どちらでも 1 つだけ。
- 手番の「ランダム」は、対戦を作るたびに、種から先手か後手かを引く（`match_choice.gd` の `draw_side`。対戦の乱数とは別に引くので、盤や対戦の進みは変えない）。
  同じ種なら同じ手番なので、「同じマップで再戦」は同じ手番で始め直す。
  ランダムの間は、2 つの軍の行の見出しを「あなた」「CPU」にする（どちらが先手か決まっていないので、陣営の色を付けない）。
  ほかのときは「あなた・先手（青）」「CPU・後手（赤）」のように、誰が動かすかと手番を書く。人どうしなら「先手（青）」「後手（赤）」。
- 手番の行の右に、先手の必殺技のゲージの始まりを 2 行の小さな字で書く（「先手: 必殺技のゲージ / 75% から」。`docs/tactical-ult.md` の「ゲージ」）。
  数は `Ults.FIRST_PLAYER_START_GAUGE` から作り、0 なら出さない（いまは 0 なので出ない）。手番の選び方（ランダム・人どうし）に依らず同じ文。パネルの大きさは変えない。
- 手番の行の下に、**選べる決まり**の行（`docs/match-setup.md` の「選べる決まり」）が 1 つずつ: 「拠点」（既定は あり）と「縫い目の様子」（既定は なし。砲台はマップの物なので行が無い。軍略は部隊が持つので行が無い。`docs/troop-traits.md`。縫い目の様子は `docs/seam-signs.md` と下の「縫い目の様子」）。
  どちらも「あり」「なし」のボタンと、右に決まりのひとことの説明（決まった大きさの欄。1 行）。
  選んだものは、次に作る対戦から効く（対戦の途中で開いたパネルで替えても、いまの対戦は変わらない）。
- 部隊は、軍を選んだあと、既定の編成（CPU の行では「CPU の編成」。コスト上限どおり。`docs/match-setup.md`）・ランダム編成・その軍の取っておいた部隊から選ぶ（`docs/deck-screen.md` の「対戦設定で選ぶ」）。
  CPU の行も人の行も同じ欄で選ぶ。既定は、どちらも既定の編成。
- 「ランダム編成」は対戦を作るときに組むので、対戦設定の場面では「編成確認」を押せない（マウスを乗せると「対戦開始で決まる」）。
  対戦の途中で開いたパネルでは、いまの対戦で組んだ部隊を見せる。部隊の選び方は対戦の場面へ引き継がれ、「同じマップで再戦」は同じ部隊、
  「新しいマップ」と「新しい対戦」は新しい種で組み直す。
- 人の行の「**初期位置**」で、初期位置の窓を開く（`game/deploy_dialog.gd`。出撃準備の初期位置と同じ縮図と、その下の駒の欄。`docs/story.md` の「出撃準備」）。
  置けるマスは本陣の前の 2 行。生成のマップは対戦ごとに形が変わるので、代表の形（マップ選択のカードと同じ種）で見せ、本陣からのずれで覚える（入れないマスに当たった駒は、おまかせの位置へ）。
  決めた行のボタンは「初期位置 ✓」。何もしなければおまかせ。軍か部隊を替えると、おまかせに戻る。CPU の行には出さない（CPU はおまかせ）。人どうしなら両方の行に出る。
  ランダム編成の行は、部隊が決まっていないので押せない。手番がランダムで後手になったときは、盤の形に合わせて返して使う（点対称の盤なら上下と左右。`docs/player-loadout.md` の「相手の側へ返す」）。
- **部隊の中身はパネルに文で並べない。** 行ごとの「編成確認」で、駒ごとの札（名前、役割、コスト、能力値、持ち物）を並べた画面を開く（`game/deck_preview.gd`）。
  札を押すと、その駒の詳しい説明（`docs/deck-screen.md` の「駒の詳細」）。
  自分の部隊も CPU の部隊も同じ見え方。「閉じる」・右クリック・Esc で閉じる。
- パネルの大きさは、選んだもの（軍、部隊、相手）に依らず同じ（`PANEL_WIDTH`。部隊の名前は欄の幅で切る）。
- 人が動かす行には「部隊編成」がある（対戦設定の場面だけ。対戦の途中で開いたパネルには出さない）。
  部隊編成（対戦用）へ寄り道し、「対戦設定へ戻る」で戻る。寄り道で取っておいた部隊が、その行の部隊に選ばれて戻る（`docs/deck-screen.md`）。
- 「対戦開始」で、選んだもの（`match_choice.gd`）の写しを対戦の場面に渡し（`docs/battle-source.md`）、それが作る `MatchSetup` で、新しい盤面で始める。自分が後手なら、CPU の番から始まる。
- 対戦の途中は、システムメニューの「対戦設定へ」で、盤面の上に開ける（再生の途中と CPU の番の間に選んだら、それが終わってから開く）。
  開いている間は、盤面の操作を受け付けない。
- **開いただけでは、いまの対戦は変わらない。** 「対戦へ戻る」（右クリック・Esc でも）で、何も変えずに閉じて、元の対戦へそのまま戻る。
  新しい対戦になるのは「新しい対戦」を押したときだけ。決着していない対戦の途中なら、押すといまの対戦が終わることを画面に書く。
  - **決着していない対戦の途中では、押すといまの対戦が終わるボタン（「マップ変更」「新しい対戦」）を 2 回押させる**
    （ターン終了・必殺技の確かめと同じ形）。1 回目でボタンが「もう一度押して変更」「もう一度押して開始」（危ない操作の色）になり、理由（何が起きるか）は
    ボタンの下の文に出す。確かめに変わった直後の 0.4 秒（`battle_ui_state.gd` の `CONFIRM_GUARD_MSEC`）の 2 回目は受けない。
    ほかの選択を変える、もう一方のボタンを押す（そちらの確かめに変わる）、右クリック・Esc（パネルは閉じない）で、確かめはやめる。
    決着のあとと、対戦設定の場面では、1 回で進む。
  対戦設定の場面では、閉じるボタンは「マップ選択へ戻る」（右クリック・Esc でも）。
- F1〜F3 と決着の画面のやり直しは、いまの設定のまま、マップと盤面だけを変える。F1〜F3 と「新しいマップ」は生成のマップ（中央平原・迷宮回廊・双子結晶）だけ（`docs/map-select.md`）。
- 対戦設定のパネル、F1〜F3、決着の画面の「新しいマップ」「対戦設定へ」、相手の切り替えは、対戦の画面に渡したもの（`docs/battle-source.md`）が許すときだけ出す。
  対戦モード（`match_choice.gd`）は、どれも許す。

## 対戦ルール

対戦の始め（出撃のあと、最初の番の前。ストーリーは前の会話のあと）に、その対戦の**勝利条件**と**縫い目の様子**を出す。対戦モードでもストーリーでも出す（途中から見せる対戦では出さない）。
コード: `game/battle_hud/hud_overlays.gd`（`show_notice`）、`game/rule_card.gd`（札 1 枚）、`game/goal_mark.gd`（勝ち方の印。スクリプトで描く）、`game/battle_texts.gd`（`rule_cards`、勝利条件の札だけなら `goal_cards`）。
テスト: `tests/game/test_rule_hud.gd`。

- 見出しは「対戦ルール」。砲台・軍略・操作の説明は入れない（砲台はマスの説明と射程の表示で分かる。人間の感想。Issue #46 の 11/23）。
- **勝利条件**の段: 人が動かす側から見た、いま効いている勝ち方を 1 つずつ札にする（印・短い名前・1 行。並びは `WinText.ORDER`）。
  将の撃破 / 本陣の占拠 / 拠点の確保 / 守り切る / 全滅 / 中ボスの撃破のうち、話ごと・設定ごとに効いているものだけ（将の撃破の無い話でも成り立つ）。
  相手が守り切る戦い（攻める側）は「時間の限り」（守り切るの印。「10 ターン目の終わりまでに勝つ」）を足す。人どうしは先手から見る（対戦モードは両方とも同じ勝ち方）。
- **縫い目の様子**の段（あれば）: 様子ごとに同じ形の札（様子の印・名前・効果）。無ければ段ごと出さない。
- 札は決まった大きさ（`RuleCard.SIZE`）で、段の真ん中に寄せて並べる（少なくても間延びしない）。勝利条件は 1 段で 3 枚まで（`hud_base.gd` の `NOTICE_GOALS`。対戦モードは将・本陣・拠点の 3 つ、話は 2 つまでと「時間の限り」）。
  枠も決まった大きさ（`NOTICE_SIZE`。勝利条件の段と様子の段が入る高さ）で、札の塊は見出しと閉じるボタンの間の真ん中に置く。
- **同じ札を出撃準備でも使う**: 出撃準備の勝利条件の欄は、ここの勝利条件の札と同じ札（`RuleCard`。`BattleTexts.goal_cards`）を 1 列に並べる。
  勝ち方の印は、上の帯の勝利条件の札・拠点の札にも出す。同じものだと分かるように。
- 札は画面の真ん中に置く（ほかの物を避けない。出ている間は、ほかの物を出さないので）。
- 閉じるボタン、どこかのクリック、Enter・Space・Esc で閉じる（閉じるまで、Enter はターン終了にならず、盤のクリックは駒を選ばず、帯のボタンも押せない）。
- **閉じてから、対戦が始まる。** 始まりは 1 つずつ順に進め、前のものが閉じるまで次を出さない（`screen_start.gd` の `_open_battle`）:
  「対戦ルール」→ 番の知らせ（「ターン 1　◯◯の番」）→ 始めの台詞（話の `[cues]`。送られるまで待つ）→ CPU の番（人が後手なら）。
  札が出ている間は、盤の上で何も進まず、マウスの下のマスも追わない（予測やマスの説明を出さない）。曲は場面に入るときに替わる（話は前の会話から同じ曲）。
  自動の対戦・スクリーンショットの道具は、札を自分で閉じてから進める。

## 縫い目の様子

縫い目の様子（`docs/seam-signs.md`。マップに付く、気候のような効果）の付いた対戦。コード: `game/battle_hud/hud_top_bar.gd`（`show_signs`。上の帯の下の札の帯と、札の窓）、
`game/sign_card.gd`（札 1 枚）、`game/sign_mark.gd`（札の印。スクリプトで描く）。テスト: `tests/game/test_seam_view.gd`。

- **流れ**: 対戦設定の「対戦開始」のあと、そのまま対戦が始まる（部隊を選び直す窓は無い）。様子は、対戦の始めの知らせに勝ち方と同じときに出る。
  対戦モードは対戦設定の「縫い目の様子: ランダム / なし」（既定はランダム）、ストーリーは話のファイルの `signs` で決まる。
- **対戦中**: 上の帯のすぐ下の左（勝ち方の札・拠点の札の下）に、決まった大きさの札の帯（様子ごとに印と名前）。マウスを乗せると、その効果の文。
  **名前をクリックすると、札 1 枚の窓**（印・名前・効果。決まった大きさ。`sign_card.gd`）が札の帯の下に開く。もう一度クリックするか、窓をクリックするか、盤をクリックすると閉じる。
  対戦の始めの「対戦ルール」にも、様子ごとに札（上の「対戦ルール」）。
- **効いたところは盤の上で分かる**: 札はルールの計算に入っているので、移動範囲・攻撃の届く範囲・脅威範囲（天裂の名残り、天裂の光、縫い代の風の巡航）、予測のパネルのダメージ（深い茂み）、
  駒の情報の能力値（増減の矢印。天裂の名残り・天裂の光）、スキルの残りのターン（張りつめた糸）、ポータルの対の色（仮縫いのずれ）が、札を含めた値で出る。
  マスの説明の森は「受けるダメージ 0.6 倍」になる（深い茂み）。

## 相手を CPU にする

- 相手（自分でないほうのプレイヤー。始めはプレイヤー2）は、CPU か人かを選べる（対戦設定、上の帯のボタンか F4）。
  人にすると、2 人が 1 台で交代する形になる。
  対戦の途中でも切り替えられる。相手の番の途中で CPU にすれば、続きを CPU が引き取る。
  人に戻せば、CPU はいまの行動を最後に手を止める。
- CPU の番は、`CpuPlayer.next_action()`（`docs/cpu-ai.md`）が返す行動を、人の操作と同じ入口（`_do`）に 1 つずつ流す（`_run_cpu`）。
  画面はルールにも CPU の考えにも立ち入らない。再生も、人の行動と同じイベントの再生をそのまま使う。
- 何をしたか追えるように、駒が動き出す前にカメラをその駒へ寄せ（`CPU_FOCUS_TIME`）、1 体の行動が終わるたびに間を置く（`CPU_PAUSE`）。
  動かずに待機するだけの駒は、見せるものが無いので、カメラを寄せず、間も置かない。
- **歩いている間、カメラがその駒を追いかける**（`OrbitCamera.follow`）。長い距離を動いても、画面の外へ出ていかない。
  攻撃のときは、攻撃する駒と相手の間へカメラを寄せる（離れた相手を撃っても、どちらも見える）。
  自分で動かした駒は追わない（行き先を自分で選んでいるので）。WASD で視点を動かすと、追うのをやめる。
- CPU の番の間は、盤面の操作・待機・取り消し・ターン終了・やり直しを受け付けない（`is_busy()`）。
  選べるマスは塗らず、メニューも、CPU の駒の進化先の選択肢も出さない（CPU が自分で選ぶ）。ターン終了のボタンが「CPU の番」（ストーリーでは「敵の番」）になる。下の帯の案内は出さない。
  視点は、CPU の番の間も動かせる。
- CPU の軍と手番は、対戦設定で選ぶ。
- CPU の番の速さの既定は、オプションの「CPU の番の速さ」（`docs/system-menu.md`）。
- **相手の番の早送りとスキップ。** 相手が CPU のとき（ストーリーも）、自分の番を終えてから次の自分の番が来るまで（中立のフェーズと CPU の番）、
  下の帯の必殺技のボタンの場所に「早送り」「スキップ」が出る。
  - 早送り: 切り替え。入れると、オプションの速さにさらに 4 倍（`battle_screen/screen_base.gd` の `FAST_FORWARD_SCALE`）を掛ける。入れたままなら、次の相手の番も早送り。
    自分の番には効かない。
  - スキップ: 押すと、自分の番が来るまでの残りを見せずに進める（CPU は同じように考えて動く。カメラを寄せる間も置かない）。
    起きたことはログに残る（`battle_log`）。対戦の途中の台詞（`docs/story.md`）が出たら、スキップの途中でも、そこで止まって送られるのを待つ（検査とスクリーンショットでは、ログにだけ残す）。
    終わったら、駒・樽・盤の上の効果の見た目を、いまの盤から作り直し、番の知らせを出して、カメラを番の始めの位置へ寄せる。
    途中で決着したら、見た目を作り直してから、決着をふつうに見せる。
  - 見せずに済ませるのは `BattlePlayback.skipping`。再生の途中（中立のフェーズの場面の間、CPU の 1 体の行動の間）でも、次の区切りから効く。
- **自分の番のおまかせ。** 下の帯のターン終了の左に「おまかせ」。押すと「もう一度押して実行」に変わり（下の帯の案内は「右クリック キャンセル」）、
  もう一度押すと、このターンの残りの駒を CPU（相手の CPU と同じ考え。`CpuPlayer`）が動かして、ターンを終える。
  確かめに変わった直後の 2 回目は受けない（ターン終了と同じ）。右クリックか盤のクリックで、確かめをやめる。
  駒が行動の途中（動いたあと）・進化先を選ぶ途中は押せない。任せている間は、相手の番と同じに見るだけ（早送り・スキップも効く）。
  人どうしの対戦でも使える（任せた番が終われば、次の人の番で止まる）。
  **任せた側の駒の進化先は、人が選ぶ**（進化を教える話で、選ぶところを飛ばさないため）。進化先を選ぶ駒が出たら CPU は止まり、
  いつもの進化先の選択肢が出る。選ぶと、残りを CPU が続ける。スキップの途中なら、スキップを解いて進化する駒に寄る。
  相手が CPU の側の進化は、これまでどおり CPU が選ぶ。

## 中立のフェーズの再生

中立の駒は、ルールの上では 1 体ずつ「動く → 攻撃する」。そのまま順に 1 体ずつカメラで追うと、何も起きなかった駒のために
カメラが盤の端から端へ飛び続けて、目で追えない。そこで、起きたことを駒ごとの**場面**に分けて見せる
（`neutral_playback.gd`。イベントを読むだけで、ルールは持たない。テストがある）。

- **静かな場面**: 動いただけ、湧いただけ（`UnitMovedEvent`、`UnitWarpedEvent`、`UnitSpawnedEvent` だけ）。
  カメラを動かさず、続いている静かな場面を**まとめて同時に**流す（待ち時間は、いちばん長く歩く 1 体のぶんだけ）。
- **見せる場面**: 攻撃した、煙幕に阻まれた、倒した、など。**必ずカメラを寄せて、1 体ずつ**見せる:
  攻撃する駒へ寄せる（`NEUTRAL_FOCUS_TIME`）→ 歩く間は追いかける → 攻撃のときは相手との間へ寄せる → 間を置く（`NEUTRAL_PAUSE`）。
- 中立の駒は、プレイヤーの駒よりゆっくり歩く（1 マスの時間は `NEUTRAL_STEP_TIME`。プレイヤーの駒は `STEP_TIME`、巡航は `CRUISE_STEP_TIME`。どれも `battle_playback/playback_base.gd`）。
- 起きた順は変えない（静かな場面をまとめるのは、間に見せる場面をはさまずに続いているものだけ）。
- **盤に中立の駒がいない番は、飛ばす。** 番の知らせ（中央の帯）も、上の帯の「中立の番」も出さず、待ち時間も置かない
  （毎回、一瞬だけ中立の番が挟まるのは落ち着かない）。途中で中立の駒が現れるマップでは、現れた番から出す
  （`neutral_playback.gd` の `phase_has_neutrals`。その番の始めに再生の盤にいた中立の駒と、その番の中で湧いた駒を数える）。
  ルールの上のフェーズは同じに進む。ログ（何も起きなかった中立の番の見出しは、もともと残さない）とターンの数え方は変わらない。

## 回復の操作

- 回復役（衛生兵・プリースト）を選ぶと、いまの位置から回復できる味方（HP が減っていて、射程の中）のマスが緑になる。
  クリックで回復する（`HealAction`）。メニューの「回復」を押すと、回復できる味方だけが塗られる（押さなくても回復できる）。
  動く前でも、動いたあとでもよい。巡航のあとは回復できない。
- 回復役も、治す相手がいなくても敵を攻撃できる。攻撃できる敵のマスは、ほかの駒と同じに赤くなる。

## スキルの操作

どのスキルも同じ操作に乗る（`docs/active-skills.md`。スキルの対象は、いつもマスで指す）。

- 駒のそばのメニューに、選んでいる駒のスキルの名前の項目が出る。クールダウンの間は「スキル（あと N ターン）」、
  対象に選べるマスが無いときは「スキル（使用不可）」と出て、押せない。スキルの無い駒では、項目そのものが出ない。
- 押すと、**対象を選ぶ途中**になる。対象に選べるマス（`Battle.options()` の `skill_cells`）だけが紫になり、
  移動や攻撃のマスは塗らない。マウスを乗せると、効果が及ぶマス（`Skill.affected_cells`）が明るい紫になり、
  そのそばに予測のパネルが出る（左下には、使う駒とスキルの説明）。
- 紫のマスをクリックすると使う（`UseSkillAction`）。使うと行動を終える。動く前でも、動いたあとでもよい。
- **行動を終えないスキル**（シャドウステップ）は、使ったあとも同じ駒を選んだままになり、動いたあとと同じに、攻撃できる相手が赤くなる。
  続けて攻撃するか、待機する。メニューに「移動を取り消す」は出ず、戻す操作（右クリック）も何もしない。
  メニューのスキルの項目の説明に「続けて攻撃可。移動の取り消し不可」と出る。
- **回数に上限のあるスキル**（アドレナリン注射）は、項目に「あと N 回」、使い切ると「スキル（使用済み）」と出る（左下の駒の情報にも残りの回数）。
- やめるには、メニューの「キャンセル」を押すか、ほかのマスをクリックするか、右クリック。
  駒の選択と、動いたあとの状態はそのまま残る（もう一度戻す操作をすると、移動の取り消し・選択をやめる）。
- 自分に使うスキル（対象が自分のマスだけ）も、同じ操作。項目を押すと自分のマスが紫になり、
  マウスを乗せなくても、その駒のそばに予測のパネル（付く状態と期限）が出る。下の帯の案内は、ほかのスキルと同じ「対象を選択」。
  その駒（紫のマス）をクリックすると使う。項目を押しただけでは使わない（押し間違いで行動を終えないように）。
- 使ったときの形は、上の「スキルの形」。置かれた効果は、上の「画面に出るもの」の形で描く。

## 必殺技の操作

必殺技（`docs/tactical-ult.md`）は駒の行動ではないので、駒を選んでいなくても使える。対象は選ばない。

- 必殺技のボタン（下の帯の右、おまかせの左）には、必殺技の名前とゲージ（%。いっぱいなら「使用可」）が出る。いっぱいになるまで押せない。
  押せない間は、ボタンの中にも溜まり具合を出す: 左から溜まった所まで陣営の色を薄く敷き、下の辺に溝と陣営の色の棒（`BattleHud.set_ult_button` に % と陣営を渡す）。
  CPU と対戦するときは、いつも人のプレイヤーのもの（CPU の番と中立の番の間も、人のゲージを出して、押せない）。
  人どうしでは、いまの番のプレイヤーのもの（中立の番の間は、プレイヤー1 のもの）。
- スキルは「ボタン → マスを選ぶ」の 2 手で使う。必殺技は選ぶマスが無いので、**「ボタン → もう一度ボタン」の 2 手**にしてある
  （押し間違いで使わないように。使ったら取り消せない）。1 回目でボタンが「もう一度押して発動」になる（直後の短い間の 2 回目は受けない。ターン終了と同じ）。
  必殺技の説明は、ボタンにマウスを乗せている間と、使うかを確かめている間、ボタンの上に出る。
- やめるには、右クリックか、盤面のどこかをクリックする。どちらも、やめるだけ（クリックしたマスへの移動や攻撃はしない）。駒の選択と、動いたあとの状態はそのまま残る。
- 使っても、選んでいた駒はそのまま（総員突撃なら、伸びた移動力のマスがすぐに塗り直される）。駒が行動の途中でも使える。
- 発動すると、画面が必殺技の色に一瞬光り、中央に必殺技の名前が出る。効果の掛かった駒には、全員に同時に陣営の色の光の柱が立ち、
  「突撃」「スキル使用可」が一度に出る（駒ごとに順に出さない。7 体でも再生の長さは変わらない）。
- ゲージが READY の間、上の帯のゲージと、押せる必殺技のボタンが、ゆっくり金色に明滅する（実時間で測る。CPU の番の速さに依らない）。

## 進化先を選ぶ操作

- 駒が上限のレベルに届くと、画面の上寄りに 2 つの札が出る。札には、進化先の名前、能力値の増減、特性が書いてある
  （`BattleHud.evolution_text`。`docs/branch-evolution.md` の表から作る）。
- 札は `BUTTON_CARD`。左に進化後の姿の額（縁は陣営の色、役割の印）、右に名前（明朝）、能力値の増減（`stats_row.gd` の欄）、特性（金）。
  左上の隅に、選ぶキーの番号（1・2）。板は上の縁が太い金で、見出しは窓の見出しと飾りの線（`docs/ui-theme.md`）。
- 札を押すか、1・2 のキーで選ぶ（`EvolveAction`）。選ぶまで、ターン終了のボタンは押せず、メニューは出ず、ほかの操作は何も起こさない。
- 進化した駒は、足元に金の輪が付く（形は変えていない。進化先は、左下の駒の情報の名前に出る）。

## 仮のもの

- **カメラの向き**: 後手を選んでも、カメラはプレイヤー1 の側から見る向きで始まる（ドラッグで回せる）。
- **駒の見た目の組**: 駒の形と動きは、組（`game/unit_looks.gd` の `SETS`。組ごとの定義は `game/looks/`）で丸ごと替えられる
  （`stage_look.gd` のテーマと同じ考え）。組は、駒の種類ごとに形・持ち物・色の付け方・動き（立つ・走る・攻撃・被弾・倒れる・身ぶり）・大きさを決めて、
  駒の体（`unit_body.gd`）を作る。足元の円盤・HP の棒・進化と状態の輪・将の冠は、どの組でも `unit_view.gd` が同じに付ける（読み方を変えないため）。
  組は体を足元の円盤（`unit_view.gd` の `BASE_RADIUS`）に収め、体の高さを返す。アイコン（`unit_icons.gd`）・会話の姿（`talk_figure.gd`）・編成の札も、いまの組に従う。
  将の別の姿（`UnitLooks.KING_LOOKS`。話のファイルの `king_figure`）は、どの組も同じ名前で持つ。
  いまの組は `kaykit`（「人形」）の 1 つだけ。人間が実機で見比べて「いまのところ一番マシ」とし（11/22）、ほかの組（盤の駒・人物・ミニ・人形 2）は外した（11/25）。
  組が 1 つなので、オプションに「兵の見た目」の行は無い。前の版の設定に残った組の番号は読み捨てる（知らない組の名前も既定の組。`UnitLooks.use`）。
  組を足すときの手順と、入れる前に確かめることは `docs/look-set-intake.md`（組が 2 つ以上になったら、オプションの行を戻す）。
- **動きのつなぎ目で姿勢を飛ばさない**（`looks/model_body.gd` の `set_timing`）: 素材の動きは、立ち姿・走り・攻撃を短いつなぎ（`BLEND_TIME`）で替える。
  立ち姿と攻撃の姿勢が離れている形は、組の定義で間合いを合わせる（`"skip"`・`"hit"`・`"blend"`）。
  - KayKit の「狙い」「射撃」の動きは、頭の数コマが「下ろした武器を構えるまで」で、そのあとが本体。狙いを立ち姿にする形（骸骨弓兵）は、
    構えるまでを飛ばして本体だけを繰り返し、射撃も構えたままから撃つ（そのぶん早く当たる）。飛ばさないと、繰り返すたびに構え直して、姿勢が飛ぶ。
  - 武器を下ろした立ち姿から撃つ形（「人形」のスナイパー）と、身構えた立ち姿から振りかぶる形（骸骨の大型・鼓手）は、攻撃の出入りのつなぎを長くする。
  - 走り出しと止まりは、どの組も長めのつなぎ（`RUN_BLEND`。0.3 秒）で替える。走りは腕と脚を大きく振るので、立ち姿との間が離れている
    （「人形」で、いちばん離れた骨が 110〜140 度。短いつなぎだと、動き出しと止まりで姿勢が飛んで見えた）。
  - `tests/game/test_unit_motion.gd` が、全部の組の全部の兵種と人物で、立ち姿の繰り返しの継ぎ目と、攻撃の出入り・走り出し・止まりのつなぎの速さを確かめる
    （走りは、立ち姿・走りのどの時刻から切り替えても）。
- **歩く道は、止まらずにつなぐ**（`battle_playback/playback_units.gd` の `_play_moved`）: 道順の全部のマスを 1 つの Tween につなぎ、マスの境目で止めない
  （マスごとに Tween を作って終わりを待つと、境目ごとに 1 コマ止まって、歩きがカクついた）。曲がり角は、向きを短く回す（`TURN_TIME`。一瞬では替えない）。
  歩き出しの向きは、その場で替える。テスト: `tests/game/test_walk_playback.gd`。
- **兵の縁取り**（オプション「兵の縁取り」。既定は切り）: 駒の体の面を裏返した殻を少し太らせて暗い色で描き、縁を付ける（`game/piece_style.gd`。`unit_view.gd` が体を作るときに付ける）。
  地面・森・範囲の色の上で、駒の形が切れて見える。素材を替えずに効く手を 4 つ試した中で、盤の大きさでいちばん効いたもの（Issue #46）。
  トゥーンふうの 2 段の陰、厚い台座と足元の柔らかい影、彩度の上げは、盤の大きさでは差が小さかったので入れていない。
  縁の太さは、面の大きさの倍率で割って、どの組でも同じ見た目の太さにする（`OUTLINE_WIDTH`）。骨の中の大きさ（FBX の 100 倍など）は見ないので、組によって少し太さが違う。
- **中立の駒**の見た目は、宙に浮く結晶のコア（`looks/core_body.gd`。どの組でも同じ）。小さい駒は黄、中ボスは紫で大きく、足元から結晶が突き出している。縄張りは描かない。
- **骸骨でない魔物と骸骨旗手**は、どの組でも同じ形（`looks/monster_body.gd`。組の人の駒の背に合わせて縮める。`look_set.gd` の `monster_height`）:
  大蝙蝠 = Quaternius の Bat を宙に浮かせ、腹を陣営の色に。ほつれ = 同じ作者の Slime を糸の青白い色に塗り、目を陣営の色に。
  糸針 = コードで組む結晶の針の束（青白く光る。根元の輪が陣営の色。動きは代わりの動き）。骸骨旗手 = Quaternius の骸骨（`looks/quaternius_skeleton.gd`）に、陣営の色の旗と腰の布。
  糸蜘蛛 = CDmir の Alien Bug（CC0。`assets/cdmir/`）の胴を陣営の色に、脚に糸の色を掛けたもの。糸喰い = Quaternius の Dragon の腹を糸の色に、翼を陣営の色に。
  殻蟹 = Quaternius の Cute Animated Monsters の Crab の殻を陣営の色に。糸茸 = 同じパックの Mushroom の笠を陣営の色に（素材の動きは立つだけ。ほかは代わりの動き）。
  絵が 1 枚で面を分けられない素材（糸蜘蛛・殻蟹・糸茸）は、絵の決まった色合いの所だけを陣営の色に塗り替える（`looks/team_recolor.gdshader`。陰影は絵のまま）。
  糸茸は顔が笠の陰に入って沈むので、笠でない所を明るく掛け、自分でも少し光らせる（`monster_body.gd` の `"tint"` と `"glow"`）。
  結び目（倒れたほつれが残すもの）は、盤の上の効果として、床に置いた青白い糸の輪 2 つ（`board_view/board_objects.gd`）。
- **組 `kaykit`**（`looks/kaykit_look.gd`）: 素材のキャラクターは 4 体なので、種類は持ち物で分けている
  （将 = 大きい騎士 + 金の輪、前衛 = 騎士 + 盾、後衛 = 弩 / 杖、奇襲 = 短剣 / 斧、回復 = 本）。
  魔物（`docs/unit-roster.md` の「魔物」）は、骸骨（KayKit の Skeletons。`assets/kaykit/skeletons/`）。素材は武器を持たないので、別の素材の武器を手の骨に付ける（`hold`）。
  外套・フードを陣営の色に塗り替える。骸骨兵は剣、骸骨射手はクロスボウ、骸骨重兵は斧と大盾で、大きく描く。
  骸骨術師は骸骨の将と同じ素材（帽子と杖）を小さく、骸骨鼓手は骸骨兵の素材に杖と剣を持たせる。
  **名前のある人物**（`docs/story.md` の「名前のある人物の形」。`kaykit_look.gd` の `PERSONS`）は、人物像（「口調の見本」の「見た目」の行）に合わせて、
  同じ骨組みのキャラクターの部品を付け替える（`swap`。頭を替えると顔・髪・ひげが替わる）。ほかのキャラクターの小物を借り（`borrow`）、兜や帽子を脱がせ（`hide`）、
  髪と衣の色見本を塗り替え（`paint`）、大きさを変える。ドーソン = 禿げ頭にひげの頭の騎士、ノエ = 小さめの軽装、マルタ = 女の頭に白い衣と本、
  ピップ = 頭巾の軽装（`Rogue_Hooded`）、イェルダ = 金髪の女の頭の騎士（兜なし）、ウル = 白ひげの禿げ頭に衣と杖と本、ティオ = 小さめのとんがり帽子、
  セリス = 黒髪の軽装に両手剣、ヴァルト = 栗色の髪の女の頭の騎士にクロスボウ、教導隊員 = 暗い茶の髪の女の頭の騎士（兜とマントなし）。

## 検査

`godot --headless --fixed-fps 60 -- --autoplay` で、自動の対戦（`autoplay.gd`）が人と同じ入口
（マスを選ぶ・駒のそばのメニューの項目を押す・戻す・ターン終了・進化先を選ぶ）だけを使って対戦を最後まで進め、
続けて小さな盤面で決まった手順の場面を通す。

場面の一覧は `game/autoplay.gd` の `SCENES`（名前と説明）が正で、**この文書には場面ごとの箇条書きを書かない**
（場面を足す PR が毎回同じところに書き足して、衝突するため）。場面は次のようなまとまりで並ぶ。

- 盤と環境: 環境オブジェクト、盤の上の効果、中立の駒、成長と進化。
- 画面の表示: 予測のパネル、駒と脅威範囲の見方、ミニマップ。
- 操作: メニューの項目、スキル、必殺技、システムメニューとログ、設定と CPU の番。

長い検査（`-- --autoplay --full`）では、そのあと盤面を作り直して残りのマップも少し動かす（そのうち 1 戦は相手を CPU にして、プレイヤー1 だけを操作する）。
途中で画面と対戦の状態（駒の数・位置・HP、樽のマス、盤の上の効果）が食い違えば失敗。メニューが画面（上下の帯の内側）からはみ出しても失敗。
最後に `autoplay: OK` を出す。

- 場面は `autoplay.gd` の `SCENES` に名前で並んでいる。`-- --autoplay --only <名前,…>` で、選んだ場面だけを回せる（`GROUPS` のまとまりの名前も使える）。
  場面はどれも、自分で盤面を作って始める（前の場面の状態に頼らない）。足すときは、`SCENES` に名前と説明を足し、`_queue_<名前>_scene()` に手順を積む。
  手順は、確かめる画面ごとのファイル `game/autoplay/*_checks.gd`（盤の上のこと、駒のこと、対戦設定とシステムメニュー、CPU の番、タイトルと部隊編成、ストーリー）に置き、
  確かめる・操作する道具は `game/autoplay/autoplay_base.gd` に置く。ファイルは `autoplay_base.gd` から順に継いで積み重なり、`autoplay.gd`（場面の一覧と回す流れ）が最後。
- 自動の対戦の間は、盤の画面が本物のマウスの位置を見ない（マウスの下のマスは、検査が乗せたこと（`hover`）だけ）。窓ありで回しても、机の上のマウスで結果が変わらない。
- 場面の中で確かめたことが外れたら、その場面の残りを飛ばして次へ進み、最後に外れたことをまとめて出して失敗で終わる。
- イベントを再生する場面（まとまり `events`）を全部回したときは、どの種類のイベントも 1 回は再生したことを確かめる。
- `tools/check.sh` は、`events` と、操作の決まりの場面（まとまり `ui`）を別のプロセスで並べて回す（`--full` を付けると、`events` のほうが長い検査になる）。
