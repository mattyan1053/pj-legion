# 画面の大きさ

コード: `game/screen_size.gd`（論理の大きさの計算と、検査で大きさを決める入口）、`project.godot` の `display/window`。
テスト: `tests/game/test_screen_size.gd`。

## いまの仕様

- 画面の部品は、基準の大きさ 1280×720（`display/window/size/viewport_*`）の上に並べ、窓の大きさに合わせて拡大・縮小する（`display/window/stretch/mode` が `canvas_items`）。
  文字も絵も、窓の大きさで描き直すので、大きい窓でもぼやけない。
- 縦横比の扱いは `expand`（`display/window/stretch/aspect`）。部品を並べる大きさ（論理の大きさ）は、基準が窓に収まる倍率で窓を割ったもの（`ScreenSize.logical_size`）。
  - **16:9 の窓は、どの大きさでも 1280×720 を等倍に拡大・縮小した、同じ見た目**（1920×1080 は 1.5 倍、2560×1440 は 2 倍、960×540 は 0.75 倍）。
  - 16:9 より横長の窓は、論理の幅が広がる（3440×1440 なら 1720×720）。縦長の窓は、論理の高さが広がる（1280×800 なら 1280×800、1024×768 なら 1280×960）。
  - **論理の大きさは、いつも 1280×720 以上。** 1280×720 に収まるように作った部品は、どの窓でも収まる。
  - 黒い帯は出さない。盤（3D）は窓いっぱいに描く（カメラは縦の画角を保つので、横長の窓では左右が広く見える）。
- 部品の置き方（どれも論理の大きさに合わせて動く）:
  - 対戦の画面: 上と下の帯は端から端まで。勝ち方の札は左上、視点の案内・ミニマップは右上、駒の情報の枠は左下、必殺技・おまかせ・ターン終了（相手の番は早送り・スキップ）は右下（隅に寄せる）。
    駒のそばのメニューと戦闘予測のパネルは、帯の内側（`BattleHud.menu_area`）に置く。会話の札は、上の真ん中。
  - タイトル、マップ選択、対戦設定、システムメニュー、オプション、決着の画面、物語選択、話の一覧、会話: 真ん中にまとめる。
  - 部隊編成は、幅を 1560（`deck_screen.gd` の `MAX_WIDTH`）より広げず、真ん中に置く。出撃準備は、1560×820（`sortie_screen.gd` の `MAX_SIZE`）より広げない。
    横長・縦長の窓で、中身の無い枠が伸びるだけになるのを防ぐ（`ScreenSize.cap`）。
  - ログは右の端に、上から下まで。

## 窓と全画面

コード: `game/window_mode.gd`（アプリ `game/app.gd` が 1 つ持つ）。テスト: `tests/game/test_window_mode.gd`。

- 初めは 1280×720 の窓で開く。窓の端をドラッグして、大きさを自由に変えられる（`display/window/size/resizable` は既定のオン）。
- 窓は 960×540 より小さくできない（`window_mode.gd` の `MIN_WINDOW_SIZE`）。これより小さいと、文字が読めないほど小さくなる。
- オプションの「全画面」（区分「画面」。`docs/system-menu.md`）で、全画面（`Window.MODE_FULLSCREEN`。枠の無い全画面）と窓を切り替える。次に起動しても残る。
- **Alt+Enter** でも切り替えられる。どの場面でも、システムメニューを開いていても効く（場面より先に受ける）。切り替えたら、すぐに設定を取っておく。
- 検査とスクリーンショットの道具は、窓に触らない（決めた大きさで回すため）。

## 大きさを変えて確かめる

- スクリーンショット: `tools/screenshots.sh godot <出力> <場面> --size=<幅>x<高さ>`（`docs/screenshots.md`）。
- 自動の対戦: `godot --headless --path . -- --autoplay --size <幅>x<高さ>`。
  画面の無い検査では窓が開かないので、その大きさの窓のときの論理の大きさ（`ScreenSize.logical_size`）を直に決めて回す。
  `--size` が無ければ 1280×720。
- 検査（`tools/check.sh`）: 操作の決まりの場面の自動の対戦（重ならない・はみ出さない）を、1280×720 と 3440×1440（論理 1720×720）の 2 つで回す。
  置き場所の計算のテスト（`tests/game/test_forecast_placement.gd`、`tests/game/test_minimap_geometry.gd`）は、1280×720 に加えて 21:9・32:9・16:10・4:3 の窓の論理の大きさでも回す（総当たりの全部は長い検査）。

## Windows の表示倍率

- `display/window/dpi/allow_hidpi` は既定のオン（画素をぼかさずに描く）。表示倍率に合わせて窓を大きく開く設定は入れていない。
  高解像度の画面で窓が小さく見えるときも、窓を広げるか全画面にすれば、窓の大きさに合わせて部品と文字が大きくなる（上の拡大）。
- 表示倍率を上げた Windows での見え方は、コンテナでは確かめられない。実機の exe で確かめる。
