# 言葉の決まり

画面の文（`game/text/*.csv`。置き方は `docs/text.md`）を書くときと直すときの決まり。
人間の言葉（Issue #49・#46 の 11/16 のコメント）から:

- 「『いまの対戦は取っておけないので、失われる』は自然な日本語じゃない。『対戦の状態は失われます』とかのほうが自然」
- 「保存ボタンが『とっておく』とかも日本語変」
- 「『まだ部隊がない。「あたらしく組む」で組む』みたいなのも説明書みたい。ゲームなら『編成なし』とかだけ出て、新部隊編成みたいなボタンがあるだけでいい」
- 「ゲームっぽいボタンの付け方や説明が全体的にされてない気がする」

## 決まり

1. **説明書の調子にしない。** 画面が操作を文で教えない。ボタンと状態の名前が見えれば分かる形にする（下の「操作の案内」）。
2. **ボタンは短い名前。** 名詞（「部隊編成」「対戦開始」「編成完了」）か、短い動詞（「出撃」「戻る」「外す」）。「〜する」を付けない。
   - 画面を移るボタンは「〜へ戻る」「〜へ」（「タイトルへ戻る」「対戦設定へ」）。
   - 決める・やめるは「決定」「キャンセル」。消す・捨てるは「削除」「破棄」（取り返せないものは赤いボタン）。
   - もう一度押すと確定するボタンは、どれも「もう一度押して〜」（「もう一度押して終了」「もう一度押して発動」「もう一度押して実行」「もう一度押して開始」）。
     「〜」は 2 字の漢語にそろえる。「もう一度押す」だけにはしない。
3. **状態は名詞で言い切る**（「編成なし」「未クリア」「出撃不可」「未解放」「行動済み」）。理由を添えるときは「出撃不可: 理由」。
4. **確かめは、何が起きるかを、です・ます調の自然な文で**（「タイトルへ戻りますか？」「対戦の状態は失われます。」）。
   確かめと知らせ（システムが人に話しかける文）は です・ます調。それ以外（ボタン、見出し、状態、説明）は言い切り（だ・である調の、文末を名詞か「〜する」で止める形）。
5. **中身の説明は読ませてよい**（スキル、持ち物、マップの説明、設定の項目の説明）。ただし 1 文を短く、主語と結果を先に書く。
6. **同じものは同じ名前で呼ぶ**（下の「用語」）。画面の名前と、その画面へ行くボタンの名前をそろえる。
7. **ゲームの世界の中の言葉と、画面の操作の言葉を分ける。**
   - 世界の中: 会話と途中の台詞、勝ち方の文、物語と話の名前（話のファイル。`docs/story.md`）。登場人物の口調で書いてよい。
   - 画面の操作: ボタン、見出し、状態、確かめ、案内。登場人物の口調を混ぜない。
   - チュートリアルの台詞は、世界の中の言葉で遊び方を伝える（教官の口調。1 行に 1 つ、どこを押すかとなぜか）。
8. **書き方の形**
   - 数字と英字は半角。数字の前後に半角の空白を置く（「ターン 3」「HP 44」「2 体」）。ただし記号に付く数（「+2」「-1」「×2」「3 / 6」）はそのまま。
   - 名前（駒・陣営・スキル・持ち物などの語）と、その前後の かな・漢字 の間には空白を置かない（「スペルブレードを表示中」「青の衛生兵が回復」）。
     表の文の差し込み（`{unit}が`）も同じ。数とマスの座標の前後の空白は、上のとおり置く（「{unit}が {cell} に現れた」）。
     英字や数で終わりうる名前（軍の「MILITARY」、部隊の名前の「部隊 1」）は、英字・数と同じに空白を置く（「MILITARY の物語」「部隊 1 の写し」）。
   - 括弧は全角（「（…）」）。名前を指すときは「」。見出しと値の区切りは半角の「: 」（「持ち物: なし」）。
   - **括弧の中に括弧を入れない。** 差し込む文が括弧を持ちうるなら（持ち物の効果の「（後衛専用）」など）、括弧で包まずに「効果: …」と区切る。
     言い換えの括弧は「・」でつなぐ（「攻撃力・回復量 +3」）。`tests/game/test_text.gd` が、持ち物の知らせと聖遺物の文で確かめる。
   - 並べるときは「・」（名前の並び）か「、」（文の並び）。表の `common.joiner`。
   - 文末の「。」は、2 文以上の説明と、確かめ・知らせにだけ付ける。ボタン、見出し、状態、1 文の短い説明には付けない。

## 操作の案内

人間の言葉（Issue #46 の 11/23 のコメント）から:

- 「『行動はコマのそばのメニューから』みたいな説明は、ゲームで見たことが無い。説明書かな？ ゲームの操作説明欄は、もっと助詞が少ない。
  『行動または移動先を選択』みたいな。それすら出さなくても分かる UI だと思う」
- 「そもそも分かりきった操作説明は出さなくていい」
- 「『いつもは 80%』の部分は要らない」

決まり:

- **分かりきった操作は書かない。** 押せば分かること（駒をクリックで選ぶ、マスをクリックで動く、メニューから行動を選ぶ、カードをクリックで決める）と、
  ボタンや見出しがもう言っていること（相手の番、進化先を選ぶ、待機は行動を終える）は、文にしない。
- **書くなら、体言止めの短い句。** 助詞を減らし、句点を付けない（「対象を選択」「未行動 3 体」）。「〜する」「〜できる」「〜してください」で終えない。
- **キーの割り当てと色の意味は、文でなく印で。** キーの印と一語（「右クリック キャンセル」「Esc 戻る」「ホイール ログ」）、色の印と一語（「■ 移動」）を、
  画面の隅に小さく並べる（`game/key_marks.gd`）。
- **比べる元の値を書かない。**「いつもは 80%」「ふつうは 2」のような、変わる前の値は添えない。いまの値だけを書く。
- **説明の行（オプション、メニューの項目、ツールチップ）も言い切りで短く。**「〜を止める」「〜が替わる」より「停止」「反映」。
  演習の話で操作を教えるのは、話の台詞の役目（決まり 7）。画面の案内では教えない。

## 陣営の呼び方

- 対戦モード: 色とプレイヤーの番号で呼ぶ（「プレイヤー1（青）」「青」、CPU が動かす側は「CPU（赤）」）。2 人で遊べ、どちらの側にも立たないので。
- ストーリー: その話の相手に合わせた**呼び名**で呼ぶ（Issue #46 の 11/26「ストーリーの敵兵味方の表現、敵によって変えたほうがゲームぽい」から。
  `names.gd` の `story_names` と `story_shorts`。出撃準備と対戦の画面が入るときに切り替える）。呼び名は話のファイルの `[ally]`・`[enemy]` の `name`・`short`、
  書かなければ軍の既定（「ベルク連邦」「リュエル騎士領」「亡者の群れ」、短く「連邦」「騎士領」「亡者」。`docs/story.md` の「話のファイル」）。
  - 長い呼び名（9 字まで）: 番の知らせ（「ベルク連邦 教導隊の番」）、決着の画面、出撃準備の敵の部隊の見出し（「敵の部隊　リュエル騎士領」）、マスの説明、ログの番の行。
  - 短い呼び名（5 字まで）: 上の帯の番の札と陣営の欄（「教導隊　兵 6」）、ログの兵の名前の前（「教導隊のパラディン」）。
  - 兵の情報の所属の札だけは、間柄の「味方」「敵」（`Names.side_relation`）。決着の画面の理由も、遊ぶ人の側から（「敗北　将が倒れた」）。
  中立は「中立」のまま。

## 「兵」と呼ぶ

人間の言葉（Issue #46 の 11/23）: 「ストーリーモードにおいてコマは登場人物なので、『駒』と呼ぶこと自体が違和感がある」「まあ兵でいいんじゃないかなあ、基本の呼び方は」

- **画面の文は、どのモードでも「駒」「コマ」「ユニット」と言わず、「兵」と呼ぶ**（「雇える兵」「兵の縁取り」「兵 5 / 6」）。
  - まず、言わない形にする（「未選択」「巻き込みなし」「未行動 3 体」）。数えるときは「体」。
  - ストーリーの間は、人を指すなら「味方」「敵」「仲間」（下の「陣営の呼び方」）、種類を指すなら「兵種」（「雇える兵種」）、決着の表の見出しは「名前」
    （鍵を分ける。`result.table.unit` と `result.table.unit.story`。`Names.story_sides` で選ぶ）。
  - 中立は「中立の敵」。
- `tests/game/test_text.gd` の `test_texts_do_not_say_piece` が、表の文と、話のファイルの「覚えること」・題を見張る。
