# 勝ち負け

コード: `rules/battle.gd`（`winner`、`is_over`、`is_draw`、`capture_turns`、`count_capture`、`settle`、`hold_turns`、`turns_left`、`end_turn`）、`rules/actions/end_phase_action.gd`、
`rules/events/game_won_event.gd`、`rules/events/game_drawn_event.gd`、`rules/events/capture_progress_event.gd`、拠点は `rules/stronghold.gd`。
テスト: `tests/rules/test_victory.gd`、`tests/rules/test_relics.gd`（中ボスの撃破）、`tests/rules/test_scenario.gd`（勝ちの条件の列）、`tests/game/test_win_text.gd`（画面の勝ち方の文）、引き分けは `tests/rules/test_map_objects.gd`。

プレイヤーごとに**勝ちの条件の列**を持ち、そのどれかが満たされた時点で決着し、`GameWonEvent`（勝った陣営と理由）が出る。決着したあとは、どの行動も受け付けない。

## 画面

勝ち方は、対戦の始めの「対戦ルール」（`docs/battle-view.md` の「対戦ルール」）、出撃準備の勝利条件の欄（「対戦ルール」と同じ札）、上の帯の勝利条件の札・拠点の札に、同じ印（`game/goal_mark.gd`。スクリプトで描く）で出す。
短い名前は画面の文の表の `battle.goal.name.<勝ち方>`（将の撃破・本陣の占拠・守り切る・全滅・<番人の名前>の撃破・拠点の確保。守り切る対戦の相手の側は「時間の限り」）。

## 勝ちの条件の列

- 列は戦いの定義（`Scenario.win_conditions`。`docs/scenario.md`）がプレイヤーごとに持ち、対戦を作るときに `Battle.win_conditions` へ写す。
  条件は、決着の理由と同じ値（`GameWonEvent.Reason`）で表す。そのプレイヤーがその勝ち方で勝てるかは `Battle.wins_by(プレイヤー, 条件)`。
- 既定（`Scenario.STANDARD_WIN_CONDITIONS`）は、両方とも「敵の将を倒す」「敵の本陣を占拠し続ける」。
  対戦モードは、これに「拠点を確保し続ける」が足される（対戦設定の既定。「拠点: なし」にすれば足さない。`docs/match-setup.md` の「選べる決まり」）。
- 勝ち方は、敵の将を倒す（`KING_DEFEATED`）、敵の本陣を占拠し続ける（`HQ_CAPTURED`）、守り切る（`TURNS_HELD`）、全滅させる（`ROUTED`）、
  中ボスを倒す（`BOSS_SLAIN`）、拠点を確保し続ける（`STRONGHOLD_HELD`）。
- 拠点のある対戦（対戦モードの既定）では、対戦を作るとき（`MatchSetup.create_battle`）に、両方の列へ拠点を確保し続けるを足す。
- 画面で勝ち方を知らせる文（上の帯の勝利条件の札と、マウスを乗せると出る文）は `game/win_text.gd` が、札（「対戦ルール」と出撃準備）は `game/battle_texts.gd` の `goal_cards` が列から作る。
  全滅させるがあって将の撃破が無い列では、「敵の将を倒しても、ほかの兵が残っていれば終わらない。」を言い添える。
  中ボスの撃破があって将の撃破が無い列では、「敵の将を倒しても終わらない。」を言い添える。
  相手が将のいない群れ（`docs/scenario.md`）なら、どちらも言い添えない（倒す将がいない）。
- 列に無い勝ち方では勝たない。
  - 「敵の将を倒す」が無いプレイヤーは、相手の将を倒しても勝たない（将は盤から消え、対戦は続く）。
  - 相手が将のいない群れ（`docs/scenario.md` の「将のいない群れ」）なら、「敵の将を倒す」では決着しない（倒す将がいない）。
  - 「敵の本陣を占拠し続ける」が無いプレイヤーは、占拠を数えない（数は 0 のまま、`CaptureProgressEvent` も出ない）。

- 決着したかは `Battle.is_over()`、勝った陣営は `Battle.winner`（決着していないか、引き分けなら -1）。

## 敵の将を倒す

- 将が倒れたら、その相手のプレイヤーの勝ち（相手の列にこの勝ち方があるとき）。倒した行動の結果の最後に `GameWonEvent` が付く。
- 誰が倒したかは問わない。起爆樽の爆発（`docs/map-objects.md`）で自分の将を倒したら、相手の勝ち。

## 引き分け

- **1 つの行動で両方の将が倒れたら、引き分け**（起爆樽の爆発に両方の将が巻き込まれたとき）。
  片方だけが「敵の将を倒す」を持つなら、引き分けではなく、そのプレイヤーの勝ち。
- `GameWonEvent` のかわりに、行動の結果の最後に `GameDrawnEvent`（理由）が付く。
- `Battle.is_over()` と `Battle.is_draw()` が真になり、`Battle.winner` は -1 のまま。決着なので、どの行動も受け付けない。

## 敵の本陣を占拠し続ける

- 自分のフェーズの終わり（ターン終了）に、敵の本陣のマスに自分の駒が乗っていれば、占拠の数が 1 進む。
  乗っていなければ 0 に戻る。
- 占拠の数が **3**（`CAPTURE_TURNS_TO_WIN`）に達したら、そのプレイヤーの勝ち。そのフェーズのあとへは進まない。
- 入っただけでは数えない（数えるのはフェーズの終わり）。
- 本陣のマスから自分の駒がいなくなったら（動いた・倒された）、その時点で 0 に戻る。
  ただし、その移動を取り消したら、動く前の数に戻る。
- **スキルで駒の位置が変わったとき**（シャドウステップ。`docs/skills/shadow-step.md`）も、同じに数える。
  本陣のマスから跳んで出れば 0 に戻り（取り消せないので、戻らない）、相手の本陣に乗っている敵と入れ替われば、その敵の占拠が 0 に戻る。
  跳んで（入れ替わって）敵の本陣に乗っても、数えるのはフェーズの終わり。
- 占拠の数が変わったときに `CaptureProgressEvent`（プレイヤーと、いまの数）が出る。
- 自分の本陣に乗っても数えない。

## 守り切る

ストーリーの話が選べる勝ち方（対戦モードには無い）。決められたターン数（`Battle.hold_turns`。戦いの定義の `hold_turns` から写す）の
ターンが終わるまで決着しなければ、守り切るが勝ちの条件にあるプレイヤー（守る側）の勝ち。

- 「ターンが終わる」のは、そのターンの中立のフェーズのあと、次のターンへ進む前（`Battle.end_turn`）。決着したら、次のターンへは進まない。
  理由は `GameWonEvent.Reason.TURNS_HELD`。
- 守る側を作るのは `Scenario.hold_for(プレイヤー, ターン数)`: 守る側の列は、いつもの 2 つに守り切るを足したもの（相手の将を倒しても、
  本陣を占拠し続けても勝てる）。攻める側の列は変えない（守り切られる前に、将を倒すか本陣を占拠し続ければ勝ち）。
- 残りのターン数（いまのターンを含む）は `Battle.turns_left()`。守り切るが、どちらの列にも無ければ -1。
- `hold_turns` が 0 なら、守り切るは働かない。両方の列に置く定義は作らない（置いたら、プレイヤー1 が守る側）。

## 全滅させる

ストーリーの話が選べる勝ち方（対戦モードには無い）。全滅が勝ちの条件にあるプレイヤーは、相手の駒（将を含む）が盤に 1 体も残っていなければ勝ち。
理由は `GameWonEvent.Reason.ROUTED`。

- 見るのは行動のあと（`Battle.settle`）。将の撃破のあとに見るので、列に将の撃破もあれば、将を倒した時点で将の撃破の勝ちになる。
  「将だけでなく全部を倒す」戦いは、列を全滅だけにする（`Scenario.set_win_conditions(プレイヤー, [ROUTED])`）。

## 中ボスを倒す

ストーリーの話が選べる勝ち方（対戦モードには無い）。中立と聖遺物を教える演習（`drill_shrine`）が、人の勝ち方をこれだけにする
（将を倒しても終わらないので、中ボスを狩らずには終われない）。

- この勝ち方が列にあるプレイヤーが、どちらかの中ボス（`docs/neutral-mid-boss.md`）に止めを刺したら、そのプレイヤーの勝ち。
  理由は `GameWonEvent.Reason.BOSS_SLAIN`。`GameWonEvent` は、聖遺物を受け取った（`RelicGainedEvent`）あと、行動の結果の最後に付く。
- 見るのは `Battle.settle`（将の撃破・全滅のあと）。止めを刺した駒がいない中ボスの撃破では勝たない。
- CPU の手は、相手が将のいない群れのときだけ、この勝ち方を読む（狩る条件を見ずに、中ボスを狩る）。ほかは、いつもどおり中ボスを狩る条件で狩る（`docs/relic-buff.md` の「CPU」）。

## 拠点を確保し続ける

対戦モードの勝ち方（対戦設定の既定で「拠点: あり」。`OptionalRules.STRONGHOLD`。`docs/map-objects.md` の「拠点」）。ストーリーの話には無い。理由は `GameWonEvent.Reason.STRONGHOLD_HELD`。
テスト: `tests/rules/test_stronghold.gd`。

- **拠点は盤に 1 つ**（`Board.stronghold_cell`）。確保は**陣営ごとに 1 つの数**で数える（`Battle.stronghold_holds`）。
  拠点を 2 つ以上置く決まりは無い（置くなら、数え方（拠点ごとか、陣営の合計か）と、上書きで 0 に戻る範囲を決める必要がある）。
  画面の拠点の札は、拠点がいくつでも同じ枠で読める形にしてある（`docs/battle-view.md` の「画面に出るもの」）。
- 自分のフェーズの終わり（ターン終了。敵の本陣の占拠を数えたあと）に、拠点に自分の駒（将でない）が乗っていて、拠点の隣（上下左右。
  拠点から 1（`Stronghold.CONTEST_RADIUS`）マス以内、マンハッタン距離）に相手のプレイヤーの駒がいなければ、そのプレイヤーの確保が 1 進む（`Stronghold.count`）。中立の駒は数えない。
- 確保が **8**（`Stronghold.HOLDS_TO_WIN`）に届いたら、そのプレイヤーの勝ち。そのフェーズのあとへは進まない。
- **相手が確保を進めると、自分の確保は 0 に戻る**（上書き）。乗らずに番を終えても、隣に相手がいて進まなくても、自分の確保は減らない。
- **将は乗っても確保を進めない**（将が前に出る理由を作らない。将の撃破と本陣の占拠は、いつもどおり）。
- 確保が変わったときに `StrongholdProgressEvent`（プレイヤーと、いまの数）が出る（進んだプレイヤーの分、続けて 0 に戻った相手の分）。
- あと何回で勝つかは `Stronghold.holds_left(対戦, プレイヤー)`（拠点が無いか、勝ちの条件に無ければ -1）。
- 数え方をこう決めた理由（比べた形と数字は、入れた PR と手直しの PR の本文）: 遊ぶ人には「乗っていれば進む」がいちばん素直なので、
  止まるのは、相手が拠点の隣まで来ている間だけにした（目で見て分かる）。周りの相手を見ない形（乗っているだけで進む。乗り続けないと 0 に戻る形も、数え始めを遅らせる形も）は、
  相手の軍が着く前に居座った側がそのまま勝ち、ほとんどの局が拠点で決まった。隣で止まる形なら、将の撃破で決まる局のほうが多い。
  数は、拠点での決着が多すぎず（将の撃破のほうが多い）、決着が早まりすぎないところ。
- 先手がやや勝ち越す。数え始めを遅らせる、後手の確保を少なくする、置き場所を後手に寄せる、を測ったが、
  数の手はほとんど効かず、置き場所の手は盤ごとに逆向きに振れて手で作ったマップのめやすを外れたので、いまのまま（数字は `docs/cpu-ai.md` の「いまの集計」）。
