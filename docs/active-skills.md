# スキル（共通の決まり）

コード: `rules/skill.gd`（スキル 1 つの定義の親）、`rules/skills.gd`（共通の決まり。スキルの並び）、`rules/skills/`（スキルごとの中身）、
`rules/actions/use_skill_action.gd`、`rules/events/skill_used_event.gd`、`rules/events/skill_ready_event.gd`、
`rules/events/skill_damaged_event.gd`、
`rules/unit.gd`（`skill_cooldown`）。
テスト: `tests/rules/test_skills.gd`（共通の決まり）、`tests/rules/skills/`（スキルごと）。

駒の種類ごとに 1 つ持つ、クールダウンのある行動。**ここにあるのは、どのスキルにも共通の決まりだけ。**
スキルごとの中身（対象、効果、数値、CPU の使い方）は `docs/skills/` に 1 つずつ置く。どのスキルが入っているかは、そのディレクトリを見る。

## 誰が持つか

- スキルは駒の種類で決まる（`Skills.of_kind(種類)`、`Skills.of(駒)`）。1 種類の駒は、スキルを 1 つだけ持つ。進化しても変わらない。
- 将と中立の駒は持たない。まだスキルの入っていない種類も、持たない（`null`）。
- スキルの定義は `Skill` の子のクラスで、状態を持たない。名前（`display_name`）、1 行の説明（`summary`）、
  クールダウン（`cooldown`）、対象のマス（`target_cells`）、効果が及ぶマス（`affected_cells`）、効果（`apply`）を持つ。

## 行動の流れの中での位置

1 回の行動は「移動（1 回まで。動かなくてもよい）→ 攻撃・回復・**スキル**・待機のどれか」（`docs/turn-phase.md`）。

- **スキルを使うと、行動を終える**（攻撃・回復・待機のかわり。`UnitActedEvent`）。使ったあとは、移動の取り消しもできない。
- **動いたあとでも、動かずにでも使える。巡航で動いた駒は使えない**（攻撃・回復と同じ扱い）。
- 使えるのは、自分のフェーズの、行動済みでない駒（`Battle.can_act`）で、クールダウンが 0 のとき。
- スキルだけの条件（動いていないこと、残りの回数など）が要るものは、そのスキルが `Skill.is_ready` で足す。

## クールダウン

- 駒が「残り」（`Unit.skill_cooldown`）を持つ。0 なら使える。対戦の始めは 0（最初のターンから使える）。
- 使うと、そのスキルのクールダウン（`Skill.cooldown()`）が付く。
- **持ち主のフェーズの始めに 1 減る**（盤の上の効果の期間と同じ数え方。`docs/field-effects.md`）。
  相手のフェーズと中立のフェーズでは減らない。使ったフェーズの中では減らない。0 より下がらない。
- つまり、クールダウン N のスキルは、**使ったターンの N ターン後にまた使える**。
  ターン 1 に使ったクールダウン 4 のスキルは、ターン 2・3・4 の始めに 3・2・1 と減り、ターン 5 の始めに 0 になって、ターン 5 に使える。
- フェーズの始めに起きることの順は、`PhaseStartedEvent`、回復の泉、再生の特性、盤の上の効果（聖域の回復、残りが減る）、
  最後にクールダウン（`Skills.start_phase`）。0 になった駒に `SkillReadyEvent` が出る（駒の番号の順）。
- 倒れた駒は盤にいないので、何も起きない。

## 対象

- 行動は `UseSkillAction.new(駒の番号, 対象のマス)` の 1 種類。どのスキルかは駒の種類で決まる。
- **対象は、いつもマスで指す。** マスを選ぶスキルはそのマス、駒を選ぶスキルはその駒のいるマス、自分に使うスキルは自分のマス。
  画面と CPU は、どのスキルも同じ形（対象のマスの並びから 1 つ選ぶ）で扱える。
- いまの位置から選べるマスは `Skills.target_cells(対戦, 駒)`（上の行から、左の列から）。使えない駒では空。
  スキルの射程と測り方（マンハッタン距離か、周り 8 マスか）は、スキルごとに決める。
- 対象を選んだときに効果が及ぶマスは `Skill.affected_cells(対戦, 駒, 対象)`（範囲のスキルの広がり。画面が塗る）。

## イベント

`UseSkillAction` が返すイベントは順に、

1. `SkillUsedEvent`（使った駒、スキル（`Skill.Id`）、対象のマス、付いたクールダウン）
2. スキルの効果のイベント（盾が置かれた、など。スキルごとの文書）
3. `UnitActedEvent`

| イベント | 中身 |
| --- | --- |
| `SkillUsedEvent` | 駒がスキルを使った。効果のイベントは、このあとに続く |
| `SkillReadyEvent` | 駒のクールダウンが 0 になった（駒、スキル）。持ち主のフェーズの始め |
| `SkillDamagedEvent` | 駒がスキルでダメージを受けた（`UnitDamagedEvent` の子。`cause` は `SKILL`。使った駒、スキル） |

## ダメージのあるスキル

駒にダメージを与えるスキルは、効果（`Skill.apply`）の中で共通の入口 `Skills.deal_damage(対戦, 使った駒, [[駒, 量], ...])` を呼ぶ。
どの駒にいくつ与えるか（範囲、敵だけか、量）はスキルが決め、与え方はここで決める。

- 並べた駒の全員に**同時に**当たる。駒ごとの `SkillDamagedEvent` が、並べた順に、間にほかのイベントをはさまずに続く。
  量は、残りの HP より多くてもそのまま（攻撃と同じ）。
- HP が 0 になった駒は、全員のダメージのあとに、同じ並びで取り除く（`UnitDefeatedEvent`）。将が倒れたときの決着は、ほかの行動と同じ。
- 使った駒に経験値が入る。相手ごとに駒の攻撃と同じ表（`Growth.damage_experience`: 当たって生き残れば 10、倒せば 50、中立の駒は 30）で数え、
  **いちばん多く入る 1 体ぶんだけ**（何体に当てても 1 回）。誰にも当たらなければ入らない。
- 予測（`Skills.preview`）、画面の見込みと再生、CPU は、`SkillDamagedEvent` を `UnitDamagedEvent` として読むので、
  ダメージのあるスキルを足しても、そのまま乗る。

## 選べること

`Battle.options()` の `skill_cells` に、いまの位置からスキルの対象に選べるマスが載る（`docs/battle.md`）。
`Battle.can_apply(UseSkillAction)` が受け付けるマスと一致する。`actions()` には、マスごとに 1 つ、回復のあと・待機の前に並ぶ。

## 予測（計算と適用の分離）

- `Skills.preview(対戦, 駒の番号, 対象)` は、使ったら起きることをイベントの列で返す。**状態は変えない**（乱数も進めない）。
  実際に使うのと同じ処理を、複製（`Battle.clone()`）の上で走らせるので、結果は必ず実際と一致する。使えなければ空。
- ダメージや回復のあるスキルは、返ってきた `UnitDamagedEvent` / `UnitHealedEvent` を読めば、相手ごとの量とあとの HP が分かる。
- 画面の見込み（`docs/battle-view.md`）と CPU（下）が、これと同じ読み方を使う。

## CPU

- CPU は、スキルの手も、ほかの手と同じに複製の上で使ってみて、起きたイベントから価値を読む（`docs/cpu-ai.md`）。
  ダメージ・回復・経験値のイベントで価値が決まるスキルは、それだけで使えるようになる。
- 盤に何かを置く、状態を付けるなど、イベントだけでは価値が決まらないスキルは、
  `CpuPlayer.SKILL_VALUES` に「スキル → 価値を見積もるメソッド」を 1 行足す。見積もり方は、スキルごとの文書に書く。
- 使うのは、動かずに使う手（どこへ動くかと比べる）と、動いた先で使う手（動いたあとに、攻撃・回復・待機と比べる）。
  スキルを使うために立つマスを探すことはしない。

## スキルを足すとき

1. `Skill.Id` に 1 つ足す。
2. `rules/skills/` に `Skill` の子のクラスを書く（調整値は、そのファイルの先頭に置く）。
3. `Skills.ALL` に 1 つ並べる。
4. 効果に新しいイベントが要れば `rules/events/` に足し、画面の再生（`board_prototype.gd` の `event_players()`）に載せる。
   駒へのダメージは `Skills.deal_damage` を呼べば足り、イベントを足さなくてよい。
5. イベントだけで価値が決まらなければ、`CpuPlayer.SKILL_VALUES` に 1 行と、見積もるメソッドを足す。
6. `docs/skills/` に文書、`tests/rules/skills/` にテストを置く。

画面の操作（スキルのボタン、対象を選ぶ、見込み）と、選べること、複製、クールダウンは、足したスキルにそのまま効く。

## まだ決めていないこと

- **行動を終えないスキル**: 仕様のシャドウステップは、ワープのあとに攻撃できる。いまの土台は「使うと行動を終える」だけなので、
  そのスキルを入れるときに、`Skills.use` に例外の入口を足す（Issue #8 の「決めること 6」）。
- **攻撃の解決に割り込むもの**（被ダメージを 0 にするバリア、確定クリティカル、身代わり、ノックバック）: 仕組みはまだ無い。
  ダメージの計算は `Combat.damage`、適用は `Combat.strike` の 1 か所ずつなので、最初に要るスキルがそこへ入れる。
