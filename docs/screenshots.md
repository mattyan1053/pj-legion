# スクリーンショット

PR に画面の絵を貼るための道具。人間はスマホで PR を見ることが多いので、見た目を確かめてほしい PR には絵を貼る。
撮るのも置くのも手元（作業のセッションのコンテナ）で回す。CI には入れない。

## 撮る

    tools/screenshots.sh godot <出力のディレクトリ> [場面,場面,…|all] [--size=<幅>x<高さ>]

- 画面の無いコンテナでは、Xvfb（仮想の画面）とソフトウェア描画（OpenGL 3 / llvmpipe）で撮る。全部（`all`）は時間が掛かるので、ふつうは要る場面だけを撮る。
- スクリプトが読み込めない（文法の誤りなど）ときは、待たずにすぐ失敗し、読み込めなかった箇所を出す。
- 撮らずに場面が作れることだけを確かめるときは、画面なしで `godot --headless --path . -- --shots <場面,…|all> --dry-run`。
  長い検査（`tools/check.sh --full`）が、作れなくなりやすい場面のいくつかをこれで回す。
- 道具は、画面（`battle_screen.gd` など）の名前の付いた入口（`place_camera`、`hover_menu_item`、`open_deck_picker` など）だけを使い、
  画面の中の変数には触らない。足りなければ、画面の側に入口を足す（中を変えても、道具が黙って壊れないように）。
- 窓の大きさは `--size`（既定は 1280×720）。窓と仮想の画面をその大きさにして撮る（`docs/screen-size.md`）。
  大きい画面ほど遅い（2560×1440 で、1 枚あたり 1280×720 の 3〜4 倍）。大きさを変えて比べるときは、出力のディレクトリを大きさごとに分ける。
- 窓の大きさの JPEG（1280×720 で 1 枚 100〜250 KB）を `<場面>.jpg` で書く。
- 場面は `tools/screenshots.gd` の `SCENES`（名前と説明）にある。一覧は `tools/screenshots.sh <godot> --list`（撮らずに、名前と説明を出す）で見る。
  **この文書には場面の一覧を書かない**（場面を足す PR が毎回同じ行に書き足して、衝突するため）。
  場面は、次のようなまとまりで並ぶ。どれも種を決めた対戦を CPU どうしで進めて作るので、同じコードからは同じ絵になる。
  - 画面の入口: タイトル、システムメニュー、マップ選択、対戦設定、部隊編成、オプション（対戦の外の画面。アプリをその場面へ切り替えて撮る）。
  - ストーリー（`story_` で始まる）: 物語選択、話の一覧、会話、出撃準備、話の対戦（守り切る話、全滅させる話、途中の会話）、決着、解放の知らせ。
  - 対戦の操作: 駒の選択、移動範囲、メニュー、マスの情報、脅威範囲、スキルの対象、必殺技、ターン終了の確かめ。
  - 予測と情報: 戦闘予測のパネル、駒の情報、メニューの項目の説明。
  - 対戦の外の枠: リザルト、ログ、ミニマップ。
  - カメラと盤の見え方: 見下ろす角度、引いた全景、盤の外、マップごとの見た目の比べ。
  - 演出の途中のコマ: 攻撃の当たり方、スキルの形、必殺技、環境オブジェクト（`_mid_animation` で撮る）。
- **場面を足す**ときは、`SCENES` に名前と説明を 1 行足し、`_scene_<名前>()` を書く。`_advance()` で CPU どうしの対戦を
  条件が来るまで進め、`_show()` で画面に出し、人の操作と同じ入口（`click_cell`、`press_menu`、`press_skill` など）で選ぶ。
  ルールや数値が変わると、同じ種でも場面が変わる。**種は決め打ちしない。** 場面の関数が偽を返したら、`_run` が種を替えて
  作り直す（`SEED` から `MORE_SEEDS` 個先まで）。場面の関数は「条件が来たか」を正直に返す（来なかったのに真を返すと、違う絵が撮れる）。
  どの種でも作れなかった場面は飛ばして、ほかの場面を撮り、最後に「作れなかった場面」をまとめて出して失敗で終わる。
- **前の場面の状態を持ち越さない。** 場面ごとに、設定、相手、ログ、マウスを乗せたこと（盤のマスとメニューの項目）、敵の全員の脅威範囲、カメラを戻してから作る（`_run`）。
  場面で新しく「乗せたことにする」状態を足したら、ここで戻す（戻し忘れると、`all` で撮ったときだけ後ろの場面が作れなくなる）。
- **演出の途中のコマを撮る場面**は、行動を始めたら終わりを待たずに、決めた時刻で撮る（`_mid_animation`）。描画の遅い環境では 1 コマが長く、
  短い演出を飛び越えるので、撮る間は時間の速さを落とす（`SLOW_MOTION`）。
- 撮る前に、画面の中央の知らせ（番の知らせなど）が消えるのを待つ（`SETTLE` のあと、さらに `BANNER_WAIT` 秒まで）。
- コンテナの描画は Windows の実機（Vulkan）と違う（影、光、文字の太さ）。最終の見え方は exe で確かめてもらう。

## 置く

    tools/publish_screenshots.sh <PR の番号> <出力のディレクトリ>

- 画像専用のブランチ `screenshots`（`main` とつながらない独立のブランチ）へ直接 push し、PR に貼る Markdown を出す。
  ブランチが無ければ作る。作業中のブランチと作業ツリーには触らない（一時のディレクトリで push する）。
- 置き場所は `pr-<PR の番号>/<いまの HEAD の短い id>/<ファイル名>`。既にあれば `-2`、`-3` … を付ける。
  同じ URL の中身は差し替えない（GitHub が画像をキャッシュするため）。直したら撮り直して、新しい場所に置く。
- 別のセッションと同時に push してぶつかったら、取り込み直してやり直す（5 回まで）。
- リポジトリは public なので、`https://raw.githubusercontent.com/<owner>/<repo>/screenshots/<パス>` がそのまま表示される。
