# スクリーンショット

PR に画面の絵を貼るための道具。人間はスマホで PR を見ることが多いので、見た目を確かめてほしい PR には絵を貼る。
撮るのも置くのも手元（作業のセッションのコンテナ）で回す。CI には入れない。

## 撮る

    tools/screenshots.sh godot <出力のディレクトリ> [場面,場面,…|all]

- 画面の無いコンテナでは、Xvfb（仮想の画面）とソフトウェア描画（OpenGL 3 / llvmpipe）で撮る。全部で 40 秒ほど。
- 1280×720 の JPEG（1 枚 100〜250 KB）を `<場面>.jpg` で書く。
- 場面は `tools/screenshots.gd` の `SCENES` にある（対戦の設定画面、対戦の途中で開いた設定画面、システムメニュー、ゲームを終える前の確かめ、設定の画面、メニューの項目の説明、対戦の始め、見下ろす角度の下限と上限、移動範囲と駒のそばのメニュー、マスの情報、
  動いたあとのメニュー、攻撃の相手を選ぶところ、駒が固まっているところのメニュー、画面の隅の駒のメニュー、脅威範囲、スキルの対象、必殺技、
  中ボスと聖遺物、決着の画面と戦績、いちばん引いた全景、盤の角とその外、カメラを回したところ、寄って見た駒の足元の印、ほかの 2 つのステージの全景）。どれも種を決めた対戦を CPU どうしで進めて作るので、同じコードからは同じ絵になる。
- **場面を足す**ときは、`SCENES` に名前と説明を 1 行足し、`_scene_<名前>()` を書く。`_advance()` で CPU どうしの対戦を
  条件が来るまで進め、`_show()` で画面に出し、人の操作と同じ入口（`click_cell`、`press_menu`、`press_skill` など）で選ぶ。
  ルールや数値が変わると、同じ種でも場面が変わる（場面が来なければ失敗で終わる。そのときは条件か種を直す）。
- コンテナの描画は Windows の実機（Vulkan）と違う（影、光、文字の太さ）。最終の見え方は exe で確かめてもらう。

## 置く

    tools/publish_screenshots.sh <PR の番号> <出力のディレクトリ>

- 画像専用のブランチ `screenshots`（`main` とつながらない独立のブランチ）へ直接 push し、PR に貼る Markdown を出す。
  ブランチが無ければ作る。作業中のブランチと作業ツリーには触らない（一時のディレクトリで push する）。
- 置き場所は `pr-<PR の番号>/<いまの HEAD の短い id>/<ファイル名>`。既にあれば `-2`、`-3` … を付ける。
  同じ URL の中身は差し替えない（GitHub が画像をキャッシュするため）。直したら撮り直して、新しい場所に置く。
- 別のセッションと同時に push してぶつかったら、取り込み直してやり直す（5 回まで）。
- リポジトリは public なので、`https://raw.githubusercontent.com/<owner>/<repo>/screenshots/<パス>` がそのまま表示される。
