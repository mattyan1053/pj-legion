# 通しで触って不具合を探す

人間が遊ぶ前に、遊ぶときに引っ掛かる不具合を先に拾う。見た目の好みは決めない（下の「不具合と好み」）。

## 道筋の作り方

- **人の操作と同じ道で通す。** 本物の入力イベント（`InputEventMouseButton`・`InputEventMouseMotion`・キー）を組んで
  `get_viewport().push_input()` や画面の名前の付いた入口（`click_cell`、`press_menu` など）へ渡す。画面の中の変数を直接いじらない
  （`game/autoplay.gd` と `docs/screenshots.md`）。
- 場面は `tools/screenshots.sh godot <出力> <場面,…>` で撮る。無い場面は `tools/screenshots.gd` に足す。
  絵は Forward+（既定。Windows の exe と同じ）で撮って見る。互換の描画の絵で見た目を判断しない（`docs/screenshots.md`）。
  画面の大きさの違いは `--size=<幅>x<高さ>` で撮り分ける（`docs/screen-size.md`）。
- CPU どうしで何局も回すと、決着の間際など手で作りにくい場面に当たる（`tools/cpu_matches.gd`、`--autoplay --full`）。
- **まず長い道を通す**: `tools/sweep.sh godot`（`story` / `versus` / `all`。既定は `all`。両方で 2 分ほど）。
  - `story`（`-- --autoplay --story-all`）: 両方の物語を第 1〜15 話まで、タイトルから画面の道で通す。話の一覧は F5 で全部を開き、
    話ごとに出撃準備 → 前の会話を 1 文ずつ送る → 途中の台詞（`[cues]`）を 1 つずつ出して送る → 小さな盤でわざと負けて、負けの台詞（`[lost]`）を見る →「話の一覧へ」。
  - `versus`（`-- --autoplay --versus-all`）: 対戦モードの全部のマップを、試しの決まり（`TrialRules.ALL`）を全部切ったものと全部入れたもので、
    タイトル → マップ選択 → 対戦設定（相手は CPU）→ 数ターン（自分の番は「おまかせ」。作戦が入なら 1 枚使う）。試しの決まりが増えても、そのまま回る。
  - 中身は `game/autoplay_sweeps.gd`。足りない確かめはそこに足す。長い検査（`tools/check.sh --full`）も同じものを回す。
- 台詞と画面の文の折り返しの切れ方は `godot --headless --path . -s res://tools/wrap_audit.gd`（`docs/battle-view.md` の折り返し）。

## 見る所

撮った絵は**自分の目で見る**（Read で開く）。数字や「撮れた」だけで済ませない。

- 重なる画面（設定、メニュー、ログ、編成）での Esc・右クリック・× の閉じ方。閉じたあとに操作が戻るか。
- 場面の切り替え（対戦 → 決着 → タイトル → もう一度）で残るもの: 枠、音、カメラ、選んだ駒、マウスを乗せた状態。
- 文字の見切れ・はみ出し・語の途中の折り返し・重なり（装備や駒の多い部隊、長い名前で）。
- 演出の途中の操作（連打、右クリック、メニューを開く）。決着の間際（最後の 1 手、本陣の占拠、引き分け）。
- 保存ファイルが壊れている・無い・古い版のとき（`docs/system-menu.md`）。設定の端（音量 0 と最大、画面の大きさの端）。
- 長く回したときのエラーのログと、オブジェクトの数が増え続けないか。

## 直し方

- **意図ごとに小さい PR**（不具合 1 つに 1 本が基本）。本文は「見つけた不具合 / 直したこと / テスト」と、前（main）と後のスクリーンショット。
- 直したら、再現するテストか自動の対戦（`game/autoplay.gd`）の確かめを足す。直す前のコードで落ちることを確かめ、そう書く。

## 不具合と好み

- 不具合: 操作が効かない、戻れない、表示が崩れる、エラーが出る、ルールと画面が食い違う。→ 直す。
- 好み・見た目が大きく変わるもの（札の置き場所、色、演出の長さ、並び）。→ **直さず Issue #46 に書く**（どこで何を見たかと、絵）。
- 迷ったら好みとして #46 に書く。

## 報告

見つけて直したもの（PR）、#46 に書いたものに加えて、次も書く。

- **見て、見つからなかった所**（次の点検で同じ所を繰り返さないため）。
- **確かめられなかったこと**（実機の描画、音、操作の手触り、作れなかった場面と「起こりうる」と見たもの）。
