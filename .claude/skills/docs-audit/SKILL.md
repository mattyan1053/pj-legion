# 文書の棚卸し

文書の置き方の正は `docs/README.md`。ここでは、照らし方と直し方だけを並べる。

## 照らし方

- 前の棚卸しのあとに変わった機能から見る（`git log` で `rules/`・`game/` が変わった PR を拾う）。
- 文書に出てくるファイル名・関数名・定数名・引数を、全部コードで引く。消えた名前、変わった名前を拾う。
- 文書の先頭の「コード」「テスト」の一覧に、抜けと消えたファイルが無いか。
- 操作の表、場面の遷移、「無い」「まだ」「後で」「仮の」と書いた所を、いまのふるまいと読み比べる。
- 数値は、検査（`tests/docs/test_doc_values.gd`）が見ている書き方になっているか。見ていない数は、定数の名前を添えて検査に乗せるか、数を使わない言い方にする。
- `README.md` の遊び方・動かし方が、いまの画面と道具に合っているか。

## 直し方

- **文書にはいまの仕様と理由だけを書く。** 経緯、元の仕様（`pj-region`）との比べ、「以前は」は消す（経緯は PR の本文に残る）。
- **コードの表を写しただけの一覧は文書に置かない**（場面、素材、盤の一覧など）。足す PR ごとに同じ行へ書き足して conflict する。
  「正はコード」と書いて、その場所（と一覧を出す道具）を指す。
- 文書とテストが食い違ったらテストが正、調整値はコードが正。ふるまいは変えない。直すべきなのがコードのほうなら、直さず報告する。
- 実測の数字は `docs/cpu-ai.md` の「いまの集計」だけに置く。ほかの文書に残っていれば、そこを指す形に直す。
- Issue（#46、#47 など）の本文がコメントで読みにくくなっていれば、本文を「いまのまとめ」に書き直す（済んだ項目、未決の項目）。コメントは経緯として残す。
- **`CLAUDE.md` は触らない。** 食い違いは報告に書く。

## 報告

- 直した件数と種類、大きかったもの。
- 見送ったものと理由。コードのほうで気になったもの（直していない）。
- 遊んで決めることが出てきたら、Issue #47（ルールと数値）か #46（見た目と操作）に足したこと。
