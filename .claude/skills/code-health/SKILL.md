# コードの健康診断

1 つの作業のセッションは 1 つの仕事しか見ない。全体を通しで読む者がいないと、同じ物が 2 か所にでき、足し忘れても誰も気付かない所が増える。
それを定期に洗う。**読むだけ。直したくなっても直さない**（直す仕事は、診断を見てメインが 1 本ずつ頼む）。

## 出すもの

- `docs/code-health.md` を**書き直す**（書き足さない。前の版は `git log` に残る）。PR は文書だけ。
- 形は、いまの文書の見出しに合わせる: 全体の診断（5 行。人間はコードを読まないので「放っておくと何が起きるか」で書く）、
  見つけたもの（多くて 15 件。何が・どこに・放っておくと・手間・急ぎ）、健康な所、これから入る大きいものの見立て、
  直す順のおすすめ（ふるまいを変えない仕事と変える仕事を分け、1 本ずつ頼める大きさに）、測る数字、確かめられなかったこと。
- **前の診断と比べる。** 「測る数字」の表は、前の値と今回の値を並べる。前の「見つけたもの」は、直った・残っている・悪くなった、を 1 行ずつ。

## 読み方

- 基準は、始めた時点の main。途中で入った大きい変更は、最後に見直す。
- **根拠はファイルと行で引く。推測で書かない。** 確かめられなかったことは、そう書く。
- 観点ごとに分けて読む（並べて読ませてよい。読ませた結果の要の所は、自分でコードを引いて確かめる）。
  1. 効果の積み方: ダメージ・移動・射程・回復の計算は 1 本の道か。順はどこに書いてあるか。効果を 1 つ足すときに触るファイルを、実際に数える。
  2. 出来事: 種類ごとに読む所（再生、ログ、戦績、予測、CPU、実測の道具）と、足し忘れを検査が拾うか。
  3. ルールと画面の境: 画面が対戦の状態を書く所、画面や CPU がルールの決まりを別に持つ所。
  4. 重複: 同じ表、ほぼ同じ関数、写しの画面・窓・部品、道具の重なり。
  5. 話の作り: 話のファイル → 会話 → 出撃準備 → 対戦 → セーブ。次に足す予定のものが足せる形か。
  6. データとコード: 兵・軍・魔物・スキル・状態を 1 つ足すときに触るファイルと、書き忘れを検査が拾うか。
  7. テストと検査: ルールの核は変えたら落ちるか。`check.sh` の時間と、中身が増えると伸びるもの。
  8. 状態: グローバルな変数、セーブの形と、古いセーブの読み替えの置き場所。
  9. 文書: 設計を知らない作業のセッションが、正しい場所に正しい形で足せるか。足りない手順。
- 直近の大きい PR が何ファイルを変えたか（`git diff --name-only <マージ>^1 <マージ>`）は、「足すときに触る場所」の実測になる。

## 測る数字

`docs/code-health.md` の「次の健康診断で見るもの・測る数字」の表を、同じ測り方で埋め直す。足した物差しは、測り方も文書に書く。

- コードの量: `git ls-files 'rules/**.gd' | xargs cat | wc -l` など。600 行超・500 行超のファイルの数。
- `check.sh` の時間: `tools/check.sh godot` を 2 回回して 2 回目（取り込みの控えがある状態）の、全体といちばん長い組。
- 写しの部品: `grep -rn '^func _label' game | wc -l` など、文書の表にある名前で数える。
- 「触るファイルの数」は、いまある 1 つ（状態、軍略、出来事、軍）の名前を全体で検索して数える。

## 守ること

- `rules/`・`game/`・`tests/`・`tools/` は変えない。`CLAUDE.md` とワークフローも触らない。
- 小さい粗は数えない。「これを放っておくと、次の機能で困る」ものだけを挙げる。
- 健康な所も書く（直さなくてよい所を、次の人が直そうとしないように）。
- 試しのブランチを作ったら、報告の前に消す。

## 報告

- 全体の診断 5 行、見つけたものを急ぎの順に上から 5 つ、前の診断から直った所・悪くなった所、直す順のおすすめ、PR の番号。
